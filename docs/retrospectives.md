# 各部复盘

每部片子交付之后在这里记一段：做了什么、哪里不足、留下了哪些做法。新片子动笔前先读，上一部的不足是下一部的起点。

## 1. 一个数据库引擎是如何实现的？——从 MyISAM 说起

2026-10-01，自制，中文，7 分 55 秒。[目录](../videos/series/database-engines/myisam/)

**做法**

- 事实由两路核对：在真实的 MySQL 5.5.62 上建表、删行、插入、模拟崩溃，每个阶段把数据文件复制出来；同时读同一版本的源码。画面里的字节、偏移、页数由脚本从这些文件生成。
- 旁白逐句合成，动画时间点由词边界推出。这套做法从这一部起沿用至今。
- 成片后的三项审查查出了三处问题：多音字「行」被读成 xíng；二分查找的探测顺序与源码不符；一句注解过度概括。

**不足**

1. 视觉是深色面板式的：渐变底、半透明圆角面板、细描边、小号的英文注脚。
2. 全片由静态版面加局部淡入组成，没有镜头语言。按现行检查有二十多处超过 3 秒的静止、两处空屏。
3. 声音只有旁白和一层铺底；音效是事后补的，只在两个试听版里。铺底的低频过重。
4. 时长比「数分钟」偏长，动笔前没有定上限。
5. 画面在四个时刻依赖播放历史（文件卡片的明暗、章节卡上打字那一行的位置）。当时没有这项检查。

**留下的做法**：两路取证；由数据生成画面；`T(句号, 词)`；成片后三审；这一部结尾提出的「四个问题」成为数据库引擎系列的线索。

## 2. luainstaller：把 Lua 脚本交给没有 Lua 的人

2026-10-01 至 10-02，自制，中文 7 分 55 秒、英文 7 分 57 秒。[目录](../videos/standalone/luainstaller/)

第一版 4 分 40 秒，体量不够；第二版按「完整的介绍片」重做。

**做法**

- 结构：在它之前（既有工具的做法与实测的失败）→ 它做什么 → 安装 → 使用 → 边界 → 实现原理（八步）→ 片尾。每一句都落在一条实测回显或一段真实产物上；「不做什么」单独成章。
- 视觉只有两种颜色（藏蓝与纸白）与两种图形（圆与直线）。月亮取自项目标志，贯穿全片：标题、章节转场的起点、八个步骤的编号（八个月相）、片尾。演示程序也是一个月相计算器。
- 双语：一套场景代码，两条时间轴。字幕写正式拼写，读法放在读法表里。
- 实现原理一章把真实数据画出来：每个字节一个点的字节图，推近到点变成字符，直接读出嵌在可执行文件里的源码。
- 配乐按章节编排，层的进出挂在句号上。
- 取证在干净的容器里做，回显里的路径干净，也证明了从零可复现。

**遇到的问题**

- 渲染悄悄丢帧：成片少了 28 秒，日志没有任何报错。原因与修复见 [pitfalls.md](pitfalls.md)「渲染」一节；渲染与封装此后都带完整性核对。
- 版面越界：会转动、会长出标签的图在最不利的位置贴到了画面边缘。此后有了按像素的越界自检。
- 配乐的低频过重：靠数值自检发现并调整。
- 一张文件布局图凭推算画错，实测后重画。
- 空画面：镜头到站时站上没有东西。此后有了空画面检查。

**取证中的旁支发现**记在该片 `FACTS.md` 的末尾，没有进入成片。

**留下的做法**：双语工具链；每屏一个 `world`、按站排开、镜头在站间移动；场间转场统一在 `after()` 里做；占位再填实；贯穿全片的母题；配乐的声明式编排；渲染的完整性核对。

## 3. 古代来的 Shell：Windows 批处理（.bat）

2026-10-01，委托制作（准备：Claude；制作：DeepSeek），中文，3 分 13 秒。[目录](../videos/standalone/windows-batch/)

**做法**

- 准备方完成取证、旁白、视觉系统、四张参考关键帧、一段示范场景、逐句对应表与任务书；受托模型完成七个场景、常驻元素、音效编排、封面、渲染、三项审查与交付说明。
- 受托模型看不到画面。为此工具改成全部用文字输出：`look.js` 把一帧写成元素列表，`scan.js` 扫全片，`check.js` 把全部检查并成一道闸门。这套工具后来成为工具包的主体。
- 任务书把「好」写成可以用工具查的规则：主体的坐标范围、字号倍数、音效密度、静止上限。

**结果**

- 闸门全部通过；三项审查未发现偏差；旁白一字未改。
- 受托模型自行做出并记录了十二项取舍，其中几项后来被吸收进工具包：
  - 镜头补间一律显式给出起止值，避免画面依赖播放历史——现在是引擎的 `cam.track`。
  - 低清预演发现开场 0.5–4.0 秒是像素级静止（浅色纸在浅色底上移动），加大了推近幅度——说明元素级的静止检查不够，像素级的预演是必要的一步。
  - 对比度检查当时不看元素自己的底色，它给标签垫了一块同色实心块来绕过——检查后来改为认元素自己的底色，并按实际像素复核。
- 它如实写明了自己看不到画面、听不到声音，并指出了需要人来通看的总览图与需要比较的试听片。

**对委托方式的结论**：取证、旁白与视觉系统由准备方定死，场景交给受托模型，是可行的分法；闸门要在交接之前就能跑通；任务书里「不要重做什么」「何时该停」与「不许为过关改规则」三条必须写明。

2026-10-02。三部片子原先各带一套工具，迁入时合并成 `kit/` 里的一套，并逐项核对了能否重建已交付的成片：

| 项 | 结果 |
|---|---|
| 旁白 | 三部的全部句子都命中原有缓存，重新生成的时间线数据与原先逐项相同 |
