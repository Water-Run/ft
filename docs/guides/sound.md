# 声音

成片的声音由三层组成：旁白、配乐、音效。配乐与音效都由程序合成（`kit/tools/mix.py`），不使用任何外部素材。本文说明音效怎么登记、配乐怎么选与编排、混音参数、数值自检的读法。

能试听的制作者实际试听代表段与最终音轨；不能试听时，记录数值检查与尚未听过的范围，交由人核对。数值通过不等于听感通过。

## 1. 音效

场景里用 `sfx(名称, 时刻, { g, p })` 登记：`g` 是相对音量（缺省 1），`p` 是声像（−1 左 … 1 右，缺省 0）。混音时按登记的时刻合成并铺到时间线上。

| 名称 | 听感 | 用在哪 |
|---|---|---|
| `key` | 按键 | 打字。`typeText` 自动登记，不用手写 |
| `tick` | 短促的滴答 | 读到下一行、刻度出现、小标签出现 |
| `blip` | 上行的短音 | 终端打出一行普通输出 |
| `pop` | 圆润的弹出 | 标签贴上、新的一项被加进来 |
| `whoosh` | 气流 | 镜头跨站点移动（`cam.to` 自动登记）、大色块刷过 |
| `thud` | 低沉的撞击 | 大数字、大字、章节号砸入；物件落位 |
| `chime` | 清亮的钟音 | 一段演示得出结果的那一刻。每个场景最多一两次 |
| `error` | 低沉的蜂鸣 | 出错、与预期不符 |
| `riser` | 上升的噪声，1.2 秒 | 大转折之前的铺垫。在转折点之前 1.2 秒登记 |
| `beep` | 机箱扬声器式的方波短鸣 | 老式计算机的画面 |
| `drive` | 软驱寻道的步进声 | 老式计算机的画面 |

规则：

1. 关键动作按含义配声；装饰位移、停留时的横移和阅读保持不要求加声。不同的动作用不同的声音，不让所有入场与换章都成为同一种 `whoosh`。
2. 同一时刻不叠两个以上的音效；相邻音效至少错开 0.06 秒。
3. 声像跟着位置走：发生在画面左侧的动作 `p: -0.4`，右侧 `p: 0.4`。
4. 连续的小动作（五个标签依次出现）用同一种音效，音量递减或保持，不要每个都用重音。
5. 重音（`thud`、`chime`、`error`）用默认音量；跟在重音后面 0.3 秒内的轻音设 `g: 0.5`。
6. 题材有新旧、内外之分时，声音也跟着分：批处理一片里「当年」的画面用 `beep`、`drive`，「今天」的画面用 `blip`、`tick`。

总闸门按 `project.json` 的 `check.sfx` 查覆盖率（不含打字声）：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `per_seconds` | 全片平均每多少秒至少一个音效 | 6 |
| `kinds` | 至少用几种音效 | 4 |
| `scene_per_seconds` | 每个场景平均每多少秒至少一个；0 表示不查 | 0 |
| `max_gap` | 任意多少秒内至少有一个音效 | 20 |

覆盖阈值在开工前随叙事和声音设计确定，不以更密、更响或种类更多代表更高质量，也不为补足数量给无意义的动作加声。既有片子的阈值不为过关而事后放宽。

## 2. 配乐

节拍服务于讲解：语义动作仍锚定 `T()` / `Tend()`，不能为卡拍移动词语、删停顿或压缩阅读时间。选定 BPM 与一个来自句号的段落起点后，音乐拍点可按 `起点 + n * 60 / BPM` 生成；转场与装饰动作在语义允许的空档对齐拍点。核心机制揭示处可以减配器、停鼓或留静默，再用一次音效强调结果。修改配音后，从句号重新算起点并重做混音。BPM、动机、配器进出写在本片配乐源码，代表段用有声预演验证。

`project.json` 的 `audio.music`：

| 值 | 内容 |
|---|---|
| `pad` | 只有铺底和声 |
| `pulse` | 铺底加八分音符的拨弦琶音；每章开头几秒自动推高 |
| `chip` | 铺底加限带方波琶音与三角波低音，早期个人电脑式的音色 |
| `score` | 按章节编排各层的进出，见第 3 节 |
| `none` | 没有配乐 |
| 文件路径（相对视频目录） | 用给定的音频文件循环铺满 |
| 以 `.py` 结尾的路径（相对视频目录） | 本片或本系列自带的配乐脚本，见第 3.1 节 |

各种配乐共用同一组和弦（Dmaj9 → Bm9 → Gmaj9 → A6sus，每个和弦四小节，96 拍/分），整段循环与节拍对齐。旁白出现时配乐与音效自动压低，片头片尾自动淡入淡出。

有人提供或指定配乐时，先按[第三方许可](../reference/third-party.md)确认使用及再分发依据，再按策划要求处理。

**给策划者选。** 配乐动笔之前先做 3 个调调的 Demo（各约 60 秒，引子、推进、最高处、收束），和文案全文、配音候选、视觉关键帧放在同一张[本地审片页](../process.md#1-主线)里。调调要契合本片的对象，更要契合已定的画面；有质感，史诗感收着用，不靠堆鼓、铜管和合唱。策划者原话（2026-10-24）：「BGM 配音等也要契合对应主体, 更有质感和史诗感」「这三个都不好 这是配音, 要五个, 我说的是配乐史诗感」（P67）「再平淡一点, 注意画面契合音乐」（P68）。选定后，画面的点亮、推进与转场落在配乐的音符和拍上（见本节第一段）。

**跨片比较。** 内置预设共用和弦与速度，切换 `pad`、`pulse`、`chip` 或仅换主奏音色不能自动算新的配乐。每片说明节奏、旋律动机、和声与段落编排的选择，并与近期作品连续试听；系列起点里的配乐脚本只是占位，按本片的对象重写（F21）。信息密集处优先保证旁白清楚，不机械地越讲越加层。数值自检不判断同质化和听感（F06）。

## 3. 按章节编排（score）

`music: "score"` 时，配乐由五层组成：`pad`（铺底）、`arpA`（中音区琶音）、`arpB`（高处的稀疏音）、`bass`（低音）、`hat`（极轻的节拍）。每章从和弦循环的开头重新起，相邻两章之间交叉淡化。哪一层在哪一段出现，写在 `project.json` 里：

```json
"audio": {
  "music": "score", "music_db": -13, "duck_db": 8, "sfx_db": -8,
  "score": {
    "weights": { "pad": 1.0, "arpA": 0.62, "arpB": 0.3, "bass": 0.3, "hat": 0.09 },
    "layers": [
      ["pad",  "open",    "outro",   1.0],
      ["pad",  "scope",   "scope",   0.85],
      ["arpA", "o5-0.3",  "open",    0.8],
      ["bass", "h2-0.9",  "how",     0.8],
      ["hat",  "h17-0.8", "h31-0.8", 1.0]
    ]
  }
}
```

每条是 `[层, 起, 止, 电平]`，后写的覆盖先写的。起止的写法：

| 写法 | 含义 |
|---|---|
| `"how"` | 场景号。作起点时是该场景的开始，作终点时是该场景的结束 |
| `"how.start"`、`"how.end"` | 明确指定场景的开始或结束 |
| `"h17"` | 句号，指该句开始的时刻；`"h17.end"` 指该句结束 |
| `"h17-0.8"`、`"f3+2.0"` | 再偏移若干秒 |

找不到的场景号或句号所在的那一条会被跳过，所以同一份编排可以用于句号相同的各种语言。

编排的思路：层的进出挂在句号上；内容最密的一章逐步加层；冷静的段落只留铺底；片尾收到只剩铺底与高处的稀疏音。

### 3.1 自带的配乐脚本

内置的几种配乐共用一组和弦与 96 拍/分的速度。题材需要另一种速度、结构或音色时，在视频目录里写一个配乐脚本（习惯放在 `tools/music.py`），把 `audio.music` 指向它：

```json
"audio": { "music": "tools/music.py", "music_db": -12, "duck_db": 7, "sfx_db": -9, "score": { "lift_cue": "d6" } }
```

- 脚本里定义 `compose(ctx)`，返回形状为 `(2, N)` 的数组（左右声道，幅度任意，混音时按峰值归一）。`ctx` 给出 `sr`（采样率）、`n`（采样数）、`total`（片长）、`scenes` 与 `cues`（各自的 `id`、`start`、`end`，即当前语言的时间线）、`audio`（本片的 `audio` 段，脚本自己的参数可以放在里面）、`lang`。
- 可另给 `FADE = (开头淡入秒数, 结尾淡出秒数)`，缺省 `(2.5, 3.0)`。电平（`music_db`）、旁白压低（`duck_db`）与限幅仍由 `mix.py` 统一处理，脚本不用管旁白。
- 段落的位置从 `ctx["scenes"]` 取，不写死秒数：各语言的时间线不同，同一份脚本要对每种语言各合成一遍。
- 结果必须是确定的：随机数固定种子。
- 不要对整条分轨做任意长度的变换或大窗口卷积：两分钟的立体声是上千万个采样，长度不是 2 的幂时一次变换可能要几秒到几十秒。混响、滤波放在逐个音符上做（同样的音只算一次，放进缓存），或把变换长度取成 2 的幂。
- 写完先看数：`audio.js` 的自检给出各场景的配乐电平、三段能量占比与旁白之下的电平。范例见 [XX 秒速通首集](../../videos/in-seconds/two-factor-auth/tools/music.py)：120 拍/分，每个 30 秒的段落 15 小节，段尾铺垫、段首落点、结论处抬起。

## 4. 混音参数

`project.json` 的 `audio` 段，均可省略：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `music` | 配乐类型，见上 | `pad` |
| `music_db` | 无旁白时的配乐电平 | −21 |
| `duck_db` | 旁白出现时配乐再压低多少 | 9 |
| `sfx_db` | 音效总电平 | −8 |
| `sfx` | `false` 时不铺音效 | `true` |
| `lufs` | 成片的响度目标（`finish.js` 按它算增益，`check.js --final` 按它 ± 1.5 核对）。不影响混音内部的比例 | −16 |
| `voice_norm` | 旁白的归一方式：`rms`（按响度对齐到 −21 dB 再软限幅）或 `peak`（按峰值归一到 0.89） | `rms` |
| `pad_low`、`pad_top` | 铺底里低音区与高音区的增益 | 0.4、1.3 |
| `limit` | 总输出超过 0.97 时整体压低 | `true` |

`voice_norm: "peak"`、`pad_low: 1`、`pad_top: 1`、`limit: false` 是最早两部片子的做法，留着是为了能逐样本重建它们的混音；新片子用缺省值。

正式混音参数写入 `project.json`，以便复现与检查。命令行的 `键=值` 只用于带 `out=<试听文件名>` 的临时混音：

```bash
node kit/tools/audio.js <视频>                                  # 正式混音
node kit/tools/audio.js <视频> --lang zh music=chip out=audio_b.wav   # 试听用的另一条混音
```

正式混音的产物在 `out/<语言>/`：

| 文件 | 内容 |
|---|---|
| `audio.wav` | 主混音：旁白 + 配乐 + 音效 |
| `audio_voice.wav` | 仅旁白 |
| `audio_nomusic.wav` | 旁白 + 音效，没有配乐 |
| `stem_music.wav`、`stem_sfx.wav` | 配乐与音效的分轨 |

混音是确定的：同样的输入得到逐样本相同的输出。改了任何入场时刻之后要重新混音，因为音效事件是从场景里登记的。

正式混音同时写 `build/audio.<语言>.json`，记录旁白、配乐、辅助源文件、配置和输出的内容校验和。封装前核对记录；旧混音、变化后的配乐脚本或试听覆盖的分轨不能混进正式交付。只修改 `audio.lufs` 时，重做封装即可。

## 5. 数值自检

`audio.js` 混完之后自动运行 `audio_check.py`，输出三样：

```
章          配乐电平   低/中/高（占比 dB）      章节卡处   旁白之下
s1           -42.8 dB    -1.4 /  -5.6 / -56.9       -36.5 dB     -45.9 dB
s2           -43.4 dB    -1.5 /  -5.3 / -54.4       -37.9 dB     -45.7 dB
成片混音：峰值 0.894，|x|>=0.999 的采样 0 个，旁白 -25.4 dB，整体 -26.7 dB
I:         -22.3 LUFS LRA:         5.7 LU Peak:       -0.9 dBFS
```

（上例取自 MyISAM 一片按旧参数重建的混音。）读法：

- **三段能量占比**（低于 150 Hz / 150–1500 Hz / 高于 1500 Hz）：看各层是否按编排进出，低频是否过重。合成铺底的低音很容易过重：上例低频 −1.4 dB、中频 −5.6 dB，即约四分之三的能量在 150 Hz 以下，小音箱上听不到、耳机里发闷，这正是 `pad_low`、`pad_top` 的缺省值后来改掉的原因。低频约 −4 dB、中频约 −2 dB 比较均衡。
- **章节卡处与旁白之下的电平差**：看压低是否生效，差值应接近 `duck_db`。
- **峰值与削波**：`|x| >= 0.999` 的采样应为 0。
- **整体响度**：这是混音阶段的值；成片的响度由 `finish.js` 处理到目标值（缺省约 −16 LUFS，见 `lufs`）。

## 6. 成片的响度与版本

`finish.js` 先量主混音的响度，算出一个固定增益再加限幅（不用单遍的 `loudnorm`，它会抽动），三个版本用同一个增益，旁白电平因此一致。目标：响度 −16 ± 1.5 LUFS（`audio.lufs` 可按片改，例如 −14），峰值不高于 −1 dBFS。策划者看过成片后嫌整体音量小，就把这一片的 `lufs` 调高（《垃圾回收的艺术》用 −14，与常见平台的参照值一致），只需重新 `finish.js`，不必重渲。

每种语言固定给出三个版本：

| 文件 | 内容 |
|---|---|
| `out/<slug>-<语言>-1080p60.mp4` | 主混音 |
| `out/<slug>-<语言>-1080p60-voice-only.mp4` | 仅旁白 |
| `out/<slug>-<语言>-1080p60-no-music.mp4` | 旁白 + 音效（配乐为 `none` 时没有这一版） |

文件名里的 `1080p60` 取自画面的实测高度与帧率；按 4K 交付（`render.scale` 为 2）时是 `2160p60`。

需要比较两种配乐时另出试听片：

```bash
node kit/tools/audio.js  <视频> --lang zh music=chip out=audio_b.wav
node kit/tools/finish.js <视频> --lang zh --audio out/zh/audio_b.wav --name 试听-复古配乐
node kit/tools/audio.js  <视频> --lang zh          # 把正式混音恢复为默认
```

交付说明据实写明配乐与音效来源、实际试听范围及未听部分。能试听的制作者亲自试听；不能的交由策划者确认，不预填“已听”或“无法试听”。只改混音参数时，重跑 `audio.js` 与 `finish.js`，再核查受影响的成片音轨。

调整 `music_db`、`duck_db`、`sfx_db` 要有实际试听或数值问题作为依据；调整后重新比较旁白清晰度、压低效果与峰值。听不到时只能记录数值检查和策划者试听反馈，不宣称听感改善。
