# 取证

取证是每部片子的第一步：先弄清事实，再写脚本。本文规定事实记在哪里、证据怎么留、哪些东西不入库。

## 1. 目录

每部视频的取证材料都在它自己的 `research/` 下：

| 路径 | 内容 | 入库 |
|---|---|---|
| `research/FACTS.md` | 逐句的事实出处：陈述 ↔ 依据 | 是 |
| `research/lab/` | 实验脚本与完整回显、取回的数据文件 | 是，逐字节保存，不做换行转换 |
| `research/_src/` | 第三方源码、安装包等 | 否。在 `FACTS.md` 里记版本、获取地址与校验和 |
| 体积大的构建产物 | 可由实验脚本重新得到的二进制 | 否。在该片目录的 `.gitignore` 里列出，并在 `FACTS.md` 里说明如何重做 |
| `tools/gen_data.py`（在视频目录下） | 把 `research/lab/` 的原始数据转成画面用的 `src/js/data.js` | 是 |

## 2. FACTS.md 的写法

- 开头写明取证日期、对象与版本。
- 「取证环境」一节列出每份记录是在什么环境里得到的（系统、版本、是否干净环境）。
- 之后按场景分节，每节一张表：句号或陈述、依据。依据要具体到能复查：哪份回显的哪一段、哪个源文件的哪一行、哪份文档的哪一节。
- 每条记录写清核查状态、适用版本或环境、来源日期与核查日期；引用网页保留直达链接与章节，引用源码保留版本或提交号。标题、字幕、封面与译文中的事实也要能对应到记录。
- 「制作署名」一节记录策划者 WaterRun、实际参与模型的名称、可确认的版本、分工，以及开源视频的 GitHub 仓库链接与记录依据，用于片尾和交付说明。仅记录可核实的信息，规则见 [standards.md](standards.md) 第 7 节。
- 成片后的三项审查中发现并更正的内容，逐条记入最后的「复核」一节。
- 取证中发现的、与题目相关但没有进入成片的事实，另列一节，供日后更新时使用。

## 3. 出处的优先级

亲手做实验取得的数据 > 源码 > 官方文档 > 其他。两路以上的出处互相印证后再写进脚本；同一原始来源的转载不算独立印证。模型输出与搜索摘要只作查找线索，必须读到原文或复现实验才能记为依据。

- 题目允许时，把真实系统运行起来取数据。能在干净环境（容器、新装的系统）里重做一遍的，就在干净环境里做：回显里的路径干净，也顺带证明了「从零可复现」。
- 推算出来的数字一律实测核对。曾有一张文件布局图按「总大小减去各部分大小」推出，结果是错的；实测（把产物真的运行一遍，列出它解出的每个文件，在产物里原样查找得到偏移）之后才画对。
- 版本史、市场份额这类外部事实，记下数据来源与截至日期。
- 竞品或既有方案的不足，用实测的失败回显展示，同时写清它们能做到什么。
- 核对来源是否支持句中的因果、比较、范围与限定条件。局部实验不能直接推成普遍结论；译文不得加强原文结论或删掉限制条件。
- 只有单一出处、来源冲突或尚无证据的陈述标为「待核实」，不得进入定稿。补足证据、收窄表述并重新核查，或删除；不能用几个模型回答一致来代替交叉核查。
- 定稿前核查一次，成片后按 [review.md](review.md) 第 5.1 节再查一次。会变化的外部事实在交付前重新确认，并记录截至日期；改过陈述或画面后重新核查对应内容。

## 4. 证据怎么留

- 实验脚本与完整回显都留在 `research/lab/`。脚本按执行顺序编号；回显与脚本同名对应（`11_usage.sh` ↔ `out_11_usage.txt`）。
- 画面上要出现的命令，先确认它在回显里原样存在。
- 画面上的数字、字节、偏移由脚本从回显与产物里算出来，场景代码里再断言一遍。
- 数据量大的输入用生成脚本代替数据本身：把生成脚本入库，并在 `FACTS.md` 里记下生成结果的校验和。回显里成段重复的内容（例如被原样回显的上千行 `INSERT`）可以用一行说明代替，同时记下原文件的校验和。
- 实验用完即清：临时建的库、目录、容器镜像、缓存；别人已有的同名目录不动。

## 5. 不写进仓库的内容

仓库是公开的开源仓库：入库即公开，没有「只给协作者看」的文件。回显、数据文件、截图说明、配置样例、提交信息都按同一标准处理，提交前过一遍将入库的改动。下列内容不出现在任何入库文件里，包括回显：

- 口令、密钥、令牌、API key。宁可现场再生成一个，也不把真实的值存档入库；脚本需要时从环境变量读。
- 内网地址、主机名、跳板方式。
- 个人目录里能识别身份的部分。回显里的用户目录在入库前替换成通用写法（例如 `C:\Users\user`），并在 `FACTS.md` 里注明做过替换。
- 第三方源码与安装包。它们各有自己的许可；这里只记版本与获取方式。

画面里同样不出现主机名、用户名、内网地址和演示目录以外的本机路径。

## 6. 由数据生成画面

`tools/gen_data.py` 是「回显与产物 → 画面数据」的唯一通道：

```bash
python videos/<…>/<视频>/tools/gen_data.py     # 读 research/lab/，写 src/js/data.js
```

- `src/js/data.js` 入库，标明「由脚本生成，不要手改」。
- 生成脚本依赖不入库的材料时，在脚本开头写明；缺少这些材料时脚本无法运行，但已生成的 `data.js` 不受影响。
- 迁移或整理取证材料之后，重新运行生成脚本并确认 `data.js` 逐字节不变。

可参考的做法：

| 画法 | 含义 | 出处 |
|---|---|---|
| 每个字节一个点的字节图 | 整份文件一眼可见，再按真实偏移分别点亮各段，最后推近到点变成字符 | luainstaller 一片的 `parts.js` |
| 字符网格逐格翻成十六进制 | 文本变字节，与生成文件逐字节比对 | 同上 |
| 源码缩略图 | 每一行画成一条短线，长度就是那一行的长度 | 同上 |
| 按比例的文件布局图 | 各部分的偏移与大小取自实测 | 同上 |
| 十六进制视图、B 树 | 数据文件的真实字节与索引页 | MyISAM 一片的 `components.js` |
