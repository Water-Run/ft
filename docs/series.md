# 系列

仓库里的视频分两类：独立成篇的（`videos/standalone/<视频>/`）与属于某个系列的（`videos/series/<系列>/<视频>/`）。本文规定系列内要保持的连续性，以及它在仓库里靠什么来维持。

## 1. 连续性指什么

同一系列的各集，观众应当一眼认得出是同一个系列，并且能把这一集与上一集放在一起比较。要保持一致的方面：

| 方面 | 内容 |
|---|---|
| 标题 | 同一种格式，例如 `一个数据库引擎是如何实现的？——<副题>` |
| 结构 | 相近的章节骨架与先后顺序；保留的栏目沿用同样的名称 |
| 贯穿的线索 | 每集都回到的同一组问题或同一种比较，使各集可以对照 |
| 视觉 | 同一套颜色、字体、字号阶梯、图形语言、章节卡与常驻元素、封面版式 |
| 演示与取证 | 尽量用同一个演示对象（同一张表、同一道小题、同一项任务），同一种取证方式，同一套度量口径 |
| 声音 | 同一种配乐类型与混音参数，同样的音效用法 |
| 开场与收尾 | 相同的片头与片尾做法；结尾引出下一集或回扣上一集 |
| 术语与读法 | 同一个术语在各集写法一致、读法一致 |

连续性不等于模板化。各项里标为「建议」的是起点：每一集按题目增删、合并、调整比重，重点落在这一集最值得讲的地方。

## 2. 靠什么维持

**系列说明** `videos/series/<系列>/README.md`。每个系列一份，写明定位与各项约定。首集制作时定下的做法写回这里，后续各集遵守；要改约定，先改这里。文件末尾「分集」一节的表格由 `catalog.js` 维护，其余部分手写。

**建议栏目**。系列可以在片单里带一组建议的栏目（`videos/catalog.json` 里该系列的 `sections`，每项有 `id`、`zh`、`en`）。它不强制：

- `new.js` 新建分集时按它生成章节草稿——脚本里每栏一章，每章一个场景文件——之后可以随题目增删调整。
- `check.js` 在本集缺少某个栏目、或保留的栏目先后与约定不同时给出提示，但不据此判定不通过。

**系列基座** `videos/series/<系列>/_base/`。首集完成后，把这一集里各集都要沿用的源码整理到这里：通常是 `src/css/style.css`（视觉系统）、`src/js/config.js`（章节卡与换场）、`src/js/parts.js`（部件）、`src/cover.html`（封面版式）。`new.js` 新建该系列的分集时，把基座盖在通用模板之上。

- 基座是「新建时拷入的一份」，不是共享引用：之后改基座不影响已经做完的各集。已完成的片子因此始终可以按自己目录里的源码重建。
- 目录名以下划线开头的不算分集，片单核对时会跳过。
- 改进了某个部件、希望后续各集都用上时，把改动同步回基座。

**片单**。分集的先后就是它们在 `videos/catalog.json` 里的顺序。

## 3. 新建一集

```bash
node kit/tools/new.js series/<系列>/<视频>
```

它依次：从片单取标题与语言 → 拷入通用模板与引擎快照 → 按建议栏目生成章节草稿 → 套用系列基座 → 把片单里这一条的状态改为制作中并更新系列说明的分集表。

开工前先读系列说明；做完之后把这一集新定下的做法写回系列说明。

## 4. 新开一个系列

```bash
node kit/tools/new.js series/<新系列>/<首集> --series-title "系列的中文名" --title "首集标题"
```

片单里没有这个系列时，`new.js` 会登记它，并生成系列说明的骨架。然后在系列说明里写明定位，在首集制作过程中逐项确定连续性约定。计划中的各集可以先在片单里登记标题（手改 `videos/catalog.json` 后运行 `node kit/tools/catalog.js`）。

## 5. 首集与后续各集的分工

- 首集承担建立系列的工作：视觉系统、章节卡、贯穿的线索、演示对象。这些决定要放在「这个系列还会有很多集」的前提下做，不为首集的题目量身定做。
- 首集的不足不必沿用。数据库引擎系列的首集（MyISAM）建立了「四个问题」这条线索，但它的视觉系统不再沿用，自下一集起重新建立。
- 后续各集先看前面几集的成片与 README，再动笔：术语、度量口径、图形的含义都要接得上。
- 一集里引用另一集时，说出那一集的标题；跨集比较的数据在本集的 `FACTS.md` 里重新给出处，不依赖另一集的记录。
