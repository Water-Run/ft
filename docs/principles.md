# 宗旨与原则

本仓库以自由软件和共产主义精神为宗旨，用大语言模型协助制作讲清楚一件事的视频，公开内容、制作方法和改进成果。以下原则指导制作中的取舍；具体步骤见[制作周期](process.md)。

## 自由软件，自由视频

本仓库是自由软件，以 GNU 通用公共许可证第 3 版或（由使用者选择的）任何更新的版本（GPL-3.0-or-later）发布，全文见 [LICENSE](../LICENSE)。

本项目对有权授权的源码、文档和视听作品均明确采用这一许可。可编辑文案、场景、音画材料及构建步骤与成片一起交付，使作品可以被研究、修改和再制作：

- **运行**：任何人都可以为任何目的观看、放映、使用这些视频。
- **研究**：每一帧都是 `f(t)`，每一句旁白都有出处，每一个数字都能回到实验里重算。
- **修改**：改一句文案、换一种配色、纠正一个事实，然后重新出片。
- **分发**：原样或修改后再发布；分发受覆盖的改编作品时，按 GPL 提供相应源码并保留接收者的权利。

本项目采用公开源码的交付方式。**自制、委托第三方、外部协作均须交付可编辑源码并按项目许可发布**；接受制作任务时就说明这一点，交付时核对，不能以换制作方或只提供成片绕开。完整材料、第三方权利与 GPL 适用边界统一见[开源交付与第三方许可](reference/third-party.md)。

## 共产主义精神

知识是人类共同创造的财富。本仓库把共产主义精神落实为具体的协作方式：

- **生产资料公开。** 工具、源码、可编辑材料和制作方法让他人取得、研究和改进；隐私、凭据及无权再分发的材料另按边界处理。
- **各尽所能，共同负责。** 人与模型按实际能力分工；取证和写作同样需要质量判断，不能因为便宜或处在前期就降低要求。
- **成果回到公共。** 一部片子里摸索出的做法，要提炼回 `kit/` 与 `docs/`，成为下一部片子的起点，而不是留在某一部片子的目录里。
- **如实记录贡献。** 人按本人意愿使用姓名、昵称或笔名，模型记录准确型号和版本；分工按实际贡献填写，不漏记、不冒领。具体规则见[署名](roles.md#5-署名)。
- **以理解和传播为目的。** 让知识更易获得、更易验证；评价依据内容与实际效果，接受有依据的批评。

## 内容大于形式

视频的价值首先在于讲了什么，以及观众能否理解。事实正确、选材有判断、解释完整、叙事连贯，比形式复杂更重要。画面、声音与技术应帮助观众理解内容。

- 先说明观众已有的知识、看完要回答的问题，以及为什么值得讲。
- 取证要形成对对象的理解：整体如何组成，一件事情如何从输入走到结果，原因和边界是什么。
- 先把文案写成能通读的讲述，再拆字幕、安排镜头。章节之间有推进，结尾回应开头的问题。
- 内容讲不通时，回到取证、取舍或改稿。更多动画、更密音效、更长文档和更多检查项都不能补上解释缺口。
- 形式必须认真完成，但复杂度由内容需要决定。质量标准和检查阈值照常执行；从内容上解决冲突，不靠装饰凑数或降低闸门。

## 好文档支撑好叙事

文档要让下一位参与者读懂、复查并继续工作。

| 文档 | 应当回答 |
|---|---|
| README 简报 | 讲给谁、回答什么、怎样推进、舍弃什么、策划者明确要求是什么 |
| FACTS 与证据 | 这句话为什么可信、在什么条件下成立、如何复查、还有什么不确定 |
| 文案与校对记录 | 讲述是否自然完整、意见怎样处理、谁明确确认了哪一稿 |
| 交接与交付记录 | 哪些真实完成了、哪些没做、依据在哪里、下一步依赖什么 |

先写结论与决定，再给依据和必要细节。只记录本片特有的信息；通用规则用链接，不把规则全文复制到每个项目。需要阅读的正文要连贯，需要查找的证据用表格；文件大小、表格行数和模型自评不是完成质量的证据。信息归属见[文档地图](README.md#4-信息归属)。

## 工作原则

1. **画面是时间的纯函数。** 整部片子是 t 的函数，任意一帧都能独立算出。这使并行渲染、逐帧检查与任何人的复现成为可能。
2. **事实有出处。** 画面与旁白里的每一项事实都记在该片的 `research/FACTS.md`，能回到原始来源或实验。模型的记忆与搜索摘要不是依据。
3. **人审定内容。** 文案经校对者明确确认之后才配音；成片由策划者实际观看、试听后决定是否接受。工具负责可以自动核对的项目。
4. **不把简单的问题交给人。** 审片页、预览与成片交出之前，制作方先做自对抗审查，把自己能发现的问题修掉；人的时间留给内容、叙事与审美的判断。见[制作周期](process.md#2-自对抗审查)。
5. **如实记录。** 没做的写没做，没看的写没看。不补造确认，不把「流程改了」写成「成片修好了」。
6. **按题材设计。** 视觉与声音围绕本片内容和讲解对象设计。值得复用的方法先整理进 `kit/` 或 `docs/`，再供其他片子使用。
7. **反馈改进规则。** 先核查原因，再改进已有规则；单片偏好留在单片，只有可推广的教训才进入公共规则，避免不断堆叠要求。见 [经验规则](lessons.md)。
8. **控制熵。** 每一类信息只有一个存放处，分仓库、系列、视频三级；派生的内容由工具生成。见 [文档地图](README.md) 的「信息归属」。
