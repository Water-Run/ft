# 场景与动态

本文说明场景怎么写：页面的工作方式、空间与镜头、元素的动作、转场、节奏，以及「画面只由时间决定」这条规则的具体含义。引擎函数的完整列表见 [engine.md](engine.md)。

写场景的制作者可能看不到画面。本文的规则都写成可以照着做、可以用工具查的形式；判断画面一律以 `look.js`、`scan.js` 的文字输出为准。

## 1. 页面怎样工作

整部片子是时间 t 的函数。

- 页面加载时，每个场景的构建函数执行一次：把元素建好，把「什么时刻发生什么」登记到一条暂停的时间线上。
- 之后工具通过 `window.seek(t)` 跳到任意时刻取帧。渲染是多个浏览器各渲一段、并行出帧，每个浏览器从自己那一段的起点直接跳入。
- 因此：构建函数里的普通代码只在加载时运行一次，不是「播放到那里才执行」；让某件事在某个时刻发生，只能通过登记函数（补间、`F()`、`keyed()` 等）。

**铁律：画面只由 t 决定。** 同一个 t，无论是顺着播到这里，还是直接跳到这里，画面必须相同。具体地：

- 不用 CSS `transition` / `animation` / `@keyframes`。
- 不用 `setTimeout`、`setInterval`、`requestAnimationFrame`、系统时间。
- 不用 `tl.call()` 与时间线回调（`onComplete`、`onUpdate` 等）。
- 不用 `Math.random()`；需要随机数时用固定种子的 `seeded(种子)`。
- `F()` 里不累加状态：`F((t) => { n++ })` 是错的，`F((t) => { el.style.width = (t / L.total * 1920) + 'px' })` 是对的。
- 一个元素只做一次入场。
- 同一个属性不要被两个补间在重叠的时间段里同时改。`to()` 式的补间在第一次被渲染时把「当时的值」记作起点：顺着播时记下的是前一个补间走到一半的值，直接跳到后面时记下的却是前一个补间的终点，两条轨迹因此不同。连续的多段运动要么首尾相接、互不重叠，要么每段都显式给出起点（`fromTo`，镜头用 `cam.track`）。
- 元素在时刻 0 的状态要正确：一开始不该出现的元素，由它的入场动作保证「入场前不可见」（`wipe`、`slam`、`slide`、`appear`、`show` 都自带），或显式 `vanish(el, 0)`。

违反时的后果是实际的：首部作品里有几处文件卡片的明暗取决于播放历史，重新渲染时各段起点一变，那几秒的画面就与原先不同。`scan.js` 的 `NONDET` 项专查这一条。

## 2. 一个场景的骨架

```js
scene('demo', ({ root, s, c0 }) => {
  // root：本场的容器（1920×1080）   s：{ id, start, end, lead, chap }   c0：内容可以开始出现的时刻（章节卡之后）
  const world = h('div', 'world', root);        // 比画面大的画布
  const cam = makeCamera(world);                // 镜头

  const head = h('div', 'abs d-2', world, tr('第一站', 'Station one')); px(head, 120, 160);
  wipe(head, c0 + 0.1, { dir: 'l' }); sfx('whoosh', c0 + 0.1, { g: 0.5 });

  cam.track(s.start, { x: 960, y: 540, z: 1 }, [                        // 镜头轨迹：起点，然后是各关键帧
    [c0 + 0.1, { z: 1.03 }, 6, { ease: 'none', sfx: false }],           // 站内的慢推
  ]);
});
```

- 所有时刻都是绝对时刻（秒），由 `T(句号, 词)`、`Tend(句号)`、`s.start`、`s.end`、`c0` 推出，不写死数字。
- 场景里第一个元素的入场不早于 `c0 + 0.1`，否则会叠在章节卡上。
- 场景文件按出场顺序列在 `src/index.html` 里；一章可以拆成数个文件。

## 3. 空间与镜头

以连续的空间和镜头运动为骨架，而不是一屏一屏换面板。

- 每个场景一个 `world`，内容按「站」排开（例如每站相隔 1920 或 2000px），镜头在站与站之间移动。
- 站内用极慢的推近保持画面不死：在轨迹里加一段 `[t, { z: 1.035 }, 5, { ease: 'none', sfx: false }]`。
- 镜头在倍数 z、中心 (x, y) 时能看到的范围是横向 x ± 960 / z、纵向 y ± 540 / z。推近之前先算一下要看的东西是否在这个范围里，再用 `look.js` 核对。

一个场景的镜头写成一条轨迹：

```js
cam.track(s.start, { x: 960, y: 540, z: 1 }, [
  [c0 + 0.1,           { z: 1.03 },          6,   { ease: 'none', sfx: false }],   // 慢推
  [Tend('a1') + 0.1,   { x: 2880, z: 1 },    1.0],                                 // 移到第二站，自动登记一声 whoosh
  [null,               { z: 1.04 },          5,   { ease: 'none', sfx: false }],   // null：接在上一段结束后 0.15 秒
  [T('a4', '字节') - 0.3, { x: 3100, y: 420, z: 1.5 }, 1.1],                        // 推近看细节
]);
```

每个关键帧是 `[时刻, 去向, 时长, 选项]`：去向只写要变的分量；时长缺省 1.4 秒；选项里 `ease` 缺省 `power3.inOut`，`sfx: false` 关掉自动登记的 `whoosh`，`g` 是它的音量。每一段的起点就是上一段的终点，由轨迹显式给出，所以镜头的位置只由 t 决定。

| 其他写法 | 作用 |
|---|---|
| `cam.cut(t, { x, y, z })` | 在 t 时刻把镜头直接放到某处 |
| `cam.to(t, { x, y, z }, { d, ease, sfx })` | 单段的移动，从「当时的位置」出发。各段在时间上不能重叠，否则画面会依赖播放历史 |
| `cam.frame(t, 元素, { pad, maxZ, d })` | 把镜头对准某个元素，四周留白比例 `pad`（缺省 0.4）。同样是单段 |

规则：

1. 每个场景至少三次明确的镜头运动（站点之间的平移、推近看细节、拉回全景），没有明确运动的时段保持缓慢漂移。
2. 看细节的推近倍数 1.3–1.6；超过 2 时字会糊，周围也全被切掉。站点之间平移用 0.8–1.2 秒，推近用 0.9–1.3 秒，拉回用 0.6–0.8 秒。把真实数据推近到「点变成字符」这类大倍率（6–12 倍）是例外，见第 8 节。
3. 镜头先到，动作后到：要强调的东西出现之前 0.2–0.4 秒，镜头已经开始朝它移动。
4. 镜头到站时，站上已经有东西：标题、占位的空心图形、终端的提示符。不要让第一个元素等到关键词才出现。
5. 上一句说完再走，下一句开始前到站：把上一句的 `gap` 留够，移动的起点写成 `Tend(上一句) + 0.1`。
6. 跨站点的大幅移动按内容选择音效，不默认每次配 `whoosh`；缓慢漂移和阅读保持不配气流声。不需要时用 `sfx: false` 关闭自动登记。
7. 推近时旁边的次要文字被画面边缘切掉是正常的；这一刻旁白讲的主体必须完整在画面里。
8. 长命令的打字用镜头跟拍：光标走到画面四分之三处之后，镜头与光标同速移动。
9. 推近以终点为准、拉远以起点为准来算镜头中心（缩放按指数走），否则镜头会先往反方向漂。

## 4. 元素的动作

| 动作 | 写法 | 适合 |
|---|---|---|
| 刷出 / 刷走 | `wipe(el, t, { dir, d })`、`wipeOut(el, t, { dir, d })`，`dir` 为 `'l' 'r' 't' 'b'` | 色块、终端、纸张、标题、线条 |
| 砸入 | `slam(el, t, { from, d })` | 大数字、大字、标签。配 `thud` 或 `pop` |
| 滑入 / 滑出 | `slide(el, t, { x, y, d })`、`exit(el, t, { x, y, d })` | 新增的一行、从画外进来的物件 |
| 打字 | `typeText(el, html, t, 每秒字数, { cursorUntil })` | 敲入命令、写代码。自带按键声，返回打完的时刻 |
| 立即出现 / 消失 | `appear(el, t)`、`vanish(el, t)` | 终端里新打出的一行输出 |
| 淡入 / 淡出 | `show(el, t, { y, x, d })`、`hide(el, t)` | 可以用，但不作为主要的入场方式 |
| 数字滚动 | `countTo(el, 起, 止, t, 秒)` | 字节数、百分比 |
| 换内容 / 换类名 | `keyed(el).at(t, { html, cls })`、`classAt(el, 类, 起, 止)`、`swapAt(el, 旧, 新, t)` | 文件名改变；某一行在一段时间内高亮 |
| 描线 | `draw(path, t, d)`、`arrowIn(path, t, d)` | SVG 线条与箭头 |
| 补间任意属性 | `to(el, t, { … })`、`fromTo(el, t, { … }, { … })`、`set(el, t, { … })` | 位置、宽度、缩放 |
| 每帧计算 | `F((t) => { … })` | 进度条、月相、任何由 t 直接算出的东西 |

规则：

1. 入场方式要有区分：同一屏里的几个元素用不同的方式或不同的方向入场，并错开 0.08–0.2 秒。全片不要只用一种。
2. 重点用揭示动作：每句旁白的关键词对应一个明确的动作，发生在那个词被读到的时刻。
3. 终端的行为要像终端：输出是整行瞬间出现，只有人敲的命令才用打字机。
4. 机制图按理解步骤推进；0.15–0.3 秒只适合已经建立的连续小动作，新概念和推导不能照这个间隔赶场。只给需要强调的关键步配声。
5. 占位再填实：把「需要三样东西」画成三个空心图形先摆出来，说到哪个，哪个填实。
6. 两屏的内容相关时，让元素跟着镜头过去（上一站的圆飞到下一站变成表格的行首），比各自淡入淡出连贯。
7. 不用无限循环的装饰动画。光标闪烁由 `typeText` 自带，或用 `F((t) => el.style.opacity = Math.floor(t * 2) % 2 ? 1 : 0)`。
8. 遮罩揭示（文字从遮罩后升起）的位移给到 140% 左右：遮罩留了上下内边距防止裁掉笔画，位移只给 110% 时字头会露出来。

## 5. 换场

`config.js` 的 `window.ENGINE` 决定场景之间怎样衔接：

| 设置 | 效果 |
|---|---|
| `sceneFade` 缺省（`true`） | 每个场景整屏淡入淡出。最省事，也最像幻灯片，正式的片子不用 |
| `sceneFade: false`，没有 `after()` | 硬切：每个场景在「本场开始后 `sceneCut` 秒」到「下一场开始后 `sceneCut` 秒」之间显示（缺省 0.45 秒）。切换的那一刻由常驻层里的整屏色块盖住，通常就是章节卡 |
| `sceneFade: false`，有 `after()` | 场景的显隐与转场全由 `after()` 编排：例如新场景用 `clip-path` 从一个圆或一条边展开，场景各带底色 |

章节卡写在 `chrome()` 里。硬切方式下，章节卡要在 `s.start + sceneCut` 之前盖满画面，在 `c0` 前后收走。章节卡要让观众读清本章要讲什么；它之后的第一句是该章的「建立」，镜头给全景。

从项目或题目里取一个母题让它参与换场，比通用的转场连贯：luainstaller 一片每次换章，新场景都从角上那颗小行星里展开。

承载信息的卡片必须留出完整可读的保持段：短标题从 2 秒起安排，标题加要点的内容卡从 3–5 秒起安排，按各语言的字数和图解复杂度增加；入场与退场另计。这是制作起点，仍须正常速度复核。超过一屏能读懂的信息先拆开，不能靠刷得更快解决。

擦除是可选动作，不是每次换章的默认答案。先判断内容是在延续对象、改变尺度、展开结构还是切换话题，再选衔接；跨片要比较动作路径和节奏，不能只换颜色、方向。通用反馈见 [feedback.md](feedback.md)。

## 6. 节奏

- 开场前半秒内画面就有东西在动。
- 演示段按因果和理解顺序推进；结论揭示后留出读完并理解的时间，不以 0.6 秒的短停顿代替阅读保持。
- 一句一个证据的段落，每句开头换站点或换主体，不在同一个静态版面上停两句以上。
- 列表项错峰 0.1–0.16 秒。
- 重头戏给足时间：先给一张总览，再推进第一站，每一步占一站。

## 7. 给图形起名字

`look.js` 列出的是 DOM 里的文字、色块与带名字的元素。画在 SVG、canvas 里的内容它只知道「这里有一块图」。所以：

- 给图形类的元素加 `data-name="软盘"` 这样的属性，它们才会以有意义的名字出现在文字输出里。
- 故意出血到画外的大字、大图形加 `data-bleed`，不报「被画面边缘切掉」。
- 故意压在别的文字上的元素加 `data-overlap-ok`，不报「文字重叠」。同一行字叠两层（反色、描边的做法）会被自动识别，不必标。

## 8. 真实数据的大倍率画面

- `<canvas>` 画完后换成 `<img>`：用 `freeze(canvas)`。渲染时 canvas 层在场景显隐切换之后会丢瓦片，预览时看不出来。
- 大倍率推近时，清晰层的淡入要等放大到位再开始，并盖住那一刻镜头能看到的全部范围。
- 需要 3D 时可以用 WebGL：先 `node kit/tools/glprobe.js <视频>` 探测，渲染时加 `--gpu 1`。三维场景同样要做成「由 t 决定状态」。

## 9. 自查循环

每写完一小段就查，不攒到最后：

```bash
node kit/tools/look.js <视频> a3 a4              # 这两句说完时的画面
node kit/tools/look.js <视频> 31.5 32.0 32.5     # 入场动作的中间状态
node kit/tools/look.js <视频> --scene demo 2     # 沿一个场景每 2 秒看一帧
node kit/tools/scan.js <视频> --from 20.6 --to 52.8
node kit/tools/check.js <视频>
```

改了入场时刻之后要重新混音：音效事件是从场景里登记的。
