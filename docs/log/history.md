## 仓库重整：分级、角色、经验规则

2026-10-20，策划者 WaterRun 要求「从根源上的彻底重置」：文档散乱、流程时有时无、片子之间同质化、反馈不成体系、前期模型越界、署名写法不统一。Claude Opus 5.5 执行，与同时在制作《垃圾回收的艺术》的会话协作挪动其目录。

- **三个层级。** 去掉 series / standalone 这一层：`videos/` 下第一层是各系列与 `standalone`，第二层是片子；系列说明放在 `videos/<系列>/README.md`，系列可设缺省语言；速通的基座移到 `kit/starters/in-seconds/`。slug 全仓库唯一，重名的改为 `lua-philosophy`、`powershell-pwsh`、`metro-design`、`china-metro` 等。（当天先拍平成一层，策划者指出第一层的分类仍要保留，随即改为现在的两层。）
- **文档。** `docs/` 分为核心（宗旨、角色、制作周期、标准、经验规则）、`guides/`、`reference/` 与只追加的 `log/`。`workflow.md`、`delegation.md`、`feedback-loop.md`、`todo.md`、`catalog.md`、`retrospectives.md` 由 `process.md`、`roles.md`、`lessons.md`、生成的 `videos/README.md` 与各片 README 的「复盘」取代；旧排期存档在 `log/plans/`。
- **角色。** 准备方只交材料与约束，不定审美方案；制作方可以推翻准备方的建议；策划者在会话里的明确要求优先于任何任务书。
- **经验规则。** F01–F20 改写成通用表述，新增 F21「每部片子自成一体」；按阶段用 `lessons.js show --stage` 读取，交付前在 `review/lessons.json` 逐条下结论。规则带 `rev`，只改措辞不让在制片的结论失效。各片原 `review/feedback.json` 转换为新格式，结论原样保留。
- **署名。** 唯一来源是各片 `project.json` 的 `credits`，写真实的模型型号；新片的片尾从这里读，`check.js --final` 核对画面上的名单。旧片的记录按可确认的信息整理，型号未记录的照实写「型号未记录」。
- **工具。** 新增 `lessons.js`、`readable.js`；`catalog.js` 生成片单索引与系列分集表；`check.js` 增加片尾名单核对与雷同提示；`repo-check.js` 增加根目录、文档登记、视频目录与署名写法的检查；渲染的缺省并发按可用内存收紧。
- **自由软件，自由视频。** 宗旨写进 `docs/principles.md` 与根 README。

## 2026-10-23：内容优先与仓库维护

本轮角色为维护者；依据策划者要求（反馈 P53）整理共享文档、系列说明、模板、索引和工具。已发布片与在制片的内容未改动；前一轮清理后保留的人工简报未改动。

- **内容与文档。** 宗旨明确内容、解释和叙事优先，文档服务复查与接续。F01、F18、F20 更新到 rev 2，规则版本为 2026-10-23.1；在制片接续时同步并据实复核，不补造结论。
- **流程。** 交审稿由唯一源稿生成连贯阅读与逐句校对视图，保留原有内容哈希和历史稿。字幕 cue 与自然口播句分开说明；验收结论区分自动通过和实际成片审查。
- **整理。** 文档入口改查当前片单，历史排期仅供回溯；去掉空计划表、失效 npm feedback 入口，修正文档章节引用、系列视觉约定冲突和数据库系列中过时的单片方案。通用规则、具体作品记录与历史保持分层。
- **开源。** 共产主义精神落实到知识与生产资料共享、协作、如实署名和改进回流。GPL、第三方制作、可编辑源码及必要材料的交付要求集中到 `docs/reference/third-party.md`；GPL 适用范围与外部权利分别说明。新片模板显示 GPL 标识，交付检查核对；GSAP 等外部依赖的许可不被改标为 GPL。
- **验证。** 31 项隔离测试通过，仓库检查通过；通用模板中英文浏览器检查确认 GPL 标识可见，另检查速通片尾脚本语法。共享检查新增 npm 入口与现行文档章节链接校验，交付检查补齐无配乐版要求。没有以本轮维护代替任何影片的事实、听感或成片验收。

## 2026-10-23：完成审计与媒体管线核对

继续审计发现封装前 WAV 的测量与旧报告不能证明最终 MP4 的状态。现改为测量实际编码后的各版 MP4，记录渲染、混音、封装和封面的内容校验和；源码、时序、输入或产物变化后须重做相应阶段。媒体命令失败、缺少空画面检查、持续到片尾的静止段均不能通过最终交付。新版项目删除 `review` 配置也不能跳过文案确认；新版交接核对填写的事实记录，不以字数代替准备质量。

| 用户要求与边界 | 当前落点与核对证据 |
|---|---|
| 内容、好文档、好叙事优先 | 宗旨、标准、流程、模板与 F01/F18/F20 一致；交审工具从唯一源稿生成连贯阅读和逐句表，测试验证静默片尾不进正文、历史稿与确认不会被重导覆盖 |
| 减少文档与工作流混乱 | 文档地图、系列说明和工具速查已整理；仓库检查验证命令入口、共享文档章节链接、片单与生成索引，生产工具按内容核对报告有效性 |
| 共产主义精神与第三方 GPL 开源 | 宗旨、贡献指南、许可说明、交付流程和模板落实共享、如实署名、可编辑源码及必要材料交付；中英文模板实际浏览器检查确认 GPL 标识可见；外部权利仍按实际许可核对 |
| 最终成品检查可信 | `npm run smoke:media` 用隔离合成短片真实执行 render/audio/finish/covers；验证正常产物、替换文件、ffmpeg 失败、跳过空画面检查，以及直到片尾的静止画面 |
| 保留人工要求与已发布版本 | 对前轮清理后记录的 1,506 个受保护文件逐项比对 SHA-256，13 个清理目录仍只含原保留简报；Kimi K2.8 登记保留，18 部已成片、7 部在制、178 个计划选题一致 |
| 测试与入库边界 | `npm test` 的 35 项测试全部通过，`npm run check:repo`、`npm run smoke`、`npm run smoke:media`、`git diff --check` 通过；测试素材与报告仅在忽略的练习目录，不登记为实际影片 |

这些证据验证的是仓库维护与制作管线，不替代真实影片的事实审查、连续观看、试听、策划者确认或具体第三方素材的权利审查。旧成片继续冻结；旧报告按原制作环境恢复，不补造新检查记录。

## 2026-10-23：署名与文字表述修订

策划者明确：「那个说人要真名改下, 倒不是一定用真名. 各个文字进行优化」，随后指定「内容优先 -> 内容大于形式」。现行入口、宗旨与标准统一采用“内容大于形式”；人的署名由本人选择，可用姓名、昵称或笔名，不要求实名，模型仍记录准确型号与版本。同步修订入门说明、发布流程、校对模板和署名提示，消除“真实身份”“真实署名”可能造成的实名歧义。署名检查不再将人的昵称套用模型占位名规则；既有贡献与历史记录保留。
