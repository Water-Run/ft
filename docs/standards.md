# 质量标准

成片必须达到的标准，自制与分工制作都适用。它是底线，不是天花板；能用工具查的已经写进总闸门（见 [验收](guides/acceptance.md)），其余要逐项看、逐项听。从反馈中提炼的具体规则见 [经验规则](lessons.md)，下文以编号引用，不复述。

## 1. 可靠

目标是可发布的科普级可靠度。

- 每一句旁白、每一个画面元素都有出处，记在该片的 `research/FACTS.md`；出处支持陈述的完整含义，写明适用版本、环境与截至日期。做法见 [取证](guides/research.md)。
- 来源冲突、证据不足或尚未证实的内容不写成定论：查清、收窄表述，或删掉。模型的记忆、搜索摘要、几个模型回答一致，都不是依据。
- 画面上的终端回显、数字、字节、年份、引文来自真实数据，由脚本生成，不手写。
- 按文档或源码重建的旧系统画面、原理示意，在画面上标「示意」。
- 画面涉及地图时，只用带审图号的标准地图服务提供的底图，不手绘国界或边界，不作领土主张的表述；底图来源与审图号记入 FACTS。
- 标题、字幕、封面与译文中的事实同样要查。
- 讲法循序渐进：先给现象，再给机制，一屏只讲一件事。核心问题、例子与理解负担见 F01–F03、F10、F11、F13。

## 2. 审美

每一帧单独截出来，都应是一张完成度高的平面作品。

**原创**

- 不抄现成产品：不照搬现有视频、网站、应用、宣传片与设计模板的文案、分镜、标志性构图或整套视觉与动效，换色、换字、换标志也不行。
- 参考别的作品时，在 README 的「设计」里写明来源与借鉴的具体方法，再按本片的事实与视觉系统重新设计。
- 讲解对象自己的标志、界面、代码与回显可以作为材料展示，注明出处与用途。
- 视觉取自讲解对象（F16）；每部片子自成一体，不沿用别的片子（F21）。

**要做到的**

- 版式有骨架：网格、强烈的字号对比、不对称构图、大面积留白或大色块。
- 配色克制：一个主色、一个强调色，其余为中性色。
- 用图形本身讲事情：把概念做成有体积、有空间关系的对象（剖面、等距、按比例的布局、可拆解的模型），而不是文字面板加标签。图形必须承载内容（F20）。
- 图形语言定下来就不破例：同一种图形在全片只有一个含义。
- 字号比直觉大：1080p 下正文 38px 起，注解不小于 28px，终端命令 40–56px。缩小一半的总览图上仍读得清，才算够大。

**要避开的**：深色渐变加光斑、点阵、暗角、噪点；半透明圆角面板、细描边、大投影，所有东西都装在卡片里；胶囊标签、小菱形图标、全大写加宽字距的小号英文注脚；撞色高亮加外发光；居中对称、四平八稳的布局；靠「换一屏面板」推进；所有元素都用同一种「淡入加上移」入场。

讲解对象自己的视觉语汇要求某种被列为「避开」的做法时（例如液态玻璃本身就是渐变与模糊），以对象为准，在 README 的「设计」里写明理由，并相应调整 `check.style`。

## 3. 动态

静帧成立，连续播放也要流畅、清晰；通过静止检测只是下限。

- 内容摆在比画面大的空间里，镜头在其中移动；场景之间用匹配剪辑、镜头穿越或图形化的转场衔接，不用整屏淡入淡出。
- 任意 3 秒内都有观众能感知、且有含义的变化；不靠镜头晃动或无意义的漂移凑数（F05）。
- 动作有预备、过冲、跟随；成组元素错峰入场；关键信息用一个明确的揭示动作交代。
- 节奏有张弛：演示段一步一拍，结论处放大、停顿、留白。看得完也看得懂（F04）。
- 每章有一个主画面（F18）；中间帧也成立（F19）。
- 镜头到站时，站上已经有东西；空画面超过半秒就显得卡。
- 快速运动的镜头开运动模糊（`project.json` 的 `render.mb`）。

## 4. 声音

- 关键动作有声，不同动作不同声音；没有含义的动作可以无声（F06）。
- 配乐为本片设计，有贯穿的铺底与低频，随章节发展（F06）。
- 配乐与音效始终低于旁白，旁白出现时自动让位。
- 配音先试听再合成（F17），读音与断句逐句核对（F12）。
- 配乐与音效由程序合成。成片固定给出主混音、仅旁白、无配乐三个版本；听不到的部分在交付说明里写明。

## 5. 语体

旁白、画面文字、封面、文档用同一种语体：

- 客观陈述事实与依据，冷静、克制；不用比喻套话、口号、感叹号。
- 不用第二人称，不用「请」等敬语，不写问候与情绪词。英文同样不用 please，尽量不用 you。
- 短：标签不超过 12 个字，一行说明不超过 20 个字，一句旁白不超过一行字幕。
- 术语的写法全片统一；数字、拉丁字母与汉字之间留一个空格。
- 不写制作者口吻的自我说明（F15）。
- 译文以中文原稿为底本，按中文的语气与用词翻译。

策划者为某一片指定了别的口吻（例如俏皮），以策划者为准，记在 README 的「简报」。

## 6. 两类片子的体量

| | 科普片 | 项目介绍片 |
|---|---|---|
| 用途 | 讲清一个主题 | 完整介绍一个项目，可用于宣发 |
| 时长 | 按系列说明；没有系列的，数分钟，动笔前定上限。非定长的上限只是参照，宁可长一点（F04） | 6–8 分钟 |
| 结构 | 按主题定 | 既有方案及其不足 → 引出项目 → 概述（含许可）→ 安装 → 使用与能力边界 → 实现原理 → 收尾信息 |
| 信息量 | 每句对应画面上的一项内容 | 每一句配一条真实回显或真实产物；既有方案的不足用实测的失败回显展示，并写清它们能做到什么；「不做什么」单独成章 |
| 重头戏 | 机制的图解 | 实现原理：一段连续的、把真实数据画出来的动画 |
| 贯穿元素 | 按视觉系统定 | 从项目自己的标志里取一个母题贯穿全片 |

质量优先，但不为慢而慢：长时间的渲染放在后台，同时做文档与核查；发现问题就改完再渲染，不为省一次渲染放过瑕疵。

## 7. 片尾

每部片子、每种语言、每个交付版本都有可读的片尾名单：「策划：WaterRun」（英文 `Planning: WaterRun`）、全部实际参与的模型及分工、「开源视频」（英文 `Open-source video`）与完整的仓库地址 `github.com/Water-Run/ft`。名单不配旁白（F14），字号、对比度、停留时间按正文同等标准检查。名单来自本片 `project.json` 的 `credits`，写法见 [角色与权限](roles.md) 第 5 节。独立 fork 按 `kit/studio.json` 写自己的策划与仓库。
