# 质量标准

本文是成片必须达到的标准，分四项：可靠、审美、动态、声音。另有原创要求、语体、两类片子的体量与片尾署名要求，自制与委托均须遵守。标准是硬性的；能用工具查的部分已写进总闸门（见 [review.md](review.md)），原创性、动画完成度、事实依据与片尾名单须逐项复核，自动闸门通过不能代替这些检查。

## 1. 可靠

目标是可发布的科普级可靠度。

- 每一句旁白、每一个画面元素都有出处，记在该片的 `research/FACTS.md`。
- 严格事实核查：脚本定稿前核对依据，成片后逐句、逐画面复核；标题、字幕、封面与译文中的事实同样要查。模型生成的文字、记忆与搜索摘要不能直接作为依据。
- 出处必须支持陈述本身，并写明适用版本、环境与截至日期。来源冲突、证据不足或尚未证实的内容不得写成定论；先查清、限定表述或删除，再进入成片。取证与交叉核查的方法见 [research.md](research.md)。
- 画面上的终端回显、数字、字节、年份、引文来自真实数据，由脚本生成，不凭记忆写，不手工改。
- 示意性质的图形（按文档或源码重建的旧系统画面、原理示意）在画面上标「示意」。
- 画面涉及地图时，只用带审图号的标准地图服务系统提供的底图，不在画面上手绘国界或边界，不作领土主张的表述；底图来源与审图号记入 `FACTS.md`。「我们的中国」系列全系列适用。
- 讲法循序渐进：先给具体的现象，再给机制；一屏只讲一件事；信息量充足但不过载。标题、开头、章节和结尾须回答同一个核心问题；材料可靠不等于适合进入正文，历史、规模数字与实现细节不能挤掉定义和逐步解释，见 [feedback.md](feedback.md)。
- 成片后做三项审查：事实、读音与节奏、旁白与画面对应。

## 2. 审美：现代主义的版式，大制作的完成度

每一帧单独截出来，都应是一张完成度高的平面作品。

**原创要求**

- 不直接抄袭现成产品，包括现有视频、网站、应用、宣传片与设计模板。不得照搬其文案、分镜、标志性构图或整套视觉与动效，再通过换色、换字、换标志当作新作。
- 参考作品时，记录来源与借鉴的具体方法，并根据本片事实、叙事与视觉系统重新设计。注明参考来源不能代替独立设计。系列内复用本仓库的视觉系统按 [series.md](series.md) 执行。
- 讲解对象的真实界面、标志、代码与回显可作为取证材料展示，须注明出处、用途与重建情况；引用材料与本片自行设计的表现形式要区分清楚。

**要做到的**

- 版式有骨架：网格、强烈的字号对比（主标题的字高可到画面高度的六分之一以上）、不对称构图、大面积留白或大色块。
- 配色克制：一个主色、一个强调色，其余为中性色；平涂。两种颜色加反白块就足以做出层次。
- 用图形本身讲事情：把概念做成有体积、有空间关系的对象（剖面、等距、按比例的布局图、可拆解的模型），而不是文字面板加标签。
- 图形语言定下来就不破例：同一种图形在全片只有一个含义，并用到底。
- 字号比直觉大：1080p 下正文 38px 起，注解不小于 28px，终端里的命令 40–56px。先看缩小一半的总览图，缩小后仍读得清的才算够大。

**要避开的**

下面这些是「模板化的科技感」，一处都不要出现：

- 深色渐变背景加光斑、点阵、暗角、噪点。
- 半透明圆角面板、细描边、大投影；所有东西都装在卡片里。
- 胶囊形标签、小菱形图标、全大写加宽字距的小号英文注脚。
- 撞色高亮加外发光。
- 居中对称、四平八稳的布局。
- 靠「换一屏面板」推进，像带动画的幻灯片或仪表盘。
- 所有元素都用同一种「淡入加上移」入场。

## 3. 动态：动画精美精良，有冲击力

动画的完成度要同时体现在构图、动作与衔接上。静帧成立，连续播放也要流畅、清晰；达到「画面在动」的检测下限不代表合格。

- 连续的镜头运动贯穿全片：推、拉、摇、移、穿越。内容摆在一个比画面大的空间里，镜头在其中移动；场景之间用匹配剪辑、镜头穿越或图形化的转场衔接，不用整屏淡入淡出。
- 任意 3 秒内都有观众能感知的画面变化。总闸门的静止检查是底线，不是目标。
- 动作有预备、过冲、跟随；成组元素错峰入场；关键信息用一个明确的「揭示」动作交代（砸入、刷出、打字、遮罩揭示）。
- 节奏有张弛：演示段一步一拍；结论处放大、停顿、留白。开场 5 秒与每章开头要清楚地建立问题；冲击力不能以章节卡和内容卡来不及读为代价，阅读保持按 [scenes.md](scenes.md) 单独计时。
- 镜头到站时，站上已经有东西；空画面超过半秒就显得卡。
- 快速运动的镜头开运动模糊（`project.json` 的 `render.mb`）。
- 动作的路径、速度、缓动、错峰与停顿逐段打磨，服务于机制讲解和注意力引导；不用无意义的漂移、抖动或反复缩放凑动态。
- 检查入场、运动中段、落点与转场接缝：主体不意外跳位，文字不闪烁、不被错误遮挡，边缘不穿帮；主次层级与可读性在运动中保持成立。
- 先验证代表性动画片段，再铺开制作；成片逐段检查动态与静帧，缺陷修正后重新渲染。不能目视或通看时，如实记录待复核范围，不宣称观感已验收。

## 4. 声音：不能只有配音

- 关键动作有声：元素出现、数据移动、转场、命中、出错，各有区别。
- 配乐有节拍，随章节推进；内容最密的段落逐步加层，冷静的段落只留铺底。
- 配乐与音效的音量始终低于旁白，旁白出现时自动让位。
- 配乐与音效由程序合成，制作者听不到。成片时固定给出主混音、仅旁白、无配乐三个版本，需要比较配乐时另出试听片，并在交付说明里写明听感未经人耳确认。

## 5. 语体

旁白、画面文字、封面、文档用同一种语体：

- 客观陈述事实与依据，冷静、克制；不用比喻、口号、感叹号。
- 不用第二人称，不用「请」等敬语，不写问候与情绪词。
- 短：标签不超过 12 个字，一行说明不超过 20 个字，一句旁白不超过一行字幕。
- 术语的写法全片统一；数字、拉丁字母与汉字之间留一个空格。
- 译文以中文原稿为底本，按中文的语气与用词翻译；英文同样不用 please，尽量不用 you。

## 6. 两类片子的体量

| | 科普片 | 项目介绍片 |
|---|---|---|
| 用途 | 讲清一个主题 | 给一个项目做完整的介绍，可用于宣发 |
| 时长 | 按该系列说明的「定位」一节；没有系列说明的按数分钟，动笔前先定上限 | 6–8 分钟 |
| 语气 | 冷静，循序渐进 | 冷静、完整，不喊口号 |
| 结构 | 按主题定；系列里的一集按该系列的约定 | 既有方案及其不足 → 引出项目 → 概述（含许可）→ 安装 → 使用与能力边界 → 实现原理 → 收尾信息（仓库地址、作者、制作说明） |
| 信息量 | 每句对应画面上的一项内容 | 每一句配一条真实回显或真实产物；既有方案的不足用实测的失败回显展示，并写清它们能做到什么；「不做什么」单独成章 |
| 重头戏 | 机制的图解 | 实现原理：一段连续的、把真实数据画出来的动画 |
| 贯穿元素 | 按视觉系统定 | 从项目自己的标志里取一个母题贯穿全片；配色与美学贴合项目本身 |

质量优先，但不为慢而慢：长时间的渲染放在后台，同时做文档与核查；发现问题就改完再渲染，不为省一次渲染而放过瑕疵。

## 7. 片尾名单与开源链接

- 每部片子、每种语言及各交付视频版本都要有可读的片尾名单，列出「策划：WaterRun」与所有实际参与制作的模型。英文版使用 `Planning: WaterRun`，人名与模型名保持原样。
- 片尾同时展示「开源视频」与本视频源码所在的 GitHub 仓库链接。本仓库地址为 [Water-Run/ft](https://github.com/Water-Run/ft)，画面可写 `开源视频：github.com/Water-Run/ft`；英文标签用 `Open-source video`，地址保持一致。网址须完整、清晰，留足阅读时间。
- 模型按实际分工列明，如取证、脚本、翻译、视觉设计、场景实现、审查，以及实际使用的图像或语音生成模型。委托片同时列准备方与受托方；同一模型可合并列出职责。
- 模型名称与可确认的版本来自本次制作记录，不以工具、客户端或平台名称代替，不猜测版本、不补写未参与的模型。服务未披露模型时，记录服务与用途并注明「模型未披露」。
- 名单、开源仓库链接及其依据记入 `research/FACTS.md` 的「制作署名」一节，并同步到本片 README；委托片还要写入 `DELIVERY.md`。`project.json` 的 `production.maker` 只记录制作者，不能代替完整名单。
- 片尾纳入脚本、分镜与时长预算，字号、对比度、停留时间和动态按正文同等标准检查；逐项能读完，不被字幕、裁切或转场遮挡。名单与开源链接必须出现在成片中，只写在说明文档里不算完成。

## 8. 首部作品留下的对照

首部作品（[MyISAM](../videos/series/database-engines/myisam/)）是「要越过的线」：深色面板式的视觉、由静态版面加局部淡入组成、声音只有旁白和一层铺底。它按现行检查会报出字号、对比度、静止、空屏与确定性等多项问题，这些项在它的配置里降为提示并如实记在它的 README 里。之后的片子不得再出现同类问题。

2026-10-09 的策划反馈将 MyISAM、luainstaller、2FA 列为正面对照（见 [feedback.md](feedback.md)）。技术缺陷仍须如实保留；内容是否讲清楚另行评价，不能因为早期片子动作或音效较少就否定其叙事价值，也不能以更多动态代替理解。
