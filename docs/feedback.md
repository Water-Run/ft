## 3. 叙事偏移：先查这一层

“事实有出处”只回答陈述是否可靠，不回答它是否值得放进这部片子。实验做得多、代码读得细、数字精确，都不能替代观众从一个问题走到一个答案的过程。下表保留初次源稿分析；随后已补充八部实际母版抽帧、平台对应抽样与精确时间线，见 [逐片复盘](reviews/2026-10-09.md#3-逐片复盘)。制作者的诊断与 P0 的直接评价分开记录，不将抽样检查写成连续通看。

| 对象 | 源稿中可定位的现象 | 叙事风险与修改方向 |
|---|---|---|
| [Lean 4](../videos/series/in-seconds/lean4/src/js/script.js) | 主线是奇数和的证明，但 `k1–k2`、`f2–f5` 插入历史；`t1–t3` 连续引入命题、类型、值；`c2–c4`、`r3–r7` 集中给出节点数、源码行数、声明数、库规模与其他大定理 | 对入门观众，规模与术语可能挤掉“程序究竟检查了哪一步、为何足以排除错误”的解释。保留同一道题，先走完一次可理解的核对，再说明策略、内核与可信边界；历史和规模只留能支撑当前问题的部分 |
| [OpenClaw / OpenCode v2](../videos/standalone/openclaw-opencode-v2/src/js/script.js) | `o5–o6` 把入口收束到进程中断，之后按项目列举版本、存储、收发、权限、分层、重试等实现；`d3–d14` 连续介绍包名和实现参数。[章节表](../videos/standalone/openclaw-opencode-v2/README.md)将“学到了什么”放到中文版 7:58，位于约 9:33 的片子后段 | 标题承诺的是一年的 Agent 工程化经验，正文容易变成两份更新说明。先按观众要解决的问题分章：旧做法遇到什么失败、为何要改、两边如何处理、代价是什么；源码与实验在需要证明这一步时出现，而不是最后才归纳它们的意义 |
| [WSL](../videos/standalone/wsl/src/js/script.js) | 标题涉及 1、2、3，评论中仍反复出现架构与版本号的口径争议（C7） | 先判断开篇是否已经建立清楚的命名对照，再安排架构与性能比较。观众对技术的争论不能证明叙事清楚，也不能直接证明技术内容有错 |

每次文案交审先给出四项：目标观众已有的知识；看完应能回答的一个核心问题；各章怎样推进这个问题；哪些查到的材料决定不讲。每章按“问题 → 必要解释或演示 → 本章答案 → 下一问”检查。删除一段不影响主线，就考虑移入说明或后续选题；保留它必须能说清用途。

定稿与成片审查分别检查标题、开头、章节和结尾是否仍在回答同一个问题。尤其检查：例子是否变成主题、版本清单是否代替因果、实现参数是否先于概念、史料是否打断推导。叙事未解决时，不靠加快旁白、增加动画或扩充片长来补救。

## 5. 制作改进与验收

下表是本轮提出并写入制作文档的要求；秒数是制作起点，不是已验证的普遍阅读速度。现有成片已经按同日复盘的范围取样检查，但尚未修改、重新渲染，不把文档变更记为问题已解决。

| 项 | 具体做法 | 检查与完成条件 |
|---|---|---|
| 叙事保持题目与受众 | 先写核心问题和逐章答案，再选择证据、例子与数字；实验、源码细节和历史材料按解释需要取舍 | 文案交审及成片复查都核对“标题承诺 → 章节推进 → 结尾回答”；未能对应的段落删减或另立选题。叙事检查先于视听包装检查 |
| 章节卡与内容卡可读 | 先分清标题卡与承载论点的内容卡。短标题的完整可读停留从 2 秒起安排；标题加要点的内容卡从 3–5 秒起安排，随字数和图解复杂度增加。入场和退场另计；信息太多先拆，不靠加快刷屏 | 每种语言记录文字全部到位至开始遮挡/退场的时段；正常速度播放能读完并辨认关系后再换场。不能只检查某张静帧或章节总长 |
| 转场与动作有区别 | 先说明这次动作表现什么关系：跟随数据、展开结构、保留对象再换视角等；擦除可以用，但不能成为所有章节与所有新片的默认答案 | 将本片与近期两部的开头、换章、解释段各取一段并排比较；若只是换颜色或扫动方向，重新设计。连续性保留在字体、图形含义和结构上 |
