### open · 无章节卡

十一月二日，OpenAI 发布了 Pando 一套重新写过的 Git 服务器 就在三周前，Anthropic 宣布 它的主代码仓库，已经彻底离开了 Git 做出 ChatGPT 的 OpenAI，做出 Claude 的 Anthropic AI 双雄，前后脚动了同一样东西 用了二十多年的 Git 为什么偏偏是它们，要重造 Git？ 又为什么，一家换掉了它，一家却把它留下？

### git · 01 Git 怎么用

一个项目的代码和全部修改历史，放在一个*仓库*里 想同时做几件事，就各开一条*分支* 做完再*合并*回去 改好的东西打成包，*推送*给服务器 别人要用，再从服务器*拉取*下来 两家各自都有一个装着大量代码的巨型主仓库

### jam · 02 仓库扛不住了

现在，AI 也来写代码了 一个工程师让几个智能体并行干活，就有好几项改动 每次推送，又让好几个测试任务去拉取同一份代码 整个公司加起来呢？ Anthropic 每天合并的改动，五月约 2,500 次 九月超过 30,000 次 光是自动测试，每天就要取出约 2,500 万次代码 每次都完整取一遍，一天就要传 600 PB 以上 OpenAI 从去年年底起，推送变慢、合并失败 可靠性一度跌破九成 卡在哪？Git 服务器通常有两个老规矩 第一，所有推送排成一队，好让整个仓库时刻只有一个样子 第二，每来一个拉取的人，都单独现算、现打一个包 人一多，这两件事都成了瓶颈

### oai · 03 OpenAI：留下 Git

OpenAI 先问：是 Git 本身到了极限 还是服务它的方式到了极限？ 它押后者：Git 的用法一点不变，只换背后的服务器 先治排队：每条分支各排各的，撞上同一条才分先后 代价是同时看几条分支，未必是同一刻的样子 OpenAI 说，人和智能体其实并不在意 再治现算：推上来的包原样存好，谁要就直接发过去 这些包在各地就近存一份，也就是*缓存* 九成九以上的请求，就地就能取到 结果，推送通常要等的时间缩短了近八成 每天送出将近 1 PB 数据，只用少量 CPU 十周上线：一名工程师设计核心，Codex 智能体写出实现

### ant · 04 Anthropic：换掉 Git

Anthropic 走得更远 Git 让每份拷贝都完整、能离线 可 Anthropic 说，它的使用者几乎全是 永远在线的智能体和自动任务 这份优点，反倒成了拖累 于是它造了 Scion：使用者不存完整仓库，要什么取什么 记录、合并改动都在服务器上完成，连推送都省了 数据存进去就不再改，于是可以层层缓存 每一层，九成九的请求就地取到 结果，CPU 和内存只有原来那套 Git 设施的两百分之一 测试任务取代码，从几分钟缩短到几秒 七个人，五个月，靠的也是 Claude 写代码 不过 Anthropic 也说，Scion 只适合极其庞大的仓库 不是给一般人替代 Git 用的

### why · 05 为什么都在重造

回到开头：为什么偏偏是这两家？ Anthropic 说，它用 Claude 写代码，比几乎任何公司都多 所以常常最先看到：瓶颈不在写代码，而在为人设计的工具 OpenAI 也说，Codex 改变了它开发软件的规模和速度 OpenAI 认为问题在服务器，所以留下 Git Anthropic 认为问题在 Git 的离线前提，所以换掉了它 但两家都拆掉了那条总队伍，都靠不变的数据层层缓存 对普通开发者，Git 的用法不会变 OpenAI 的部分改进，已经并入了 Git 本身 但 Anthropic 预计，六到十二个月内 会有更多公司撞上同一堵墙
