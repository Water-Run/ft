### 交审前的自对抗修改（2026-11-03）

内部稿没有导出交审，这里记录改了什么、为什么改。

1. **时长。** 最早的稿子按实测语速推算约 5 分 40 秒，超出「3-4m」。删去的内容：Git 的邮件出身（与 04 章「每份拷贝都完整、能离线」重复）、「Git 镜像」这个新词、25 GB 单独一句（画面上写 25 GB × 2,500 万 ≈ 600 PB）、Pando 的上游贡献单独一句（并进 05 章）、Anthropic 文末那句与 Pando 的呼应、「瓶颈是按人的规模造出来的工具」（与 w3 重复）。
2. **事实。** 「Git 本身一点不改」改为「Git 的用法一点不变」：OpenAI 发布了自家的 Git 客户端构建，客户端其实有改动（FACTS OA-1、OA-16）。「总是最先发现」改为「常常最先发现」（AN-5 原文是 often）。「全公司的代码放进同一个大仓库」改为「装着公司大量代码的巨型主仓库」：两篇原文只说 monorepo，没说全公司。「大部分代码是 Claude 写的」没有出处，改为「靠的也是 Claude 写代码」（AN-12）。「几乎所有使用者都是智能体」只在 Anthropic 说，改为由 Anthropic 署名（a3）。「人和智能体并不在意」改由 OpenAI 署名（p6，OA-10）。
3. **因果与问题闭合。** 开场的第二个问题「为什么一家换掉、一家留下」原稿没有回答。补上 OpenAI 原文的提问：「是 Git 本身到了极限，还是服务它的方式到了极限？」（p1–p2），05 章用 w5 收束：「一家认为问题在服务器，一家认为在 Git 的离线前提」。05 章的「总队伍」回扣 02 章的第一条老规矩。
4. **双雄。** 05 章只有 Anthropic 一家说明自己为什么最先撞墙，补上 OpenAI 的说法（w4：Codex 改变了它开发软件的规模和速度），两家对等。
5. **新词。** 「合并」原稿用到却没交代，在 g3 补上；「客户端」改成「使用者」；「提交」不进旁白（a7 说「记录、合并改动」）。
6. **措辞。** 「代价是几条分支不再严格同步」容易被理解成服务器之间同步，恢复为「同时看几条分支，未必是同一刻的样子」。
