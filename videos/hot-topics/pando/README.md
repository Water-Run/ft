## 简报

<!-- 立项时写，准备方或制作方都可以写。策划者在会话里提的要求，原话与日期照录在这里，优先于任何缺省做法（docs/roles.md 第 2 节）。 -->

- 目标观众已有的知识：听说过 OpenAI、Anthropic、ChatGPT、Claude；不一定知道 Git 是什么、仓库怎么推送与拉取。
- 看完能回答的一个核心问题：为什么 AI 巨头都在重造 Git？——AI 写代码让推送、拉取、合并暴涨，Git 服务器「所有推送排一队」「每个拉取者现算一个包」的老规矩成了瓶颈；Anthropic 还认为 Git 为离线设计的前提不适合永远在线的智能体。
- 用哪个具体例子走完解释，关键因果与边界是什么：一个工程师让几个智能体并行干活 → 好几项改动、好几次推送 → 每次推送又触发好几个测试任务拉取同一份代码（OpenAI 原文的例子）。边界：两家都只为自己的巨型主仓库做了改造，普通开发者的 Git 用法不变；Scion 不是通用的 Git 替代品。
- 逐章怎样推进，各章的答案：开场（两件新闻、AI 双雄、两个问题）→ 01 Git 怎么用（仓库、分支、合并、推送、拉取）→ 02 仓库扛不住了（例子、两家的数字、两条老规矩）→ 03 OpenAI 留下 Git（各分支各排各的队；包原样存好、缓存下发；结果）→ 04 Anthropic 换掉 Git（使用者永远在线；服务器做提交合并；不变的数据层层缓存；结果与边界）→ 05 为什么都在重造（两家为何最先撞墙、路线的不同与相同、对普通开发者的影响；信息截止时间写在片尾名单里，不配旁白）。
- 决定不讲的材料与理由：Mononoke 署名争议（只有二手报道，且偏离主问题）；packfile、因果一致性、LSM 压实等术语（只在画面上出现）；GPT-6 Astra 形式化验证、Claude Mythos 重写导入管线（细节，挤占时长）；Anthropic 文末「Git 服务器不必与客户端同一做法」与 Pando 的呼应（第 3 稿有，为压时长删去，可恢复）。

- **三套样式**（策划者要求 OAI 段用 OpenAI 风格、Anthropic 段用 Anthropic 风格）：开场、01、02、05 章中性浅灰纸色、ft 蓝强调；03 章纯白底、纯黑、方角、细线、Inter；04 章米色暖底、深石板色、陶土橙、思源宋体、圆角。品牌字体是商业字体，用 OFL 开源字体模仿。章节卡也分三套，03、04 章的卡片上方放该公司的标志。
- **标志**（策划者看过 r1 后要求「OpenAI, Anthropic, ChatGPT, Claude要出现Logo」）：四个标志的路径取自各家官网（`research/MATERIALS.md`），只用来指明所讲的对象。两家的文字标出现在开场、01 章末两家的主仓库、02 章数字段、03 与 04 章页眉和章节卡、05 章两栏；ChatGPT 与 Claude 的标志出现在开场「做出 ChatGPT」「做出 Claude」，Claude 的标志另在 04 章「靠的也是 Claude 写代码」处出现；封面也用标志。
- **两家的半屏**：开场与 05 章左半铺 Anthropic 的米色 `#f0eee6`、右半铺 OpenAI 的纯白，垫在中性灰底上，Git 压在两半的接缝上；开场时右半白底第一帧就在（片子从 OpenAI 讲起），左半随 Anthropic 出场铺开。
- **每章的主画面**：开场是一条时间轴加左右两家、中间的 Git；01 章是一个仓库（文件 + 修改历史）原地长出分支、合并，再推送、拉取，最后胀成两家的巨型主仓库；02 章右侧一台 Git 服务器全章常驻，左侧依次演示例子、两家的数字、两条老规矩（一条总队伍、每人现打一个包）；03 章一张架构图（命令不变 → Pando → 对象存储 → 各地缓存），四条分支各排各的队；04 章一排五台机器，从各背一份完整仓库变成薄客户端，长出三层缓存；05 章回到开场的左右两栏，拆掉 02 章那条总队伍。
- **配乐**：`tools/music.py`，C「双色」，100 拍/分；开场到 03 章用冷音色，04 章换暖音色，05 章两种交替。我只核对了数值，没有亲耳听。
