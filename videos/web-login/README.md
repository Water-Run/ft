# 200 秒了解 Web 登录机制：怎么验证你是你

「XX 秒速通」第 20 集，中英两版，各 200.00 秒。沿同一次登录走：登录之后网站为什么再也不问密码（会话、Session ID、Cookie）→ 不查表的另一种做法（JWT）→ 第一次是怎么认出你的（哈希、钓鱼、短信码、passkey、验证码）→ 换别的平台来认（OAuth 2.0、OIDC）→ 结论：服务器认的从来不是你本人，而是你出示的证据。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`，逐句分镜见 `brief/storyboard-detail.md`，交付说明见 `DELIVERY.md`。

## 开工反馈应用

反馈版本：2026-10-19.4（F01–F17）。逐项记录在 `review/lessons.json`；相关复盘：`docs/log/feedback.md` 的 P0–P29、`docs/log/reviews/2026-10-09.md`（2FA 9 分、Lean 4 3 分）。WaterRun 本轮特别提醒：避免「刷过去」（F04），以 Lean 4 为反面、2FA 为正面。

目标观众已有的知识：每天上网、登录过各种网站；知道密码、短信验证码、指纹、第三方登录这些词；没有系统学过 cookie、session、JWT、OAuth、passkey 的区别。

看完应能回答的一个核心问题：网站怎么确认屏幕对面是「你」——答案是它从来只认你出示的证据：第一次看你拿出的秘密或钥匙，之后认你带回的编号或票。

逐章怎样推进问题：「它再也没问过密码」→ 会话：HTTP 不记事 → 服务器记会话、发编号 → Cookie 运送、查表认出你；代价是编号被拿、跨站请求 → 网站一大共用一张表是负担 → JWT：签名的票、不查表；代价是收不回 → 短票加长票 → 那第一次怎么认出你：密码只存哈希 → 会被钓鱼 → 短信码也会被转走 → passkey 只给注册的网站签名 → 验证码只分辨人和程序 → 换平台来认：OAuth 是授权、OIDC 给 ID Token；代价是信任集中 → 收束。

本片决定不讲的材料及理由：盐、Secure / HttpOnly / SameSite、CSRF 的防法、PKCE 与 state、JWT 的受众检查、会话固定、撞库、账号恢复、SAML。200 秒里每多一个名词就少一步解释；删去清单与代价见 `review/NOTES.md` 第 7 轮。

## 视觉系统

包豪斯（策划者指定）：红 `#E2412C`、黄 `#F2C230`、蓝 `#2F57B0` 三块纯色加黑与米白，平涂。形状的含义全片不破例：红圆 = 你知道的（密码），蓝方 = 你拥有的（手机、设备），黄三角 = 你本人，黑框 = 服务器，蓝色票根 = Session ID，墨黄红三段 = JWT，单向压模 = 哈希，红钥匙与黑锁块 = passkey 的私钥与公钥，斜线 = 不可信的一方（偷来的副本、假网站）。黄三角从头到尾都在服务器的黑框外面，结尾把这件事说出来。完整规范见 `src/design/STYLE.md`。

与系列的关系：保留定长时间线、字幕带与秒尺（刻度走过变红，读头是黄三角）、左上剩余秒数；右上角仪表是本集的「服务器看到」：一只小黑框里显示服务器此刻收到的证据（密码 → Session ID → JWT → 密码 → 短信码 → passkey 签名 → 一次性码 → ID Token → 证据）。换场：新场景从下一件证据的形状里长出来（会话从蓝方、JWT 从横带、第一次认证从红圆、第三方登录从中线推开、收束落下一只黑框），片尾按系列用直刷。

与近期作品的区别（F05、P3）：Dense/MoE 用风格派的黑线分格、Tmux 用卡带未来主义、PostgreSQL 取官网样式；本集用圆方三角的几何拼合，没有黑线格、没有终端面板。参考来源只有策划者给的「包豪斯」风格卡，构图、形状语义与动作是本片自行设计，没有照搬任何海报或产品界面。
