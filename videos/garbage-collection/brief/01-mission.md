# 01 任务与标准

本文件只写本片特有的内容。通用质量标准在仓库 `docs/standards.md`，不要抄过来。

## 1. 这部片子讲什么

标题：**垃圾回收的艺术**

一句话：内存里的东西怎么知道该不该留、谁来收、代价记在谁头上。

核心问题：**它怎么猜出一块内存没用了？又怎么在程序狂奔时打扫，还不让人察觉？**

目标观众：写过程序、用过带 GC 的语言，但没想过「对象什么时候真的被释放」的人。不假设知道标记—清扫、分代、三色标记这些名字——它们要在片子里被解释出来。

不讲：训练方法、运行时实现细节、具体产品的性能对比、任何 benchmark 数字。

## 2. 结构

时间以 `node kit/tools/timeline.js videos/garbage-collection` 为准。当前稿估算 566 秒（9 分 26 秒），落在 `check.duration` 的 400–640 秒内。

| 场景 | 章节卡 | 时长 | 讲什么 | 主题落点 |
|---|---|---|---|---|
| `open` | 无 | 约 71 s | 格子纸；每秒六千七百万个；64 MB 撑不住；换个活法 11 MB；一秒清 136 次；隐形管家是垃圾回收 | 它难在哪：程序从不交代哪块不要了 |
| `count` | 01 引用计数 | 约 66 s | 实时记账；8 字节；1→2→3→2→1；归零即释放；循环引用；拆环器 | 最直觉的办法与它的死穴 |
| `trace` | 02 标记—清扫 | 约 76 s | 从根出发追踪；McCarthy 1960；符号位拨成负；一轮好几秒；Lua 二十万张表 | 第二个办法与它的代价 |
| `gen` | 03 分代 | 约 70 s | 1983 利伯曼与休伊特；分代与新区；三代 0/1/2；第 0 代收 136 次；卡表 | 按年龄分家与老对象指向新对象 |
| `tri` | 04 三色与写屏障 | 约 153 s | 1978 迪杰斯特拉；并发标记；三色白灰黑；黑不能指白；涂灰；写屏障；Lua 注释铁律；419 步；增量；G1 并发；.NET 卡表四条指令 | 不停程序地标记，靠一条家规与一道拦截 |
| `cost` | 05 谁来买单 | 约 69 s | 收得越勤 CPU 越旺；Nim 自己挑；ARC；Rust 所有权；C 与 Zig；两种账单 | 精妙不免费，账记在不同人头上 |
| `close` | 无 | 约 62 s | 它不知道，只是还找不找得到；1960 论文与那条脚注；六十多年 | 回到最初的问题 |

## 4. 本片的质量要求

通用标准见 `docs/standards.md`（可靠、审美、动态、声音），四项都是硬标准。本片另外要求：

- **一张纸上的黑与红。** 瑞士国际主义：看不见的网格、中性的无衬线字、左对齐右不齐、大片留白，黑与米白加一个高饱和红。观众看着像一张讲清楚了的工程图，不像一段动画。
- **一个图形只有一个含义。** 方格＝对象，线＝指针，红色＝收集器的动作，灰＝已扫描。观众看了十秒就该建立这套语汇。
- **数字要有口径。** 六千七百万、64 MB、11 MB、136 次、8 字节、28 MB、14 MB、419 步，每个都注明来源与单位，不许出现没有出处的数字。
- **机制名先给白话。** 任何一章的第一句都先说这东西在干什么，再说它叫什么。

## 5. 语体与术语

画面文字与旁白同一种语体：客观、克制，不用比喻套话、不用感叹号。

| 类别 | 统一写法 |
|---|---|
| 机制名 | 引用计数、标记—清扫、分代、三色标记、写屏障、增量、并发、拆环器、卡表、所有权、ARC |
| 英文原名 | 首次出现时给中文说法；原文引用用英文原样并注明「译」 |
| 专名 | CPython、Lua、.NET、PHP、Nim、Rust、Zig、Java、McCarthy（麦卡锡）、利伯曼（Liberman）、休伊特（Schwartz）、迪杰斯特拉（Dijkstra） |
| 数字 | 六千七百万（不用 6700 万）、64 MB、11 MB、136 次、8 字节、28 MB、14 MB、419 步、300 步；年份 1960 / 1983 / 1978 逐字读 |
| 代码 | `a.Next = b` 逐字念「a 点 next 等于 b」；`free` 念英文 |
| 出处 | 一行简短署名，格式「实测：<系统与版本>」或「<来源> <年份>」 |
