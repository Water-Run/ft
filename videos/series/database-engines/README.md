# 数据库引擎

逐个讲解数据库引擎的内部实现：数据怎样落到磁盘或内存里，一次读写在引擎内部经过哪些步骤，这种设计换来了什么、放弃了什么。面向写过 SQL、没有读过引擎源码的观众。

## 定位

| | |
|---|---|
| 讲什么 | 逐个数据库引擎的完整底层科普：内部实现、数据怎样落盘、一次读写的全过程、这种设计的取舍 |
| 面向谁 | 写过 SQL、没有读过引擎源码的观众 |
| 怎么讲 | 深入底层、深入浅出；务必严格事实核查，以该引擎真实运行的数据与同一版本的源码为准，注明版本；全系列统一的视觉风格与节奏 |
| 每集多长 | 5–10 分钟。例外：第二集（InnoDB）按策划 2026-10-09 的要求为 14–16 分钟，其中事务性详解约 4–5 分钟 |

## 连续性

同一系列的各集保持一致的做法记在这里：首集制作时定下来，后续各集遵守；要改就先改这里。各项的含义见 [docs/series.md](../../../docs/series.md)。标为「建议」的是起点，不是限制：每集按题目增删、合并、调整比重。

| 项 | 约定 |
|---|---|
| 标题 | `一个数据库引擎是如何实现的？——<副题>`，副题点出该引擎的特点 |
| 贯穿的线索 | 首集提出了一个引擎必须回答的四个问题：数据怎么放、怎么找、怎么并发、出错怎么办。每一集都回到这四个问题上，并与此前各集的答案对照 |
| 结构（建议） | 定位（在数据库里处在哪一层、用在哪里）→ 存储布局 → 行或记录的格式 → 写入、删除与空间复用 → 索引 → 一次查询的全过程 → 并发 → 故障与恢复 → 四个问题的小结，引出下一集 |
| 演示与取证 | 各集尽量用同一张示例表与同一批数据（首集是 `users(id, name, age)` 与 `notes(id, body)`），便于跨引擎对照；事实由「真实版本上的实验」与「源码」两路核对，画面上的字节与数字由脚本从实验产物生成 |
| 视觉与声音 | 首集（MyISAM）的深色面板式视觉不沿用。各集的视觉取自所讲引擎自己的材料（官方文档的插图、标志色、官网字体），不复用其他系列或其他影片的设计语言。第二集（InnoDB）取自 MySQL 9.7 手册的 InnoDB 架构图与 MySQL 标志色：浅灰底、圆角面板与面板标题、青色深浅的页块、文件与日志图标、虚线框表示示意；标志蓝 #00758F 给此刻讲到的东西，标志橙 #F29111 给锁、被锁的空隙与脏页；拉丁字用 Open Sans。镜头只在站与站之间移动，停留时不晃动。定义见 `innodb/src/css/style.css` 与 `innodb/README.md`「视觉系统」；第三集开工时把与引擎无关的部分（版面网格、字号阶梯、镜头与静止检查的做法）整理成系列基座 `_base/`。配乐每集自写 `tools/music.py`，不共用曲子 |
| 承接上一集 | 每集开头用「上一期我们讲到……」引出上一集并列出它的局限，上一集只作引子；上一集的问题在对应章节穿插回应。每个回顾点可在上一集的脚本或 README 中找到出处；版本不同时写明版本。逐条对照写在本集 README 的「与上一集的承接」一节。规则见 [docs/series.md](../../../docs/series.md) 第 6 节 |
| 概念的引出 | 第二集引出并定义事务、ACID、多粒度加锁、预写日志、MVCC、隔离级别、快照隔离与 OLTP（联机事务处理）。后续各集直接使用这些词，只在需要时用一句回指，不再展开；每集只讲本集的引擎，不夹带其他数据库的内容 |
