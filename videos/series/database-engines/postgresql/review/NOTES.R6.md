## 怎么改

以 MyISAM 一集的口播为正面对照（反馈 P1、P9、P11）：短句、具体对象、每句回答上一句留下的疑问。逐句重写，不是删改。

| 第 5 稿的问题 | 第 6 稿的做法 |
|---|---|
| 抽象名词堆叠：「访问路径」「传播得不同」「能力组合」「开放接口」「共同决定」 | 换成看得见的动作与数字：「第 0 页，第 1 项」「新行放在第 9 项」「少跳一次」「不用背着主键」 |
| 句子是结论，不是过程；读者要自己补中间步骤 | 同一条 alice 记录走完：查找 → 30 改 31 → 两个版本 → 谁读到哪个 → VACUUM 清掉 30 → 改成 32 后崩溃 |
| InnoDB 对比在章内频繁插入 | 每章最多一处，放在本章例子走完之后，用「这里和 InnoDB 不一样」「这和 InnoDB 的 redo 是同一个思路」接入 |
| 章名是术语（「怎么并发」「出错怎么办」） | 改为问题或动作：「改一行，发生了什么」「同时读写」「旧版本去哪了」「崩溃以后」「为什么先考虑它」 |
| 历史章人名、年份、论文过密 | 只留伯克利、Ingres、POSTGRES 名字含义、加入 SQL、1996 改名；新增「从一开始就想让用户自己添加类型和索引」，在第 08 章回扣 |
| 比较章像功能清单 | 三个「比如」各给一个具体用途；扩展从「还记得它最初的目标吗」引出 |
| 口径与限制句打断节奏（o7 等） | 按意见删 o7；限制只保留在比较章两句（调查不说原因、迁移前实测），口径标在图上 |
| 低频术语：空闲空间映射、项目指针、聚簇记录、检查点推进起点 | 删去空闲空间映射；指针、行头、快照、预写日志在第一次出现时用一句话说明作用 |

事实依据未变，仍只用 FACTS 已有条目；本轮未新增事实。改写时复核了措辞强度：Ingres 写「一个早期的关系数据库」（H02），InnoDB 主键读取写「少跳一次」而非「更快」（T10），崩溃实验写「数据库进程崩溃」而非断电（T21）。
