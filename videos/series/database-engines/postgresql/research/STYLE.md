# 视听方案：PostgreSQL 的工业秩序

本轮为文案与事实测绘配套方案，尚未制作关键帧、正式场景或配音。事实只引用 [FACTS](FACTS.md)，审美要求来自 WaterRun。成片以 1920×1080、60 fps 为目标。

## 风格怎样随历史展开

全片保持同一套轴线、字号阶梯和蓝色语义；变化来自所讲材料和对象的演进。不是复刻各年代官网，也不声称 PostgreSQL 曾采用本片排版。

| 阶段与 cue | 本片的表现方式 | 怎样进入下一段 |
|---|---|---|
| 开场 o1–o14 | 第 5 稿：PostgreSQL 蓝与中性灰两条折线，按 2018–2026 九年数据（`lab/out_10_trend.json`）逐年绘出，2023 年交叉处落点；两端读数随旁白出现。图上固定标 Stack Overflow 开发者调查、全部答题者、多选自报、2024 起题目措辞变化。随后 MyISAM / InnoDB 收进 MySQL 一侧，镜头转向上升的 PostgreSQL 线。 | 折线收束为系统边界，进入定位与来历。MySQL 用中性色，不画成失败方；排名只建立位置，选型解释留给比较章。 |

## 参考来源与原创边界

- PostgreSQL [官方 wiki 标志入口](https://wiki.postgresql.org/wiki/Logo)与[三色大象 SVG](https://wiki.postgresql.org/images/a/a4/PostgreSQL_logo.3colors.svg)：取主蓝 **#336791** 和识别材料；不照搬官网布局。官方单色蓝变体实际另用蓝色，不把所有变体称作唯一品牌色。
- 1970 年论文、伯克利回顾、18 手册只提供事实与结构关系；长摘要不进入画面。题名仅在必要时短引并附中文译题，不能把一屏论文当作机制动画。
- 真实页结构、项目指针、快照与日志先后来自本片研究。工程剖面为本片原创示意，画面明确标“示意”；图形尺度需要数字时从生成数据读，不用臆造偏移或页大小。
- 参考 MyISAM 的连续解释方法；改进 InnoDB R8 的章题过快、文献负担和面板解释。两者不作为本片配色、构图或音乐模板。

## 颜色、字体与图形语义

| 项 | 方案 |
|---|---|
| 主色 | PostgreSQL 蓝 #336791：当前被解释的实体、实际生效路径 |
| 中性色 | 纸白 #f4f5f6、石墨 #20282e、纯白 #ffffff；旧版本使用同色降低视觉权重，保持可读对比 |
| 状态强调 | 铁锈色 #a94819：冲突、等待、不能回收；配文字或形状，不能只靠红绿区分 |
| 中文 | Sans SC（Noto Sans SC），正文 42–48px，注解 30–32px；历史的短年份可用 Serif SC |
| 拉丁 / 数字 | Inter；SQL、偏移和时序数据用 Mono（JetBrains Mono），终端正文至少 40px |
| 尺度 | 标题 160–200px，主结论 96–120px，次级 60px；机位缩放后仍满足字号要求 |
| 数据行 | 有实体厚度的横条；同一业务 id 跨场景持续存在，物理版本分成不同条，不把业务行与某个 ctid 画成永久绑定 |
| 页 | 有边界的矩形剖面；项目指针小槽与元组实体分开；平面图不冒充真实比例的 3D 内存模型 |
| 事务与快照 | 独立的竖向时间轨和截面界线；不是围住整张表的大锁框 |
| 索引 | 分支与有序槽；只有解释树路径时出现，实际小表根即叶，不虚构三次物理读盘 |
| 日志 | 单向推进的持久化记录带，与内存页、数据文件分区；清楚区别“已进内存”与“已持久化” |

拟用文字配色的对比度分别为 13.699、5.513、6.018、5.303，均超过 4.5:1；来自 [实算记录](lab/out_05_style.json)。这只验证配色数值，实际截图、材质和运动仍待验证。

## 代表机制段的动作

| cue | 初态 → 触发 → 可见变化 → 结果 | 必须避免的误导 |
|---|---|---|
| d6–d10 | 真实 8 KiB 页 → 插入八行 → 指针端与元组端相向占用 → 中间空位明确 | 不能把八行刚好填满页；不能把 16 KiB 的两页索引画成两层树。 |
| q4–q9 | 八行直扫 → 20,000 行对照 → 实际计划选择索引 → 键指到堆项目、再检查可见性 | 不按 EXPLAIN 毫秒数制作“性能冠军”柱图；不把每次页访问称作磁盘 I/O。 |
| q12a–q12d | 二级索引分别带主键或堆位置 → 显示后续定位路径 → 主键变宽的影响只沿相关结构传播 | 宽主键是依据文档画的示意，不伪造 users 整型主键被改成宽键的实验；不画整体性能冠军。 |
| q16–q18 | 历史段出现过的几何点 → 距离运算 → GiST 实际查找路径 | 只解释索引如何配合类型，不展开另一条业务故事；不冒称点表安装了 PostGIS。 |
| u2–u4、u20–u21 | 有空间的页被选择 → 新元组进入；删除先改版本状态 → 稍后进入回收判断 | 新增部分是源码/文档示意，不使用虚构的逐字节 INSERT/DELETE 回显。 |
| u6–u19 | 年龄 30 → 新增版本 31 → 旧版本指向新版本 → 原索引项经页内链找到新值 | HOT 条件说全；InnoDB 的 undo 对照只画当前差异，不复制它的整段工作空间。 |
| m1–m14 | 同一对版本 → 未提交/新 RC/旧 RR 三条轨道选择 → 第二笔写入等待 | 快照不是整表副本；普通读、写锁与版本判断分清，不把 xmax 非零等同已删除。 |
| v4–v9 | 旧快照仍需 30 → 清理保留 → 事务结束 → 老元组回收、旧项目转为重定向 | 回收不是删除整条业务行；入口保留与元组内容保留分开。 |
| w5–w17 | 内存页变化 → WAL 先持久化 → 允许数据页写回 → 崩溃重做与可见性判断 | 不把内存修改也排在日志持久化之后；未提交事务也可能产生 WAL。 |
| b7–b9 | 合成任务集 → 仅 open 子集进入部分索引 → JSONB 的 kind=alert 通过 GIN 查询 | 数量和计划取自 out_08_compare.json；JSONB/GIN 是查询关系示意，没有真实 GIN 页字节取证，不能画成已解码物理格式。 |
| b10–b12 | 两段预约范围重叠 → 排他约束拒绝冲突 → 同一事务边界覆盖检查与写入 | 依据已有真实预约实验，仅短示意约束组合，不插入完整预约章节。 |
| b13–b22 | 新类型/运算/索引接口 → 扩展的中文用途 → 框架与托管案例 | PostGIS / pgvector 为文档核查，未在本机测试；Django 显示“真实项目建议考虑”，不能误标成默认配置。 |

章题原则：入场约 0.35 秒，完整稳定阅读至少 2.4 秒，再进入正文；第 3 稿脚本 lead 为 3.2 秒候选预算。复杂图不放在短章卡中。信息密集段机位固定，局部动作推进关系；跨空间移动控制在解释需要的接缝，不靠漂移凑动态。

## 配音指导

声音是成熟、平稳的技术纪录片叙述：中低音区、清楚的辅音、自然呼吸；靠语义重音与停顿体现严谨，避免刻意压低嗓音、广告式强调和播标题式句句收重。历史段允许稍宽的句尾留白，机制段把“谁、何时、为什么看见哪个版本”读完整，故障和拒绝不增加戏剧性。

项目音色仍为模板候选，**未定音色、未试听**。确认全文后，以同段候选进行比较，再选择整片配置。不能因为 InnoDB 使用过某一音色就视为本片已经合适；近期 P14/P20 明确指出音色和断句问题。

| 代表句 | 试听目的 |
|---|---|
| o1–o5、h8–h17 | MyISAM、InnoDB、Ingres、Postgres 与年份，名称和系列承接读得自然 |
| q7–q12 | 页号、项目号、主键叶子和数据“行”的读音；索引到堆的关系完整 |
| u15–u19 | HOT 的条件与动作连贯，不把字幕切分读成几次无关的句子 |
| m6–m11 | 新 RC 与旧 RR 快照对应的 31 / 30，不能在“事务”后过度收句 |
| w5–w10 | 内存修改、日志持久化、数据页写回三个时刻，重音不能读反先后 |
| o5–o5a | 57.9% 与 35.1% 的百分比读法；不读成两个无单位的小数 |
| b9–b22 | JSONB、GIN、PostGIS、pgvector、Django、Supabase 的名称与中文用途；按概念停顿，避免功能清单式连读 |

字幕与合成文本的差异统一放在 `script.js` 的 SAY / tts 中。续句停顿 0.22 秒是候选安排，不等于已确认自然。ASR 只筛错读；人耳按实际音轨逐段确认，不能写“已试听”或“工业音色已验收”。

## 配乐、音效与片尾

确认后另写本片配乐脚本，不沿用内置 pulse 曲子。候选为 76 BPM 的低密度机械节拍、短促低音与稀疏和声；历史段稀疏，快照段退到单层，更新和恢复按动作保留空隙。具体旋律、和声与分层在声音制作时编写，未合成、未听。

写入用干燥短击，索引命中用轻微单音，锁等待只在开始时给一次抑制音，拒绝用短低音，恢复完成用克制的落点。章卡不默认 whoosh，每次转场不加气流。听感比较以主混音、仅旁白、无配乐三个版本进行；数值合格不代表符合本片气质。

zCredit 为 **14 秒静音片尾预算**，列策划 WaterRun、实际分工 6.1Sol、开源视频完整地址；后续实际使用的语音等模型据实追加。阅读保持、字号、遮挡和声音收束均待最终视频验证。
