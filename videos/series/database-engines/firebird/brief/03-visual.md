# 03 视觉：材料、要求与自由

**视觉系统、关键帧、分镜细化、各场景、封面都是你的活。** 准备方只给「必须用的材料」和「必须满足的要求」，不给版面、不给类名、不给构图。

## 1. 必须用的材料（这是「契合 Firebird 的风格」的具体含义）

| 材料 | 值 | 出处 |
|---|---|---|
| 火焰三色 | 金 `#FAAC19`、橙 `#F68A21`、红 `#EE2B24` | firebirdsql.org 的火鸟标志位图，像素统计见 `research/lab/out_09_logo_colors.txt` |
| 官网正文墨色 | `#17222b` | firebirdsql.org 样式表 |
| 拉丁字体 | **Heebo**（OFL 1.1，文件已在 `src/type/`） | firebirdsql.org 样式表 |
| 官网标志位图 | 火焰由金黄经橙到红，落在红橙方框里 | firebirdsql.org |
| 官网语汇 | `isql` 的 `SQL>`、`MON$` 监控表字段名、`.fdb` 的页结构、页类型的官方编号与名称 | Firebird 官方文档与源码 |

这些值已经锁在 `project.json` 的 `check.style.palette` 与 `src/css/style.css` 的 `:root` 变量里，闸门按字面比对。

**除了这些，你还可以用**：`#f7f7f5` 纸白、`#ffffff`、`#d9d4cb` 沙灰、`#8a8378` 灰，以及从三色派生出来的深浅变化。**需要更多颜色时从这三色派生，并加进 `check.style.palette`**（说明派生理由），不要引入与 Firebird 无关的色相。

**怎么用它们由你定。** 「火焰＝引擎、外壳＝灰框」这类图形语言的选择是你的判断，不是本任务书的规定。

## 2. 必须满足的要求

### 2.1 认得出是 Firebird（F16）

随机截取成片的若干帧，不看字幕与旁白，也要能认出在讲 Firebird。画面上要有常驻的身份标识（标志或字标），位置与做法按系列约定。

### 2.2 版式与完成度（`docs/standards.md` 第 2 节）

- 网格、强烈的字号对比、不对称构图、大面积留白或大色块。1080p 下正文 38px 起、注解不小于 28px。
- 一个主色、一个强调色、其余中性色。平涂。两种颜色加反白块就足以做出层次。
- 用图形本身讲事情：概念要做成有体积、有空间关系的对象（剖面、拆解、布局），不是文字面板加标签。
- 图形语言定下来就不破例：同一种图形在全片只有一个含义。
- 每一帧单独截出来都应是一张完成度高的平面作品。缩小一半仍读得清才算够大。

**不要出现**（这是仓库级禁令，闸门也会查）：深色渐变背景加光斑/点阵/暗角/噪点；半透明圆角面板把所有东西装进卡片；胶囊标签、菱形图标、全大写宽字距的英文注脚；撞色高亮加外发光；居中对称、四平八稳的布局；靠「换一屏面板」推进；所有元素同一种「淡入加上移」。

### 2.3 每章一个主画面（F18）

每一章要有一个以 Firebird 自己的对象为主角、观众看完能说出「这一段画的是什么」的主画面。表格逐行出现、文字高亮、淡入这类最小动作只能作辅助。

### 2.4 不能「刷一下」（F04，核心）

- 关键结论、对比和报错完整出现后，至少稳定「1.5 秒 + 必要文字字数 ÷ 5 字/秒」再退场。
- 一步机制完成（状态变化、比对结果、拒绝）之后另留看懂这一步的时间，其间不引入新东西。
- 关键信息不在一句旁白的最后半秒才出现；镜头推近时要看的内容必须在画内。
- 数字与读数出现时镜头停住。元素退场交代去向，不在刚到达时直接消失。

### 2.5 画面缺陷要躲开（F19）

PostgreSQL 与 Web 登录两集都在交付后才发现文字溢出、元素压盖、渐变途中字与底同色。本片要盯住三处：

1. 三个二进制体积数字并排时，按实测字符宽度排版，数字用等宽字，标签不压数字。
2. 页类型分布图上的页号标注放在色块外的留白里，不压在色块上；色块不越出图框。
3. 字节偏移的十六进制视图按实测字节数逐字节排版；反色高亮只改底色，不同时渐变字色。

后到的元素不盖住正在讲的内容。

### 2.6 不写说明取舍的小字（F15）

画面与旁白不出现「示意」「只列常量名不列值」「按源码分支构造」这类标注。数据来源只用一行简短署名。

**本片特别容易犯的一条**：行版本头的字段级布局没有逐字段核实。所以画面上**只画「同一个物理行在页上出现几份」这个可数事实**，不画行内每个字节的字段含义。

### 2.7 字体

拉丁字与数字用 **Heebo**，中文用 **Sans SC**，代码与回显用 **Mono**。不要写系统字体名（`sans-serif`、`monospace` 等会被闸门拦下）。字体已随片放在 `src/type/`，`@font-face` 已在 `src/css/style.css` 里声明。

## 3. 你要交的东西

| 交付物 | 位置 | 说明 |
|---|---|---|
| 视觉系统 | `src/css/style.css` | 在准备方给的 `:root` 变量与 `@font-face` 之上重建：字号阶梯、版式、部件类名、图形语言、章节卡（`.chapter` / `.no` / `.ti`，`config.js` 的 `chrome()` 按这三个类名生成章节卡） |
| 关键帧 | `src/design/keyframes.html` | 三到四张静态版面：标题、信息最密的一屏、图解、章节卡。做两到三个方向，按 `docs/standards.md` 自评后选定一个，并说明选了什么、为什么 |
| 示范场景 | `src/design/scene-demo.js` | 十来秒，用到镜头、两三种入场动作、打字机、音效登记。它是你自己照着写的范例 |
| 分镜细化 | `brief/storyboard-detail.md` | 每句一行：画面上有什么、从哪来、怎么动、镜头在哪、什么音效 |
| 场景实现 | `src/js/scenes/` | 把十一个骨架写实 |
| 封面 | `src/cover.html` | 16:9 与 4:3 各一版，另出 2 倍像素 PNG。缩到 360 像素宽仍要读得清主标题；底部约 15% 不放文字 |

## 4. 已有的骨架

`src/js/scenes/` 下十一个文件，场景号与顺序已定，每个文件里有一句「这一段要让观众明白什么」：

`open` → `history` → `engine` → `modes` → `store` → `update` → `concur` → `durable` → `outro` → `next` → `credits`

场景号与 `src/js/script.js` 里的 `id` 一一对应；`index.html` 已按顺序加载。
