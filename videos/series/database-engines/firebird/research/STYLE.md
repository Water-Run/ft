# 视听方案：Firebird 的火与节拍

本轮为文案与事实测绘配套方案，尚未制作关键帧、正式场景或配音。事实只引用 [FACTS](FACTS.md)，审美要求来自策划者与 [docs/feedback.md](../../../../docs/feedback.md)。成片以 1920×1080、60 fps 为目标。

## 一、这套视觉为什么是 Firebird 的

策划者要求「严格契合 Firebird 的风格，随便一帧都能认出是 Firebird」。Firebird 自己给出去的材料只有三样，但每一样都够用：

| 材料 | 取到的东西 | 出处 |
|---|---|---|
| 官网标志（一只火鸟） | 火焰由金黄经橙到红；这就是本片的母题与配色 | `firebirdsql.org/img/site/firebird.png`，像素统计见 `lab/09_logo_colors.py` |
| 官网样式表 | 正文墨色 `#17222b`、链接色 `#2e6474`、拉丁字体 Heebo | `firebirdsql.org/template/css/style.css` |
| 官网本身 | 标语「The true open-source relational database」；isql 的 `SQL>` 提示符；`MON$` 监控表；`.fdb` 的页结构 | 官网首页与本机实测回显 |

**配色**（`project.json` 的 `check.style.palette` 锁死，源码里不出现别的颜色）：

| 用途 | 色值 | 来自 |
|---|---|---|
| 主色：火焰红 | `#EE2B24` | 标志火焰的下段 |
| 中间调：火焰橙 | `#F68A21` | 标志火焰的中段 |
| 强调色：火焰金 | `#FAAC19` | 标志火焰的上段 |
| 墨 | `#17222b` | 官网正文色 |
| 纸白 | `#f7f7f5` | 底色 |
| 沙灰 | `#d9d4cb` | 分隔线与次级块 |
| 灰 | `#8a8378` | 注解文字 |

**字**：拉丁文字与数字用 Heebo（OFL 1.1，随片放在 `src/type/Heebo-wght.ttf`），中文用 Sans SC，SQL、isql 回显与字节用 Mono。

**母题：火焰**。全片只有一个图形语言：

- **火焰 = 引擎**。引擎在库文件里、在进程里，是热的、有能量的。
- **灰色方框 = 服务端外壳**。壳是可选的、灰的、没有火。
- **火焰从方框里升起**，说「引擎住在库里，外壳在外面」；外壳被收走时，火焰还在。
- **火苗分成三股**，说提供程序按顺序试。
- 火焰用红/橙/金三块**平涂**画成，不用渐变填充（总闸门 `check.style.flat` 禁渐变、阴影、模糊、圆角）。

**图形语言不破例**：火焰只指引擎；灰框只指外壳；方格只指页；一条按页切分的带只指 `.fdb` 文件；方波形的字只指 isql 回显。

**与前两集的差别**（P7、P28、F16）：MyISAM 与 InnoDB 是深色面板，PostgreSQL 是官网蓝配大象——本片不借用任何一套，用 Firebird 自己的火焰色与火鸟标志，视觉上换一个家族。

## 二、每章的主画面（F18）

PostgreSQL 一集因为「动画过于简陋，缺乏视觉冲击力」被记为 P31。本片开工前就为每章定一个以 Firebird 自己的对象为主角的主画面。

| 章 | 主画面 | 动作 |
|---|---|---|
| 02 引擎是库，服务端是壳 | 三个并排的方块：黑框（引擎插件）、灰框（客户端库）、更小的灰框（服务端程序），各自按实测体积等比缩放 | 镜头从最小的服务端框推近，火焰从它背后升起；三个体积数字落位后同屏静止 |
| 03 同一个库文件，三种走法 | 一条 `.fdb` 文件带在中间，三条路从左侧分叉过来 | 远程那条路连到网络图标后熄灭；环回那条路连到本机图标；嵌入式那条路直接钻进文件。停掉服务端时，前两条路变红断开，第三条仍亮 |
| 04 数据怎么放 | 240 个小方格排成的页阵，按实测页类型上色 | 一页一页按类型点亮；数据页与索引页用红与金标出；事务清单页单独被圈出 |
| 05 一次修改 | 数据页（第 231 页）的局部放大，两份 `alice` | UPDATE 提交后，页面上凭空长出第二份 `alice`，两份之间用一条虚线连着「同一个逻辑行」 |
| 06 怎么并发 | 两块并排的读数板（写者 / 读者） | 写者板变成 31，读者板还是 30；写者按下「提交」后读者板才翻成 31 |
| 07 出错怎么办 | 服务端进程剖面：两个专职角色各占一个位 | 脏页从缓存流向磁盘；旧版本被回收线程拖走 |

## 三、逐句画面对应

按策划者「文字要能对应惊艳、直观、Firebird 风格的动画」的要求：写稿时以「这句话在屏幕上发生了什么」检验，说不出画面的句子删掉或改写。

**全片统一的语言**

- 不「刷一下」（F04 核心）：每个关键状态完整出现后，按「1.5 秒 + 必要文字字数 ÷ 5 字/秒」再退场；关键信息不压在旁白最后半秒；镜头推近时要看的内容必须在画内。分镜阶段为每个关键状态写预计稳定时长，成片逐个实测。
- 画面上不写制作者口吻的说明小字（F15）：页类型分布、页偏移、三个体积都直接是实测值，不加「示意」之类。
- 运动只表达关系：生长、连接、分流、挪走。不用擦除式刷入，不用整屏换面板；镜头只在站与站之间移动，停留时单向慢推。

**开场与来历（o1–h6）**

| 旁白 | 画面 |
|---|---|
| o1–o3 | 画面上只有一个灰框（服务端）；框里的火焰被抽走，框变成空壳，但旁边的数据条还在动 |
| o4 | 火鸟标志（官网标志位图，注明出处）落在画面上，转成本片自绘的三块平涂火苗 |
| o5 | 三个引擎的方块排成一列：MySQL 灰、PostgreSQL 灰、Firebird 带火。只标名字，不作比较 |

## 四、版面上三处高风险（F19）

PostgreSQL 结尾表格高亮褪色时字与底同色、Web 登录文字溢出与压盖，都是交付后才发现的。本片提前盯住三处：

1. **三个体积数字并排**（e6–e9）：按实测字符数定宽，数字用等宽字，标签不换行、不压数字。
2. **页类型分布图上的页号标注**：标注放在色块外侧的留白里，不压在色块上；色块不越出图框。
3. **字节偏移的十六进制视图**：逐字节排版，宽度按实测字节数算；高亮只用底色，不同时改字色。

后到的元素不盖住正在讲的内容；元素的退场交代去向（外壳被抽走时画出它被收走）。

## 五、声音

### 配音

- 音色：**未定**。`project.json` 暂记 `Chinese (Mandarin)_Male_Announcer`、语速 1.08，**这只是占位，未经试听**。按 F17，开工配音前先试听候选：句子要有起伏、该强调处有重音、长句不被念平；避开 WaterRun 评过「懒洋洋」的 `Reliable_Executive`。
- 试听代表段三组：`e6–e9`（三个数字的读法与重音）、`m2–m4`（外文专名与协议名）、`c3–c6`（长句不被念平）。
- 读法集中在 `script.js` 的 SAY 表；年份、版本号、字节数、偏移在对应 cue 的 `tts` 字段里直接写成中文读法，不让 TTS 猜。
- ASR 只筛查候选，最终由人耳逐段确认。

### 配乐（电子乐，富有节奏感）

`tools/music.py` 自写，**124 拍/分，四踩贯穿全片**。

| 项 | 选择 | 理由 |
|---|---|---|
| 速度 | 124 BPM | 与系列其他片明显不同：2FA 120 拍/分（稀疏纪实，以秒针贯穿）、PostgreSQL 72 拍/分（工业铺底）、InnoDB 偏持续低频。124 + 十六分音符驱动，听感明确是「电子」 |
| 音色 | 方波拨弦、加法合成锯齿酸性贝斯、四踩底鼓、滤波噪声 hat、方波琶音 | 电子乐的基本语汇；母题动机用方波，一听就与前面几片区分开 |
| 母题 | 三个音（A C E）上行后回落 | 对应火焰的三层（金/橙/红）；在每章章首与结论处出现，其余段落只留它的节拍骨架 |
| 和声 | A 小调：Am – F – C – G，每小节一个和弦，四小节一轮 | 比系列其他片的 D 小调更亮，配合「引擎在库文件里」的轻快感 |
| 编排 | 逐章加层：open 只有低频脉冲 → history 加方波拨弦 → engine 四踩 + 十六分酸性贝斯 → modes 加宽立体声垫 → store/update 加十六分琶音 → concur 峰值 → durable 回稳 → outro 全开 → next 收拢 → credits 只剩铺底与低音 | 层数随叙事推进，听觉上能感到结构；不用「换一屏」的办法 |
| 存在感 | 全片持续有低音与铺底（pad 与 sub 不在任何一章缺席），章首一个落点、update 章末一个 riser | 按 P27：配乐要有存在感，不能用稀疏的钢琴或和弦代替 |
| 混音 | `music_db −11`、`duck_db 7`、`sfx_db −10` | 与 PostgreSQL 一集同档，便于跨片比较 |

配乐与音效由程序合成，制作者听不到。数值自检（`research/lab/10_music_smoke.py`）：峰值 0.648，十一段场景 RMS 从 0.025（open）到 0.107（concur），无整章无声。**听感仍需人耳确认。**

### 音效

只给关键动作，每种含义固定一种声音：外壳出现与消失用一次落点；页类型分布落定用一次 chime；两份副本出现用一次 tick；提交与读数变化用一次轻击；回收旧版本用一次短低音。**不铺 whoosh**，不靠音效密度替代讲清楚。
