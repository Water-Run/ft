# 视觉与声音的材料与约束

本文件记录**受托方要用的官方材料**与**必须满足的硬约束**，不规定画面怎么设计、不规定配乐怎么写。

- **归受托方的**：视觉系统（字号阶梯、版式、部件、图形语言）、各章的主画面与实现、动效、音效、封面、配乐。
- **归准备方的**：事实与出处、旁白稿、章节结构、以及这份材料清单与约束。
- 具体怎么做，看 `brief/03-visual.md` 与 `brief/05-motion-sound.md`；那里写的是「要满足什么」，不是「照着画什么」。

策划者的要求原话：**「视觉风格要求严格契合 Firebird 的风格」「配乐电子乐，富有节奏感」「片长 4–7 分钟」**。下面把「Firebird 的风格」落实成可查的材料与数值，把「电子乐」落实成可核的要求。

## 3. 硬约束

### 3.1 全片通用（来自 `docs/standards.md`，不可商量）

- 版式有骨架：网格、强烈的字号对比、不对称构图、大面积留白或大色块。1080p 下正文 38px 起、注解不小于 28px。
- 配色克制：**一个主色、一个强调色，其余是中性色**。平涂。两种颜色加反白块就足以做出层次。
- 用图形本身讲事情：把概念做成有体积、有空间关系的对象，而不是文字面板加标签。
- 图形语言定下来就不破例：同一种图形在全片只有一个含义。
- **不出现**：深色渐变背景加光斑/点阵/暗角/噪点、半透明圆角面板、胶囊标签与菱形图标、撞色高亮加外发光、居中对称布局、整屏淡入淡出换面板、所有元素同一种「淡入加上移」。
- 画面只由时间 t 决定；时间点写成 `T(句号, 词)`。
- 关键结论、对比和报错完整出现后，至少稳定「1.5 秒 + 必要文字字数 ÷ 5 字/秒」再退场（F04，核心）。这一步机制完成之后另留看懂这一步的时间。

### 3.2 本片额外要躲开的坑（F19，来自 PostgreSQL 与 Web 登录的成片评价）

- 三个二进制体积数字并排时，按实测字符宽度排版，数字用等宽字，标签不压数字。
- 页类型分布图上的页号标注放在色块外的留白里，不压在色块上；色块不越出图框。
- 字节偏移的十六进制视图按实测字节数逐字节排版；反色高亮只改底色，不同时渐变字色。
- 后到的元素不盖住正在讲的内容；元素退场交代去向。

### 3.3 不写制作者口吻的自我说明（F15）

画面与旁白不出现「示意」「只列常量名不列值」「按源码分支构造」这类说明取舍、脱敏或默认处理的标注。不展示的东西直接不展示；数据来源只用一行简短署名。

**本片特别容易犯的一条**：行版本头的字段级布局没有逐字段核实（见 `research/FACTS.md` 的「不确定的字节口径」）。所以画面上**只画「同一个物理行在页上出现几份」这个可数事实**，不画行内每个字节的字段含义，也不加「示意」来打圆场。

### 3.4 每章要有一个主画面（F18）

PostgreSQL 一集因为「动画过于简陋、缺乏视觉冲击力」被记为 P31。**每一章要有一个以 Firebird 自己的对象为主角、观众看完能说出「这一段画的是什么」的主画面**；逐行出现、文字高亮、淡入这类最小动作只能作辅助。

用哪个对象、怎么动、什么节奏，是受托方的判断。

## 4. 声音的要求

### 4.1 配乐

策划者的要求：**电子乐，富有节奏感**。落实成可核的要求：

- 必须是**程序合成**的电子乐，写成 `tools/music.py`，由 `mix.py` 调用（写法见 `docs/sound.md` 第 3.1 节与 `docs/tools.md`）。
- **有节奏感**：要有明确的节拍与律动，不是稀疏的点缀。
- **有存在感**（P27）：先有一层贯穿全片的低频或铺底，再加动机与节奏；旋律稀疏不等于克制。InnoDB 与 OpenCart 的配乐太弱，MyISAM 的持续铺底才是参照。
- **与本系列前三集听得出来**（P3、F06）：2FA 是 120 拍/分的稀疏纪实（以秒针贯穿），PostgreSQL 是 72 拍/分的工业铺底，InnoDB 偏持续低频。本片是电子方向，节奏与音色要与之明显不同。换 preset、换主奏音色不算差异化。
- 配乐服务于讲解：信息最密的段落要保证旁白清楚，不能机械地越讲越加层。
- 结论处（`z8`）抬起而不是提前用完；片尾收拢。
- 配乐与音效由程序合成，制作者听不到：数值自检（`audio.js` 的输出）之外，听感由人确认，要如实写明。

### 4.2 音效

- 只给**有语义的关键动作**配音效：数据落位、连接建立与断开、页类型分布落定、副本出现、提交与读数变化、回收旧版本。
- 不用默认气流声（`whoosh`）填满动作；慢移、阅读保持、镜头推移可以无声。
- 同一类动作用同一种声音，音量递减或保持。

### 4.3 配音

- 音色**待定**。`project.json` 的 `tts` 段是占位，按 F17 要先试听候选音色与语速再定。
- 试听要覆盖三组：三个二进制体积的读法与重音（`e6`–`e9`）、外文专名与协议名（`m2`–`m4`）、长句不被念平（`c3`–`c6`）。
- 读法集中在 `src/js/script.js` 的 `SAY` 表；年份、版本号、字节数与偏移在对应 cue 的 `tts` 里直接写成中文读法。

## 5. 片尾

`credits` 场景是 13 秒静默 cue（`pause: 13`、`credits: true`、无 `tts`、字幕为 `null`）。名单与链接**只在画面上，不配旁白**。名单按 `research/FACTS.md` 的「制作署名」，须含策划者 WaterRun、全部实际参与模型与分工，以及「开源视频」与完整可读的 `github.com/Water-Run/ft`。
