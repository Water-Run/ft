# 测绘路线

这一份只记「讲什么、怎么讲、丢掉什么」。每条陈述的依据在 [FACTS.md](FACTS.md)。

## 主问题

> 在你按下回车、SSH 还没登录成功的那一秒里，到底发生了什么？

这句问话就是标题承诺的兑现方式：**不是讲 SSH 有哪些功能，是讲一次连接在登录之前依次做完了什么。** 全片按这一次连接的时间顺序走，不按功能清单走。

片名「搞懂 SSH」里的「搞懂」落在三件可检验的事上：观众看完能复述一次连接的阶段顺序；能说清每一阶段防住了什么；能指出这套办法自身的盲区。

## 受众前提

- 用过 `ssh` 命令连过机器，知道「连上去会提示输密码或直接登录」。
- 知道公钥、私钥这两个词，但不知道它们在协议里出现在哪一步。
- 不知道 SSH 是一套协议而不是一个程序，也不知道传输层与用户认证是两层。
- 不知道「协商」这件事的存在——以为算法是写死的。

不假设：密码学背景、模运算、哈希与签名的区别、任何 RFC 的内容。

## 逐章答案

| 章 | 本章问题 | 本章答案 | 下一问 |
|---|---|---|---|
| 现象 | 敲下回车之后那一秒，屏幕上没发生什么，为什么？ | 因为在屏幕上出现任何东西之前，连接已经协商完算法、换出密钥、验过服务器 | 那这套流程到底是什么 |
| 它是什么 | SSH 是什么，为什么值得看 | 一套协议；1995 年 Ylonen 的第一版，2006 年定为 RFC 4253；分传输层与认证层，传输层只认服务器不认用户 | 协议说要做哪几件事 |
| 算法清单协商 | 双方怎么知道该用什么算法 | 各自发一份按偏好排序的清单，客户端取自己清单里第一个对方也有的；没有共同的就断开 | 清单选完了，密钥从哪来 |
| 密钥交换 | 两台机器怎么在公开信道上换出只有它们知道的密钥 | Diffie-Hellman：各自随机取数、各自算出 e 与 f、两边本地算出同一个共同值，这个值不过网 | 共同值不证明对面是谁 |
| 主机密钥 | 怎么确认对面是那台机器 | 服务端把哈希 H 用主机私钥签名；客户端用主机公钥验签名，并把公钥跟本地 known_hosts 对照 | 身份对了，密钥怎么用 |
| 密钥派生 | 共同值怎么变成真正加密数据的密钥 | 六次哈希各带一个字母 A–F，派生出两个方向的 IV、加密密钥与完整性密钥；之后所有包连包头一起加密 | 服务器确认了，该你了 |
| 用户认证 | 怎么证明「我是我」 | 认证层 ssh-userauth；公钥认证是唯一必须实现的方法：报公钥、拿回确认、用私钥签一份含会话标识与用户名的数据、服务器验签 | 这套办法哪里不牢靠 |
| 边界 | 这套办法自身的盲区在哪 | 第一次连接本地没有旧记录可比；转发认证代理等于交出钥匙的用法；端口转发在隧道里再开一条通道 | 所以那一秒究竟做了什么 |
| 结论 | 回到开头 | 登录框出现之前，协商、换密钥、验服务器、证明自己这四件事都已经做完 | —— |

## 贯穿的讲法

- **一次具体的连接**。所有机制都挂在那一条实测连接上：它的协商结果（curve25519-sha256、ssh-ed25519、chacha20-poly1305@openssh.com）、它的主机密钥指纹、它的 known_hosts 那一行、它的服务端日志。不举第二个例子。
- **每一步先问「防住了什么」**。这是本片与「协议介绍」的分界线。协商防住的是双方算法对不上；密钥交换防住的是窃听者；主机密钥防住的是冒充；公钥认证防住的是别人用你的账号。
- **先给现象，再给术语**。迪菲-赫尔曼先讲「两边各自算、结果相同」这一层，再给名字；known_hosts 先讲「本地存过的那份主机公钥」，再给文件名。

## 舍弃的材料

| 舍弃 | 理由 |
|---|---|
| SSH 1 的历史、patented 算法对协议设计的影响 | 属于史料，不回答「这一秒发生了什么」。只保留 DSA 当年是唯一必选项这一句，因为它解释「为什么协议里会有一个 160 位的算法」。 |
| OpenSSH 的治理结构与移植史 | 属于项目介绍，不是机制。只保留「由 OpenBSD 项目的开发者维护」这一句，出现在「它是什么」章，用来定位「现在大家用的 ssh 是哪来的」。 |
| 端口转发、agent 转发的配置写法 | 属于用法。边界章只讲这两件事带来的权限含义，不讲命令行参数。 |
| 具体的默认算法顺序 | 「支持什么」不等于「默认选什么」，而默认顺序要按版本查文档（见 FACTS「查过但决定不写」）。只讲这一条连接协商出的结果。 |
| 包格式的每个字段、MAC 的具体算法、压缩 | 讲包长字段被加密这一点就够说明「外面看不出内容」；再细就变成协议规范朗读。 |
| 认证方法全集（口令、键盘交互、hostbased、GSSAPI） | 认证层讲了公钥这一种就够；讲全集会稀释「唯一必须实现」这个事实。 |
| 密钥长度、位强度的横向比较 | 没有对照实验，就不报倍数。 |
| 中文与英文的双语节奏差异 | 英文是直译草稿，等中文确认后重译，不在本轮调两种语言的节奏。 |

## 视觉方向

见 [STYLE.md](STYLE.md)。本片用俄国构成主义（Russian Constructivism）作为表现系统——这是系列约定的正式例外，保留定长时间线、语速、字幕带与秒尺、剩余秒数、右上角仪表的位置与做法，换掉「计时盘」那一套图形语言。

构成主义在这里不是装饰：斜切平面就是连线两端的对峙，楔形就是「此刻」和推力，紧固钉就是协议里逐个钉进去的六次哈希，骑缝章就是主机私钥签在哈希上的那一笔。图形承担解释任务，不是贴图。
