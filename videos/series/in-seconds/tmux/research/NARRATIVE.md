# 叙事测绘

本文件只记录面向观众的讲述顺序与取舍，不是旁白稿。事实与依据在 `FACTS.md`。

## 观众前提

用过终端、ssh 或 VS Code 的终端，知道 `cd`、`ls`、`vim` 这类基本命令；没有系统用过 tmux 的 session/window/pane，也不知道 detach 后程序为什么还活着。

## 一个核心问题

关掉终端之后，程序为什么还在跑；tmux 到底替谁记住了什么。

## 逐章问题与答案

| 章 | 观众的问题 | 本章要回答 | 画面上的主要证据 |
|---|---|---|---|
| 1 现象与定义 | 终端离开以后，数为什么还在；tmux 是什么 | 离开前数是 4，离开后数是 9；走的只是眼前这块终端。把计数留住的程序叫 tmux：同一块屏幕里可以有多个终端 | 实验第 8 节两次读文件。口播不说屏幕上的数字在跳 |
| 2 沿革 | 它从哪来，为什么和眼前这件事有关 | 2007 年写出来的；作者当时用 screen，写明不是要复制；要同一页同时出现在多个终端上；2009 年成了 OpenBSD 里自带的程序。说完回到同一个数 | 采访与导入报道。不报 nscr，不报 3.8，不把 0.1 的日期说成项目开始 |
| 3 基本名词 | session、window、pane、server、client 各是什么 | 这些终端放在一起是 session；占满屏幕的一页是 window；切开的一块是 pane；留住这一组的进程是 server；看和按键的一端是 client；伪终端是 tmux 给程序准备的终端，留在 server 上。这一组有两个 window，第二个切成两块，计数在其中一块 | 实验第 5、8 节。3.4 只在画面角标。不把 pane 块数加总 |
| 4 怎么用 | 要按哪些键 | 前缀 `C-b`，然后 c / d / % / 引号，以及 `tmux attach`。不说键和命令同名 | 默认键表 |
| 5 键往哪去 | 按下去的键谁先拿到 | 刚才这些键由 tmux 收下，其余送给 pane 里的程序。没有 client 时，读到的是 9 | 源码的键表路径只留这一层。字节解析、重画、PANE-A 这一轮不口播 |
| 6 边界 | 程序还在，要怎样才停 | 程序还在是因为 server 还在。这个还在只算终端离开。kill-server 让 server 停，里面的程序也停 | 实验第 10 节。不说不能恢复，不把关机再开说成测过的结果 |

## 决定不讲

- tmux 配置文件的完整写法、插件管理器、主题生态。会把 128 秒变成配置课。
- copy mode 的全部键位。只讲 `[` 进入、`]` 粘贴，以及它为什么需要（pane 里没有外层终端的滚动条）。
- Windows 上的 psmux、iTerm2 的 tmux 集成、systemd 托管。它们是另一条实现路径。
- 性能对比、内存占用、启动时间。本次没有做对照测量。
- “tmux 是 screen 的替代品”这种站队式说法。作者自己说不是要复制 screen。
- 口播里的 nscr、3.8 和 3.4。nscr 只是原型名字；3.8 的发布不解释这次数；3.4 只留在画面角标。
- 「好读的代码」和「可扩展」。它们不回答终端离开后数为什么还在。
- 「每一块里跑着一个程序」。计数在其中一块，伪终端是给程序准备的，这句不再单列。

## 开场可用的钩子（不是定稿）

- 第 4 轮的钩子：终端离开了，计数的程序还在；离开前数是 4，离开后数是 9。两次读数在 6 秒内说完。不说屏幕上的数字跳过一段，也不用「你」。
- 旧方案留下备查：先让计数在 pane 里跑，然后 detach，再接回来。那一版容易把两次读文件说成画面上的数字在跳。
