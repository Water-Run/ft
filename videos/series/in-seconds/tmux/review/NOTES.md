## 句与依据

4 和 9 是 `/tmp/ft-tmux-lab/counter` 的两次读数：离开前 4，离开后 9，当时 client 数为 0。口播说「数从 4 到 9」，不说屏幕上的数字跳到了 9。

m6「计数的进程，是 server 启动的」：实验里 pane 的 ppid 是 server，计数是送进这个 shell 的 `while` 循环，不是 server 另外执行的一个程序。

m8 只说 tmux 3.4 有两个 window。第二个 window 分成两块 pane。第一页当时还有一块 pane，口播没有把块数加总。

m10 到 m12 先给 pane 和伪终端对上，m13 才叫 session，避免「一组」没有着落。

u3 不说「分离」。主动 detach 和手册里的断线，口播都收成「离开」。e2 把「还在」限制在离开，实验没有测重启，不说「不能恢复」。

i1、i2 对应「按键先查表，没有命中才进 pane」。口播不说「命令表」。c 不是命令名 `new-window`，所以不说「同名」。

i4「读成字」是 VT100/ANSI 状态机写入屏幕格子的口语。这一轮不报 VT100。i5 对应「不把原字节转交给 client」。i6 只说这一个 client，不说同时连着很多个。

i7 和 i8 是两次实验，不能画成同一次：PANE-A 是给另一块 pane 送命令后的读屏，发生在后来那次 attach 之前；4 到 9 是 client 已经为 0 的时候。3.8 里 `fdforkpty` 分出伪终端和子进程，这一轮不口播；m6 用的是 3.4 的父子进程关系。

3.4 只出现在 m8。口播里没有 3.8。
