# 200 秒了解 Lean 4：什么是形式化证明，以及它为什么可靠

「XX 秒速通」系列的第 2 集。一部 200 秒的科普片：用一条小定理（前 n 个奇数的和等于 n²）说明什么是形式化证明，Lean 4 怎样把人写的几行策略变成证明项交给内核检查，以及这种检查靠什么可信、边界在哪里。中文与英文两个版本，时长相同。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`；系列的约定见 [`../README.md`](../README.md)。

## 内容

全片 200 秒：六个正片场景各 32 秒（120 拍/分下正好 16 小节），片尾名单 8 秒。右上角的读数每秒把 n 加一，全片从 1² 试到 200²。

| 场景 | 起点 | 内容 |
|---|---|---|
| open | 0:00 | 现象：1 + 3 + 5 + 7 = 4²，一圈一圈加下去总是 n²；Lean 逐个试到一百万都成立，但 n 有无穷多个 → 片名 → 证明是可以逐步核对的推理，历来由人核对 → 1998 年开普勒猜想的证明：300 页加约四万行程序，审稿人未能确认 |
| formal | 0:32 | 形式化证明的定义：纸上的五行各自写成式子，由程序检查 → 时间轴：1968 Automath、1998 与 2003–2014 Flyspeck、2013 Lean、2023 Lean 4.0 → 把开头的命题写成 Lean |
| types | 1:04 | 命题是类型，证明是值，检查证明就是检查类型（假命题配 `rfl`，Lean 报类型不符）→ 归纳法：先证 0，再证 k ⇒ k + 1，多出的一圈是 2k + 1 → 两步覆盖全部 n |
| kernel | 1:36 | 策略不是证明本身 → Lean 生成证明项，按树展开 3 347 个节点 → 内核逐个节点核对类型 → 内核的源码 8 071 行，其余源码 71 万行 → 策略、自动化与 AI 都在内核之外，错的证明项被内核拒收 → 人、Lean、内核三者的分工 |
| trust | 2:08 | `sorry` 留下 `sorryAx` → `#print axioms` → 这条定理向下依赖 2 565 条声明 → 核心库 66 200 条声明全部重放 → 内核的独立实现 → Mathlib 的 290 195 条定理 → 费马大定理的形式化 |
| edge | 2:40 | 边界：名字叫黎曼猜想、命题是 1 + 1 = 2 的定理照样通过，命题是否表达原意仍要人来读 → 2024 年 AlphaProof → 不论谁写的证明，过的是同一个内核 → 逐个去试只试到 200，证明覆盖全部 n → 结论 |
| outro | 3:12 | 制作名单与开源仓库地址 |

**定长的时间线。** 片名里的秒数就是成片的时长。`src/js/script.js` 里每个场景带一个 `at`（开始的时刻），`TOTAL = 200`；一场的旁白说完后余下的时间留白到下一场的定点，说不完就记入 `L.problems`，总闸门不通过。两种语言的场景起点相同。

**一条定理贯穿全片。** 开场的方点阵、第三场的归纳、第四场的证明项与第五场的依赖，讲的都是 `sumOdd_eq_sq` 这一条：先看到现象，再把它写成 Lean，然后看 Lean 与内核各自对它做了什么。只用 Lean 自带的核心库，不依赖 Mathlib。

## 视觉系统

沿用系列的「计时盘」：墨色 `#0c0d0f`、纸色 `#f2efe8` 两种底，一种强调色朱红 `#ff4a1c`；平涂，不用阴影、渐变与圆角；代码、数字与数据用 JetBrains Mono，拉丁文字用 Inter，中文用 Noto Sans SC。本集的图形语言叫「方点阵」：

| 约定 | 含义 |
|---|---|
| 一个方点 | 一个被数、被查的单位：先是奇数里的「1」，后是证明项的一个节点、一条声明、一条定理 |
| L 形的一圈 | 归纳的一步：从 k 到 k + 1 多出的 2k + 1 个方点 |
| 纸色底 / 墨色底 | 写给人读的（纸上的证明、命题、策略）/ 机器里的（证明项、内核、依赖） |
| 斜线 | 还没有验证的：没试过的 n、没查过的程序、跳过的证明、名不副实的名字、尚在进行的形式化 |
| 朱红 | 只给「此刻」与结论：刚加上的那一圈、内核正在查的位置、被拒的证明项、公理、结论；整屏朱红只用于片名与结论两张卡 |
| 墨色的方框 / 朱红的方框 | 读的人 / 程序。开场里逐行打勾的是墨色方框，结尾它再出现一次，只框住命题 |

常驻元素：底部的字幕带上沿是一把 200 格的秒尺，一秒一格，各场景的起点是长刻度；左上角是剩余秒数；右上角的仪表是一个小方块加「n² = 和」，每秒在方块的右、下两边画一圈 L 形，n 加一。换场用同一个动作：新场景从右、下两边像一圈 L 形那样加上来，内角沿对角线从右下走到左上，一拍盖满全屏。片尾名单不属于正片的分段，由左向右直刷。

三处大幅度的画面：

- **放大视野的方点阵**（`parts.js` 的 `lattice`）：视野里是 V×V 个方点，V 按指数增长；方点小到看不清之后改画每 10 个、每 100 个……一道缝的格线，一级一级冲向左上角。开场用它从 4 冲到一百万，再继续放大，试过的那一块缩向角上；第三场的结尾用它铺满全屏。
- **一格一个节点**：证明项的 3 347 个节点排成 104 列，朱红的线自上而下扫过，扫过的变亮。
- **连续拉远的三级**：依赖（51 格见方）是核心库（258 格见方）的左上角，Mathlib 的定理（539 格见方）在它右边；镜头由该场自己按 t 算出，倍数按指数插值。

**参考与原创。** 没有参照某一部现成的视频或产品。三处取材于讲解对象本身或数学里通行的画法，并按本片内容重新设计：

- 「前 n 个奇数排成正方形」是这条恒等式通行的图示（每加一个奇数就在正方形外面加一圈 L 形）。本片把它用作全片的图形母题、仪表与换场，这些用法是本片自己的。
- Lean 的源码、目标、报错与 `#print` 的回显是取证材料，按编译器的输出原样排出（去掉行首的「文件:行:列」），用本片的字体与配色，不仿任何编辑器的界面。
- 时间轴上的「L∃∀N」取自 Lean 官方标志的写法（把 E、A 写成 ∃、∀）：画面上是用本片的等宽字体排的四个字符，不是标志图形的复制。

选定方向之前比较了三组关键帧（各两到三张静帧）：a 方点阵（一个方点是一个单位，L 形的一圈是归纳的一步）；b 推演线（前提在线上、结论在线下，证明画成一棵由横线搭成的树）；c 校样（一页证明，读的人在页边逐行打勾）。选 a：它能把「试」与「证」、有限与无穷画成同一种图形，并且能从 4 个方点一直用到 29 万条定理；b 依赖观众认得逻辑记号，且画面以文字为主；c 只适合讲「人读」的那一段，于是把它并进 a，成为开场的第二站。

## 取证

- 实验在 Linux 上用 Lean 4.34.1 做，工程在 `research/lab/proof/`，脚本 `research/lab/00_env.sh` 至 `05_mathlib_stats.sh` 按序运行，回显在 `out_*.txt`。各文件做什么见 `research/FACTS.md` 的「环境与版本」。
- 证明项的节点数与依赖闭包由 Lean 的元程序算出（`SumOdd/Stats.lean`）；「绕过策略把错的证明项直接交给内核」也是一段元程序（`SumOdd/Kernel.lean`），得到的是内核自己的报错。
- 内核与其余源码的行数在 v4.34.1 的源码上数（`04_kernel_size.sh`）；Mathlib 的定理数取自官方统计页并记下日期（`05_mathlib_stats.sh`）。
- `tools/gen_data.py` 把上述结果转成 `src/js/data.js`，并在转换时做断言；场景代码不手写这些内容。
- 历史节点与定义逐条读到原文，列在 `research/FACTS.md`。

重做一遍（需要 elan、Python 3、git 与 curl）：

```bash
cd videos/series/in-seconds/lean4/research/lab
./00_env.sh && ./01_build.sh && ./02_run.sh && ./03_recheck.sh && ./04_kernel_size.sh && ./05_mathlib_stats.sh
```

`05` 取的是当天的统计数，重做会得到新的数与新的日期；`03` 的耗时随机器而变。其余结果在同一版本的 Lean 下应逐字节不变。

## 读法

字幕写正式拼写，送去合成的文本按 `script.js` 的 `SAY` 表或该句的 `tts` 字段替换，均经 `tts_probe.js` 试验：

| 字幕 | 合成文本 | 原因 |
|---|---|---|
| `1 + 3 + 5 + 7：…` | 一，加三，加五，加七：…（英文 One plus three plus five plus seven: …） | 算式要读成一句话 |
| Lean 4 | Lean 四 | 中文音色下数字读法不稳 |
| 四万行、八千行 | 四万航、八千航 | 「行」会被读成 xíng |
| 300 页 | 三百页（英文 Three hundred pages） | 数字读法 |
| `k + 1`、`2k + 1` | k 加一、二 k 加一（英文 k plus one、two k plus one） | 算式 |
| Mathlib | Math Lib（英文 Math lib） | 连写时中文音色读不出来 |
| 66,000、290,000、n = 200（英文） | sixty-six thousand、two hundred ninety thousand、n equals two hundred | 数字与等号 |

画面上出现但旁白不念的专名：de Bruijn、Automath 的作者与地点、HOL Light、Isabelle、Flyspeck、AlphaGeometry 2。
