# XX 秒速通

每集在标题写明的秒数内讲清一个主题：一个概念、一项机制或一个工具。秒数是上限也是卖点：信息密度高、没有铺垫，开门见山。面向想快速搞懂的观众。

## 定位

| | |
|---|---|
| 讲什么 | 在极短的时间内快速了解一个知识：一个概念、一项机制或一个工具 |
| 面向谁 | 想快速搞懂的观众 |
| 怎么讲 | 富有节奏感，配乐完整，引人注目；无观看负担的同时把知识学到；开门见山，不铺垫 |
| 每集多长 | 96、100、128、150、192、200、256 秒之一（区间 96–256 秒）；标题里写明的秒数即成片时长，各集不同 |

首集《120 秒关于什么是 2FA，以及它是怎么工作的》成片于本约定之前，时长 120 秒，保留，不在上述可选值之列；此后各集只取可选值。

## 连续性

同一系列的各集保持一致的做法记在这里：首集（[`two-factor-auth`](two-factor-auth/)）制作时定下来，后续各集遵守；要改就先改这里。各项的含义见 [docs/series.md](../../../docs/series.md)。

| 项 | 约定 |
|---|---|
| 标题 | `<秒数> 秒…`；英文 `<主题> in <秒数> Seconds: …`。秒数即该集时长上限，取自「定位」一节的可选值 |
| 时长 | 成片时长恰为标题里的秒数，各语言相同。做法：`script.js` 里每个场景带 `at`（开始的时刻），`TOTAL` 为全片时长；旁白超出定点时记入 `L.problems`，总闸门不通过。`project.json` 的 `check.duration` 设为 `[秒数 − 0.1, 秒数 + 0.1]` |
| 结构 | 现象或问题（开头 6 秒内，不铺垫）→ 片名卡 → 它是什么 → 它怎么工作（重头：把真实数据一步步算出来或拆开来）→ 边界或比较 → 一句结论 → 片尾名单（约 7.5 秒，不配旁白）。没有章节卡；题目自身有周期时按它分段（首集 120 秒 = 4 个 30 秒的时间步），否则每段 30 秒左右 |
| 讲法 | 一句一件事，每句落在画面上的一个动作；数字、字节、回显来自实验（`research/lab/` → `tools/gen_data.py` → `src/js/data.js`）；历史节点只写读到原始来源的，并在画面上给出年份 |
| 语速 | 中文 `+6%`，英文 `+8%`；英文「过快」阈值为每秒 4 词（`check.pace`），中文用缺省值 |
| 视觉 | 「计时盘」系统：墨色 `#0c0d0f`、纸色 `#f2efe8`、朱红 `#ff4a1c`，平涂、无圆角；数字与数据用 Mono，拉丁文字用 Inter，中文用 Sans SC；字号阶梯见基座的 `style.css`。朱红只给「此刻」与结论；整屏朱红只用于片名与结论两张卡 |
| 常驻元素 | 底部字幕带（墨色）上沿是一把按全片秒数刻度的秒尺，走过的变朱红；左上角是剩余秒数，最后 5 秒逐秒跳动。右上角留给本集的「仪表」：一个与题目有关、全片都在走的读数（首集是此刻的验证码与 30 秒表盘） |
| 换场 | 取本集仪表里的一个动作做全片唯一的换场方式（首集：换码的那一拍，表盘指针扫过全屏）；片尾名单另用直刷 |
| 声音 | 配乐由基座的 `tools/music.py` 合成：120 拍/分，一秒两拍，全片每秒一声「秒针」；编排随场景的先后加层，最后一个正片场景转半拍并在结论处抬起（`audio.score.lift_cue` 指向结论那一句），片尾只留铺底与秒针。画面上的重音吸附到 0.25 秒的网格（`config.js` 的 `Q()`）。混音：`music_db −12`、`duck_db 7`、`sfx_db −9`；音效覆盖 `per_seconds 2.5`、`kinds 6`、`scene_per_seconds 4`、`max_gap 6` |
| 封面 | 16:9 左墨右纸、4:3 上墨下纸：墨色一侧是主题词、秒数（朱红块）与片名，纸色一侧是取自正片的一个真实读数 |
| 片尾 | 左侧主题词与一句话的概括，右侧名单（策划、模型与分工、旁白合成、读音回听、网页检索、开源视频地址），格式见首集的 `s4_outro.js` |

**例外。** 第 5 集 [`dense-vs-moe`](dense-vs-moe/) 按策划者的要求改用风格派（De Stijl）的视觉：纸色、墨色加红黄蓝三原色，黑色粗线分格，不用朱红与表盘；封面改为左红右白（稠密 | MoE），不用左墨右纸；配乐换成本集自带的布吉伍吉（`dense-vs-moe/tools/music.py`）。时长与定长时间线、语速、常驻元素的位置与做法（字幕带与秒尺、剩余秒数、右上角的仪表）、120 拍/分与每秒一声的秒针仍照上表。理由：这一集的题目——参数都存着、每个 token 只用到一部分——正好是风格派「黑线围出的白格，只有少数格涂色」的构图，图形本身就能讲事。

**例外。** 第 19 集 [`harness`](harness/) 按策划者的要求改用终端视觉：近黑底、暖白字、一种琥珀色，等宽字只给名称和参数，不用朱红、圆表盘、扫描线和荧光绿。封面右侧是三行循环和光标，不是左墨右纸上的表盘。时长、定长时间线、语速、常驻元素的位置、120 拍/分与秒针仍照上表。右上角仪表预定为循环步数，换场预定为光标整行重绘；这两项要等文案确认后做进场景。理由：这一集讲的是包在模型外面的那层程序，画面应像一份可核对的记录，而不是一块计时盘。中文稿已于 2026-10-19 落盘，待后续模型优化。

**已定方向（2026-10-19；2026-10-20 改题重规划）。** 第 4 集 [`pistol-shooting`](pistol-shooting/) 讲手枪射击。视觉参考《赛博朋克：边缘行者》。这套画面没有单独的流派名：动画是 Studio TRIGGER 做的，导演今石洋之，角色设计吉成曜。夜之城的赛博朋克设定被画成高饱和、强对比、广角和低角度，单帧信息塞满，动作用逐帧错开的颜色留下冲击。策划要求节奏和冲击都非常强，看到爽的同时学习，并强调三维效果：体积、透视和景深参与讲解。旁白保持客观，爽感和三维都落在画面与节奏上。参考的是这种画法，不照搬角色、夜之城或片中图形。目录已建，场景仍是计时盘基座，三维还没做；正式例外等这套画面画进源码后再写。第 16 集 [`model-parameters`](model-parameters/) 讲模型的各个参数，视觉用液态玻璃，2026-10-20 由《96 秒速通模型卡》改题重规划而来，目录保留液态玻璃视觉规范与骨架，取证与文案待重做。时长、定长时间线、语速和常驻元素的位置仍照上表。

**已定方向（2026-10-19）。第 7 集 [`ssh`](ssh/) 改用俄国构成主义。** 本集讲 256 秒搞懂 SSH，仍以一次连接贯穿，但**不沿用「计时盘」视觉系统**，改用俄国构成主义（Russian Constructivism）的图形语言：斜切的大色块互相压过、大得快要撑出画面的粗黑体字、楔形、紧固钉与铆钉、摄影蒙太奇式的照片剪贴、元素像被图钉钉住的不对称版面。禁用圆角、渐变、阴影与柔边过渡。**调色板反而不用改**：构成主义的标准三色就是红黑白，与本系列的朱红 `#FF4A1C`、墨色 `#0C0D0F`、纸色 `#F2EFE8` 几乎重合，只换图形语言与排版。

本片的图形母题取自讲解对象本身（F16）：连线两端作为对峙的几何块；握手时两端各推出自己的数字、相乘得同一值；主机密钥用骑缝章式图形压在连接线上，对应 RFC 4253 §8「用主机私钥对交换哈希签名」；密钥派生的六个字母 A–F 用六枚紧固钉依次钉进版面，对应 §7.2 的六次 HASH。右上角仪表（本集常驻）做成斜向进度条，随算法协商 → 密钥交换 → 主机认证 → 用户认证走满全片。**全片唯一的换场是斜切平面横扫全屏**。

配乐本集自带 `tools/music.py`，向 20 世纪 20 年代管弦写作的质感靠：强推进的弦乐重复音型、铜管重音落在关键揭示上、打击乐做节奏骨架、和声带棱角，整体动态拉到最满以求震撼（策划要求）。基座那支 120 拍/分、每秒一声秒针的极简配乐不再照用；建议把每秒一声的「秒针」保留为打击层里的一个元素，让定长时间线的系列识别不至于全丢——这一条连同整套视觉例外，等 WaterRun 确认文案并把画面写进源码后再写成正式约定。

保留的系列约定：成片时长恰为 256.00 秒、定长时间线、语速中文 +6% / 英文 +8%、底部字幕带与秒尺、左上角剩余秒数与右上角仪表的**位置与做法**。

**闸门配置的第一处破例（2026-10-19，策划者拍板；2026-10-20 改题后继续沿用）。第 16 集 [`model-parameters`](model-parameters/) 关掉 `check.style.flat`。** 该集用液态玻璃，需要底板的垂直渐变、卡片背后的高斯模糊与磨砂、以及投影，这三者都被 `flat: true` 禁掉。因此该集 `check.style` 设为 `flat: false`、`no_radius: false`，调色板在系列五色之外补 `#0B0F14`、`#151B23`、`#F4F1EA`、`#5CC8D8`。

**此前六集都不曾关掉 `flat`**——dense-vs-moe、harness、web-login、pistol-shooting 等视觉例外一律保留 `flat: true`，只扩调色板、必要时去掉 `no_radius`。所以这是一次有记录、有理由的例外，不是新常态。以后再遇同类需求，逐集单独拍板，不要顺手跟进。

**不受本次破例影响的硬规则**：颜色仍只能用调色板里的值、不得写 `rgb()`/`rgba()`/`hsl()`（半透明请用 `opacity`）；不得用 emoji；字体只用系列三套；画面仍必须只由时间决定。

**改题后的绑定（2026-10-20）。** 该集原为《96 秒速通模型卡》，讲沿一张模型卡逐栏读用途、限制与评测口径；同日按策划者决定改题重规划为《96 秒速通模型的各个参数》，**视觉风格保持一致**：液态玻璃的材质、底板、光带、卡片纸面与仪表规则原样沿用，变的是**讲解对象与绑定关系**——原先压在玻璃上的是一张模型卡，现在是一份真实的模型参数表，四种玻璃形态改绑为四类参数（参数量=薄玻璃片、结构参数=厚玻璃块、上下文长度=裂纹玻璃、词表与 token=磨砂玻璃），右上角仪表由「六栏模型卡轮廓」改为「四行参数表轮廓」。原片的事实、稿本与校对记录随改题作废。完整规范见该集 `research/STYLE.md`；绑定是准备方的提案，待第 4 步关键帧后交策划者确认。

**视觉例外（2026-10-18 方向；第 20 集视觉系统与关键帧已于 2026-10-19 落盘，第 11 集关键帧未做；两集均待 WaterRun 确认）。** 第 11 集 [`tmux`](tmux/) 拟用卡带未来主义（Cassette Futurism）：机架、CRT pane、磁带仓=session、频道旋钮=window、插头=client；荧光绿/琥珀只压 CRT 黑底，红色只给警示灯；UI 12fps 步进。第 20 集 [`web-login`](web-login/) 用包豪斯：红/黄/蓝 + 黑/米白，圆=知道、方=拥有、三角=本身、黑框=验证者、票=session；形状可切半/旋转，字也当形状。两集都保留上表的定长时间线、语速、字幕带/秒尺、剩余秒数、右上角仪表的位置与做法，只更换视觉系统；理由分别是「tmux 的 server/client/pane 适合被画成控制台物件」与「认证因子/验证动作适合用几何拼合讲」。完整规范在各集 `src/design/STYLE.md`；第 20 集另有 `src/design/kf.html`。两集都要在 WaterRun 确认后再改成正式约定。

**制作反馈补充（2026-10-09）。** 先按 [feedback.md](../../../docs/feedback.md) 检查叙事：秒数约束不应挤掉定义、例子和逐步解释，历史和参数清单不能抢占主线。基座的节拍、音乐和直刷换场是实现起点；每集仍须按题目选择旋律动机、段落编排与转场关系，不把全片每次换章的刷屏、同一声气流或相同的加层顺序当成系列识别。保留上表的系列约定时也要做跨片比较；需要改变约定则记录例外和理由。

**系列基座** `_base/`：`new.js series/in-seconds/<视频>` 新建分集时把它盖在通用模板之上，得到一份能直接通过扫描的 60 秒骨架。

| 文件 | 内容 |
|---|---|
| `project.json` | 本系列的语速、渲染、混音与检查阈值（`check.duration` 随 `TOTAL` 一起改） |
| `src/js/script.js` | 定长时间线（`at`、`TOTAL`、`L.problems`）与三场骨架 |
| `src/js/config.js` | 常驻元素（字幕带与秒尺、剩余秒数、右上角的仪表容器 `HUD.right`）、节拍网格 `Q()`、缺省的直刷换场 |
| `src/js/parts.js` | 与题目无关的部件：斜线块、字节格、比特格、日历换算 |
| `src/css/style.css` | 「计时盘」视觉系统 |
| `src/js/scenes/` | 开场（含片名卡）、演示、片尾名单三个示例场景 |
| `src/cover.html` | 封面版式 |
| `tools/music.py` | 配乐脚本 |

基座是首集做完后整理出来的通用部分；首集里与题目有关的部件（逐位滚动的验证码、30 秒表盘、指针扫屏换场、自己缩放的时间轴）留在首集的 `parts.js`、`config.js` 与场景里，需要时到那里取。
