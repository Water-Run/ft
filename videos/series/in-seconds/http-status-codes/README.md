## 开工反馈应用

反馈版本：2026-10-20.1。本集逐项记录在 `review/feedback.json`；规则来自仓库 `docs/feedback-rules.json`。配音前须填写适用性、具体计划和文案 / 分镜定位；交付前补实际主成片的时间、哈希和验证结论。相关复盘：`docs/feedback.md` 的 P0–P38（Web 登录「后半段跑题、阅读负担略大」是本集最直接的负面参照；PostgreSQL 是视觉正面对照；Lean 4 是叙事反面）。

目标观众已有的知识：每天上网、在浏览器地址栏见过 404，也知道服务器会「出错」；知道 200 大概是「成功」。不知道五类的分界、不清楚 401 与 403、301 与 302 的区别，更不知道同一个码可能来自服务器、框架还是网关。

看完应能回答的一个核心问题：HTTP 响应里的这个三位数在说什么、由谁发出、出了事该谁负责——答案是：首位数字决定它属于哪一类（1xx 中间、2xx 成功、3xx 重定向、4xx 客户端的错、5xx 服务端的错），而具体是哪个码、谁发出来的，要看服务器实际返回了什么：源站给 2xx/3xx/4xx/5xx，框架用 Allow 说清方法，限流中间件给 429 并附 Retry-After，网关用 502/504 报告它跟上游出了问题。

逐章怎样推进问题、最后回答什么：先用一个具体场景把「三位数」摆出来 → 给出五类的分界与一条硬规则（首位数字定类别，不知道的码按同类 x00 看待）→ 按遇到频率过一遍最常用的那些码，每个只给一句话加一个关键头字段 → 换一个问题：同一个码是谁发的？源站、框架、网关、条件请求四条来源各有各的证据 → 收在责任归属：4xx 是请求方要改，5xx 是服务端要改，502/504 是例外。

本片决定不讲的材料及理由：状态码在真实流量里的出现频率（没有一手统计，只按「常见」分组，不给百分比）；102、103、207、226、418、451 等边缘码（IANA 有登记但 RFC 9110 未定义，展开就要占用 96 秒里最宝贵的时间）；各框架实际返回哪些码（取决于实现，未逐一核对）；HTTP 版本史（96 秒放不下，且对象是观众每天见到的）；重定向的自动跟随规则细节（RFC 9110 §15.4 讲得很细，但本片只回答「码在说什么、谁发的」）。

沿用系列基座的「计时盘」系统：墨色 `#0c0d0f`、纸色 `#f2efe8`、朱红 `#ff4a1c`，平涂、无圆角；数字与数据用 Mono，拉丁文字用 Inter，中文用 Sans SC；朱红只给「此刻」与结论，整屏朱红只用于片名卡与结论卡。

本集把讲解对象自己的东西做成身份标识（F16）：HTTP 状态行 `HTTP/1.1 404 Not Found` 是本集反复出现的视觉母题；响应头字段（Location、Allow、Retry-After、WWW-Authenticate、ETag）用等宽字排成真实的头块；本集的实验回显（终端里的响应）作为「证据」出现在需要的时刻。

图形约定：一条自上而下的五段色带 = 五个类别，当前类别一段转朱红；一张扁盒 = 一个状态码，盒里左是码号、右是一句话；头字段 = 盒下方的小等宽行；产生者 = 空间位置（源站在最左、网关在最右），同一个码从哪一格冒出来就说明是谁发的。

右上角常驻仪表（本集专用）：一条按类别累计的状态码计数条——每讲过一个码，码号就飞进计数条并归到它所属的那一段；全片唯一的换场就是计数条推进到下一类时的一次直刷，片尾按系列约定用直刷。底部字幕带与秒尺、左上角剩余秒数照系列约定。

未使用外部参考作品：没有引用任何现成产品的界面、图标或插图；状态行与头字段来自 RFC 的示例格式与本集自己的实验回显。

- 标准（2026-10-20 逐条读取）：RFC 9110（HTTP Semantics，2022-06）第 15 章——§15 五类定义、§15.1 概览、§15.2 的 100/101、§15.3 的 200/201/202/203/204、§15.4 的 301/302/303/304、§15.5 的 400/401/402/403/404/405、§15.6 的 500/501/502/503/504；RFC 6585（2012-04）§4 的 429；IANA「Hypertext Transfer Protocol (HTTP) Status Code Registry」（updated 2025-09-15），用于核对每个码的登记状态与它对应的 RFC 9110 小节号。
- 实验：`research/lab/11_status_codes_server.js` 起两个只监听 127.0.0.1 临时端口的最小 HTTP 服务——一个源站，一个网关（转发到源站，上游连不上就自己回 502，上游 1 秒不回就自己回 504）；`research/lab/11_status_codes.ps1` 启动服务并用 curl 逐个触发 18 个场景，把完整回显写进 `research/lab/out_11_status_codes.txt`。脚本与回显同名对应，回显按本机原样（CRLF）保存，未做换行转换。
- 环境版本：Node v24.21.0、curl 8.22.0 (Windows) Schannel、PowerShell 7.6.7、Microsoft Windows NT 10.0.26340.0；这些也记在回显的首段里。
- 脱敏：实验只监听 127.0.0.1 的临时端口，回显里没有主机名、用户名、本机路径或任何真实站点；已逐行检查。
- 画面数据来源：状态行、头字段、响应体都取自上面那份回显，不手写；正文里的 RFC 表述在 `research/FACTS.md` 的「逐章」表里逐条对应小节号。
- 重做一遍：在本集目录下先 `node research/lab/11_status_codes_server.js`（或直接跑 `11_status_codes.ps1`，它会自己起停服务），即可重新得到 `out_11_status_codes.txt`。
