## session · 无章节卡

预估 56.0 秒。

| 句号 | 字幕 / 旁白原文 |
|---|---|
| s1 | 登录成功后，服务器要记住这次验证结果。 |
| s2 | HTTP 不记得上一次请求，服务器生成随机会话编号。 |
| s3 | 编号放进 cookie，浏览器之后每次请求自动带上。 |
| s4 | 服务器查会话表：编号存在、没过期，就认这次会话。 |
| s6 | 编号泄露就能冒充你；登录后换新编号，注销时让它失效。 |
| j1 | 会话表有个麻烦：服务器一多，就要共享这张表。 |
| j2 | 另一种做法，是把验证结果放进签名令牌，服务器不存表。 |
| j3 | JWT 就是这种令牌：头部、载荷、签名。 |
| j4 | 前两段只是编码，不是加密；谁拿到都能读。 |
| j5 | 服务器验证签名，再查有效期和受众。 |
| j6 | 代价是撤销麻烦，所以要短命；token 谁拿到谁用。 |
