### 这一轮改了什么

第 6 轮把你指出的分类问题改对了（Session 一等、Cookie 只运送），但写法变成了电报体：每句塞两三个术语，攻击那一场整段只列名词（「会话：Session ID 被偷、CSRF、固定」）。这正是 Lean 4 的负面模式。第 7 轮逐句重写，原则如下：

1. **同一次登录贯穿全片。** 开头的现象改成「之后看订单、改地址，它再也没问过密码」。会话一场回答它为什么不再问，认证一场回答第一次怎么认的，第三方登录回答「换别人来认」。
2. **「三件事」代替「四层」。** 第 6 轮把「令牌」列为与认证、会话、授权并列的一层。这又是一处分类错误：令牌是会话和授权所用的载体，不是一个独立问题。现在开场只分三件事：认证、会话、授权。Cookie 只运送，JWT 是票的格式，结尾再回扣一次。
3. **每个机制只讲一条主因果。** 做法 → 为什么能认出你 → 代价 → 代价引出下一种：会话表 → 多台服务器共用表的负担 → 签名票 → 难收回 → 短有效期；口令会被假网站骗走 → 短信码也会被转走 → passkey 只给注册的网站签名。
4. **删掉单独的攻击一场。** 每个机制的缺点在本场讲清因果；只念名字的攻击面（会话固定、撞库、回调配置错误）不进正文。
5. **结尾直接回答标题。** e2：「服务器认的从来不是你本人，而是你出示的证据。」这句是秒速通配乐抬起的结论句。
6. **口语化、术语少。** 不出现「哈希」「慢哈希」「盐」「受众」「CSRF」缩写；「验证码」专指选图、拖滑块，短信的叫「短信码」，避免同词两义。

### 这一轮为什么重写

用户指出：不能把 Cookie、JWT 和密码并列，这是分类错误；Session 没有成为一等概念；开场白也不对，应该用“Web 的登录机制是什么样的？服务器是怎么知道，你，是你？”这种具体问句，而不是先念制作说明。

1. **先分层**：认证 / 会话 / 授权 / 令牌。四层回答不同问题，不是四个竞品。
2. **Session 成为一等概念**：服务器创建会话，保存用户、权限、过期时间；Session ID 是标识；Cookie 只是把 ID 带回服务器；服务器查会话表。Cookie ≠ Session。
3. **JWT 是 token 格式，不是 Session**：为了不存会话表，把声明签进 token；三段、编码≠加密、验签/过期/受众；Access Token 访问资源，Refresh Token 续期；撤销和被盗是代价。
4. **认证方式单独讲**：口令（知道）、短信码（拥有）、passkey（私钥）、验证码（只判人）；认证回答“你是谁”，会话回答“怎么记住”。
5. **授权/委托单独讲**：OAuth 2.0 管授权，OIDC 加身份层返回 ID Token；资源服务器验签名和受众；信任会转移。
6. **开场**：o1 输入账号口令 → o2 cookie 出现 → o3 cookie 只是运输，Session 才是状态 → o4 用用户给的那句问句收束，片名卡落在这一句。

### 需要讨论的具体取舍

1. **四层结构**：先讲 Session/JWT，再回到认证方式；是否接受这种“先记住、再认证”的顺序？
2. **JWT 36 秒**：三段/编码≠加密/验签/Access/Refresh/撤销，是否够？
3. **认证方式 30 秒**：口令、短信码、passkey、验证码各一句，是否够区分？
4. **OAuth/OIDC 28.7 秒**：只讲授权/身份层/三种 token/验签/信任转移，不展开 code/PKCE；是否够？
5. **开场 o4**：直接用“Web 的登录机制是什么样的？服务器是怎么知道，你，是你？”是否合适？
