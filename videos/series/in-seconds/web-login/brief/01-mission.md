# 01 任务与标准

## 1. 这部片子讲什么

标题：**200 秒了解 Web 登录机制：怎么验证你是你**

一句话：登录先回答三个问题——你是谁（账号声明）、你怎么证明（口令/一次性码/passkey）、之后怎么记住（cookie/JWT）；联合登录把“证明”交给别人，攻击者则从每一环找最弱处。

结构（200 秒，估算；实测以 `timing.<语言>.js` 为准）：

| 场景 | 起点 | 时长 | 讲什么 | 主题落点 |
|---|---|---|---|---|
| `open` | 0:00 | 19.0s | 每日登录的多种形态；三个问题；一张 SID | 钩子 + 片名 |
| `credentials` | 0:19 | 47.0s | 账号声明、口令/TLS/盐/慢哈希、一次性码、passkey/WebAuthn | 证明“你知道/你拥有/你本身” |
| `session` | 1:06 | 41.7s | HTTP 无状态、cookie/session ID、会话表、JWT/token、bearer、轮换 | 记住你 = 一张可被偷的通行证 |
| `federation` | 1:47 | 32.9s | Google 登录、OAuth 授权≠认证、OIDC、code/PKCE、SAML/SSO | 联合登录只是转移信任 |
| `attacks` | 2:20 | 32.0s | 钓鱼、撞库、XSS/HttpOnly、CSRF/SameSite、fixation、JWT 泄露 | 每一环都可能被冒用 |
| `close` | 2:52 | 19.4s | 三个问题收束；每一环都有假设 | 验证你是你 = 让每一环难被冒用 |
| `outro` | 3:12 | 8.0s | 片尾名单与开源地址 | 不配旁白，7.5s 阅读 |

观众前提：每天上网、登录过网站；知道口令、短信码、指纹/人脸、第三方登录这些词；没有系统学过 cookie、session、OAuth、JWT、WebAuthn 的区别。

看完应能回答：网站怎么确认屏幕对面是“你”，而不是拿着你的口令、cookie、验证码或 token 的别人。

决定不讲：所有 OAuth grant type、SAML 断言细节、JWT/JWKS 细节、账号恢复/风控/设备指纹、具体厂商实现差异。SAML/SSO 只保留一句“一次登录，多个系统”；200 秒里这些细节会挤掉“登录到底发生什么”的主线。

## 2. 本片的质量要求

包豪斯平面作品，不是“聊天界面介绍片”。每一帧单看应成立：三四个大形状、字很少、左对齐/不对称、平涂、边缘干脆。动画要有冲击力，但不能用无意义漂移；形状的拼合/压模/盖章/拒绝必须解释机制。

必须越过的上一部问题：不用轮播式“换面板”、不用全片同一种擦入、不用气流声填满动作；章节卡与内容卡要给完整阅读时间（本片没有章节卡，片名/结论卡同样按 3–5 秒算）。

## 3. 语体与术语

- 客观、冷静、短句；不用第二人称、比喻、口号、感叹号。
- 标签不超过 12 个汉字；一行说明不超过 20 个汉字；旁白一行字幕内。
- 统一写法：`session ID`、`Set-Cookie`、`HttpOnly`、`SameSite`、`WebAuthn`、`passkey`、`OAuth 2.0`、`OIDC`、`JWT`、`PKCE`、`SAML`、`SSO`、`MFA`。
- 数字与拉丁字母、汉字之间留一个空格。
- 画面上的协议名可以保留英文；中文旁白第一次出现给中文解释。
