# 01 任务与标准

## 1. 这部片子讲什么

标题：**200 秒了解 Web 登录机制：怎么验证你是你**

一句话：登录验证先分四层——认证、会话、授权、令牌；Session 是服务器会话状态，Session ID 是标识，Cookie 只是运输；JWT 是 token 格式，不是 Session；再讲认证方式与 OAuth/OIDC 委托。

结构（200 秒，估算；实测以 `timing.<语言>.js` 为准）：

| 场景 | 起点 | 时长 | 讲什么 | 主题落点 |
|---|---|---|---|---|
| `open` | 0:00 | 21.0s | cookie → Session ID → Session；四层骨架 + 片名 | 先分清层 |
| `session` | 0:21 | 38.3s | 服务器会话、Session ID、Cookie 运输、查表；缺点：表/偷/CSRF | 会话不是认证 |
| `jwt` | 0:59 | 36.0s | token 格式≠Session；三段/编码≠加密/验签；Access/Refresh；撤销 | 令牌不是会话 |
| `authn` | 1:35 | 30.0s | 口令知道、短信拥有、passkey 私钥、验证码判人 | 认证方式 |
| `oauth` | 2:05 | 28.7s | OAuth 授权、OIDC ID Token、Access/Refresh、验签/受众 | 授权与委托 |
| `attacks` | 2:34 | 21.1s | 会话/JWT/认证/授权各层攻击面 | 分层攻击面 |
| `close` | 2:55 | 16.9s | 四层：不同问题，不同代价 | 收束 |
| `outro` | 3:12 | 8.0s | 片尾名单与开源地址 | 不配旁白 |

观众前提：每天上网、登录过网站；知道口令、短信码、指纹/人脸、第三方登录这些词；没有系统学过 cookie、session、OIDC、JWT、passkey 的区别。

看完应能回答：网站怎么确认屏幕对面是“你”，而不是拿着你的口令、cookie、验证码或 token 的别人。

决定不讲：所有 OAuth grant type、SAML 断言细节、JWT/JWKS 细节、账号恢复/风控/设备指纹、具体厂商实现差异。SAML 不单独展开，委托验证只保留“另一个身份提供方验证，交回断言”的骨架；200 秒里这些细节会挤掉“服务器到底在验证什么”的主线。

## 2. 本片的质量要求

包豪斯平面作品，不是“聊天界面介绍片”。每一帧单看应成立：三四个大形状、字很少、左对齐/不对称、平涂、边缘干脆。动画要有冲击力，但不能用无意义漂移；形状的拼合/压模/盖章/拒绝必须解释机制。

必须越过的上一部问题：不用轮播式“换面板”、不用全片同一种擦入、不用气流声填满动作；章节卡与内容卡要给完整阅读时间（本片没有章节卡，片名/结论卡同样按 3–5 秒算）。

## 3. 语体与术语

- 客观、冷静、短句；不用第二人称、比喻、口号、感叹号。
- 标签不超过 12 个汉字；一行说明不超过 20 个汉字；旁白一行字幕内。
- 统一写法：`session ID`、`cookie`、`HttpOnly`、`SameSite`、`passkey`、`OIDC`、`SAML`、`JWT`、`验证码`。
- 数字与拉丁字母、汉字之间留一个空格。
- 画面上的协议名可以保留英文；中文旁白第一次出现给中文解释。
