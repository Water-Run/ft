# 叙事测绘

本文件只记录面向观众的讲述顺序与取舍，不是旁白稿。事实与依据在 `FACTS.md`。

## 观众前提

每天上网、登录过各种网站；知道口令、短信验证码、指纹/人脸、第三方登录这些词；没有系统学过 cookie、session、OAuth、JWT、WebAuthn 的区别。

## 一个核心问题

网站怎么确认屏幕对面是“你”，而不是拿着你的口令、cookie、验证码或 token 的别人。

## 主线：三个问题

登录看起来有很多种，其实在回答三件事：

1. **你是谁**：账号是声明（claim），不是证明。
2. **你怎么证明**：口令/一次性码/passkey；对应知道/拥有/本身。
3. **之后怎么记住**：cookie session 或 JWT/token；两者都认票不认人。

联合登录（OAuth/OIDC/SAML SSO）是把“证明”交给另一个网站；攻击面则从每一环找最弱处。

## 逐场问题与答案

| 场 | 观众的问题 | 本场要回答 | 画面上的主要证据 |
|---|---|---|---|
| 1 open | 登录到底在验证什么 | 不是名字，是一组可验证的凭证；先给三个问题 | 四种登录碎片 → 三栏骨架 → 一张 SID |
| 2 credentials | 我填账号和口令，网站收到什么 | 账号是声明；口令经 TLS 到服务器；只存唯一盐 + 慢哈希；一次性码不防钓鱼；passkey 用公私钥/域名绑定 | 账号声明；TLS 通道；盐 + 压模；OTP 被转发；钥匙/公钥 |
| 3 session | 之后为什么不用再填 | HTTP 无状态；传统 session ID 放 cookie、查会话表；另一种是把身份签进 JWT/token；两者都是 bearer | `Set-Cookie`；会话表；签名长条；轮换/过期 |
| 4 federation | 为什么能用 Google 登录 | OAuth 是授权，OIDC 加身份层；code + PKCE；SAML/SSO 是同一类 federation | 第三方框；授权钥匙；ID Token；assertion |
| 5 attacks | 别人怎么冒充我 | 钓鱼/撞库；XSS 读非 HttpOnly cookie；CSRF 借浏览器带 cookie；fixation；JWT 被偷 | 假框；泄露口令纸片；脚本黑块；SameSite 栏；旧票根 |
| 6 close | 那“验证你是你”到底靠什么 | 声明、证明、记住；每一环都有假设，攻击者找最弱的一环 | 三栏收拢；链上缺口；最终拼合 |
| 7 outro | 谁做的 | 策划、准备方、受托方、旁白、开源地址 | 名单与网址 |

## 决定不讲

- 各种口令哈希算法的完整实现与参数调优。只讲“唯一盐 + 慢哈希”；Argon2id/bcrypt 只做画面标签，不进旁白。
- OAuth 的所有 grant type、隐式流历史、SAML 断言细节。SAML/SSO 只保留一句“一次登录，多个系统”。
- JWT 的完整 JOSE 规范、JWKS 轮换、密钥管理。只讲“签名≠加密”“别放秘密”“短命/绑定用途/撤销”。
- 账号恢复、客服重置、风控评分、设备指纹。它们是另外的章节。
- 具体厂商的 passkey 实现差异、同步/设备绑定细节。讲 WebAuthn 的公私钥/随机挑战/域名绑定即可。
- 任何“某网站不安全”的个案判断。没有做渗透测试。

## 开场钩子

- 四种登录碎片同时出现：口令、验证码、指纹、Google 登录；收成“你是谁/怎么证明/怎么记住”。
- 再给一张 `SID=...` 的票根：它不是名字，也不是口令，为什么服务器看到它就认为是我？
