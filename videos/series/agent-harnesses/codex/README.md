# CodeX CLI 是怎么实现的？

《CodeX CLI 是怎么实现的？》是一部 9 分钟左右的源码讲解片，中文为主，配英文版。它按一次真实任务的走向拆开 OpenAI 开源的编码智能体命令行工具 CodeX CLI：一句用户输入怎样变成模型请求、模型怎样要求调用工具、工具在什么约束下执行、结果怎样回填给模型。片中引用的每一处代码都指得出仓库里的文件与行号，依据是一次固定的检出。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`。

目标观众已有的知识：用过编码智能体（ChatGPT、Claude Code、Codex 或 OpenCode 任一），知道它能读文件、改文件、跑命令；知道模型能调用工具这件事，但不清楚背后是谁在接、接在哪一层。不需要读过 Rust 或 TypeScript 源码。

看完应能回答的一个核心问题：CodeX CLI 把「用户一句话」变成「模型请求 → 工具执行 → 结果回填」这一回合时，中间的每一段是哪个文件负责的；以及它凭什么敢在本机执行模型给的命令。

本片决定不讲的材料及理由：

- **不运行 Codex CLI 做实测**。需要 ChatGPT 登录或 API key，按 `docs/research.md` 第 5 节不入库。片中因此把「一次任务怎么走」写成源码与官方文档所述的路径，并明确说是按源码讲的，不伪装成录屏。
- **不讲模型能力与评测分数**。与「这个 Harness 怎么搭的」无关，是另一个问题（P0 的教训：不堆版本与参数）。
- **不讲 Codex Cloud 的内部实现**。官方标为不开源，只能讲能观察到的边界（系列说明的硬性要求）。
- **不讲 Skills、Plugins、Hooks、Memories 等周边功能**。它们各有专章，本片 9 分钟放不下；放进去就变成功能清单。
- **不讲 IDE 扩展的具体做法**。同样因为不开源；本片只在第 02、05 章交代它存在且不开放。
