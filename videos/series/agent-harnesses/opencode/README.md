# OpenCode 是怎么实现的？

《OpenCode 是怎么实现的？》是一部 9 分钟左右的源码讲解片，中文为主，配英文版。它按一次真实任务的走向拆开开源编码智能体 OpenCode：一句用户输入怎样变成模型请求、模型怎样要求调用工具、权限规则怎样在中间生效、结果怎样回填给模型；并说明这个项目「一个核心、多种外壳」的形态是怎么来的。片中引用的每一处代码都指得出仓库里的文件与行号，依据是一次固定的检出。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`。

目标观众已有的知识：用过编码智能体（ChatGPT、Claude Code、Codex 或 OpenCode 任一），知道它能读文件、改文件、跑命令；知道模型能调用工具这件事，但不清楚背后是谁在接、接在哪一层。不需要读过 TypeScript 源码。

看完应能回答的一个核心问题：OpenCode 把「用户一句话」变成「模型 → 工具 → 结果回填」这一回合时，中间的每一段是哪个文件负责的；以及它为什么把权限做成一套可以按「动作 + 资源」书写的规则，而不是一个总开关。

本片决定不讲的材料及理由：

- **不运行 OpenCode 做实测**。需要模型账号或 API key，按 `docs/research.md` 第 5 节不入库。片中因此把「一次任务怎么走」写成源码与官方文档所述的路径，不伪装成录屏。
- **不讲《OpenClaw / OpenCode v2》那套「一年演进」**。那正是 P0 点名的失败做法：把包名与实现参数当内容。本片只讲一个项目当前这一份检出的机制。
- **不讲模型能力、评测与模型目录**。与「这个 Harness 怎么搭的」无关。
- **不讲「Go 那支变成 Charm 的 Crush」**。仓库自己的记录是 Go 实现被就地替换成 TypeScript；这一旁述在仓库里找不到依据，记在 `research/FACTS.md`「尚待核实」，本片不采用。
- **不讲 LSP 的完整实现**。核心包里 LSP 运行时尚未接上（只有 TODO），本片只讲配置与默认行为，并说明这个边界。
- **不讲 Model Context Protocol、Agents、Skills、Rules、Formatters 等周边**。各占一章，放进 9 分钟会变成功能清单。
