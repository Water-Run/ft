# 06 验收与收尾

## 文案阶段

`node videos/opencart-1-5-admin/tools/check_handoff.cjs` 分开检查材料与人工确认。它不会批准稿本，也不声称音频、正式动画或成片存在。

检查九章、逐段依据、分镜完整覆盖、关键字 cue、当前内容哈希、A 方向和 F01–F14 计划。中文未批准时不进入制作。用户批准的范围按原话记录，英文单独处理。

## 制作质量

| 项目 | 必须取得的证据 |
|---|---|
| 子系统解释 | 按 SUBSYSTEMS 的问题复述完整路径；登录、会话、权限、数据库不能省成标签 |
| 事实 | R1 / A18 / S19 逐条对应；静态、旧实验、示意、推断有范围标注 |
| 阅读 | 章节卡 ≥2.5 秒稳定区；关键结论 ≥3 秒；多步对照 ≥5 秒。记录文字到位、镜头停止和退场的实际时间 |
| 动作 | 同一请求 / 用户 / 订单可追踪；拒绝先停下再给结果；查看连续片段，不只看单帧 |
| 翻译 | 英文术语、源码和证据有中文说明；中文稿、英文稿、两种时间线一致对应 |
| 配音 | 自然语气、关键术语、相邻句、断句逐段试听；ASR 只提供候选问题 |
| 脱敏 | 公开源码、生成图、字幕、音频、封面和投稿说明分别核对；私有数据不进入生成链 |
| 成片 | 1920×1080 / 60 fps；各语言时长在确认预算内；测最终 MP4 音轨的响度和峰值 |
| 署名 | WaterRun；实际 GPT-6 Astra、历史 Claude Opus 5.5 与后续真实参与者及分工；“开源视频”与完整 GitHub 地址；至少 12 秒可读 |

自动闸门按仓库 review.md 全部运行，特别是 `check.js --final` 和 `lessons.js check --stage final`。保存各语言正式主 MP4 的 SHA-256、实际时段和检查方法。预演文件不能代替最终主片。

## DELIVERY 必须说明

交付物路径；实际检查输出；事实、配音、画面三项审查；原创与动画完成度；逐版本片尾核对；F01–F14 同编号复盘；未通过或未做；需要人判断的听感；复现命令。

新发现的共性问题保留证据，交准备方回填总反馈；不要修改工具或关掉检查把失败变成通过。

## 归档与清理

交付、发布、归档、清理分别记录。先运行 `clean.js` 预览；按仓库 lifecycle.md 将生成物归档到仓库外，逐文件校验并做恢复抽验，再清理。本片还未生成这些文件，不预填“已归档”。

保留源稿、事实、匿名研究输出、校对与最终验收记录。第三方下载缓存、音频、成片和截图按忽略规则留在产生它们的机器上，跨机器只同步源码。
