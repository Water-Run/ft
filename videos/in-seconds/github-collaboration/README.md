「这些」指同一次会话里对 GitHub 协作的讲解，要点是：

- 创建 PR 为什么要先 Fork 仓库、再开一个新分支，而不是直接往别人的仓库里加代码。
- PR 不是「把代码加进去」，而是请求合并的申请页；代码在提 PR 之前就已经提交并推送到某个分支上。
- Issue 与 PR 为什么共用同一套编号，号码为什么不回收，为什么编号属于仓库而不是属于人。
- 草稿 PR、合并，以及 `Refs` 与 `Closes` 的区别。

### 受众与核心问题

- **受众**：没有用过 GitHub 协作的人，包括新手程序员和不写代码、只参与协作的人。按系列约定，低认知负担，不假设观众会 Git 命令。
- **核心问题**：我没有权限改别人的项目，为什么还能给它提改动？
- **一句话答案（草案，待取证后定稿）**：没有写权限，就 Fork 出自己的副本；开分支把这次改动和主线隔开；再用 PR 请原仓库的维护者审了决定要不要并入。

### 解释路径（草案，以文案为准）

按系列结构骨架：现象或问题 → 片名卡 → 它是什么 → 它怎么工作 → 边界或比较 → 一句结论 → 片尾。

1. **现象**：想给别人的项目改一行字，却发现推不上去。
2. **它是什么**：Fork 是一份属于自己的完整副本；分支是副本里一条与主线隔开的工作线。
3. **它怎么工作**（重头）：在分支上改并提交、推到自己的副本，再对原仓库发起 PR。强调 PR 是「申请页」：看到的改动早就在分支里，合并前不影响原仓库主线。Issue 是说清「要解决什么」的地方；PR 与 Issue 共用编号，所以 `#12` 在这个仓库里只指向一件事。
4. **边界或比较**：有写权限的团队可以不 Fork、直接在原仓库开分支；Fork 的编号与原仓库各自独立；合并之后改动才进主线。
5. **结论**：Fork 解决没有权限，分支解决要隔开，PR 解决要被审。

### 取舍：「没提到的东西」怎么处理

旁白主动教的新名词不超过四个：Fork、分支、Pull Request（PR）、Issue。其余的只在画面上当标签，或留给别的集。

| 内容 | 建议 |
|---|---|
| clone、远端名 `origin` 与 `upstream` | 画面标签，不进旁白；演示 Fork 副本与本机、原仓库三者的关系时一笔带过 |
| commit 与 push | 一句话带过，不演示命令，细节归《150 秒速通 Git》 |
| 草稿 PR（Draft） | 进旁白一句：还没准备好合并，先给人看 |
| 审查（review）与自动检查 | 画面上出现，旁白一句话说明「合并前有人看、有机器查」，不展开 Actions |
| 合并方式（merge commit、squash、rebase） | 留给别的集，本集只说「合并」 |
| 保持 Fork 与原仓库同步 | 150 秒放不下，不进旁白，留给别的集 |
| 标签、指派、里程碑 | 不讲 |
| `Refs` 与 `Closes` | 进旁白：只是关联，还是合并时自动关闭，取证后再定怎么说 |
| 编号共用与不回收 | 本集的一个「原来如此」，放在 Issue 与 PR 一起出现的地方，约 15 秒 |

## 设计

**例子（2026-11-16 策划者选定，替换菜谱例子）。** 全片只用一个虚构例子：开源仓库「阿梅 / 活动报名」的 `src/signup.js` 第 13 行写成 `if (age > 18)`，刚满 18 岁的人报不上名。路人报了 Issue #12「刚满 18 岁报不上名」；你 Fork、开分支 `fix-age`、把 `>` 改成 `>=`、提交推送、发 PR #13「年龄判断改成大于等于」（写 `Closes #12`）；阿梅在第 13 行留言、检查通过、合并，#12 自动关闭。它是真正的一行代码改动，PR 页上「改了哪一行」就是字面意思；旁白里「大于」与「大于等于」读得出区别；GitHub 用户名只能用英文字母，中文名不会撞上真实账号。画面上的代码用等宽字体并关掉连字，`>=` 显示为两个字符，不连成「≥」。画面上的编号簿（#1–#13，空一个号）是示意，依据是 F6 的实测规律，不冒充某个真实仓库。

**叙事。** 现象（没权限却能提改动）→ 先分清 Git 与 GitHub、谁能直接改 → 三步各配一个「为什么」→ 编号的「原来如此」→ 边界（有写权限不用 Fork；GitLab 叫法不同，底下仍是 Git）→ 结论回答开头。逐句依据见审片页的逐句表与 `review/NOTES.md`。

**选定（2026-11-16）：A 为主，结合 C；配音温暖少女；配乐 B。** 逐段的做法：

| 段 | 主画面（A：同一个浏览器里的 GitHub 页面） | 结合 C 的地方 | 右上仪表 |
|---|---|---|---|
| open | 「阿梅 / 活动报名」的 `signup.js`，第 13 行的 `>` 被框出；片名卡压在这页上 | — | 改动：还没开始 |
| what | 同一个仓库页：分支下拉与提交数标「Git 自带」，Fork 按钮与 Issues、Pull requests 标签页标「网站的功能」；写权限画成维护者名单旁的锁 | — | 同上 |
| how | Fork（按钮 → 副本页）→ 分支下拉新建 fix-age → 编辑与提交 → PR 页（三处原地注解）→ 合并 | PR 页的 Conversation 标签就是 C 的时间线：开草稿、逐行意见、检查、合并一条条往下长 | Fork 了 → 在分支上 → Draft #13 → Open #13 → Merged #13 |
| numbers | 从 PR 标题的「#13」推近 | C 的编号簿：#1–#13 的 Issue 与 PR 交错、空号不补；Closes #12 让 #12 关闭 | 换成「仓库的下一个号」#14 |
| boundary | 原仓库页上直接开分支；换个平台只换标签上的叫法 | — | Merged #13 |
| close | 三步与各自的理由，回到已经改成 `>=` 的那一行 | 时间线收成一行行结论 | 同上 |

镜头只在一页里推近、平移，换页时带着同一个对象（第 13 行那个 `>` 或编号 #13）过去（F29）。

**配乐（选定 B，已写成 `tools/music.py`）。** 80 拍/分、D 大调，两支旋律演片子的过程：开场一支马林巴；b1「点 Fork」第二支颤音琴进来，逐音照抄、晚一个八分音符（副本）；b3「开分支」第二支改走反向的线；b8–b9 讲「PR 是申请」时第二支收小；b13「点合并」后一拍两支并成同度，钟片落在这一拍；编号与边界减配器、加摇铃；e1 结论抬起。落点都取自句号，配音实测后自动对齐。按估算时间线试跑：峰值 −1.0 dBFS，各段 RMS 从开场 −20.8 dB 到重头段 −13.8 dB，没有空白（草稿 `out/audition/music/film-sketch.mp3`，听感待策划者判断）。

**封面（`src/cover.html`，初稿）。** 策划者要求「有冲击力」。白底、Primer 浅色：左边绿色状态胶囊「150 秒速通」、两行特大的「GitHub / 协作」（236px，约画面高的五分之一）、一句钩子「别人的项目，没权限也能提改动？」；右边是全片那一处改动——放大的一行代码 diff「− if (age > 18) / + if (age >= 18)」（`>` 与 `>=` 加底色）和一颗绿色的「Merge pull request」按钮、一个将要按下去的指针；背后一个铺满半幅的 Pull Request 图标（极浅的绿）。不用 GitHub 标志（Invertocat），只用 Octicons（MIT）与界面部件。4:3 重新排布：标题在上，按钮与 diff 分在下方两侧。底部 15% 不放字；缩到 360 与 180 像素宽仍读得出主标题（审片页「封面」一栏）。正式出图（`covers.js`，2 倍 PNG 与 JPG）要等文案确认。

**视觉方向（审片时的三个候选，静帧在 `src/design/keyframes.html`）。** 三个方向都取自 GitHub 自己的材料（Primer 令牌、Octicons、真实页面的部件，F16），比较的是讲法：

| 方向 | 主画面 | 本片要观众理解的 | 关键揭示 | 常驻仪表（右上） | 配乐建议 |
|---|---|---|---|---|---|
| A 跟着一个 PR 走（浅色，界面临摹） | 同一个浏览器里的 GitHub 页面：仓库页 → Fork → 副本 → PR 页 | 每一步在真界面上点哪里、看到什么 | PR 页上三处原地注解「从哪、到哪、改了哪一行」（b10） | 改动的状态：还没开始 → Open #13 → Merged | A 提交 |
| B 一条改动的旅程（深色，网络图） | 两个仓库两条带，一个提交点从分支经 PR 回到主线 | 权限边界、隔开、申请是结构关系 | 点停在分支上而原仓库主线不动（b6）；合并时点变紫并入主线（b13） | 缩小的线，点走到哪亮到哪 | B 分支与合并 |
| C 一个编号的生平（浅色，时间线部件） | GitHub 的时间线，事件往下累积；右侧编号簿 | 事情按什么顺序发生；编号从哪来 | 编号簿里 #12、#13 挨着（c3） | 仓库的下一个号 | C 仓库网络 |

制作方建议 A 为主画面，「为什么要隔开 / 要申请」几句（b4–b6、b9）插入 B 的网络图，编号段（c1–c4）用 C 的编号簿；声音在 Fork 复制、推送、点合并三个动作上落点。只选一个方向也成立。

**配音候选。** MiniMax speech-2.8-hd 的 5 个此前没用过的中文音色：`Chinese (Mandarin)_Warm_Girl`、`Chinese (Mandarin)_Warm_Bestie`、`Chinese (Mandarin)_Gentle_Senior`、`Chinese (Mandarin)_Southern_Young_Man`、`chunzhen_xuedi`；每个按自己的快慢定语速（1.17–1.25），让全片都能放进 150 秒而不压停顿。

**配乐小样。** 三首各 60 秒，程序合成、本片原创，拍点在 0.25 秒网格上：A「提交」120 拍 F 大调，钢琴与键盘声；B「分支与合并」80 拍 D 大调，两支马林巴先分开、第 45 秒并回同度；C「仓库网络」120 拍，铺底与玻璃质感琶音。
