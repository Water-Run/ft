### open · 无章节卡

一个开源的报名工具：刚满 18 岁，却报不上名。 代码写的是“大于 18”，正好 18 岁的被挡在外面。 可这是别人的项目，你没有权限改。 但在 GitHub 上，你照样能提改动。怎么做到的？

### what · 无章节卡

先分清：*Git* 是个工具，记下每一次修改； *GitHub* 是个网站，把这些项目放到网上。 Fork、PR、Issue 都是网站的功能，不属于 Git； 分支和提交，才是 Git 自带的。 每个*仓库*，只有拿到写权限的*维护者*能直接改。 其他人改不了，但有三步办法：Fork、开分支、提 PR。

### how · 无章节卡

第一步，在原仓库点 *Fork*。 GitHub 把仓库复制一份到你名下，这份副本随你改。 第二步，在副本里开一条*分支*，叫 fix-age。 分支从主线岔出去，怎么改，主线都不变。 把“大于”改成“大于等于”，提交，推送到副本。 改动在你的分支上了，原仓库一个字没变。 第三步，回原仓库发起 *Pull Request*，简称 PR。 意思是“请你拉取”：请维护者把改动拉过去。 它不是直接改进去，而是一页申请， 写明从哪条分支、合到哪里、改了哪一行。 维护者能逐行提意见，也能让机器跑检查。 没改完，可以先开成草稿：能看，不能合并。 维护者一点合并，改动才进原仓库的主线。

### numbers · 无章节卡

你的 PR 编号是 #13。为什么不是 #1？ 仓库里还有 *Issue*，用来记下要解决的问题。 Issue 和 PR 共用一套编号：#12 报的正是这个问题。 编号属于仓库，按先后排，用过就不回收。 PR 里写 Closes #12，合并时，#12 自动关闭； 只写 #12，只是提一下，不会关。

### boundary · 无章节卡

本来就有写权限的人，不用 Fork： 直接在原仓库开分支、提 PR。 换个平台，叫法也变：在 GitLab，PR 叫合并请求。 底下记录修改的，始终是 Git。

### close · 无章节卡

没有权限，就 Fork；要隔开主线，就开分支； 要人审，就提 PR。 开源项目，谁都能提改动；收不收，维护者说了算。
