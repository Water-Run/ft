# 96 秒了解 HTTP 状态码

「XX 秒速通」系列第 22 集，中英两版，成片时长恰为 96 秒。讲 HTTP 响应第一行里那个三位数：五个类别怎么分、实际最常遇到的那几个各自在说什么，以及同一个码可能出自源站、框架还是网关。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`，讲解对象自己的材料见 `research/MATERIALS.md`。

## 开工反馈应用

反馈版本：2026-10-20.1。本集逐项记录在 `review/lessons.json`；规则来自仓库 `docs/lessons.json`。配音前须填写适用性、具体计划和文案 / 分镜定位；交付前补实际主成片的时间、哈希和验证结论。相关复盘：`docs/log/feedback.md` 的 P0–P38（Web 登录「后半段跑题、阅读负担略大」是本集最直接的负面参照；PostgreSQL 是视觉正面对照；Lean 4 是叙事反面）。

目标观众已有的知识：每天上网、在浏览器地址栏见过 404，也知道服务器会「出错」；知道 200 大概是「成功」。不知道五类的分界、不清楚 401 与 403、301 与 302 的区别，更不知道同一个码可能来自服务器、框架还是网关。

看完应能回答的一个核心问题：HTTP 响应里的这个三位数在说什么、由谁发出、出了事该谁负责——答案是：首位数字决定它属于哪一类（1xx 中间、2xx 成功、3xx 重定向、4xx 客户端的错、5xx 服务端的错），而具体是哪个码、谁发出来的，要看服务器实际返回了什么：源站给 2xx/3xx/4xx/5xx，框架用 Allow 说清方法，限流中间件给 429 并附 Retry-After，网关用 502/504 报告它跟上游出了问题。

逐章怎样推进问题、最后回答什么：先用一个具体场景把「三位数」摆出来 → 给出五类的分界与一条硬规则（首位数字定类别，不知道的码按同类 x00 看待）→ 过一遍日常会遇到的那些码，每个只给一句话加一个关键头字段 → 换一个问题：同一个码是谁发的？源站、框架、网关、条件请求四条来源各有各的证据 → 收在责任归属：4xx 是请求方要改，5xx 是服务端要改，502/504 是例外。

本片决定不讲的材料及理由：状态码在真实流量里的出现频率（2026-10-21 查证过：没有可复查的一手统计，HTTP Archive 与 Web Almanac 都没有状态码分布报告，RFC 与 IANA 也不给频率；片中只按「日常会遇到」分组，不给百分比、不声称排序）；102、103、207、226、418、451 等边缘码（IANA 有登记但 RFC 9110 未定义，展开就要占用 96 秒里最宝贵的时间）；各框架实际返回哪些码（取决于实现，未逐一核对）；HTTP 版本史（96 秒放不下，且对象是观众每天见到的）；重定向的自动跟随规则细节（RFC 9110 §15.4 讲得很细，但本片只回答「码在说什么、谁发的」）；HTTP/2 与 HTTP/3 的报文结构（与「那个三位数」无关；相关材料已记在 `research/MATERIALS.md`，本片不用）。

## 内容

段与时间以 `src/js/script.js` 的定点为准（那里是唯一来源）。下表是文案的段落结构与各段讲什么。

| 段 | 起点 | 讲什么 |
|---|---|---|
| open | 0.00 | 现象与问题：你发出网页请求，却只收到一个三位数；404 是没找到，500 是服务器崩了；这叫 HTTP 状态码。随后 1.9 秒片名卡（无旁白） |
| what | 12.53 | 它是什么：它在响应第一行，靠首位分五类；1xx 处理中、2xx 成功、3xx 重定向、4xx 请求有错、5xx 服务端故障；陌生码按首位算，如 471 当 400 |
| history | 28.77 | 它从哪来：1990 年 HTTP 只传文件，还没有状态码；后来包成报文才加上这一行报结果；从 1.1 到 2022 年的 HTTP/3，版本换了码没改 |
| common | 41.95 | 一次请求走过的检查：到真正存资源的源站按步过检——语法错回 400、缺凭据回 401、权限不够回 403、找不到资源回 404、找到就回 200、缓存仍有效只回 304 |
| who | 62.64 | 谁发的：源站崩了回 500；前面的限流层回 429；中间转发的网关或代理不改源站的码，上游无效才发 502、超时发 504 |
| close | 78.63 | 出错谁负责：先看第一位数字；4xx 改请求、5xx 等恢复；502 和 504 卡在上游；三位数写清了请求停在哪、该谁负责 |
| outro | 92.67 | 片尾名单与开源地址（无旁白，约 3.3 秒） |

**这一版讲哪几个码**：400、401、403、404、429、500、502、504，加上 200 与 304（定稿旁白没有 405，画面也不加）。96 秒装不下更多，选材见 `research/FACTS.md`「02 日常会遇到的那些码」的 02-21 条：这一组不指排名，指日常会直接遇到、且各自带一个能说明问题的头字段。

## 视觉系统

策划者 2026-10-21 定的风格方向（原话）：**卡带、未来**。制作方（Claude Opus 5.5）把它落成「应答机」：卡带未来主义的机器面板，材料取自讲解对象本身——终端里的 curl 回显、状态行、响应头字段。先做了三张关键帧（片名卡、信息最密的过检线、链路图解），确认方向后铺开；关键帧页面在定稿后删去（`src/` 的文件都计入成片是否过期的核对）。

**颜色**（`src/css/style.css`；`project.json` 的 `check.style.palette` 随之换成这七个色值，见下面「取舍」）：

| 变量 | 色值 | 含义（全片不换用） |
|---|---|---|
| `--case` | `#E4DAC4` | 米色面板：机器的外壳，也是全片的底色 |
| `--case2` | `#CBBFA3` | 面板上凹下去的一块：机器的机身 |
| `--ink` | `#14120E` | 墨色屏：机器吐出来的响应原文；机器的铭牌条 |
| `--amber` | `#FFB52E` | 主色，琥珀色的荧光字：响应的数据（状态行、头字段、码） |
| `--red` | `#EF4B28` | 强调色，只给出错的两类：4xx、5xx 的码，请求停下来的那台机器 |
| `--dima` / `--mute` | `#A8874F` / `#5F584B` | 屏上、面板上的次要文字 |

对比度：琥珀压墨 10.6:1，朱红压墨 5.1:1，墨压朱红 5.1:1；朱红压米色只有 2.7:1，所以朱红在米色上只作色块、不作字色。

**字**：状态码的大字用像素字 VT323（`Pixel`，卡带年代终端的点阵字）；超大的数字（开场的 404、500，片名卡的 96）用自绘的 5×7 方点阵（VT323 放到五六百像素时字形发糊）；回显与头字段用 Mono；中文用 Sans SC，拉丁文字用 Inter。

**图形语言**：米色方块 = 机器；墨色屏 = 那台机器的输出（屏上的字都取自 `research/lab/out_11_status_codes.txt`，由 `tools/gen_data.py` 生成 `src/js/data.js`，不手写）；码牌 = 一个状态码；三色线缆（琥珀、墨、朱红三道平行线）= 机器之间的连接，请求包与回来的码沿它走；圆点 = 指示灯。码从哪台机器里冒出来，就是谁发的。

**常驻元素**：底部字幕带上沿的秒尺（走过的刻度变琥珀）；左上角剩余秒数（像素字）；右上角「应答表」——最近一次回来的状态码与它首位对应的类别灯（1–5），全片随码的出现而跳。

**每段的主画面**（F18）：

| 段 | 主画面 | 主要的动作 |
|---|---|---|
| open | 左边终端、右边回来的码 | 请求包出去，点阵的 404、500 扫出来；推近状态行，把码框成「状态码」；三色线缆扫过，片名卡 |
| what | 五格的类别架 | 404 回显的第一行反白、首位以外的两位暗下去；实验里测到的码整组落进五格（F22），念到哪类哪格亮灯；陌生的 471 从回显里出来，只看首位，落进 4xx，与 400 一起亮 |
| history | 版本磁带 | 1990 那格只有文件、报结果的一行是空的；1996 报文框住文件，状态行进来；镜头移到 1997、2015、2022 三站，三行里的 404 在等宽字里落在同一列 |
| common | 源站里的过检线 | 六个码一开始就挂在各自的闸下；一次次请求沿线缆跑，停在拒绝它的闸，闸灯变红、码牌反白，屏上的终端日志追加这一次的回显；200 把文件送回客户端，304 让客户端用手里的副本 |
| who | 整条链路：客户端 → 网关 → 限流 → 源站 | 从源站里面拉远（与上一场是同一帧的缩小副本，匹配剪辑）；500 从源站、429 从限流层、502/504 从网关冒出来；经网关的 404 被盖上 `X-Gateway` 的戳，码不变 |
| close | 责任图 | 同一条链路直接切进来；错误码排成一排，只看首位；4xx 归客户端「改请求」，5xx 归源站「等恢复」，502/504 挪到网关与上游之间；最后整张图亮一遍 |
| outro | 一次「200 OK」 | 名单排成响应头：状态行 `HTTP/1.1 200 OK`，下面每行「字段: 值」 |

**换场**：话题变了的地方（open→what、what→history、history→common、close→片尾）新场景从右侧推进来，中缝一道竖着的三色线缆；common→who 与 who→close 是同一画面的直切（匹配剪辑），镜头接着拉远或接着讲。

**参考**：未参考任何现成作品的界面、分镜或插图。「卡带未来主义」只作为风格方向（米色机身、单色荧光屏、条纹），版式与部件都按本片的对象重新画。

**取舍**（推翻准备方建议的地方与理由）：

- 准备方写的「沿用系列基座的计时盘视觉（墨 / 纸 / 朱红）」与 `check.style.palette` 里的那五个色值，是系列起点的占位；经验规则 F21 要求每部片子自成一体，策划者又定了「卡带、未来」，所以整套换掉。调色板仍是七个色值的白名单，`flat`、`no_radius`、`no_emoji` 照旧打开，只是白名单换成本片的颜色；字体白名单加了仓库自带的 `Pixel`（VT323）。这不是放宽，是声明本片的视觉系统。
- 右上角的仪表：准备方建议「按类别累计的计数条」；改成「应答表」（最近一个码 + 类别灯），因为它直接显示「这个三位数」本身，并且与正文的五类同一套灯。
- 「一条自上而下的五段色带 = 五个类别」改成五格的类别架：码要整组摆进各自那一类（策划者要求的「全部的码摆一团」），色带放不下码牌。
- 产生者的空间顺序：准备方写「源站在最左、网关在最右」；改成客户端在左、源站在右，与请求流向一致，限流层贴在源站前面（旁白说「前面的限流层」）。
- 405 没有进画面：定稿的旁白里没有 405，按 F02 不加新码。

## 声音

- **配音**：见「读法」与 `review/NOTES.md`「配音与读法」。中文严肃女声（策划者的硬约束）；音色由制作方按 MiniMax 的描述与语速选定，**待策划者试听确认**。
- **配乐**（`tools/music.py`，程序合成，为本片新写）：8 位芯片音乐（策划者的硬约束「8 位电子乐，契合 90 年代计算机风格」）。只用游戏机芯片的四路声音：两路方波（占空比 12.5 / 25 / 50%）、一路 4 位阶梯三角波作低音、一路 15 位线性反馈移位寄存器的噪声作鼓；音量包络按 60 Hz 一帧一级地走。120 拍/分（一拍 0.5 秒，与画面 0.25 秒的节拍格对齐），A 小调。编排随段落走：open 只有低音与稀疏琶音，片名卡上一记镲 + 三音的「三位数」动机；what 进鼓；history 抽掉鼓，只剩细占空比（12.5%）的琶音，像更早的机器；common 最密（十六分低音、25% 琶音、满拍的镲）；who 换到 Dm–Am–B♭–E 的更暗和声；close 主旋律进来，x4「短短三位数」那一拍抬到 A 大三和弦；片尾收在一个长和弦上。
- **音效**：只给有含义的动作，不同动作不同声音——请求包发出 `blip`；错误码回来 `error`，成功的码回来 `beep`；码牌整组落位 `drive`（软驱寻道声）；点名、刻度 `tick`；标签贴上 `pop`；结果揭晓 `chime`；片名与大字落位 `thud`；推入换场 `whoosh`。打字声由打字机自动登记。
- **混音**：`music_db −12`、`duck_db 7`、`sfx_db −9`（系列约定）。数值自检：各段低 / 中频能量占比约 −2 / −3 至 −5 dB，没有削波。**制作方听不到声音，配乐与音效的听感需要人来判断。**

- 标准（2026-10-20 逐条读取，2026-10-21 取原文复核）：RFC 9110（HTTP Semantics，2022-06）第 15 章——§15 五类定义、§15.1 概览、§15.2 的 100/101、§15.3 的 200/201/202/203/204、§15.4 的 301/302/303/304、§15.5 的 400/401/402/403/404/405、§15.6 的 500/501/502/503/504；RFC 6585（2012-04）§4 的 429；IANA「Hypertext Transfer Protocol (HTTP) Status Code Registry」（updated 2025-09-15），用于核对每个码的登记状态与它对应的 RFC 9110 小节号。
- 复核（2026-10-21）：把两份 RFC 的纯文本原文取到本地（副本 SHA-256 记在 FACTS「环境与版本」），逐条比对了事实表 51 条的小节号与措辞，**未发现错误**；复核明细见 `research/FACTS.md`「复核」一节。
- 实验：`research/lab/11_status_codes_server.js` 起两个只监听 127.0.0.1 临时端口的最小 HTTP 服务——一个源站，一个网关（转发到源站，上游连不上就自己回 502，上游 1 秒不回就自己回 504）；`research/lab/11_status_codes.ps1` 启动服务并用 curl 逐个触发 21 个场景，把完整回显写进 `research/lab/out_11_status_codes.txt`。脚本与回显同名对应，回显按本机原样（CRLF）保存，未做换行转换。2026-10-21 补做的三组场景：401 与 403 的分界、未登记的码 471、网关转发时带上 `X-Gateway` 标记头。
- 讲解对象自己的材料：状态行文法、原因短语、官方登记的码表、本片用到的响应头字段，记在 `research/MATERIALS.md`。

- 画面数据来源：状态行、头字段、响应体都取自上面那份回显，不手写；正文里的 RFC 表述在 `research/FACTS.md` 的「逐章」表里逐条对应小节号。

| 404、500、429…… | 四零四、五零零、四二九（逐位） | four-oh-four、five hundred、four twenty-nine | MiniMax 缺省念「四百零四」；开发者口头逐位念 |
| 1xx … 5xx | 一字头 … 五字头 | one-ex-ex … five-ex-ex | 写成 four-x-x 时英文被念成「zix」 |
| HTTP、HTTP/3 | H T T P、H T T P 三 | H T T P、H T T P three | 逐字母 |
| 1.1、1990、2022 | 一点一、一九九零、二零二二 | one point one；年份由音色自己念 | |
| 第一行、这一行 | 第一航、这一航 | — | 「行」被念成 xíng（回听为「这一型」） |
| 重试、重传 | 虫试、虫传 | — | 避免「重」念成 zhòng |

**自动闸门**：`check.js --final` 的结论见下面「复现」一节运行的结果（本节写入时已全部通过的项目：文案校对、源码规则、场景齐全、自成一体、时长与节奏、两种语言的全片扫描与音效覆盖、经验规则复核、交付物与片尾名单）。

**看过、听过的范围**（制作方能看图，不能听声音）

- 看过：全片两种语言的逐句总览图与关键时刻的总览图；成片 MP4 上每一处换场、两处匹配剪辑、片名卡扫入的中间帧（逐 0.15 秒左右抽帧）；四张封面。`readable.js` 两种语言逐 0.1 秒复测。低清预演没有 2 秒以上的静止；成片检查无 3 秒以上静止、无空画面。
- **没听过**：配音、配乐、音效都没有听过。只做了数值自检（各段低 / 中频能量、旁白压低、峰值）与 Whisper 回听（英文逐词对上；中文只剩同音字）。
- **没有以正常速度连续观看**：节奏、看懂一步机制的时间，以逐帧与可读时长测量为准，连续观看的结论留给策划者。

**需要策划者判断的事项**

1. **配音音色**（F17）：中文 `Chinese (Mandarin)_News_Anchor`、英文 `English_ConfidentWoman`，语速 1.2 / 1.25。试听片与候选在 `audio/probe/`（`audition-*.mp3`）。不合适时改 `project.json` 的 `tts.voice` 或 `tts.speed`，重跑 `tts.js`，再按「复现」从混音起重做；场景时刻随 `T()` 自动跟着走，但语速变了要按 `review/NOTES.md` 的办法重算各段定点。
2. **配乐与音效的听感**（F06）：8 位芯片音色是否「契合 90 年代计算机风格」、音量是否合适。调整只改 `tools/music.py` 或 `project.json` 的 `audio` 段，重跑 `audio.js` 与 `finish.js`，不必重渲。
3. **读音与断句**（F12）：Whisper 回听已对上（「传」改成单音字「船」合成之后逐句回听为 chuán，见 `review/NOTES.md`）；按规则仍以人耳为准，全片旁白听一遍。
4. **连续观看**（F04）：可读时长的下限都已达到，只剩运动中的请求包与码牌标签、换场的中间帧；节奏与「看懂一步」要正常速度连续看一遍。
5. **视觉方向**：「卡带、未来」落成了米色机身 + 琥珀荧光屏 + 像素字的「应答机」（见「视觉系统」），没有另做几个方向供挑选。
