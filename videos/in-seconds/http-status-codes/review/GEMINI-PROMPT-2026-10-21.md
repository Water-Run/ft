## 事实（不能改，也不能凭记忆补）

现稿里的每一句都有出处，出处在 `research/FACTS.md`（63 条编号事实）。**下面是与现稿直接相关的部分，你不要改动这些事实，只改怎么说。**

**五类的分界**（RFC 9110 §15）：状态码是三位整数；**首位数字决定类别**，后两位不承担分类作用。1xx 信息（请求已收到，处理继续中）、2xx 成功（请求已成功接收、理解并接受）、3xx 重定向（还需进一步动作）、4xx 客户端错误（请求有语法错误或无法被满足）、5xx 服务器错误（服务器未能满足一个看起来有效的请求）。

**未知码怎么办**（RFC 9110 §15）：客户端不必理解所有已登记的码，但必须理解它属于哪一类；遇到不认识的三位数，**按该类的 x00 处理**（收到 471 就当 400 看待）。100–599 之外的值无效。

**一次请求可以有多个响应**（RFC 9110 §15）：零个或多个 1xx 中间响应，之后恰好一个最终响应。

**沿革**（RFC 9110 §1.2，以及各版 RFC 的出版信息）：

- HTTP 自 **1990 年**引入起就是万维网的主要信息传输协议。起初极简：**只有一个 GET 方法**，请求一份 presumed hypertext 文档，响应直接就是文件内容。
- 随 Web 增长，HTTP 扩展为**把请求与响应包在报文里**、能传任意数据格式、能路由经中间设备。这些协议后来分别被定义为 HTTP/0.9 与 HTTP/1.0。
- HTTP/1.1 于 **1995 年**推出，**1997 年**发布为标准（RFC 2068），**1999 年**修订（RFC 2616），**2014 年**再修订（RFC 7230–7235）。
- HTTP/2 于 **2015 年**发布（RFC 7540）：在 TLS 与 TCP 之上引入多路复用的会话层，带字段压缩与服务端推送。
- HTTP/3 于 **2022 年**发布（RFC 9114）：用 QUIC 作安全的多路复用传输，跑在 UDP 之上而不是 TCP 之上。
- **三个大版本共享同一套语义，彼此没有互相废止**；版本换了，状态码一个都没改。

**日常遇到的那 11 个码**（RFC 9110 §15、RFC 6585 §4；每条都有本机实测）：

| 码 | 含义 | 关键点 |
|---|---|---|
| 200 | 请求成功 | 200 的内容随方法而变（GET 是目标资源、HEAD 同 GET 但不传数据、POST 是动作的结果…） |
| 304 | 收到的是条件 GET/HEAD；条件为真本来会回 200，但客户端手上已有有效表示，服务器不必再传内容 | 客户端把缓存里那份当作 200 的内容用 |
| 400 | 服务器不能也不会处理该请求，因为被认为是客户端的错误 | 请求语法畸形、消息分帧无效、欺骗性请求路由 |
| 404 | 源站没有目标资源的当前表示，或不愿透露它存在 | 404 不区分暂时还是永久；已知是永久的应优先用 410 |
| 401 | 请求未被应用，因为缺少目标资源的有效认证凭据 | **必须带至少一个 WWW-Authenticate 挑战** |
| 403 | 服务器理解了请求但拒绝履行 | **带了凭据但凭据不足**；客户端不应自动用同样的凭据重试 |
| 405 | 请求行里的方法源站认识，但目标资源不支持 | **必须生成 Allow 头**，列出该资源当前支持的方法 |
| 429 | 用户在给定时间内发了太多请求（限流） | 响应体应说明情况，可带 Retry-After；**429 响应不得被缓存** |
| 500 | 服务器遇到了预料之外的情况，无法完成请求 | — |
| 502 | 服务器**在充当网关或代理时**，从上游收到了无效响应 | — |
| 504 | 服务器**在充当网关或代理时**，没有及时收到上游的响应 | — |

**谁发的**（RFC 9110 §15 + 本机实测）：

- 2xx、3xx、4xx 里除 304 外，通常由**源站**（真正持有资源的服务器）产生。
- **304** 由条件请求触发：客户端带上 If-None-Match，服务器比较后判定客户端手里的副本仍然有效。
- **405** 带 Allow 头，是框架或路由层在告诉客户端「这个资源支持哪些方法」。
- **429** 带 Retry-After，通常由限流中间件产生；RFC 6585 明确说该规范不定义如何识别用户、也不定义如何计数。
- **503** 由源站自己产生（临时过载或计划维护），可带 Retry-After；存在 503 并不意味着一旦过载就必须用它，也可以直接拒绝连接。
- **502 与 504** 由网关或代理产生——两者的 RFC 条文都写明是「服务器在充当网关或代理时」发生的。
- **网关不发明新的码**：同一个 404 经网关转发过来，仍然是源站产生的那一个。

**责任归属**（RFC 9110 §15.5、§15.6）：4xx 整类表示「客户端似乎出错了」；5xx 整类表示「服务器知道自己出错了，或无法执行请求的方法」。

**这一版没讲、也不要加进来的**（96 秒装不下，列出来是为了让你别建议加）：201、204、301、302、503 这几个码；1xx 的单独讲解（只在类别里点到）；各框架实际返回哪些码；状态码在真实流量里的出现频率（**没有可复查的一手统计，片中不给百分比，也不声称排名**）；102、103、207、226、418、451 等边缘码；HTTP 的机制细节（chunked、内容协商、范围请求）；QUIC 的内部机制。
