## 三项审查

**事实**：画面上的协议文本只取 FACTS「画面数据」：`Set-Cookie / Cookie: SID=31d4d96e407aad42`（RFC 6265 §3.1 示例）、`code=SplxlOBeZQQYbYS6WxSbIA&state=xyz` 与两条令牌（RFC 6749 §4.1.2、§4.1.4 示例），三段 JWT、改一位数字后的应得签名、ID Token 的 iss / sub / aud、passkey 的挑战值都由 `research/lab/01_lab.js` 实算；SHA-256 约每秒一百万次、scrypt（OWASP 参数）约每秒五次是同一脚本在制作机上的实测，画面只作量级对比。旁白每句的依据见 `review/NOTES.md` 逐句依据表，本轮没有新增事实陈述。用 `look.js` 截每句说完那一刻的画面（中英各 46 帧，`shots/sheets/`）逐张对照。

**读音与节奏**：`asr.js` 整段回听加存疑句单句转写。中文：同音字误识（公药、甲网站、摘药、失手）不算错；「一对钥匙」原读法单句回听成「一堆」，改读法「一对儿钥匙」后重配；「OAuth 2.0」中文版各写法都被听成「OOS」，留待人耳。英文：p4 原稿被读成插入语「you know」，改为 that you know 重配；p1 被听成「how do you recognise」，改为主动句重配。`stats.js`：中文中位每秒 5.0 字，只有 o3 一句短问句超过 6.3；英文中位每秒 3.0 词。

**旁白与画面对应**：`scan.js` 用按第 11 稿重写的 `expect.*.json` 逐句核对，中英两版 0 错误；另用逐 0.1 秒取帧的阅读时间审查（见 F04）补查「说到即出现、出现后读得完」。

node $V/research/lab/01_lab.js && node $V/tools/gen_data.js
