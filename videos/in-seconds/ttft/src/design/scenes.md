## 1. 叙事与画面的总设计

**核心问题：为什么第一个 Token 来得慢，之后却一个接一个？** 名字「首 Token 延迟」一句话就说清，所以 96 秒讲的是大模型的工作方式与尺度：先说这段等待是对话里体感延迟的主要来源 → 模型每次只写一个 Token，写每一个都要参考前面所有的 Token → 所以写第一个之前要先读完整个输入，输入的 Token 同时处理、中间结果存进缓存 → 之后每个新 Token 只在缓存上续一小步 → 重复提问时，开头相同的部分会命中缓存、不用重新读，首 Token 延迟通常更短（两句）→ 输入越长，第一个来得越晚 → 尺度：聊天里一秒以内算快，开着深度思考的要几十秒以上 → 它不说明整段回答多久。

**例子用程序员的场景**：提问「写一个判断质数的 Python 函数」，输出的 Token 是 `def`、`is_`、`prime`、`(`、`n`、`):`……（代码 Token 用 Mono 字体）；长输入是「整个代码文件」；缓存复用的是「上次已读过的代码文件」。切分是示意，不代表任何真实分词（画面标「示意切分」）。

**贯穿的对象：一排 Token 列**（输入 6 列 + 输出从第 7 列起；列距 156，块 140×104；缓存格在列下）。write、prefill、reuse、close 共用同一套几何；length 把「读完输入」画成一条随长度变宽的横条；scale 是对数刻度的尺度尺。

| 图形 | 含义（全片不换义） |
|---|---|
| 琥珀 `--ac` | 只给首 Token 延迟相关：光标、计时读数、第一个 Token、首 Token 延迟括号、TTFT 的四个首字母 |
| dim 实心块（`.tok` 的 `in`） | 输入（提问）的 Token |
| paper 实心块 | 被处理过的输入 Token / 已写出的输出 Token |
| 琥珀块 | 客户端收到的第一个 Token |
| ink2 底 dim 字块（`.tok.rest`） | 还没写出的输出 |
| 缓存格（140×52） | 每个 Token 的中间结果：输入每列一格，同时存满；之后每个新 Token 只多一格 |
| 括号 | 一段被计入某指标的时间：琥珀 = 首 Token 延迟，paper = 另一段说明范围 |

数字都是示例或有出处：光标等待的 2.00 秒、长度与时间是人为设定（画面标「示例」「示意」）；尺度一场的数字来自 FACTS（ClickHouse 指南 2026-07；Artificial Analysis 榜单快照 2026-11-18），画面上带出处一行。`TTFT` 出现在片名卡、封面，以及 define 一场的展开动画里；其余标签都用「首 Token 延迟」。

## 2. 全片配置（`src/js/config.js`、`index.html`、`parts.js`）

| `Tend('e2')` 起 | 静停到场景末（至少 1.0 秒），配乐收束 |

### 3.8 `outro`（93.0–96.0，约 3 秒）

策划者 2026-11-18 明确要求片尾名单压到 2–3 秒（高于系列缺省的约 7.5 秒）。起点的 `s9_credits.js`：名单来自 `project.json` 的 `credits`，不配旁白，`GPL-3.0-or-later` 与仓库地址可见；底色 ink。因为只有约 3 秒，名单**一次性整屏出现**（`lead` 0.3 秒后即全部在场，不逐行入场、不做动画），字号不小于 36px，只放必需的几行：策划、模型与分工（每个模型一行）、「开源视频」、仓库地址、`GPL-3.0-or-later`。`check.js` 若对名单停留时间报错，如实报告，不放宽阈值。**交付前 `credits.models` 要写成实际参与的模型准确型号与分工**（`docs/roles.md` 第 5 节）。

## 5. 声音

**音效**（`sfx(名, 时刻, {g})`，名称见 `docs/guides/sound.md`；覆盖要求写在 `project.json` 的 `check.sfx`）：`tick`（Token 块逐个落下、缓存升起、TTFT 字母逐个出现）、`pop`（标签贴上、缓存升起）、`thud`（片名、「首 Token 延迟」大字、深度思考块）、`chime`（第一段落下：open 的 `t_f`、prefill 的 `T('r3','之后')` 与 `T('r5','更短')`、close 的 `T('e2','之后')`，每场至多两次）、`whoosh`（换场、输入块同时亮起、TTFT 展开，`g: 0.4–0.5`）。起点自带的剩余 5 秒 `tick` 保留。

**配乐**（`tools/music.py` 重写；已选方向 01「脉冲 · 清晰节拍」，100 BPM，小样音符环 `[60,67,64,67,62,69,65,69]`，见 `tools/audition_audio.py`）。程序合成，`compose(ctx)` 返回 (2, N)。不用起点的 D 小调与 120 拍的「秒针」（F21）；每小节 2.4 秒，`audio.score.lift_cue` 为 `"o3"`（`project.json` 已改）：

| 小节（时刻） | 场 | 内容 |
|---|---|---|
| 0–4（0–12 秒） | open | 每拍一声很轻的滴答（像计时器）+ 极低的持续音；第 4 小节起加一个单音每小节一次，悬着 |
| 5（12.0） | 片名 | 满和弦 + 轻底鼓（与 `thud` 同拍），然后起拍 |
| 6–12（14.4–31.2） | define | 脉冲琶音（八分音符）+ 滴答，平稳；TTFT 展开那一拍加一个上行的短音 |
| 13–16（31.2–40.8） | write | 保持脉冲；每个新 Token 落下时重音落在拍上 |
| 17–25（40.8–62.4） | prefill | 读完输入那段铺一层缓慢上升的滤波，所有输入块同时亮起的那一拍抬起；第一块琥珀落下处（`r3`）释放，之后滴答变均匀；`r4` 的复用换幕那一拍略收，第二次琥珀落下处（`r5`）再抬一次 |
| 26–29（62.4–72.0） | length | 低音走动，随横条变宽再拉长一拍，第二行琥珀块落下处落一个低音 |
| 30–34（72.0–84.0） | scale | 变疏，留脉冲与长音；每个新读数一个高音 |
| 35–38（84.0–93.0） | close | 落回主和弦；`e2` 的落点所在拍抬起；其后只留铺底 + 滴答，最后一小节滴答停在小节线上（「计时停了」） |
| 38.75–40（93.0–96） | 片尾 | 主和弦铺底，最后 3 秒淡出，无滴答 |

响度与让位由 `mix.py` 统一处理（`music_db −12`、`duck_db 7`）。制作者听不到声音：出片前跑 `audio.js` 的数值自检，听感交人确认；没听的范围在 NOTES 写明。

## 6. 逐步实现与自查

1. 第 0 节闸门 → `tts.js` → 回听 → 调时间线。
2. 写 `config.js`（拍子、`METER`、`HUD.right`、换场）、`parts.js` 的部件、各场景文件；**每写完一个场景就** `node --check` 该文件，然后 `node kit/tools/look.js videos/in-seconds/ttft <句号>` 和中间时刻看一帧，与对应的 keyframes 帧对照；`node kit/tools/scan.js videos/in-seconds/ttft --from <起> --to <止>`。
3. 先做有声代表段：`prefill` 一场（含「同时亮起」「缓存升起」「第一块琥珀落下」「命中缓存」），再做 `define` 的 TTFT 展开；用 `preview.js` 的区间预演看动作与旁白对不对得上；通过再铺开其余各场。
4. 全片：`node kit/tools/sheets.js videos/in-seconds/ttft every 3` 通看；`node kit/tools/check.js videos/in-seconds/ttft`；出预览 `node kit/tools/preview.js videos/in-seconds/ttft --round r1`。交出前按 `docs/process.md` 第 2 节做自对抗审查，运行 `node kit/tools/lessons.js videos/in-seconds/ttft sync`、复核 F05、F20–F25、F29。
5. 不为通过检查放宽阈值或改工具；检查不过先改画面。镜头不动。画面只由 t 决定：不用 CSS 动画、定时器、`Math.random()`；元素的起点一律 `fromTo` 显式给出；TTFT 展开用 `F()` 每帧由 t 算 `k`，不累加状态。

## 7. 已知风险

- 旁白时长：估算对 13 句实测的平均绝对误差约 0.36 秒/句；open 的估算余量最小，配音后可能要微调 `gap`。
- 「同时亮起 / 同时存满」是 prefill 一场的核心，必须在同一帧发生，不要错开；错开会讲成「逐个处理」。
- 缓存复用只提一句：画面不写命中率、延迟减少的数字、价格与有效期；出处一行写明「命中要求开头完全一致」，也不要暗示一定更快（官方文档说不保证）。
- 画面的 Token 切分、示例对话「写一个判断质数的 Python 函数」、输入长度与时间都是示意；尺度一场的数字是出处标明的行业目标与榜单快照，不是实测，更不要点名模型或厂商。
- 开场读数是「实时 2 秒」；其余场的 2.00 是同一个示例读数的保持值。
- 片尾只有约 3 秒：名单必须整屏一次出现，字要够大，否则读不完；这是策划者的明确要求，读不完的风险在 NOTES 如实写明。
