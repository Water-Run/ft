## 连贯阅读

先通读问题、解释与章节推进，再到逐句表定位意见。下文按源稿顺序连接字幕，保留原文字与标点；不含静默 cue。口播读法与停顿另按配音规则核对。

### open · 无章节卡

消息发出去了，为什么回答迟迟不出现？ 我们用一个计时器，看懂这段等待 模型的输出由一个个 Token 组成 从发送请求，到收到第一段有效输出 这段时间叫首 Token 延迟，也叫 TTFT

### journey · 无章节卡

请求先经过网络，到达服务端 如果服务正忙，还可能需要排队 轮到它后，模型先处理输入内容 再开始生成，服务把第一段结果送回来 客户端收到这一段，计时停止

### measure · 无章节卡

假设十点整发出请求 两秒后收到第一段有效输出 那这次客户端测得的首 Token 延迟是两秒 这是演示数字，不代表实际服务速度 空的响应消息，不算有效输出

### boundary · 无章节卡

第一段到了，后面的回答还在生成 首 Token 延迟短，不等于全文很快结束 比较服务时，要用相同的计时口径 还要考虑输入长度和当时的负载 它衡量的，是回答开始前等了多久
