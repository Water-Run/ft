## 连贯阅读

先通读问题、解释与章节推进，再到逐句表定位意见。下文按源稿顺序连接字幕，保留原文字与标点；不含静默 cue。口播读法与停顿另按配音规则核对。

### open · 无章节卡

向 LLM 提问之后，光标闪一会儿，第一个字才出现 之后文字却一个接一个冒出来 这段等待，是对话里体感延迟的主要来源

### define · 无章节卡

回答是一小段一小段写出来的，每一小段叫一个 *Token* 从发出请求，到收到第一段有内容的输出 这段时间就是 *首 Token 延迟*，缩写 *TTFT*

### write · 无章节卡

模型写回答，每次只能写一个 Token 写每一个新 Token，都要参考前面所有的 Token

### prefill · 无章节卡

写出第一个 Token 之前，要先读完整个输入 输入的 Token 同时处理，中间结果存进缓存 之后每个新 Token，只在缓存上续一小步 重复提问时，开头相同的部分会命中缓存 不用重新读，首 Token 延迟通常更短

### length · 无章节卡

同样的问题，附上整个代码文件 要先读的内容多了，第一个 Token 就更晚

### scale · 无章节卡

聊天里，首 Token 延迟一秒以内算快 开着深度思考的模型，要等几十秒以上 首 Token 延迟短，不代表整段写完快

### close · 无章节卡

第一个 Token 慢，是因为要先读完输入 之后才一个接一个地写
