# 96 秒速通模型的各个参数

一部 96 秒的中英双语科普短片：拿到一个模型，别人的回答往往不是「多大」这一个数字，而是一串单位各不相同、量级差着几个数量级的参数。讲法是逐类参数往下走，每类都按同一套讲法——它是什么、单位是什么、量级多大、怎么读——并在一处点明「参数量不等于能力」的口径陷阱。成片时长必须恰好 96.00 秒。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`。

## 简报

策划者对本片的明确要求（原话，2026-10-20）：

- 「**这片是面向更入门的用户的科普。**」——按此把讲解压到最少的名词：全片只引入参数量、上下文长度、token、词表、激活参数五个新词，其余（层数、隐藏维度、注意力头）当作参数表上要读的三个读数，各用一句大白话带过，不作概念讲解。
- 「**模型不要太老，至少 26 年 8 月之后的。**」「**qwen3 这种一年半前的模型就属于典型的太老。**」——本片讲到的模型一律换成 **2026 年 8 月之后发布**的开源模型；筛选过程与依据见 `research/lab/06_recent_models.py` 与 `out_06_recent_models.txt`，每个仓库的创建时间记在 `research/FACTS.md`「数据来源」一节。
- 「**落盘一个反馈：BGM 的同质化。大量旋律类似，高度雷同，没有契合每个视频的独特不同。就算不类似的，也整体风格相近，"味道"一样。BGM 应该是对应每个视频更加客制化的。**」——已记入 `docs/log/feedback.md` 的 P40。本片按新要求执行：**配乐为本片新写**，与最近两部（Dense/MoE、Web 登录）并排试听要能说得出各自是什么、有什么不同；只换音色、速度或段落编排不算。

2026-10-20 改题重规划时的其余决定（原话见 git 历史提交 53fdb6d 与本片 `research/MAP.md`）：题名《96 秒速通模型的各个参数》；成片时长必须恰好 96.00 秒；视觉保持策划者指定的液态玻璃不变；不出现各家厂商商标与模型页装饰。

**核心问题**：看到一个模型的那些参数（参数量、层数、隐藏维度、上下文长度、词表……），每个是什么、单位多少、量级多大、怎么读？看完应能说清每项的单位与量级，并知道「参数量 ≠ 能力」这类口径陷阱。

**逐章答案**：open 现象（答案不是一个数字）→ p1 参数量（是什么、单位、量级）→ p2 结构参数（模型长什么样）→ p3 上下文长度（单位是 token 不是字）→ p4 词表与 token（为什么不能按字数算）→ edge 口径陷阱（总参数 ≠ 激活参数，参数量 ≠ 能力）→ concl 结论（先看单位，再看量级，最后看口径）。逐句答案见 `review/NOTES.md`「交审说明」。

**时长与语言**：成片时长必须恰好 **96.00 秒**（`project.json` 的 `check.duration` 是 [95.9, 96.1]）；语言 **zh 与 en**（英文稿在中文确认后译，同步重交审）。

看完应能回答的一个核心问题：拿到一份模型参数表，能说出每项的单位与大致量级，并知道参数量不等于能力这类口径陷阱。

逐章怎样推进问题、最后回答什么：见 `research/MAP.md`「逐段推进」——open 抛出「为什么答不上来」，然后逐类参数按「它是什么 → 单位 → 量级 → 怎么读」推进（参数量 → 结构参数 → 上下文长度 → 词表与 token），边界章点明口径陷阱，结论落在「先看单位，再看量级，最后看口径」。

本片决定不讲的材料及理由：具体模型之间的横向对比与跑分（超出「读懂参数」，且各家口径不一致，另立选题）；训练细节、推理框架、部署与量化（不是一条线，96 秒塞不下）；MoE 的总参数与激活参数机制（只点一句口径，展开是第 5 集《Dense/MoE》的事）；完整字段表（挤掉量级与单位的解释）；模型卡怎么读（原《96 秒速通模型卡》的内容，随改题作废）。

## 内容

场景与时长以 `node kit/tools/timeline.js videos/in-seconds/model-parameters` 为准。96 秒是上限也是卖点，宁可删内容也不压留白。中文稿的时间线（估算，总长 96.00 s，各场余量 0.65–0.90 s）：

| 场景 | 起点 | 内容 |
|---|---|---|
| open | 0:00 | 现象：有人问「这个模型多大」，答案不是一个数字而是一串参数；这些数字都写在模型仓库的配置文件里。**片名卡落在 o2（约 0:02）** |
| p1 | 0:12 | 参数量：是什么（模型里学出来的数字的个数）→ 单位（个；名字里的 M 百万、B 十亿、T 万亿）→ 量级（这一列里最小一亿多，最大两万多亿） |
| p2 | 0:27 | 结构参数：同一份文件里还写着模型长什么样——层数 42、隐藏维度 2048、注意力头 16，各一句大白话 |
| p3 | 0:43 | 上下文长度：模型一次最多能读多少东西；单位是 token（词表里的一条），不是字；上限 13 万 |
| p4 | 0:56 | 词表：模型认识的所有词条；中文一个 token 一两个字、英文四五个字母；所以上下文长度不能按字数算 |
| edge | 1:10 | 口径陷阱：参数量大不一定更强；混合专家模型存了 240 亿参数，每次只用 25 亿 |
| concl | 1:20 | 结论：先看单位，再看量级，最后看口径；参数量只是一项 |
| outro | 1:28.5 | 片尾名单与开源链接，静默 7.5 秒，不配旁白 |

本片引入的新名词共五个：参数量、上下文长度、token、词表、激活参数。层数、隐藏维度、注意力头只作参数表上的三个读数出现，各配一句解释，不作概念讲解。

## 视觉系统

**液态玻璃**（策划者指定；2026-10-20 改题重规划时确认与原《96 秒速通模型卡》保持一致）。完整规范见 [`research/STYLE.md`](research/STYLE.md)，要点：

- **保留不动**（系列约定）：字幕带与秒尺、左上角剩余秒数、120 拍/分与每秒一声秒针、定长时间线、语速。
- **只换视觉系统**：深墨到冷灰的底板（`#0b0f14` → `#151b23`）配一条固定方向的宽光带；卡片本身是暖白的**纸**（`#f4f1ea`），玻璃感来自它的厚度边、折射亮边、背后模糊与 45° 高光——**玻璃是介质，不盖住表上的字**。
- **四类参数四种玻璃形态**，各只在本片这一处作类别识别：参数量=薄玻璃片，结构参数=厚玻璃块，上下文长度=裂纹玻璃（硬边界），词表与 token=磨砂玻璃。
- **右上角仪表**（`hud-r` 容器）：一张缩小的参数表轮廓，四行竖排，读到哪行亮哪行，点亮用朱红 + 一次 0.3 秒高光扫过；最后 5 秒四行全亮。镜头在「逐行读」段纵向下移时与它同步。
- 全片一个连续空间，镜头始终能看到这张表的边缘；参数值读数段落镜头完全停住。
- **参考与原创**：不使用外部视觉参考作品，玻璃形态按模型参数表这一对象自行设计；字体与朱红/纸色沿用系列基座，冷调底板与青色折射为本集新增。**禁用**各家厂商商标与模型页装饰，只用公开字段与通用排版。

## 读法

`script.js` 的 `SAY` 表目前只有四条，都是**未经试听**的初稿（`tts_probe.js` 与 `tts.js` 都要求文案已获确认，本轮无法试听）：

| 写法 | 送去合成的文本 | 说明 |
|---|---|---|
| `token` | 偷肯 | 未经试听。若听起来别扭，改成「托肯」或直接按英文单词念（注意 `T('p3_3', 'token')` 取词时合成文本里已经不是 `token` 了） |
| `M`（p1_3） | emm | 未经试听。M 是百万的单位符号，读英文字母名 |

| `T`（p1_3） | tee | 未经试听。T 是万亿的单位符号 |
