## 这集要让人带走的一件事

敲下回车之后、登录框出现之前的那一秒里，两台机器先做完四件事：对上一种彼此都会的加密，换出一把不从网上传的钥匙，认明服务器，再证明你是你。

旁白就走这一条线。画面上可以出现实验回显里的原词，当作这次连接自己的标签。嘴里不考这些名字。

建议的讲述顺序（可以改句子，不要改这条线）：

1. 敲下回车，屏幕静了一秒。两台机器要先商量好，你才能进去。
2. SSH 是登录远处那台机器的一套规矩，不是某一个程序的名字。
3. 两边先对上一种彼此都会的加密。对不上就断开。
4. 两边各留一个秘密，算出同一把钥匙。这把钥匙本身不从网上传。
5. 服务器拿出身份。你的电脑跟上次记下的那份比对。对不上就断开。第一次没有旧记录，不核对就点同意，就可能认错人。
6. 然后证明你是你。私钥留在你身边，送出去的是签名。这次没有用口令。
7. 登录框出现之前，这四件事已经做完。

## 可以用的事实

只许使用下面这些。写每一句时标出编号。编号以外的说法，即使你觉得对，也标成「待核」，并且不要放进正文。

| 编号 | 可以怎么说 | 不能说成 |
|---|---|---|
| H1 | 连上之后，两端先报自己的版本 | 第一件事就是换密钥 |
| H2 | 然后两边各发一份自己会哪些算法的清单，按自己的偏好排 | 清单是按字母排的；这份清单等于今天的默认 |
| H3 | 加密算法取你这边清单里、对方也会的第一个。一个都对不上，就断开 | 一定会选某一种固定算法 |
| H4 | 两边各留一个不送出去的秘密，各自算出同一个密钥。这个密钥本身不在网上传 | 把这次连接说成用了迪菲-赫尔曼；把 e、f 说成这次发出去的数 |
| H5 | 这次实测的密钥交换不走规范正文里的那种旧换法。旧换法的名字和这次回显里的算法名都不要念出来 | 「RFC 规定 SSH 只用某几种算法」；「现在默认就是某算法」 |
| H6 | 光换出密钥，还不能认服务器是谁 | 换密钥等于认过服务器 |
| H7 | 服务器用自己的私钥，给这次交换得到的一个摘要签名。你的电脑用它的公钥验。对不上就断开 | 把摘要的输入公式念出来 |
| H8 | 这个公钥还要跟你电脑里上次记下的那份一样，才算数。以后这把身份变了，会当场报错 | 第一次连接也已经有记录可比 |
| H9 | 第一次连接没有旧记录。默认先问人，人点头才记下。不核对就接受，挡不住有人冒充服务器 | 第一次连接是安全的；SSH 能替你认出冒充 |

| H11 | 这一次实验走的是公钥，没有用口令 | 所有 SSH 登录都不用口令 |

## 第 2 稿为什么要改

第 2 稿事实更严，但仍然是协议走查。它让观众记住 RFC、人名、OpenBSD、三个算法全名、迪菲-赫尔曼对照、A 到 F 和 ssh-userauth。按上面的受众，这些该退出旁白。第 2 稿全文如下，只作对照，不要在它上面做小修补。请按「讲述顺序」重写一版。

敲下 ssh 命令，回车，屏幕静了一秒。这一秒里，两端先报上自己的版本。然后才换密钥，并验明服务器。这套流程叫 SSH，本片按这一次连接拆开。

SSH 是一套协议，不是一个程序。1995 年，Tatu Ylonen 公开了第一个版本。2006 年，它成了标准文档 RFC 4253。它分成两层。底下这层先认服务器。这一层不认你是谁。认你是谁，留到上面那一层，后半段再讲。今天这份 ssh，由 OpenBSD 项目的开发者维护。

报完版本，两端各发一份清单。清单里写着自己支持哪些算法，按偏好排。加密算法取客户端清单里第一个对方有的。一个共同的都没有，双方当场断开。这条连接用的是 Windows 上的 OpenSSH 9.5p2。密钥交换用 curve25519-sha256。主机身份用 ssh-ed25519。加密用 chacha20-poly1305。这几项是这一次的结果，不是规范里的必选项。

规范正文先写另一种换法，叫 Diffie-Hellman。两边各留一个秘密，把算出来的数发给对方。两边各自算出同一个密钥。这个密钥本身，不在网上传输。这次连接没有用这种换法。回显里写的是 curve25519-sha256。换密钥本身，还不认服务器是谁。

服务器有一把身份密钥，叫主机密钥。服务器要签的，是这次交换得到的一个哈希。服务器用主机私钥给这个哈希签名。客户端用主机公钥验这个签名，对不上就断开。公钥还得跟本地存的那份对得上，才算数。本地存这些公钥的地方叫 known_hosts 文件。第一次连上，本地没有记录可比。默认先问人一声，点头才写进文件。以后再来，主机密钥变了会当场报错。

身份对了，还要把共同的数变成能用的密钥。办法是反复做哈希，每做一次加一个字母。一共算六次，字母从 A 排到 F。A 和 B 是两个方向的初始向量。C、D 是加密密钥，E、F 是完整性密钥。从这一刻起，发出去的内容全部加密。连包头一起加密，外面看不出传的是什么。每包都算一次校验码。双方再各发一条消息，新密钥从下一条开始生效。

服务器是谁已经清楚了，现在该证明你是谁。接着客户端请求认证服务，叫 ssh-userauth。公钥认证是唯一必须实现的方法。客户端先把公钥报过去，服务器回一个确认包。客户端用私钥签一份数据：会话标识、用户名、方法名。服务器拿公钥验这份签名，对了就放行。私钥始终留在本机，路上只有公钥和签名。这条连接走的正是公钥，口令没用上。

有一处要留心。第一次连接，本地没有旧记录可比。这时不核对就接受，就挡不住有人冒充服务器。

所以那一秒，做完了四件事。对上算法。换出密钥。验明服务器。证明自己。登录框出现前，这四件事已经做完。
