## 目标观众的知识前提

- 用过 `ssh` 命令连过机器；知道「连上去会提示输密码，或者直接登录」。
- 知道公钥、私钥这两个词，但不知道它们在协议里出现在哪一步。
- 不知道 SSH 是一套**协议**而不是一个程序。
- 不知道传输层与用户认证是**两层**。
- 不知道「协商」这件事的存在——以为算法是写死的。

**不假设**：密码学背景、模运算、哈希与签名的区别、任何 RFC 的内容、任何 OpenSSH 内部结构。

## 核心问题与逐章答案

| 章 | 本章问题 | 本章答案 | 下一问 |
|---|---|---|---|
| open | 敲下回车之后那一秒，屏幕上没发生什么，为什么？ | 因为屏幕上出现任何东西之前，连接已经协商完算法、换出密钥、验过服务器 | 那这套流程到底是什么 |
| what | SSH 是什么，为什么值得看 | 一套协议；1995 年 Tatu Ylonen 的第一版，2006 年定为 RFC 4253；分传输层与认证层，传输层只认服务器不认用户 | 协议这一层要做哪几件事 |
| kex | 双方怎么知道该用什么算法 | 各自发一份按偏好排序的清单，客户端取自己清单里第一个对方也有的；没有共同的就断开 | 清单选完了，密钥从哪来 |
| dh | 两台机器怎么在公开信道上换出只有它们知道的密钥 | Diffie-Hellman：各自随机取数、各自算出 e 与 f、两边本地算出同一个共同值，这个值不过网 | 共同值不证明对面是谁 |
| hostkey | 怎么确认对面是那台机器 | 服务端把哈希 H 用主机私钥签名；客户端用主机公钥验签名，并把公钥跟本地 known_hosts 对照 | 身份对了，密钥怎么用 |
| derive | 共同值怎么变成真正加密数据的密钥 | 六次哈希各带一个字母 A–F，派生出两个方向的 IV、加密密钥与完整性密钥；之后所有包连包头一起加密 | 服务器确认了，该你了 |
| userauth | 怎么证明「我是我」 | 认证层 ssh-userauth；公钥认证是唯一必须实现的方法：报公钥、拿回确认、用私钥签一份含会话标识与用户名的数据、服务器验签 | 这套办法哪里不牢靠 |
| edge | 这套办法自身的盲区在哪 | 第一次连接本地没有旧记录可比；转发认证代理等于交出钥匙的用法；端口转发在隧道里再开一条通道 | 所以那一秒究竟做了什么 |
| close | 回到开头 | 登录框出现之前，协商、换密钥、验服务器、证明自己这四件事都已经做完 | —— |

## 决定不讲的材料

| 舍弃 | 理由 |
|---|---|
| SSH 1 的历史、专利对协议设计的影响 | 史料，不回答「这一秒发生了什么」。只保留「DSA 当年是唯一必选项」这一句，因为它解释「为什么协议里会有一个 160 位的算法」。 |
| OpenSSH 的治理结构与移植史 | 项目介绍，不是机制。只保留「由 OpenBSD 项目的开发者维护」这一句，出现在「它是什么」章。 |
| 端口转发、agent 转发的配置写法 | 属于用法。边界章只讲这两件事带来的权限含义，不讲命令行参数。 |
| 具体的默认算法顺序 | 「支持什么」不等于「默认选什么」，而默认顺序要按版本查文档。只讲这一条连接协商出的结果。 |
| 包格式的每个字段、MAC 的具体算法、压缩 | 讲「包长字段被加密」这一点就够说明「外面看不出内容」；再细就变成协议规范朗读。 |
| 认证方法全集（口令、键盘交互、hostbased、GSSAPI） | 认证层讲了公钥这一种就够；讲全集会稀释「唯一必须实现」这个事实。 |
| 密钥长度、位强度的横向比较 | 没有对照实验，就不报倍数。 |
| 「这一秒只用了两个来回」 | RFC 4253 §1 的 2–3 个来回含服务请求与接受通知，不只是密钥交换；不报这个回数。 |
| 「SSH 比 Telnet 安全」 | 没有比较对象与威胁模型就说不出这句话。改为说清传输层做哪三件事。 |
| Ylonen 的国籍与单位 | RFC 4253 的作者栏只给了姓名与单位，没有一手依据，不写。 |

完整清单见 `research/FACTS.md` 的「查过但决定不写进旁白」一节。

## 句与依据

每句的事实依据在 `research/FACTS.md`，按「陈述 ↔ 出处 ↔ 核实方式」逐条列出。以下标出**推断与简化**：

- **k5、k6、k7、k8** 是本机那一次实测的协商结果，不是协议规定。依据在 FACTS「本机这一次协商的结果」。画面必须带上 `OpenSSH 9.5p2` 的版本角标。
- **d5「两边各自把对方的数乘上自己的秘密」** 是 RFC 4253 §8 第 2、3 步的口语化：`K = e^y mod p` 与 `K = f^x mod p`。没有把模运算写进口播。
- **d7「这个共同的密钥，没有在网络上传输过」** 是从 RFC 4253 §8 的消息格式推出来的：K 只出现在哈希输入里，不在任何一条消息的字段中。
- **d8「窃听者只看到 e 和 f」** 限定为被动窃听。主动攻击者可以自己做一次 DH 交换——这正是 hostkey 一章要补的。旁白因此用「窃听者」而不是「中间人」。
- **h4「对不上就断开」** 是 RFC 4253 §7.1「If there is no such algorithm, both sides MUST disconnect」与 §8 第 3 步合并后的口语。
- **e2「第一次连接没有记录可比，是它自己的盲区」** 依据是 RFC 4253 §8 第 3 步允许客户端不核对就接受主机密钥（那样挡不住主动攻击），以及 `ssh_config(5)` 的 `StrictHostKeyChecking` 默认是 `ask`。
- **e4「对方主机上能碰代理的人，就能借你的身份登录」** 依据是 `ssh_config(5)` 的 `ForwardAgent`：拿到远端 socket 权限的人不能取走密钥材料，但能用 agent 里的身份完成认证。旁白没有说「密钥会被拿走」。
- **e6「能到哪儿，取决于两端的配置」** 依据是 `ssh_config(5)` 的 `LocalForward` / `RemoteForward` / `DynamicForward` / `PermitRemoteOpen`。
- **w2、w3、w7** 的年份与归属见 FACTS「它是什么」。

**没有出现在旁白里的画面信息**（受托方做场景时可以画，但不进字幕）：`SSH_MSG_KEXINIT` 的十一个字段全表、cookie、e/f 的具体数值、`SSH_MSG_USERAUTH_PK_OK` 的报文结构、known_hosts 的完整行。

## 对抗审稿 · 第 1 轮（Grok 4.7，待 WaterRun 回应）
