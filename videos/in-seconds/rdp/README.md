## 简报

**受众。** 系列定位：入门、普及、低认知负担（见系列说明「受众」）。不假设观众知道什么是协议、端口、编码；会用 Windows，可能用过 QQ 远程、向日葵一类软件或游戏串流。

**核心问题。** 隔着网络操作另一台 Windows 电脑，画面是怎么传过来的？RDP 的做法「优雅」在哪里？

**解释路径（第 2 稿）。**

1. 引子：用过 ToDesk、UU 远程吧？它们把那边的屏幕录成视频一帧帧发给你；Windows 自带的远程桌面走另一条路——RDP 发过来的是画面的画法。
2. 历史：1998 年，一台服务器分给很多人用、便宜终端（代号 Hydra）；2001 年 XP 专业版带上它。
3. 本质区别：站的位置。视频流远程站在屏幕外面，只认像素；RDP 站在 Windows 里面，在指令变成像素之前接过来，交给你的电脑自己画。
4. 例子：在远程记事本里打一行字（录像 600 多字节 / RDP 字形先缓存、字母 d 九个字节、一行九个字 47 字节）；往下翻一页（录像这一帧 23159 字节 / RDP 一句搬移 14 字节加补几行）。
5. 优雅之处：画多大由你这边说了算。连上时报上屏幕大小、缩放、键盘布局、时区，那边的桌面照你的屏幕重新排；窗口拉大拉小分辨率跟着变。录像只能整张缩放。复制、打印、声音各有通道。
6. 局限：和 Windows 绑得很深。被连的必须是 Windows（家庭版不行）；只懂 Windows 的画法，整屏在变的游戏、电影说不过来，Windows 8 以后图片和视频交给视频编码。视频流远程只认像素，反倒哪个系统都能连，还拼帧率、能打游戏。
7. 收尾：录像看到的是结果；RDP 知道每一笔怎么画，所以能照着你的屏幕重新画一遍。

**不讲。** 安全与漏洞（BlueKeep 等）、NLA/CredSSP 认证细节、RemoteApp、多显示器、授权与 CAL、Citrix ICA 的技术细节、连接序列的十个阶段。

**名词预算。** 旁白里主动教的只有：RDP、视频（录像的办法）、指令、通道；「缓存」不起名，说成「存到你这边」。端口、T.120、H.264、GDI、分辨率数值只上画面。

## 取舍与未解决的问题

- **经典指令与今天的 Windows。** 规范样例的字节数来自 MS-RDPEGDI（经典绘图指令）。Windows 8 之后的服务器何时仍发这些指令，规范没写；文案把它说成「RDP 的做法」并在画面标「经典绘图指令」，新管线只讲有出处的部分（填色、搬移、缓存、H.264 混合、4:4:4）。
- **对比口径。** H.264 字节数是本机实验（`research/lab/02`），与规范样例不是同一块屏幕；旁白只说同类变化的量级，不说倍数。
- **「主流视频流远程」的名单。** 有一手出处的是 Parsec（官方博客）与 Sunshine + Moonlight（README）。国内常见的远程软件没有读到技术原文，不点名。

常驻元素按系列约定：底部字幕带上的秒尺、左上剩余秒数、右上角仪表——本片的仪表是「这一步 RDP / 录像各传多少字节」。字体只用仓库自带的 Inter、Noto Sans SC、JetBrains Mono（Segoe UI 不随仓库发布）；不用 Windows 徽标。
