## 连贯阅读

先通读问题、解释与章节推进，再到逐句表定位意见。下文按源稿顺序连接字幕，保留原文字与标点；不含静默 cue。口播读法与停顿另按配音规则核对。

### open · 无章节卡

在 Windows 里开一台虚拟机，跑 Linux。 跑 Java 程序的 JVM，也叫虚拟机。 它们是一回事吗？ Linux 这样的操作系统，要直接管处理器、内存和磁盘。 一台电脑只有一套硬件，两套系统怎么都管？ 办法是用软件造一台虚拟电脑，给 Linux 用。 这里的 Linux，叫*客体系统*； 这台虚拟的电脑，叫*系统虚拟机*。

### type1 · 无章节卡

那真实的硬件谁来分？一层叫*虚拟机监控器*的软件。 客体以为自己直接管着硬件，其实监控器在背后接手。 按监控器放在哪一层，分成两类。先看开源的 Xen。 开机后，Xen 直接跑在*裸金属*上： 就是没装操作系统、光秃秃的硬件。 Xen 随后启动一套负责管理的 Linux， 连它也是 Xen 上的一台虚拟机。 监控器直接装在裸金属上，这叫*第一类*，也叫裸金属型。

### type2 · 无章节卡

回到开头那台电脑，开机先启动 Windows。 VirtualBox 像普通软件一样装在上面。 这套 Windows，叫*宿主系统*。 比如客体往自己的磁盘写一份数据， VirtualBox 把它写进 Windows 上的一个文件。 客体看到一块盘，Windows 只看到一个文件。 监控器借宿主系统干活，这叫*第二类*，也叫宿主型。

### process · 无章节卡

那 JVM 也要启动一整套操作系统吗？ 不用。JVM 只是操作系统上的一个程序， 随 Java 程序启动，也随它结束。 Java 源码会编译成*字节码*： 写给 JVM 的指令，不针对哪款真实处理器。 比如程序调用加法，传入二和三。 头两条指令，把二和三依次叠进一个栈。 加法指令取出这两个数，把五放回去。 最后一条把五返回，程序打印出五。 同一份字节码，能交给不同平台上兼容的 JVM 去跑。 只给一个程序提供执行环境的，叫*进程虚拟机*。

### compare · 无章节卡

两者不是一回事，要看谁在用这台虚拟机。 操作系统用的，是系统虚拟机； 监控器在裸金属上是第一类，在宿主系统上是第二类。 VMware 的 ESX 是第一类，Workstation 是第二类。 单个程序用的，是进程虚拟机。 Docker 容器两样都不是：它不造虚拟电脑， 容器里就是程序本身，只是被隔开，共用宿主系统的内核。 这些还能套着用：刚才的 Linux 客体里，照样能跑 JVM。
