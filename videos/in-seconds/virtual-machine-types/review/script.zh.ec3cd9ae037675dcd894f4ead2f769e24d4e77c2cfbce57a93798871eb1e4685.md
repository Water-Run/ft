## 连贯阅读

先通读问题、解释与章节推进，再到逐句表定位意见。下文按源稿顺序连接字幕，保留原文字与标点；不含静默 cue。口播读法与停顿另按配音规则核对。

### open · 无章节卡

Windows 里开个 Linux，叫虚拟机。 跑 Java 程序的 JVM，也叫虚拟机。 它们是一回事吗？ Linux 这样的操作系统，要直接管处理器、内存和磁盘。 一台电脑只有一套硬件，两套系统怎么都管？ 办法是用软件造一台虚拟的电脑，让 Linux 在上面运行。 在虚拟电脑上运行的系统，叫*客体系统*。 这台虚拟的电脑，就叫*系统虚拟机*。

### type1 · 无章节卡

真实的硬件，由一层*虚拟机监控器*来分配。 客体以为自己直接管着硬件，其实监控器在背后接手。 按监控器放在哪一层，分成两类。先看 Xen。 开机后，Xen 直接在硬件上启动， 把处理器和内存分给各台虚拟机。 Xen 随后启动一套负责管理的 Linux， 连它也是 Xen 上的一台虚拟机。 监控器直接在硬件上，这叫*第一类*，也叫裸机型。

### type2 · 无章节卡

回到开头那台电脑，开机先启动 Windows。 VirtualBox 像普通软件一样装在上面。 这套 Windows，叫*宿主系统*。 比如客体往自己的磁盘写一份数据， VirtualBox 把它写进 Windows 上的一个文件。 客体看到一块盘，Windows 只看到一个文件。 监控器装在宿主系统上，借它干活， 这叫*第二类*，也叫宿主型。

### process · 无章节卡

那 JVM 也要启动一整套操作系统吗？ 不用。JVM 只是操作系统上的一个程序， 随 Java 程序启动，也随它结束。 Java 源码会编译成*字节码*： 写给 JVM 的指令，不针对哪款真实处理器。 比如程序调用加法方法，传入二和三。 头两条指令，把二和三依次叠进一个栈。 加法指令取出这两个数，把五放回去。 最后一条把五返回，程序把它打印出来。 这些指令，JVM 可以逐条照做，也可以先译成处理器指令。 同一份字节码，能交给不同平台上兼容的 JVM 去跑。 只给一个程序提供执行环境的，叫*进程虚拟机*。

### compare · 无章节卡

所以两者不是一回事： 系统虚拟机给操作系统一整台电脑， 进程虚拟机给一个程序一套执行环境。 两者还能套着用：刚才的 Linux 客体里，照样能跑 JVM。 分辨时先问：谁在用这台虚拟机？ 是程序，就是进程虚拟机。 是操作系统，就是系统虚拟机； 再看监控器在硬件上还是宿主上，分出第一类和第二类。
