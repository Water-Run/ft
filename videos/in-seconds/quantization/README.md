### 受众与核心问题

- **受众**：系列缺省的广大观众。用过或听说过大模型，知道模型有「大小」，但不假设会看参数表、不知道什么是精度和位宽。按系列约定，低认知负担，不假设观众懂数据类型。
- **核心问题**：一个模型要变小，办法是什么，又会丢掉什么？标题里的「方式」与「代价」是同一个问题的两半，每一场都要回答它（F01）。
- **一句话答案（草案，待取证后定稿，不是已确认的事实）**：量化是把模型里每个数用更少的位来存，换得体积变小；代价是每个数都变粗糙了，粗到一定程度，模型的回答就会变差。

### 解释路径（草案，以文案为准）

按系列结构骨架：现象或问题 → 片名卡 → 它是什么 → 它怎么工作 → 边界或比较 → 一句结论 → 片尾。

1. **现象或问题**：同一个模型，有人说要几十 GB，有人在普通电脑上就跑起来了。差在哪里？
2. **它是什么**：模型的体积主要来自一大堆数（参数）；每个数占几位，决定了总体积。量化就是少用几位去存每个数。
3. **它怎么工作**（重头，必须用能算出来的真实数据，不编数字）：从一小组真实数出发，把它们对到更少的档位上，让观众亲眼看到「粗了」；再换算成整个模型的体积。
4. **边界或比较**：位数越少越小，也越粗；同一个模型在不同位数下的体积与表现的对照；只说有出处的、有实验的结论。
5. **结论**：量化用精度换体积，换得多、丢得多；选哪一档是在体积和表现之间做取舍。

## 待取证

以下是待查的问题，**不是已确认的事实**。开工时逐条取得一手来源或亲手实验，才能进 `research/FACTS.md`，不凭记忆写进文案。

1. 量化的定义；常见的位宽（例如 16 位、8 位、4 位）各占几个字节；「参数量 × 每个数的位数 ÷ 8 = 体积」的换算在真实模型的发布信息里是否对得上（含缩放系数等额外开销）。
2. 把一组数对到更少的档位上，最简单、最有代表性的做法是什么（供画面用的小例子）；这一步的误差怎么量。
3. 同一个模型在不同位宽下的体积与表现：哪些模型有官方或可复现的数据？表现的指标用什么（困惑度、基准分、实际回答）？降幅随位宽怎么变，有没有「降到某一位突然变差」的拐点？
4. 体积变小之后，运行速度与显存占用是否一定改善；哪些条件下不会。
5. 可做的实验：在小模型上实际做 8 位与 4 位量化，量出体积、量化误差与表现的变化，回显与脚本放进 `research/lab/`，画面数字由 `tools/gen_data.py` 生成。不使用真实账号、内网或私有数据。
