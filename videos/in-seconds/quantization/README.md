### 受众与核心问题

- **受众**：听说过 AI 大模型，没接触过参数、位、精度这些词的人。按「观众不知道什么是位」来写。
- **核心问题**：一个模型是怎么变小的，变小时丢了什么？
- **一句话答案**：模型文件里全是数；量化让每个数少占几位，办法是把它换成少数几个值里最近的一个。数因此变粗，压到 4 位分数还看不出差别，再往下就掉了。

### 逐场

贯穿的东西是开头那两个文件：55 GB 的原版显卡装不下，17 GB 的版本装得下、分数几乎一样。每一场都在解释这 38 GB 的差别，结尾回到那块显卡。

| 场 | 句号 | 回答什么 | 依据（FACTS） | 画面上要出现的事实 |
|---|---|---|---|---|
| open 引子 | o1–o4 | 同一个模型有大有小，小的也能用；这个办法叫量化 | A3、E8、E1、E3 | 模型名 Qwen3.8 27B；55 GB、17 GB、显卡 24 GB；89.9%、90.4%；o4 说完出片名卡（片名只上画面） |

### 取舍

| 内容 | 处理 |
|---|---|
| 模型名 | Qwen3.8 27B 只上画面，旁白说「有个 AI 模型」「开头那个模型」。型号念出来对入门观众是一串听不懂的音 |
| 新名词 | 旁白主动教的只有「量化」和「位」。「位」用「16 个 0 或 1」带出来 |
| 机制的说法 | 不用尺子、刻度、编号等比方，直接说「先定 16 个值，每个数换成最近的那个，文件里只记换成了第几个」。不讲这 16 个值的间距怎么定（真实文件不是「最大值除以 8」，B7） |
| 档位的叫法 | 「8 位的、4 位的、2 位的、1 位的」，跟评测原文的叫法（D1）。1 位那个文件实际平均约 1.8 位，z2 用「大致」；画面标各自的真实文件名 |
| 机制与成绩用的不是同一个文件 | 讲机制的 32 个数来自 Q4_0，成绩表里 4 位的是 Q4_K_M（17 GB）。同是 4 位档，配方不同；旁白只说「4 位」，画面各标真名，不把 Q4_0 的「不到三成」说成 17 GB 的来历 |
| 分数 | 旁白说成数（九成、八成五、一成），精确值在画面。「4 位比原版多对一题」不进旁白，画面上 90.4% 高于 89.9% 时在旁边标「多对 1 题，属正常波动」（E3、E9） |
| 名词混眼熟 | 旁白只念 BF16、Q8、Q4、NVFP4，放在成绩表之后；FP8、AWQ、GPTQ、MLX 等只铺画面 |
| 速度 | 「NVFP4 是 BF16 的两倍半」删出旁白：另一份测试、另一台机器、混合配方（E7、E10）。要留只上画面并标明条件 |
| 不讲 | 参数是什么意思、训练中的量化、激活与 KV 缓存的量化 |

## 视觉与声音的约束

策划者原话：「紫色, 简洁有力的画面」。按这句话做了一个方向的三张关键帧，`src/design/keyframes.html?f=1|2|3`，等策划者在审片页认可后生效。

- **主对象**是「文件」这根横条。开头两根（55 GB、17 GB）加一条 24 GB 的线；中段钻进横条，看里面 32 个数怎样换成 16 个值；结尾退出来，五根并排，旁边是分数。全片是这一个对象在变，不换页。
- **颜色各有一个意思**：深紫底 `#1B0E3F`；紫 `#7C3AED` 是体积（存下来的位）；白 `#FFFFFF` 是分数与正文；淡紫 `#CFC2FF` 是说明小字，暗紫 `#3C2785` 是装不下的、被丢掉的部分；黄 `#FFD23F` 只给界线（24 GB、瞎蒙 25%）和出问题的地方（四个数变成一个、1 位的分数）。
- 常驻元素按系列约定：字幕带与秒尺、左上剩余秒数；右上仪表显示「当前文件多大 / 每个数占几位」。
- 音色：策划者选定「精英青年 beta」（MiniMax `speech-2.8-hd`，音色 `male-qn-jingying-jingpin`，试听时 1.25 倍速），已写进 `project.json` 的 `tts`。
- 配乐：策划者选定 B「刻度」。小样在 `tools/music_sketch.py` 的 `direction_b()`：A 小调五声，两台马林巴反复同一短句，一个 12 步、一个 16 步，错开又对齐，木质的刻度声贯穿。正式配乐 `tools/music.py` 由制作方按这条小样写满 120 秒。

## 交接

写给接手的制作方。
先读 [制作周期](../../../docs/process.md) 与 `node kit/tools/lessons.js show --stage <阶段>`，再按下面的顺序做。

1. **先拿到文案的确认。** 音色和配乐已选定。策划者答复里没有提文案和视觉，`approval.json` 仍是 `pending`。开工第一句先问策划者「第二稿文案是否通过、紫色方向是否认可」，把原话记进 `review/NOTES.md`「明确确认」并同步 `approval.json`；没有这句话不配音，不代填。
2. **按实测排定点。** `script.js` 里各场的 `at` 是按每秒 5.2 字估的草稿。选定音色后逐句实测，重排 `at`，留出片名卡（o4 之后约 1.5 秒）和每场结尾的停顿。选定的「精英青年 beta」是五个里最快的：1.25 倍速实测每秒 6.29 字，全稿约 72 秒，旁白可用约 96 秒，会多出 20 秒出头。这些时间给片名卡、how 与 test 两场里动画做完之后的停留，以及每场结尾；不要留成画面不动的空白（`check.still_seconds` 为 2.5）。要是觉得太松，降语速或加内容都得先问策划者。换别的音色放不下时删句，不压停顿；可删的顺序：先把 b3 并进 b4，再删 h2 的后半句。z1 里的 NVFP4 不能删，策划者要求提到。
3. **`src/` 里除 `script.js`、`data.js`、`design/keyframes.html` 之外都是起点的占位**（场景、`style.css`、`cover.html`、`tools/music.py`），按关键帧重做。`project.json` 的 `check.style.palette` 已换成上面的紫色。
4. **数字只从 `src/js/data.js` 取**（`tools/gen_data.py` 由 `research/lab/` 生成）。画面上的每个数、每个位串都要算得出来：16 位的位串由数值算（关键帧里有算法），4 位的位串就是 `codes` 的二进制。不手写、不编。
5. **每句旁白对应一个画面动作**，逐场的「画面上要出现的事实」一项都不能少。t4 一句里有两行（8 位、4 位），分别跟着词出现。

容易出错的地方：

- 「量化」的「量」读 liàng；BF16、Q8、Q4、NVFP4 的读法在 `script.js` 的 `SAY` 表，合成后要听一遍（或看识别结果）确认字母没被吞。
- 关键帧第 2 张里，最小的那个数（−0.024292）落在第 0 个值的左侧之外，这是真实情况（B7），照画，不要把它挪进去。
- 线不要穿过文字：瞎蒙线右侧要给 1 位的分数留出位置。
- 片尾名单取自 `project.json` 的 `credits`，不配旁白；接手的模型把自己的准确型号和分工加进去。

未解决、留给策划者：模型名要不要念出来；速度那一条要不要上画面；三条配乐小样是否沿用。
