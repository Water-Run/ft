# RDP：Windows 远程的优雅实现

一部约 360 秒的独立科普片，中英两版。讲 RDP 怎么把一台远程 Windows 的桌面送到你屏幕上：它复用了哪套协议骨架、一次连接里依次发生什么、虚拟通道与图形编码怎么省带宽，以及它和 VNC、SSH 各自的分工。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`。

## 开工反馈应用

反馈版本：2026-10-20.1。本片逐项记录在 `review/lessons.json`；规则来自仓库 `docs/lessons.json`。配音前须填写适用性、具体计划和文案 / 分镜定位；交付前补实际主成片的时间、哈希和验证结论。相关复盘：`docs/log/feedback.md` 的 P0–P38（Lean 4 与 OpenClaw v2 为叙事反面；MyISAM、PostgreSQL、2FA 为正面），`docs/log/reviews/2026-10-09.md`。

目标观众已有的知识：用过远程桌面、TeamViewer 或向日葵这类工具，知道「远程控制另一台电脑」是怎么回事；知道有 3389 端口、知道 SSH 是命令行连过去。不了解协议分层、不知道 RDP 与 VNC 有什么不同、没听说过 TPKT、MCS、CredSSP。

看完应能回答的一个核心问题：RDP 凭什么能把一台远程 Windows 的桌面送到你屏幕上还能操作——答案分三层：它复用了 ITU-T T.120 会议协议那套成熟骨架（X.224 建连接、MCS 建通道、T.128 交换控制信息），往里塞自己的一套图形与输入语义；连接建立后由能力集决定双方能做什么，靠虚拟通道把剪贴板、磁盘、打印、音频接过来；代价是它把「服务器是谁」这件事交给了 TLS 与 CredSSP，而不是 RDP 自己。

逐章怎样推进问题、最后回答什么：先说它要解决的是「看见并操作另一台机器的桌面」而不是传文件 → 拆协议分层，说明它站在 TCP 之上却不是自己发明的协议栈，而是 X.224 + MCS + GCC 的组合 → 沿着一次连接走完十个阶段，标出「什么时候开始传键鼠、什么时候开始传画面」这条分界 → 展开能力面：静态与动态虚拟通道、批量压缩与 RLE、RemoteFX 图形管线、UDP 传输与前向纠错，并讲清安全层为什么必须靠 TLS/CredSSP → 收在边界上：与 VNC（RFB 送帧缓冲矩形）、SSH（送字节流与通道）的分工，以及各自适用的场合。

本片决定不讲的材料及理由：各 RDP 版本对应的 Windows 版本与发布年份（没有一手来源，FACTS 里标了待核实）；Citrix ICA 与 T.120 的历史沿革（同上，宁可不讲也不做历史故事）；压缩比、码率、延迟等具体数字（本机没有可复现的实测环境）；许可（licensing）流程的细节（不影响理解主线）；打印与智能卡的报文格式（虚拟通道的机制讲清即可）；MS-RDPBCGR 的 PDU 字段表（画面上给分层图，不给字段表）。

## 内容

| 场景 | 起点 | 内容 |
|---|---|---|
| open | 0:00 | 远端桌面在你屏幕上出现：键鼠怎么回去、画面怎么回来 → 本片问题 → 五章路线 |
| why | 0:12 | 它要解决的不是传文件，是让另一台机器的桌面「可见且可操作」；RDP 还要让两端组件能通信 |
| layers | 0:42 | TCP 之上为什么还有四层：TPKT（4 字节头）→ X.224（Class 0 连接请求/确认）→ MCS（建域、挂用户、加通道）→ GCC（交换核心/安全/网络数据）→ RDP 自己的图形与输入语义 |
| session | 1:54 | 一次连接的十个阶段走一遍：连接发起 → 基本设置交换 → 通道连接 → 安全开始 → 安全设置 → 网络探测 → 许可 → 多路传输引导 → 能力交换 → 连接收尾；标出「确认能力后客户端才能发输入、服务器收到字体表后才能发画面」这条分界 |

| boundary | 4:54 | VNC 的 RFB 送帧缓冲矩形、SSH 送字节流与通道；各自的适用条件；本片结论 |
| outro | 5:52.5 | 片尾名单与开源地址（无旁白，约 7.5 秒） |

方向（待第 4 步取样后定稿，写进 `src/design/STYLE.md`）：本片的讲解对象是「一份协议规范加一台远端 Windows」，所以视觉语汇取自这两处自己的材料——

- 规范侧：Microsoft Learn 上 Open Specifications 文档的版式（标题层级、带编号的小节标签、等宽字体的字段名、线框式的结构图）。这些是 Microsoft 自己的文档部件，用它们做画面等于「让画面长得像那份规范」。
- 实物侧：Windows 远程桌面客户端的窗口与图标，作为「远端桌面真的在你屏幕上」的物证。
- 图形约定：同一个图形只表一件事——嵌套框 = 协议层（外层 TCP、内层依次 X.224 / MCS）；并排的扁盒 = 阶段或码；分叉的支线 = 虚拟通道；带小箭头的一条 = 一次连接的时间轴。
- 转场：不用整屏擦除。换场由「同一根连接的时间轴往前推一格」或「套娃框再加一层」完成，表达的是「继续往里走」。
