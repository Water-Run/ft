# 05 动态与声音

你看不到画面、听不到声音，所以这里把「好的动态和声音」写成可以照着做、可以用工具查的规则。

## 1. 镜头

镜头是本片的骨架。`const cam = makeCamera(world, 1920, 968)` 之后：

| 写法 | 作用 |
|---|---|
| `cam.cut(t, { x, y, z })` | 在 t 时刻把镜头直接放到某处（场景开头定初始位置） |
| `cam.to(t, { x, y, z }, { d, ease, sfx })` | 从 t 时刻起用 d 秒移到某处。`x, y` 是镜头中心在 world 里的坐标，`z` 是放大倍数。默认 `d = 1.4`，缓动 `power3.inOut`，并自动登记一声 `whoosh`（`sfx: false` 关掉） |
| `cam.frame(t, 元素, { pad, d, maxZ })` | 把镜头对准某个元素，四周留白比例 `pad`（默认 0.4） |

镜头在 `z` 倍放大、中心 `(x, y)` 时，能看到的 world 范围是：横向 `x ± 960 / z`，纵向 `y ± 484 / z`。推近之前先算一下要看的东西是否在这个范围里，再用 `node tools/look.js` 核对。

规则：

1. **每个场景至少 3 次明确的镜头运动**（站点之间的平移、推近看细节、拉回全景），并且在没有明确运动的时段保持**缓慢漂移**：例如用 `cam.to(t, { z: 1.05 }, { d: 5, ease: 'none', sfx: false })` 让画面在 5 秒里极慢地推近 5%。这样任何时刻画面都在动。
2. **推近的倍数**：看细节 1.3–1.6；不要超过 2（字会糊，周围也全被切掉）。站点之间平移用 0.8–1.2 秒，推近用 0.9–1.3 秒，拉回用 0.6–0.8 秒。
3. **镜头先到，动作后到**：要强调的东西出现之前 0.2–0.4 秒，镜头已经开始朝它移动。
4. **镜头运动与旁白对齐**：起点写成 `T(句号, 词) - 0.3` 这样的形式。
5. 快速的大幅移动（跨站点）配 `whoosh`；缓慢漂移不配音效。
6. 推近时旁边的次要文字被画面边缘切掉是正常的；但这一刻旁白讲的主体必须完整在画面里（`scan.js` 的 EXPECT 项只认完整可见的文字）。
7. 推近之前把会伸进字幕条的大字先收走（见范例里 `claim` 的处理）。

## 2. 元素的动作

可用的动作（`src/js/engine.js`、`src/js/util.js`）：

| 动作 | 写法 | 适合 |
|---|---|---|
| 刷出 | `wipe(el, t, { dir, d })`，`dir` 为起刷的一侧 `'l' 'r' 't' 'b'` | 色块、终端、纸张、标题、线条。本片的主力入场方式 |
| 刷走 | `wipeOut(el, t, { dir, d })` | 上述元素的退场 |
| 砸入 | `slam(el, t, { from, d })` | 大数字、大字、标签。配 `thud` 或 `pop` |
| 滑入 | `slide(el, t, { x, y, d })`，`x, y` 为起始偏移 | 新增的一行代码、从画外进来的物件（软盘） |
| 滑出 | `exit(el, t, { x, y, d })` | 物件离开 |
| 打字 | `typeText(span, html, t, 每秒字数, { cursorUntil })` | 敲入命令、写代码。自带按键声 |
| 立即出现 / 消失 | `appear(el, t)`、`vanish(el, t)` | 终端里新打出的一行输出（终端的输出就是瞬间出现的） |
| 数字滚动 | `countTo(el, 起, 止, t, 秒)` | 3164、4.45 这类数字 |
| 换内容 / 换类名 | `keyed(el).at(t, { html, cls })`、`classAt(el, 类, 起, 止)`、`swapAt(el, 旧, 新, t)` | 文件名从 `.txt` 变 `.bat`；某一行在一段时间内高亮 |
| 补间任意属性 | `to(el, t, { … })`、`fromTo(el, t, { … }, { … })`、`set(el, t, { … })` | 位置、宽度、缩放等 |
| 每帧计算 | `F((t) => { … })` | 进度条、任何「由 t 直接算出」的东西。函数里不能累加状态 |

规则：

1. **入场方式要有区分**：同一屏里的几个元素用不同的方式或不同的方向入场，并错开 0.08–0.2 秒。全片不要只用一种。
2. **重点用揭示动作**：每句旁白的关键词对应一个明确的动作，发生在那个词被读到的时刻（`T(句号, 词)`）。
3. **终端的行为要像终端**：输出是整行瞬间出现（`appear`），只有「人敲的命令」才用打字机。
4. **机制图一步一拍**：读一行 → 光束伸出 → 屏幕出现回显或输出，每一步之间 0.15–0.3 秒，各有一声。
5. **元素在时刻 0 的状态要正确**：一开始不该出现的元素，用 `vanish(el, 0)` 或让它的入场动作（`wipe` / `slam` / `slide` / `appear` 都自带「入场前不可见」）来保证。`scan.js` 的 NONDET 项会查「跳到任意时刻」与「顺着播到这里」是否一致。
6. 不要用无限循环的装饰动画。光标闪烁由 `typeText` 自带，或用 `F((t) => el.style.opacity = Math.floor(t * 2) % 2 ? 1 : 0)`。

## 3. 节奏

- 开场前 0.5 秒内画面就要有东西在动。
- 章节卡是全片最响、最快的时刻；它之后的第一句是该章的「建立」，镜头给全景。
- 演示段（机制图）节拍均匀；结论句（b4「替人敲命令」、c5「执行一条，读一条」、d6「默认关闭」、e9「不会移除」）用大字砸入，随后停留 0.6 秒以上不加新东西。
- s5 一句一个证据：每句开头换站点或换主体，不要在同一个静态版面上停两句以上。

## 4. 音效

登记方式：`sfx(名称, 时刻, { g, p })`。`g` 是相对音量（默认 1），`p` 是声像（−1 左 … 1 右，默认 0）。混音时由 `tools/mix.py` 程序合成。

| 名称 | 听感 | 用在哪 |
|---|---|---|
| `key` | 按键 | 打字（`typeText` 自动登记，不用手写） |
| `tick` | 短促的滴答 | 读到下一行、刻度出现、小标签出现 |
| `blip` | 上行的短音 | 终端打出一行普通输出 |
| `pop` | 圆润的弹出 | 标签贴上、新的一行代码被加进文件 |
| `whoosh` | 气流 | 镜头跨站点移动（`cam.to` 自动登记）、大色块刷过 |
| `thud` | 低沉的撞击 | 大数字、大字、章节号砸入；终端或纸张落位 |
| `chime` | 清亮的钟音 | 一段演示得出结果的那一刻（每个场景最多 1–2 次） |
| `error` | 低沉的蜂鸣 | 出错、与预期不符：文件打不开（c3）、得到的是 1 不是 2（d3） |
| `riser` | 上升的噪声（1.2 秒） | 大转折之前的铺垫：o4 之前、片名之前。在转折点之前 1.2 秒登记 |
| `beep` | 机箱扬声器式的方波短鸣 | **只用于「当年」的画面**：早期终端打出一行、`A>` 提示符出现 |
| `drive` | 软驱寻道的步进声 | **只用于「当年」的画面**：DOS 重新打开文件、软盘滑入 |

规则（`node tools/check.js` 会查带 ★ 的）：

1. ★ 每个看得见的动作一个音效。全片不含打字声至少 56 个事件（平均每 3.5 秒一个），每个场景至少「场景秒数 ÷ 5」个。
2. ★ 至少用 6 种不同的音效；只用上表里的名称。
3. ★ 任意 8 秒内至少有一个音效。
4. **声音要分新旧**：「当年」的画面（s1、s3 前半、s2 的源码站点）用 `beep`、`drive`；「今天」的画面用 `blip`、`tick`。这是声音上的复古对照。
5. 同一时刻不要叠两个以上的音效；相邻音效至少错开 0.06 秒。
6. 声像跟着位置走：发生在画面左侧的动作 `p: -0.4`，右侧 `p: 0.4`。
7. 连续的小动作（五个命令依次砸入）用同一种音效，音量递减或保持，不要每个都用 `thud`。
8. 音量：`thud`、`chime`、`error` 这类重音用默认值；跟在重音后面 0.3 秒内的轻音设 `g: 0.5`。

## 5. 配乐与混音

配乐是程序合成的，三种可选（`project.json` 的 `audio.music`，或 `node tools/audio.js music=…` 临时指定）：

| 值 | 内容 |
|---|---|
| `pulse`（正片默认） | 铺底和声 + 八分音符的拨弦琶音，章节开头几秒自动推高 |
| `chip` | 铺底和声 + 限带方波琶音与三角波低音，早期个人电脑式的音色 |
| `pad` | 只有铺底和声 |

旁白出现时配乐与音效自动压低，片头片尾自动淡入淡出，都由 `mix.py` 处理，不用你管。

正片用 `pulse`。另出一条 `chip` 的试听片 `out/试听-复古配乐.mp4`（做法见 `AGENTS.md` 第 5 节第 10 步），由用户听过之后决定用哪个。**不要自己调 `music_db`、`duck_db`、`sfx_db`**：你听不到，调了也无从判断。

`node tools/audio.js` 会打印每种音效的数量和各场景的音效数，用它核对上面的规则。
