# 06 验收

验收分三层：自动闸门（工具查）、三项审查（你对照文字输出逐项查）、交付说明（写给用户）。

## 1. 自动闸门

```
node tools/check.js            制作期
node tools/check.js --final    交付前
```

输出逐项「✓ 通过 / ✗ 不通过」和明细，最后一行是结论。只有「全部通过」才算过。**不允许通过修改 `tools/` 下的脚本、放宽阈值、删改 `brief/expect.json` 来通过。**

### 1.1 各项的含义与处理办法

| 项 | 查什么 | 不通过时怎么办 |
|---|---|---|
| 源码规则 | 场景、`config.js`、`style.css`、`cover.html` 里有没有禁用的写法：CSS 动画与过渡、定时器、时间线回调、随机数、阴影、渐变、模糊、圆角、调色板以外的颜色、系统字体、emoji | 按提示的文件与行号改。颜色用 `var(--…)`；动画用引擎的补间；需要「每帧算」用 `F()` |
| 场景齐全 | 七个场景都已实现并在 `index.html` 里加载，没有残留的 TODO，每个场景都用了镜头，`chrome()` 已实现 | 补上 |
| 时长与节奏 | 总长 175–200 秒；每句字幕不超过一行；单句不超过 6 秒 | 一般不会出问题；改了 `gap` 之后超出范围就改回去 |
| 全片扫描 | 即 `node tools/scan.js`，见 1.2 | 见 1.2 |
| 音效覆盖 | 事件总数、每场景数量、种类数、最长无声间隔、名称是否合法 | 给缺音效的动作补登记，见 `05-motion-sound.md` 第 4 节 |
| 交付物（`--final`） | 成片、仅旁白版、试听片、字幕、封面、`DELIVERY.md` 是否齐全；成片时长、规格、响度、静止段；源码是否在渲染之后又改过 | 缺什么补什么；源码改过就重新渲染和封装 |

### 1.2 全片扫描的各类错误

`scan.js` 每 0.5 秒取一帧，用文字规则检查。错误码在方括号里。

| 错误码 | 含义 | 处理办法 |
|---|---|---|
| `EXPECT` | 某句旁白说完的那一刻，`brief/expect.json` 要求的文字不在画面上（或不完整：被画面边缘切掉、伸进字幕条、不透明度不到一半都不算数） | 用 `node tools/look.js --cue <句号>` 看那一刻画面上实际有什么。常见原因：元素出现得太晚（把入场时刻提前到这句结束之前）；镜头推得太近把它切掉了（调整镜头中心或倍数）；文字写得与要求不一致（照 `FACTS.md` 改）；一句完整的文字被拆进了多个块级元素（放进同一个元素） |
| `OVERLAP` | 两段文字的范围重叠超过 20%，持续 1.5 秒以上 | 挪开其中一个，或让旧的先退场。确属有意压盖（章节卡、角标）才加 `data-overlap-ok` |
| `SMALL` | 文字的实际大小（算上镜头缩放）小于 26px，持续 1.5 秒以上 | 放大字号，或别把镜头拉得那么远 |
| `CONTRAST` | 文字与它底下的颜色对比度不够（小字要 4.5:1，56px 以上的大字要 3:1） | 多半是琥珀色文字放在了纸色底上，或 `--dim` 放在了墨色底上。按 `03-visual.md` 第 2 节的搭配表改 |
| `EMPTY` | 画面上 1 秒以上没有任何内容 | 把下一个元素的入场提前，或让上一个元素晚点走 |
| `STILL` | 画面 3 秒以上没有任何变化（不算字幕和进度条） | 加镜头漂移或元素动作，见 `05-motion-sound.md` 第 1 节规则 1 |
| `NONDET` | 同一时刻，「顺着播到这里」和「直接跳到这里」的画面不一样 | 画面必须只由 t 决定。检查：有没有元素缺少「入场前不可见」的初始状态；有没有在 `F()` 里累加变量；同一个属性有没有被两个补间在重叠的时间段里同时改 |
| `PAGE` | 页面脚本报错，或 `T()` 找不到句号 / 词 | 报错信息里有原因。`word not in cue`：这个词不在该句的合成文本里，用 `node tools/timeline.js <句号>` 查可用的词 |

提示（`!` 开头，不影响通过，但要逐条看一眼）：

| 提示码 | 含义 |
|---|---|
| `CUT` | 文字被画面边缘切掉 1.5 秒以上。推近时边缘的次要文字被切属正常；如果被切的是这一刻的主体，要改 |
| `CAPZONE` | 文字伸到了字幕条后面。同上 |
| `DENSE` | 同时可见的文字超过 16 段。考虑分步出现 |

### 1.3 低清预演

`node tools/preview.js` 快速渲染一遍低清版本，从像素层面找静止段（比 `scan.js` 的 `STILL` 更接近观众的实际感受：元素在变但变化太小时，这里会查出来）。超过 3 秒的静止段必须消除；2.5–3 秒的建议也处理。

## 2. 写场景时的自查循环

每写完一小段就查，不要攒到最后：

```
node tools/look.js --cue a3 a4            看这两句说完时的画面（文字描述 + 存图）
node tools/look.js 31.5 32.0 32.5         看某几个时刻（查入场动作的中间状态）
node tools/scan.js --from 20.6 --to 52.8  扫这个场景
```

`look.js` 的输出每行是一个可见元素：种类、位置与大小（x y w h，已含镜头变换）、字号、颜色、文字、元素的类名。读法见 `07-tools.md` 第 2 节。**以它为准判断版面**，例如：两个元素的 x 范围是否错开、主体是否在 `x 96…1824`、`y 56…928` 之内、最大的字是否是最小的字的 4 倍以上。

## 3. 成片后的三项审查

渲染、封装之后做。每项的结论写进 `DELIVERY.md`，事实审查的结论另写进 `research/FACTS.md` 的「复核」一节。发现问题就改、重渲、重查，直到这一轮查不出问题。

### 3.1 事实

对 `research/FACTS.md` 里的每一句（o1 … f3）：

1. 运行 `node tools/look.js --cue <句号>`，把画面上出现的每一段文字与 `FACTS.md` 的对应行逐字比对：终端回显、代码、数字、年份、版本号、引文、出处标注。
2. 检查画面上有没有 `FACTS.md` 里没有的事实性内容。有就删掉。
3. 早期 DOS 的终端画面是否都带「示意」。
4. 有没有出现本机路径、主机名、用户名（`D:\batlab` 除外）。

在「复核」一节列一张表：句号、核对了哪些文字、结果（一致 / 已更正为……）。

### 3.2 读音与节奏

```
node tools/asr.js       逐句并排打印「合成文本」与语音识别「听到」的文本
node tools/stats.js     语速与停顿
```

- 读音：识别结果里的同音字、英文大小写与拼写偏差属于识别误差，不算错。要看的是：有没有漏词、有没有把英文单词逐字母拼读、数字读法是否正确、「行」是否读成 háng（识别结果里是「行」或「航」都对）。读错了就改该句的 `tts` 字段，重新合成。
- 节奏：没有「过快」「过长」「停顿过短」的句子。

### 3.3 旁白与画面的对应

对每一句：这句话讲的东西，是不是在这句话的时间里出现在画面上、并且是画面的主体？

- `scan.js` 的「逐句」一段给出了每句说完时画面上的文字，通读一遍，确认每句的内容与旁白对应，没有「旁白已经讲下一件事了，画面还停在上一件事」。
- 对关键词的动作抽查：`node tools/look.js --cue c6:0.7` 看 c6 这句进行到 70% 时的画面，确认对应的元素此刻已经出现。每个场景抽 2–3 处。
- 生成两套总览图留给用户审片：`node tools/sheets.js cue`、`node tools/sheets.js every 4`。

## 4. 交付说明 `DELIVERY.md`

写在项目根目录。语体客观克制：陈述做了什么、结果是什么，不写自我评价（「精美」「流畅」「完美」这类词不要出现）。结构如下：

```markdown
# 交付说明

## 交付物
（表格：文件、规格或大小、说明。成片的时长、分辨率、帧率、响度照 finish.js 的输出填）

## 闸门结果
（贴 `node tools/check.js --final` 的完整输出）

## 三项审查
### 事实
（核对了多少句，发现并更正了什么；没有发现问题就写「未发现偏差」）
### 读音与节奏
（asr.js 与 stats.js 的结论；改过哪些句子的读法）
### 旁白与画面对应
（抽查了哪些时刻，结论）

## 需要用户亲自判断的事项
- 声音：配乐与音效由程序合成，制作者无法试听。正片用节拍配乐，另有复古配乐的试听片，由用户比较后决定。
- 画面：（如实写明你能否看图；不能就写：版面与动态只经过文字化检查，未经目视，请用户通看 out/sheets/ 下的总览图与成片）
- （其他你拿不准的地方）

## 取舍
（制作中做过的决定及理由：某句画面简化了什么、某处与分镜建议不同的做法）

## 未做或未通过
（没有就写「无」）

## 复现
（从头到尾重新生成成片的命令序列）
```
