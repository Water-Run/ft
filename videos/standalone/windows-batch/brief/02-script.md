## 3. 脚本的格式

```js
{
  id: 's3', chap: ['03', '逐行读盘'], lead: 1.4, tail: 0.5,   // chap：章节号与标题；lead：章节卡占用的秒数；tail：场景结尾的留白
  cues: [
    ['c5', '今天的 cmd.exe 仍然执行一条、读一条', { tts: '今天的 CMD 点 EXE 仍然执行一条、读一条。' }],
    //  句号   字幕（画面底部显示）               送去合成的文本（与字幕读法不同时才写）；gap：这句之后的停顿秒数，默认 0.3
    ['oT', null, { pause: 2.8 }],                // 无旁白的纯画面停顿
  ],
}
```

- 时间线由 `layoutScript` 从脚本和实测时长算出，不要自己算秒数。
- `T('c5', '读')` 取的是合成文本里「读」这个字被读到的时刻。**词要在合成文本里找**（有 `tts` 字段的句子，合成文本和字幕不同：例如 `cmd.exe` 读作「CMD 点 EXE」，`1993 年` 读作「一九九三年」）。先运行 `node tools/timeline.js <句号>` 看这句有哪些词。找不到词时引擎会在控制台警告，`scan.js` 会把它报成错误。
- 多音字「行」（一行、逐行）在合成文本里被自动换成了同音的「航」；`T('c6', '一行')` 这样写仍然能匹配（引擎会做同样的替换）。

## 4. 能不能改

默认不改。旁白的每句话都对应 `research/FACTS.md` 里的一条依据，措辞是推敲过的。

允许的改动只有两类，改完都要重新合成并回听：

1. **调停顿**：为了让画面动作做得完，可以改某句的 `gap`（0.2–0.9 秒）或场景的 `tail`。总长保持在 175–200 秒。
2. **调读法**：如果 `node tools/asr.js` 显示某个词读错了，改这句的 `tts` 字段（字幕不变）。

不允许：增删句子、改变陈述的内容、改数字、合并或拆分句子、改句号。如果你认为某句话有事实错误，停下来向用户报告，不要自行改写。

改动之后：

```
node tools/tts.js       重新合成改过的句子，更新时间线
node tools/audio.js     重新混音
node tools/asr.js       回听核对
```

画面里凡是用 `T()` 写的时间点会自动跟着新的时间线走。
