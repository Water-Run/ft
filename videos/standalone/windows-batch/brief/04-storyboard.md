# 04 分镜要求

这份文件规定每个场景**必须交代什么**，并给出**建议的做法**。必须交代的内容是硬性的（`brief/expect.json` 会逐句检查）；建议的做法你可以调整，但要符合 `03-visual.md` 与 `05-motion-sound.md`。

动手写代码之前，先把你的细化分镜写成 `brief/storyboard-detail.md`：每句旁白一行，写明画面上有哪些元素（world 坐标）、各自怎么入场、镜头从哪到哪、登记什么音效。先想清楚再写，比边写边改省事得多。

## 1. 通用做法

### 1.1 空间与镜头

每个场景建一个 `world` 容器，所有内容放进去，镜头在 world 上运动（写法见 `src/design/example_scene.js`）。

- world 的坐标系：镜头中心在 `(960, 484)`、`z = 1` 时，world 坐标就是画面坐标。
- 一个场景分成 2–4 个**站点**，每个站点是 world 里一块 1920×968 的区域，承担几句旁白。站点横向或纵向排开（例如第二个站点的原点在 `x = 2100`），镜头在站点之间平移；在站点内部推近看细节。
- 站点之间留出 180px 以上的空隙，避免镜头正对一个站点时露出邻站的边。
- 一个站点里的东西不要一次全出现：随旁白一步一步来。

### 1.2 「文件 → 屏幕」机制图

s1–s4 都用同一种图：左文件、右屏幕、琥珀色标出读到的行、琥珀光束连到屏幕（`03-visual.md` 6.3）。保持左右关系全片一致：**文件永远在左，屏幕永远在右。**

### 1.3 每句旁白的画面

- 这句话讲到的东西，在这句话说完之前必须已经完整出现在画面里（不被切、不在字幕条后面）。
- 关键词被读到的那一刻，对应的元素做出动作（出现、变色、移动）：用 `T(句号, 词)`。
- 上一句的东西如果这句不再需要，就移走或让镜头离开，不要越堆越多。

## 2. 常驻元素与转场

`src/js/config.js` 里 `sceneFade: false`：场景之间是**硬切**，引擎让每个场景的内容只在「本场开始后 0.45 秒」到「下一场开始后 0.45 秒」之间显示。切换的那一刻必须被 `#hud` 里的整屏色块盖住。

### 2.1 章节卡（s1–s5，各 1.4 秒）

设场景起点为 `s.start`：

| 时刻 | 动作 | 音效 |
|---|---|---|
| `s.start` | 一块 1920×968 的**琥珀色块**从左向右刷满内容区（0.35 秒，`wipe` 方向 `l`） | `whoosh` |
| `s.start + 0.30` | 章节号砸入：Grot 900、460px、墨色，左对齐 `x = 96`，可以出血 | `thud` |
| `s.start + 0.42` | 章节标题刷出：`.t-hero`、墨色，在章节号右侧或下方 | `tick` |
| `s.start + 0.45` | （引擎在色块底下换场景） | — |
| `s.start + 1.05` | 色块连同字一起向右收走（0.35 秒，`wipeOut` 方向 `r`），露出新场景 | `whoosh` |
| `s.start + 1.40` | 章节角标在左上角出现 | — |

场景自己的内容从 `c0`（= `s.start + 1.05`）开始入场。上一个场景要在自己的 `s.end` 之前把动作做完，不要求退场（色块会盖住）。

章节卡文字给 `data-overlap-ok`（它盖在场景之上）。

### 2.2 open → s1、s5 → end

- open 结尾是整屏墨色的片名帧，s1 的章节卡直接盖上去。
- s5 → end 没有章节卡：在 `end` 的 `s.start` 用一块**墨色块**从右向左刷满内容区（0.35 秒，`whoosh`）。`end` 场景自己的底色就是整屏墨色（在 world 之下放一个 1920×968 的墨色块），所以色块在 `s.start + 0.5` 之后直接消失即可，观众看到的是画面被墨色吞没后变成片尾。

## 3. 逐场景

下面每个表里，「必须在画面上」一栏就是 `brief/expect.json` 对这一句的要求（这句说完的那一刻，这些文字必须完整可见，大小写不限，空格不限）。时刻以 `node tools/timeline.js` 为准。

### 3.1 `open`（0 – 20.6 秒）：先今天，再拉回 1981

这是全片冲击力最强的地方：前 10 秒是今天的 Windows 11，然后一下子砸出 1981。

| 句 | 必须在画面上 | 建议的做法 |
|---|---|---|
| o1 | `新建文本文档.txt` | 纸色底。一张 `.sheet` 从上方刷出，文件名是 `新建文本文档.txt`（Mono 没有中文字形，样式里已设好回退到黑体），里面是空的，只有第 1 行的行号和闪烁的光标。镜头缓慢推近。片子从第 0.3 秒起就要有东西在动 |
| o2 | `echo hello`、`hello.bat` | 第 1 行打字机打出 `echo hello`（按键声）。读到「扩展名」时文件名换成 `hello.bat`，换的那一下在文件名底下闪一道琥珀色块 |
| o3 | `D:\batlab>echo hello` | 读到「双击」：右侧一块 `.slab.now` 砸入（`.hd`：`Windows 11 · cmd.exe`），依次出现 `D:\batlab>echo hello`（`.in`）和 `hello`。这是真实回显（FACTS o1–o3） |
| o4 | `1981` | 转折。读到「1981」：镜头急速拉远并平移到第二个站点，巨大的像素字 `1981`（`.n-pixel`，墨色，可出血）砸入，配 `thud`。前一个站点完全离开画面 |
| o5 | `1985`、`Windows 1.0` | `1981` 下方一条时间轴（`.rule`）向右画出，到 `1985` 的刻度停住，刻度上方写 `Windows 1.0`、`1985`（Grot）。两个刻度之间的线段是琥珀色，标 `4 年` |
| oT | `古代来的`、`Shell`、`Windows 批处理（.bat）` | 片名帧，按 `kf.html?k=1`：整屏墨色从下往上刷满（`riser` 接 `thud`），「古代来的」「Shell」逐行砸入，琥珀细条画出，副题刷出；右侧像素 `A>` 与闪烁的琥珀光标块。停留期间镜头极慢地推近（保持有运动） |

这一章的关键是让观众看见「替换发生在读入的那一刻」：光束把整块代码**提走**的时候，`%n%` 当场变成 `1`。

| 句 | 必须在画面上 | 建议的做法 |

| d1 | `%n%` | 一张 `.sheet`（`expand6.bat`，六行，照抄 FACTS）和一块 `.slab.now`。第 5 行里的 `%n%` 单独包一个 `span`，读到「百分号」时给它琥珀底 |

## 4. 自查清单（每个场景写完都过一遍）

- [ ] 这一场每句旁白说完时，`expect.json` 要求的文字都完整可见（`node tools/scan.js --from … --to …`）。
- [ ] 终端和文件里的内容与 `research/FACTS.md` 逐字一致；早期 DOS 的屏幕带「示意」。
- [ ] 文件在左，屏幕在右；当年用像素字，今天用等宽字。
- [ ] 镜头至少有 3 次明确的运动，且没有超过 3 秒的静止。
- [ ] 入场动作至少用了三种（`wipe` / `slam` / `slide` / `typeText` / `appear`），没有全用 `show()`。
- [ ] 每个可见动作都登记了音效，种类有区分。
- [ ] 同时可见的文字不超过 16 段；琥珀色同一时刻只标一件事。
