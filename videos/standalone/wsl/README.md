# 从 WSL 1 到 WSL 2，再到「WSL 3」

一部讲 Windows Subsystem for Linux 三个节点的科普片：2016 年的 WSL 1（把 Linux 系统调用翻译成 NT 内核的调用）、2019 年的 WSL 2（虚拟机里的真内核），以及 2026 年 9 月发布的 3.0 版软件包与它带来的 WSL 容器。中文版 5 分 33 秒，英文版 5 分 31 秒，面向有编程基础的观众。

全片由一个实验串起来：同一份 Alpine Linux 根文件系统，用三种方式各运行一次，每次执行 `uname -r`。三个答案依次是 `4.4.0-26100-Microsoft`、`6.18.40.1-microsoft-standard-WSL2`、`6.18.40.1-microsoft-standard-WSL2`。结论是：1 与 2 是架构的代号，3.0 是软件包的版本号；片名里的「WSL 3」因此带引号。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`。

## 视觉系统

题目要求全片浅色，并让风格随各时期微软自己的设计风格变化。本片据此分三个年代，每一章取它所讲那一年的设计语言，同一批部件（终端、方框、条形、章节卡、底栏）各有三套皮肤：

| 年代 | 用在 | 特征 |
|---|---|---|
| Windows 10 的平面风格 | 第一章（2016） | 白底、黑字、纯色磁贴、直角、无投影；标题用极细的大字；入场是由右向左的滑入 |
| Fluent Design | 第二章（2019） | 浅灰底上叠半透明的亚克力面，柔和投影，小圆角；标题用半粗体；入场带纵深 |
| Windows 11 | 开场、第三章起（2021–2026） | Mica 底、白色圆角卡片、细描边；标题用粗体；入场带一点回弹 |

全片不变的约定：

- 终端一律深底浅字，是画面里唯一的深色块，只放真实回显。
- 各年代的蓝只给「此刻正在讲的那一项」；红只表示「没有 / 失败」，绿只表示「有 / 一致」。
- 底栏左侧的三个方格是三次提问的答案：空心是还没问，实心是已经得到。右侧的日期是此刻讲到的那一天。底栏的颜色随年代换（Windows 10 的任务栏是深色的）。
- 第三章的时间轴上，背景与年份的字重随年份由左向右依次换成三个年代的样子。

**与仓库质量标准的关系。** `docs/standards.md` 第 2 节把渐变、圆角、投影列为要避开的做法。本片的第二、四章用到了它们：亚克力的透色、Mica 底上的色团、卡片的圆角与投影，都是那两套设计语言本身的特征，是按题目要求做的有意例外，限定在对应年代的场景里；第一章保持平涂与直角。`project.json` 因此没有打开 `check.style.flat` 与 `no_radius`。模糊滤镜全片没有用（色团是径向渐变）。

**方向的比较。** 比较过两个方向，对照帧可以重做：

- 方向 A（采用）：三个年代各取其设计语言，部件换皮。
- 方向 B：全片一套中性的平面样式（纸色底、墨色字、一个橙色强调色），年代只体现在章节卡的年份上。在页面地址后加 `?dir=b` 即可看到（`src/design/dir-b.css`），例如 `look.js --url "/index.html?lang=zh&dir=b&t=134.4" --size 1920x1080`。

B 的单帧更克制，但三章看不出年代的差别，不符合题目的要求。还考虑过整屏仿当年的桌面，没有做：那是照搬现成产品的界面。顺序上，方向 A 是先做成的，方向 B 的对照帧是之后用同一批场景换样式得到的。

**参考来源与原创。** 参考的是微软公开的三套设计语言的一般特征（Windows 10 的平面磁贴与细体字、Fluent Design 的亚克力与纵深、Windows 11 的 Mica 与圆角），借用的是材质、字重与入场方式这一层；版式、构图、图解与动效都按本片的内容设计，没有复刻任何具体的界面、网页或视频。画面里出现的真实材料（帖子原文、发布页的标题、报道标题、命令回显、源码行）是取证材料，各自带出处；终端窗框是示意性的三种样式，不是某个终端程序的界面重建。字体用仓库自带的 Inter、Noto Sans SC 与 JetBrains Mono，没有使用微软的字体。

## 取证

事实由三路得到，互相印证：

1. **本机实验**（`research/lab/10–19`）。在一台装了 WSL 3.0.2 的 Windows 11 上：记录两套版本号；把同一份 Alpine minirootfs 分别按版本 1、版本 2 导入并逐项对比（内核版本、系统调用、存储、解压计时）；再用 `wslc import` 导入成映像，在容器里跑同样的命令，并查看会话虚拟机的内部。做完后全部清理。
2. **源码**（`research/_src/WSL/`，标签 3.0.1，不入库）。版本号的校验、容器虚拟机所用的内核文件、`wslcsession` 与 `dockerd` 的通信方式都取自源码。
3. **官方原文**（`research/lab/01–03`）。公布日期、设计说明与官方给出的数字取自微软的博文、文档与 GitHub 的发布记录；帖子取原文。

重做一遍：

```bash
python research/lab/01_fetch_sources.py > research/lab/out_01_fetch_sources.txt   # 取回原始网页与接口响应到 research/_src/web/
python research/lab/02_extract.py       > research/lab/out_02_extract.txt         # 摘出引用的原文
python research/lab/03_releases.py      > research/lab/out_03_releases.tsv        # 全部发布记录
git clone --depth 1 --branch 3.0.1 https://github.com/microsoft/WSL research/_src/WSL
# 10–15、19 是 PowerShell 7 脚本，在装有 WSL 3.0.x 的 Windows 11 上按编号执行，回显各存为 out_<编号>_*.txt
python research/lab/18_sanitize.py --user <用户名> --host <主机名>               # 回显入库前的处理
python tools/gen_data.py                                                          # 生成 src/js/data.js
```

实验改动的东西：两个名为 `ft-wsl1`、`ft-wsl2` 的发行版，一个名为 `ft-alpine` 的映像，两个容器，目录 `C:\ftlab`，都由 `19_cleanup.ps1` 删除。WSL 容器默认会话的存储盘是 `wslc` 首次使用时自动建立的，留在原处。计时的数字只适用于那台机器（Defender 实时保护开启），画面上都标了「本机实测」。

## 读法

字幕写正式拼写，读法在 `script.js` 的 `SAY` 表里：

- `WSL`、`WSLc`、`wslc` 逐字母读；`wslservice`、`wslcsession` 读成字母加单词；`dockerd`、`containerd` 读成单词加 D。
- `virtiofs` 写成 `virtio F S`（读作 virt-ee-oh F S）。写成 `virt I O F S` 会被逐字母拼读。
- 版本号逐位读：`3.0.1` → 三点零点一 / three point oh point one。内核版本号里的 `26100` 逐位读。
- `2004 版` 读成二零零四版 / version twenty oh four。
- `ext4`、`9P`、`cgroup` 各按字母与数字读。

`asr.js` 回听两种语言各 70 句，没有漏词与数字读错。整条音轨识别时第一句的「2026 年」被听成「2016 年」，单独合成再听是「2026 年」，属识别误差（`tts_probe.js` 的结果）。

**闸门。** `check.js --final` 于 2026-10-07 全部通过（源码规则、场景齐全、时长与节奏、两种语言的全片扫描、音效覆盖、交付物）。扫描的提示项没有清零，留下的有三类，都是有意的：底栏里的三个方格与日期被提示为「伸进字幕条」；第三章的时间轴随镜头滚动，标签在画面两侧被切；88 秒的长条与它的读数出血。

**审查中改掉了什么。** 逐条记录在 `research/FACTS.md` 的「复核」一节，这里只列结论：

- 事实：四处表述收严（一个没有出处的「所以」、一句「不是一代新架构」、一张图里的标注、两行小字的措辞）；三条原先只有单一出处的事实补了独立印证。
- 读音：`virtiofs` 的读法改过一次；两种语言各 70 句回听无漏词、无数字读错。
- 旁白与画面：「88 秒」那一句的读数原先落在句后，英文版一处动作落在句后，结尾一句画面下半空着，都已改。
- 动态：一段 3.9 秒的静止、全片第 0 帧机位不定、描线前露出的圆点、压住文字的印章，都已改。

共渲染三轮，前两轮都因审查发现问题而作废。

**原创。** 参考来源与比较过的方向见「视觉系统」。没有照搬现成产品的文案、分镜、构图或动效。

**片尾。** 从两种语言的成片里各抽出片尾一帧核对过：名单、分工与「开源视频 github.com/Water-Run/ft」齐全，与 `research/FACTS.md` 的「制作署名」一致。2026-10-07 打开该地址，仓库公开可访问。

**需要人来判断的事项**

- 配乐与音效的听感。两者由程序合成，制作者听不到；数值自检正常。配乐用内置的按章节编排，各章的区别在层的进出（`project.json` 的 `audio.score`）。不合适时改 `audio` 段后重跑 `audio.js` 与 `finish.js`，不必重新渲染画面。
- 中文版第一句「2026 年」的读音是否清楚。语音识别在这一句上时对时错，判断读音正确，详见「复核」。
- 两种音色与语速（中文加快 8%，英文加快 9%）是否合适。
- 连续播放时的观感。制作者只看过静帧与总览图：全片每 4 秒一帧的总览、两种语言每句一帧的总览（`sheets.js every 4`、`sheets.js cue`）。
- 发布：未发布。发布后按 `docs/workflow.md` 第 11 节回填本节、`FACTS.md` 的「复核」与根 README 的「已成片」表。

**取舍**

- 片名里的 WSL 3 加了引号。立项时的片名没有引号；取证表明 3.0 是软件包的版本号，而不是继 WSL 1、WSL 2 之后的第三代架构。
- 三个年代三套皮肤，是对质量标准里「不用渐变、圆角、投影」的有意例外，见「视觉系统」。
- 计时的数字只来自一台测试机，画面上都标「本机实测」，不引用官方当年的「最多 20 倍」。
- 英文版里 `wsl.exe` 的回显是用它自己的字符串表换算的，不是在英文系统上截的。
- 各场景的标题距画面顶边约 30 像素；越界自检复量后，a11 与 c14 两句的内容距左右边缘 57 像素（标准 60）。没有为这些再渲染一轮。

**未做**

- 「官方称 virtiofs 约快一倍」没有做对照实测，片中写明是官方的说法。
- WSL 容器的 API、Defender 与 Intune 的管理没有讲，也没有实测。
- 没有逐句对应表（`expect.<语言>.json`）；旁白与画面的对应是逐张看图核的。
