# 后台案例脱敏与展示规则

本案例的公开代号为 CASE-A。公开研究文件只保留应用相对路径、代码结构、计数、哈希及必要的通用业务名称。真实项目名和身份映射留在原工程的私有忽略目录，不随材料包同步。

## 已交付材料的边界

本包不含私有源文件原文、配置副本、数据库导出、登录态、抓包、日志、照片或生产截图。测绘脚本从私有工作区读文件，在输出端采用白名单，只输出结构与统计。官方源码仅记固定提交、直达链接和文件哈希，源码下载缓存没有放进公开包。

| 内容 | 处理方式 |
|---|---|
| 项目、公司、客户、供应商、店铺、仓库、真实人员 | 案例与业务对象使用固定的通用代号；不公开映射表 |
| 域名、IP、主机、端口、跳板和个人路径 | 从公开证据删除；保留应用相对路径 |
| 口令、令牌、Cookie、会话、API 密钥、签名下载地址 | 不采入公开材料；演示时现场生成独立测试值 |
| 订单、物流单、商品条码、员工编号、账户编号 | 全部重新构造合成编号；不保留真实前缀、尾号或可关联哈希 |
| 数量、金额、工资、时间、客户备注 | 使用合成记录，明确标注；不对真实行做简单替字后发布 |
| 商标、商品图、头像、快递面单、二维码 | 移除或改为独立的演示资产；二维码不能只遮文字部分 |
| 公开署名 WaterRun 与 ft 仓库 | 依据制作规范保留，不与业务身份混用 |

源码中的通用路由如 `sale/order` 是结构证据；真实服务器上的完整 URL、会话参数或用户标识不属于这类证据。版本字符串 `1.4.9.3`、`1.5.6.4` 是版本信息，脱敏检查不能误将其当作 IP 地址而损坏事实。

## 演示数据约定

后续可用“演示仓 A”“演示店 B”“操作员 C”和 `DEMO-ORDER-001` 等独立编号。商品名称使用无品牌的演示品，联系方式不生成可拨通或可投递的真实目标。金额、数量和日期以合成业务规则重新生成，先验证乘积、汇总和关联，再用于画面。

合成示例与源码测量必须分开标注：文件计数、行号和字节数来自本轮实测；演示订单金额和库存变化是构造输入，不能写成真实业务规模、效率或绩效。

## 截图和录制前的检查

1. 从合成数据源开始，确认数据库和所有外围连接器均指向演示环境；不依赖前端遮罩处理真实响应。
2. 检查页头、面包屑、头像、浏览器地址栏、标签标题、状态栏、滚动区域、悬浮提示、弹窗、下载文件名和打印预览。
3. 检查隐藏输入、页面源代码、控制台、网络请求和图像内容；可见文字替换不代表原始数据已移除。
4. 重建界面标“示意”，合成数据标“演示数据”；真实截图需要另行逐帧检查。
5. 对实际交付的字幕、封面和编码视频再做一次检查。本次源码资料的检查不能代替成片检查。

## 本轮核验

核验范围为这批新增文档、两份脚本和两份 JSON 回显。采用文本模式检查、已知标识符与地址匹配、URL 域名白名单、JSON 解析和人工内容复读。脚本没有输出源文件内容，JSON 没有业务记录或运行凭据。机器检查的项目、结果及文件哈希见 [验证记录](lab/verification.json)。

自动模式检查不能证明所有未知身份信息都被识别。本轮材料采用最小白名单结构，并由人工检查正文和输出字段；未来新增截图、源代码摘录、业务样例或调试回显都需重新核验。
