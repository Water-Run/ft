# 05 动作、声音与口播

## 动作表达

所有运动由时间 t 计算；用 cue / 词边界定位，禁止定时器、CSS 动画、随机抖动和回调时间线。镜头移动只为转移注意力，阅读时稳定。

一段动画至少交代输入、变化、结果。请求携带路由和条件，SQL 高亮对应筛选行，记录带着订单编号返回；写状态时只改主表相应单元格，再插入历史行。不能用擦屏、翻卡或装饰性流光代替这些动作。

先制作“Cookie 取回会话 → token 比较 → access / modify”代表片段。用连续播放验证对象可追踪和可读性，再铺开其他章节。关键帧正确不等于运动中正确。

## 配音先试听

当前 Yunyang 是配置初值，尚未定为最终听感。文案批准后，选当前音色及一个可用的自然中文候选比较，不为挑音色重写稿件。代表段：

| 段落 | 检查内容 |
|---|---|
| a1–a6 | PHP / MySQL / route，长句语气和主从关系 |
| s1–s5 | Cookie、会话编号、服务器身份三者能否听清；逗号处不生硬重启 |
| p3–p5、d5–d8 | access / modify、MyISAM / InnoDB、事务与回滚的读音；因果句是否一口气挤完 |

字幕保留正式拼写。读法只写入 SAY / tts，不用全局替换“行”等多音字。Shopify、OpenCart、PHP、SQL、MySQL、MySQLi、MyISAM、InnoDB、Twig、Cookie、token、AJAX、JSON、LIMIT 都需以实际音频校对；不能凭 ASR 一致就判人耳通过。

分句由标点和字宽生成，逗号尾的 cue 使用短间隔。独立合成可能破坏连贯语气，必须听相邻句拼接；需要合并句子或改含义时回到交审。旁白不靠提高语速压到旧的 12 分钟预算。

## 声音

请求、拒绝和数据落位可用短促且克制的提示声；不是每次移动都加声。稳定阅读段保持安静，不沿用刷声。BGM 在完成口播试听后按本片 UI 气质选择和编排，不能直接把初始 pulse 预设当完成设计。

检查主混音、无配乐版和最终 AAC；数字阈值按仓库标准。每个听感结论写试听的实际文件与时段。InnoDB 的语音质量和断句问题保持为待验证项，不能用本文件关闭。
