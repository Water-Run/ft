## 简报

策划者要求（2026-10-26 会话原话）：

> Firebird作为独立片:
> 既能做服务又能嵌入式, 数据库小众的第三选择: Firebird
> 不再是专注引擎实现的内部 5-7min

主旨是介绍 Firebird 这个小众的数据库选择，围绕服务端与嵌入式两种使用方式组织讲述。观众不必看过数据库引擎系列；具体的使用方式、场景与边界开工后重新取证，再形成独立文案。

旧版材料只作为可追溯来源。新定位须重新取舍、写稿并交校对确认，随后再进入制作。

策划者要求（2026-11-08 会话原话，与上文冲突处按这里执行）：

> 计划制作Firebird那个视频.
> 视频包括Firebird的正式Logo(包括封面). 这个视频和数据库引擎系列不一样, 是更入门更粗浅的介绍, 底层部分简单带过不需要深入, 让观众知道这个数据库就行.
> 画风遵循Firebird官方文档的风格的同时, 引入2.5D(伪3D)贯穿全片. 独特小众, 体现Firebird风格的电子配乐. 预计时长4min
> 叙事更加活泼跳跃, 一个明确的主线, 完整的故事.
> 有点像OpenCart那期.

> 音乐可以带点摇滚因素, 画面和内容富有节奏感

> 包括封面也是独特的, 包括Firebird Logo和视觉风格体系的, 2.5D的, 独特排版

> 面向的观众主要是认识主流的数据库 但根本不知道这个小众的第三选择 Firebird的

系列的「不用 Logo」约定不适用于本片：本片是独立片，策划者明确要求正式 Logo。

**核心问题**：这个让火狐改了名的数据库是什么来头，今天能拿来做什么。**路径**：火狐改名（钩子）→ 客房创业 → 公司放手、用户接住 → 六天分叉 → 后门 → 回到改名 → 服务与嵌入式两边都站 → 回到火狐。底层只讲多版本一句话。

## 设计

三个方向（立体手册 / 层叠纸剧场 / 海报手册）与三张封面的探索稿见审片页，源文件 `src/design/kf.html`，取材见 `research/MATERIALS.md`。

策划者选定（2026-11-09）：视觉「AB有机融合 内容偏A 封面偏B」；封面「如上」，即偏 B；配音 `Arrogant_Miss`（嚣张小姐），MiniMax speech-2.8-hd，语速 1.2（试听语速，全片再按实测调）；配乐 C（Motorik 电子摇滚）。

配乐小样 `tools/music_sketch.py`：共同动机取自名字，FIREBIRD 中可作音名的字母为 F、E、B、D。

## 复盘

本机 Python 没有 scipy，配乐工具用 numpy 自写了滤波与拨弦；`look.js --url` 要求页面根元素 id 为 `stage`。
