## 文案与校对

唯一文案源稿：`src/js/script.js`。指定校对者：WaterRun。

```bash

```

导出的 `review/script.zh.<哈希>.md` 供逐句阅读，意见写在 `review/NOTES.md`。先取得明确确认，再按真实记录填写 `review/approval.json`；中文通过后翻译并校对英文。具体边界见仓库 `docs/guides/script-review.md`。

目标观众已有的知识：写过 Python、Lua、C#、PHP 一类的程序，见过 OutOfMemory 一类报错；知道堆/栈的大致区别；没有系统学过标记、清扫、分代、三色、写屏障。

看完应能回答的一个核心问题：运行时怎么知道一块内存“已经没用了”，又怎样在不长时间打断程序的前提下把它收回来。

逐章怎样推进问题、最后回答什么：开场（o1–o10：格子纸即堆 → 一秒六千七百万个数都数不过来 → 攥住不放，收五次也收不回，内存耗尽，四种报错你总见过一种 → 放手则堆只有 11 MB、136 次回收程序一个字都没管 → 什么是垃圾回收 → 程序不会说“我不要了” → 两问 → 五个名字与账单）→ 01 引用计数（对象开头 8 字节里的数，归零当场释放；环卡在 1；Python 与 PHP 另请拆环器，各报收 2 个；妙处：对象自己知道什么时候该走）→ 02 标记—清扫（从根出发走一遍叫追踪，刚才那个环够不着照收；以后用不用说不准，能不能找到现在就能算；麦卡锡 1960 的符号位；标记只认活的，没标的清扫挨个请走；Lua 一轮 28 MB 掉到 14 MB）→ 03 分代（短命对象占大头；新区小、收一次快所以勤收；.NET 对象 0→1→2，一秒 136 次都在第 0 代；老指新靠卡表打勾；妙处：经验观察长成堆的形状）→ 04 三色与写屏障（迪杰斯特拉 1978：别停程序；三色；黑牵白又断灰路就丢；迪杰斯特拉的家规；写屏障；Lua 源码里的规矩与改表时的后退屏障；419 步，这叫增量；Java 的 G1 后台标记头停一下尾停两下，这叫并发；.NET 的卡表四条指令，写入和打勾都在屏障里；妙处：程序员一行屏障都没写，却得了一个边跑边标记的收集器）→ 05 谁来买单（收得勤 CPU 烧得多；Nim 让你自己挑，只留引用计数叫 ARC、环永不释放；Rust 的所有权一块内存只认一个主人，Nim 的 ARC 同理只是还在数数；C 与 Zig 自己 free；谁都没白吃，账记在不同人头上）→ 收束（它不知道内存没用了，只知道还找不找得到；麦卡锡的脚注；从一停好几秒到一秒一百多次）。

本片决定不讲的材料及理由：复制与压实的独立章节、Go 与 Swift 的例子（事实与实验保留）、CPython 环收集器的内部算法、Lua 的两种白、Java 幸存区细节、调参手册、跨运行时基准。理由见 `research/NARRATIVE.md`。

## 视觉系统

**2026-10-20 改为「内存条」**（受托方 Claude Opus 5.5）。策划者在委托会话里要求画面「惊艳、有节奏感」，并明确「不要和 XX 秒速通那些瑞士风格和配乐同质化」；准备方交来的瑞士风格（米白底、墨字、红笔，`research/STYLE.md`、`brief/03-visual.md`）与「XX 秒速通」几乎是同一套，因此作废。受托方做了三个方向的关键帧（`src/design/keyframes.html` 的 k=1–9：钴蓝之堆、夜场、内存条），策划者看过截图后指定绿色这一套。

颜色取自内存条本身（F16）：阻焊层的绿是底色（整片就是一块「堆」），铜线的浅绿画格子，丝印白是字、白对象与指针，芯片黑是活对象与运行时的真实输出，金手指的金色只给收集器的动作（标记、清扫、拦截）。三色标记直接用片中的三种颜色：丝印白 = 白、灰 = 灰、芯片黑 = 黑。字体：中文大字 Serif SC（「艺术」的版面感），正文 Sans SC，数字与拉丁 Inter，代码 Mono。平涂，无阴影、渐变、模糊、圆角。色板 8 色写在 `src/css/style.css` 与 `project.json` 的 `check.style.palette`（规则的严格程度未变：flat、no_radius、no_emoji 照旧，色板与字体名单换成新系统的）。

节奏：全片落在一条 108 拍/分的拍网上（`src/js/config.js` 的 `BPM`、`qb()`）。方块落位、金线、数字跳动按八分或十六分音符走；每次换章，上一章被「回收」——32×18 块格子按下一章机制的顺序（随机、从左到右、自下而上、从根出发的波、逐行打印）盖满画面，再按上一章机制的顺序收走，落点就是配乐的强拍。配乐 `tools/music.py` 自写（见「声音」）。

每章一个主画面：开场「六千七百万个对象铺满 64 MB 的板，撞墙；换个活法只用最上面六行，一道道金线扫过」；01「对象 A 展开成 16 个字节，前 8 个字节里的计数 1→2→3→2→1→0，归零当场碎掉」；02「从根出发一拍一层烧过去的标记，随后一道金线清走没被碰到的」；03「整块堆裂成三层地层，一个对象逐层掉下去」；04「黑牵白、灰松手，白被冤杀——倒带——家规落下，写屏障在写下指针的一刻把白涂灰」；05「黑底上三张热敏纸账单一行一行打出来」；收束「横梁在不可预知的未来与严苛的硬件之间摆动、停平」。

参考来源与独立设计：颜色取自实物内存条（阻焊绿、丝印、芯片、金手指）的一般外观，没有照搬任何产品、网站或视频的版式与动效；三色标记的颜色语义取自 Dijkstra 1978 与 Lua `lgc.h` 的白、灰、黑；论文页面只排题名、作者、刊名与所引原句，不仿制期刊版式。准备方的 `research/STYLE.md` 与 `brief/03-visual.md` 保留原样，作为改向前的记录。

## 声音

配乐：`tools/music.py`（受托方自写，`project.json` 的 `audio.music`）。108 拍/分，十六分音符带摇摆；四踩底鼓、二四拍掌声、沙锤与副歌段的开镲；正弦低音按和弦根音切分，并像侧链压缩那样在每个底鼓后让一下；马林巴式木槌（加法合成）弹两条交错的固定音型，每四小节一个四音动机；暖铺底贯穿全片，给低频分量。和声是多利亚调式的 i9–IV9 摇摆，每章换调（开场 C、01 E♭、02 F、03 G、04 A、05 B♭，收束回到 C）。结构跟着故事走：换章落在强拍上砸下低频与镲（与画面的格子盖满同一拍）；内存耗尽、1960 年「这一停就是好几秒」、冤杀三处整段停住；错误墙与麦卡锡脚注只留铺底；「平衡」一句是终止式；片尾只留木槌与铺底。和「XX 秒速通」的区别：那边是 120 拍/分、D 小调 i–VI–III–VII、每秒一声秒针与拨弦，没有主动机。

音效：只用 `mix.py` 自带的 11 种，按含义固定：方块落位 pop、计数与逐步 tick、收集器扫过 whoosh、砸入与落点 thud、得出结果 chime、报错与冤杀 error、换章前 riser、打字 key（含账单打印）、1960 年的老机器 drive 与 beep、终端行 blip。镜头移动的自动气流声全部关掉。

混音：`music_db −9`、`duck_db 7`、`sfx_db −9`。数值自检（2026-10-20）：旁白之下的配乐约 −36 dB（旁白约 −21 dB，低约 15 dB），章节卡处约 −29 dB；低 / 中频能量占比约 −3.5 / −3.5 dB，没有削波。**听感未经人耳确认**（制作者听不到声音）。
