# 叙事测绘

本文件只记录面向观众的讲述顺序与取舍，不是旁白稿。事实与依据在 `FACTS.md`。

## 观众前提

写过 Python/JavaScript/Java/Go 一类的程序，见过 `OutOfMemoryError`、GC 日志或“内存泄漏”这个词；知道堆和栈的大致区别；没有系统学过标记、清扫、分代、三色、写屏障这些机制。

## 一个核心问题

程序怎么知道一块内存“已经没用了”，又怎样在不长时间打断程序的前提下把它收回来。

## 逐章问题与答案

| 章 | 观众的问题 | 本章要回答 | 画面上的主要证据 |
|---|---|---|---|
| 1 钩子 | 内存不用了，为什么不还给系统 | 因为“不用了”不是程序能直接说清的事；GC 要用可达性来推断 | 1959/1960 年 Lisp 的 free list；McCarthy 的脚注 |
| 2 引用计数 | 数一数有多少人指着它，不就完了 | 计数到零立即回收；但环会让计数永远不归零 | Python 实验：2→3→2；X/Y 环；`gc.collect()` 返回 2 |
| 3 追踪 | 如果没人“数”，怎么找垃圾 | 从 roots 出发走对象图，走不到的就是垃圾；mark-sweep / copying / mark-compact 的差别 | McCarthy 的符号位标记；V8 的 free-list 与 forwarding pointer |
| 4 分代 | 为什么要把对象按年龄分家 | 大多数对象死得早；新代勤收、老代少收；remembered set 记录老指向新 | V8 的 nursery/intermediate/old；Lieberman-Hewitt 的 region/generation |
| 5 并发 | 收集的时候程序不能停太久，怎么办 | 三色、写屏障、并发/增量/并行；STW 只剩很短的阶段 | Go 1.5 的三色与 write barrier；G1 的 SATB；V8 的 concurrent marking |
| 6 代价 | 有没有免费的午餐 | 吞吐、暂停、内存三者取舍；不同运行时选不同的点 | Go 的 GOGC 公式；G1 的暂停目标；Swift ARC 与 Rust 所有权 |
| 7 收束 | 那“垃圾回收的艺术”到底是什么 | 是在程序的行为不可完全预知的前提下，用一套可证明的规则，把“不再需要”变成“可以复用” | 回到 McCarthy 的脚注与 1983 年的分代论文 |

## 决定不讲

- 某个具体 GC 算法的完整伪代码（Cheney 队列、Baker 的 invariant、SATB 的屏障细节）。讲清直觉与代价即可。
- 各语言的 GC 调参手册。会把片子变成运维课。
- 某个版本的基准测试、暂停时间排行榜。本次没有做跨运行时测量。
- 分代 ZGC、Shenandoah、V8 的 Oilpan 等更细的分支。只在需要说明“同一抽象有多种实现”时提一句。
- 引用计数的完整实现（延迟引用计数、Coalescing、 backup tracing）。只讲基本计数、环、weak。

## 开场可用的钩子（不是定稿）

- 直接引用 McCarthy 的脚注：他早就把这件事叫“garbage collection”，但论文里没敢写，怕实验室的语法女士不让他过。然后说：这个“不敢写进论文”的词，后来成了整个行业的名字。
- 或者先跑 Python 实验：`del a` 之后 `__del__` 立刻打印，weakref 立刻变 None；再把 X/Y 的环摆出来，`del` 之后 weakref 还在，直到 `gc.collect()`。同一个“删除”，两种命运。
