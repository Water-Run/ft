# 04 分镜：逐场景

每场写清四件事：**要让观众明白什么**、**空间怎么布置**、**每句对应画面上的什么**、**建议的做法**。先写这张表，再写代码。

`expect.zh.json` 写的是**必须出现的文字**；怎么摆是你的决定。

## open · 开场（约 71 秒）

要让观众明白：内存是一张格子纸；程序造对象很快；GC 在背后替它收。

| 句 | 画面上有什么 | 建议 |
|---|---|---|
| o1–o1b | 一张越铺越大的格子纸；每造一个对象占一格 | 格子从左往右铺开，镜头跟着走 |
| o2–o2b | 六千七百万个格子 | 数字用可见速度滚上去，占满整屏宽 |
| o3–o3b | 64 MB 的堆；报错原文 | 格子铺到边界就停；撞墙画面要标出对象数、耗时、GC 次数 |
| o4–o4b | PHP、Java、Node 的报错拼贴 | 各报各的，语气不同 |
| o5–o5b | 同样六千七百万个，堆只占 11 MB | 格子释放后回收，空间没涨 |
| o6–o6b | 一秒内清扫 136 次 | 红色竖线以 136 次/秒的节奏刷过 |
| o7–o7b | 「垃圾回收」这个名字 | 名字落下，但**不要画成一个人或一个管家** |
| o8–o8b | 「这块，我不要了」 | 程序从不交代这件事 |
| o9–o9b | 两个问号：怎么猜、怎么收 | 问号在画面上，不是旁白里 |
| o10–o10b | 记账 → 追踪 → 分代 → 并发；妥协与权衡 | 四个词依次落位；这是全片路线 |

| 句 | 画面上有什么 | 建议 |

## trace · 02 标记—清扫（约 76 秒）

要让观众明白：从根出发走一遍，走得到的活、走不到的垃圾；代价是一次停顿。

| 句 | 画面上有什么 | 建议 |
|---|---|---|
| b1–b2 | 根（栈上的变量、全局变量）；追踪 | 从根出发，指针线一路走 |
| b2a | 刚才那个环，从根上摸不着 | 呼应 01 章 |
| b3 | 「以后用不用」与「现在能不能找到」 | 两个时间尺度并排，这是本片的一个关键对照 |
| b4 | 1960；McCarthy 的 Lisp | 大年份 |
| b5 | 符号位拨成负；再扫一遍 | 符号位要看得见 |
| b6 | 一轮好几秒 | 停顿要真的停住几秒，不要一闪而过 |
| b7 | 「标记—清扫」 | 名字与白话同时给 |
| b8–b9 | Lua 二十万张活表 + 二十万张废表；28 MB → 14 MB | 这两段是实拍回显，数字与内存都要对 |

## 写这张表时的两条要求

- **每场要有一个说得出名字的主画面。** 不是「方格在动」，而是「四十万张表被 419 步清空」这种能被复述的画面。
- **事实不能从画面里长出来。** 数字、代码、引文一律来自 `research/FACTS.md`；`expect.zh.json` 里的字必须完整出现。
