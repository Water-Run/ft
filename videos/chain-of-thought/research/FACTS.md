# 事实

取证日期：2026-10-18。对象是 Chain of Thought（CoT）：让语言模型在给出答案前先生成中间推理步骤，这种做法怎样被提出、怎样被使用、在哪些条件下可能有效，以及为什么不能把生成的步骤直接当成模型的真实思考过程。

本文件只登记陈述和依据，不规定片子的结构、时长分配、画面或措辞。来源编号见 `sources.json`。

## 定义与边界

| 陈述 | 依据 | 状态 |
|---|---|---|
| CoT 是让模型生成「一系列中间推理步骤」，再给出最终答案；Wei 等的定义就是 a series of intermediate reasoning steps | `wei-2022` 摘要 | 已读摘要 |
| Wei 等系统化的 CoT prompting 用法是 few-shot：在提示里放几个「问题 + 推理步骤 + 答案」的示例，让模型照着写 | `wei-2022` 摘要 | 已读摘要 |
| 论文在三个大模型、算术/常识/符号推理任务上报告提升；并称这种能力在足够大的模型上才明显出现 | `wei-2022` 摘要 | 已读摘要 |
| 一个具体报告：540B 参数模型 + 8 个 CoT 示例，在 GSM8K 数学应用题上达到当时的 SOTA，超过带 verifier 的微调 GPT-3 | `wei-2022` 摘要 | 已读摘要；不写具体准确率，因为摘要没给 |
| CoT 生成的文字是「可见的中间步骤」，不等于模型内部真实的计算过程；Turpin 等专门研究了这种解释可能不忠实 | `turpin-2023` 摘要；`wei-2022` 摘要 | 已读摘要；这是本片的核心边界 |
| 「先思考，再回答」描述的是输出格式：先生成推理文本，再给答案；它不是「模型真的先想了一遍」的证据 | `wei-2022`；`turpin-2023` | 本文件归纳 |

## 一个用于讲解的具体例子

下面的题目是本片自拟的示意，不是论文里的题目；只用来展示「直接答」与「写步骤」的差别。

| 陈述 | 依据 | 状态 |
|---|---|---|
| 题目：仓库里原来有 23 箱纸，上午送来 7 箱，下午用掉 3 箱，还剩多少箱 | 本片自拟的算术题（示意） | 不需要外部来源；计算可复核 |
| 直接答：27 箱 | 23 + 7 − 3 = 27 | 计算 |
| 写步骤：原来 23；上午 +7 = 30；下午 −3 = 27；答案 27 | 同上 | 计算 |
| 这个例子的作用只是让观众看到「中间结果被写出来」；它不能证明 CoT 在所有任务上都更好 | 本片说明 | 不进入定稿的因果结论 |

## 三种常见用法

| 陈述 | 依据 | 状态 |
|---|---|---|
| Few-shot CoT：给少量带推理步骤的示例；Wei 等的 8 个示例就是这种做法 | `wei-2022` 摘要 | 已读摘要 |
| Zero-shot CoT：不加示例，只在问题后加一句「Let's think step by step」，模型就会先写步骤再回答 | `kojima-2022` 摘要 | 已读摘要 |
| Zero-shot CoT 的报告数字：text-davinci-002 上 MultiArith 17.7%→78.7%，GSM8K 10.4%→40.7% | `kojima-2022` 摘要 | 已读摘要；论文报告，不是本片复现 |
| Self-consistency：不让模型只走一条贪心路径，而是采样多条推理路径，再选出现最一致的答案 | `wang-2022` 摘要 | 已读摘要 |
| Self-consistency 的报告提升：GSM8K +17.9%、SVAMP +11.0%、AQuA +12.2%、StrategyQA +6.4%、ARC-challenge +3.9% | `wang-2022` 摘要 | 已读摘要；相对于 CoT 基线，具体设置见论文 |
| Self-consistency 的直觉是：复杂问题可能有多条不同的思考路径，但正确答案通常只有一个；把路径边缘化后投票 | `wang-2022` 摘要 | 已读摘要 |

## 从「一条链」长出的变体

| 陈述 | 依据 | 状态 |
|---|---|---|
| Scratchpad（2021）：让模型把中间计算结果写到「草稿纸」上，再继续算；从长加法到执行任意程序都受益 | `nye-2021` 摘要 | 已读摘要 |
| ReAct（2022）：把 reasoning trace 与 task-specific action 交替生成；推理帮助模型计划、跟踪、更新行动，行动让模型去外部知识库/环境取信息 | `yao-react-2022` 摘要 | 已读摘要 |
| ReAct 的报告数字：ALFWorld 绝对成功率 +34%、WebShop +10%，只用一到两个 in-context 示例 | `yao-react-2022` 摘要 | 已读摘要；论文报告 |
| Tree of Thoughts（2023）：把 CoT 推广到在「thoughts」上搜索；考虑多条路径、自评、前瞻、必要时回溯 | `yao-tot-2023` 摘要 | 已读摘要 |
| ToT 的报告数字：Game of 24 上 GPT-4 + CoT 只有 4%，ToT 达到 74% | `yao-tot-2023` 摘要 | 已读摘要；论文报告 |
| 这些变体的共同点：都不只是「多写几句话」，而是改变搜索/采样/行动的结构 | `nye-2021`；`yao-react-2022`；`yao-tot-2023` | 本文件归纳 |

## 为什么可能有效

| 陈述 | 依据 | 状态 |
|---|---|---|
| 多步问题需要把中间结果留在上下文里；CoT 让模型把中间结果写成 token，后面的步骤可以引用它们 | `nye-2021` 摘要；`wei-2022` 摘要 | 已读摘要；机制解释是本文件归纳 |
| 生成更多 token 也意味着在推理时多花计算；测试时计算可以换性能 | `snell-2024` 摘要 | 已读摘要 |
| Snell 等报告：compute-optimal 的测试时计算分配，比 best-of-N 基线效率高 4 倍以上；在 FLOPs 匹配下，小模型在已有非平凡成功率的题上可以超过 14 倍大的模型 | `snell-2024` 摘要 | 已读摘要；论文报告，不写成普遍规律 |
| DeepSeek-R1 用纯强化学习激励推理，不需要人工标注的推理轨迹；模型出现 self-reflection、verification、动态策略调整等模式 | `deepseek-r1-2025` 摘要 | 已读摘要 |
| R1 的报告：在数学、代码竞赛、STEM 等可验证任务上，优于用人工演示做监督学习的对照；这些模式还能用来指导更小的模型 | `deepseek-r1-2025` 摘要 | 已读摘要；论文报告 |
| 「CoT 有效」不等于「CoT 的文字就是模型真实推理」；效果与忠实性是两件事 | `wei-2022`；`turpin-2023`；`deepseek-r1-2025` | 本文件归纳 |

## 什么时候不能信、不能滥用

| 陈述 | 依据 | 状态 |
|---|---|---|
| CoT 解释可能系统性歪曲预测的真实原因：在 few-shot 提示里把答案偏置成 (A)，或加入社会偏见，模型会为错误答案编造看似合理的解释，且不提及偏置 | `turpin-2023` 摘要 | 已读摘要 |
| Turpin 等报告：在 13 个 BIG-Bench Hard 任务上，偏置使准确率最多下降 36%（GPT-3.5 与 Claude 1.0） | `turpin-2023` 摘要 | 已读摘要；论文报告 |
| 因此，CoT 不能直接当作「模型为什么这样做」的可靠审计记录；它可能是事后合理化 | `turpin-2023` 摘要 | 已读摘要；本片的核心限制 |
| CoT 的收益依赖模型规模、任务和提示方式；Wei 等说这种能力在足够大的模型上才明显出现，不能把它推广到所有模型/所有任务 | `wei-2022` 摘要 | 已读摘要 |
| 生成更长的推理文本会增加 token、时间和成本；测试时计算不是免费的 | `snell-2024` 摘要 | 已读摘要；成本结论是直接推论 |
| 对简单任务、或模型本来就能直接答对的任务，CoT 不一定划算；本片没有做这类对照实验，不写「一定更差」 | 本片说明 | 待核实，不进入定稿 |
| 模型可能隐藏/摘要推理过程；如果看不到完整 CoT，就不能把「没看到」当成「没有推理」 | 本片说明 | 未取证产品行为，不写死 |

## 边界与常见误说

| 说法 | 核查结果 | 依据 |
|---|---|---|
| “CoT 就是让模型把心里想的说出来” | 不准确。CoT 是生成的中间步骤文本；它不保证忠实于模型内部计算 | `turpin-2023`；`wei-2022` |
| “只要加一句 Let's think step by step，所有任务都会变好” | 不准确。Zero-shot CoT 在论文的若干基准上有效，但不是所有任务/模型的保证 | `kojima-2022` 摘要；`wei-2022` 摘要 |
| “CoT 一定提高准确率” | 不成立。Turpin 等展示了偏置下 CoT 为错误答案编解释、准确率下降；任务/模型/提示也影响收益 | `turpin-2023`；`wei-2022` |
| “Self-consistency 就是多问几次取多数” | 不完整。它采样多条推理路径，再对最终答案做边缘化/投票；关键在路径多样性，不只是重复同一提示 | `wang-2022` 摘要 |
| “ToT 就是更长的 CoT” | 不准确。ToT 在 thoughts 上做搜索、自评、前瞻与回溯，改变了推理结构 | `yao-tot-2023` 摘要 |
| “ReAct 只是 CoT 加工具调用” | 不完整。ReAct 交替生成 reasoning trace 与 action，让推理和外部观察互相更新 | `yao-react-2022` 摘要 |
| “R1 证明了模型真的在思考” | 不能这样写。R1 展示了用 RL 激励出的推理行为和可验证任务上的提升；是否/怎样对应人类意义上的“思考”不是论文的结论 | `deepseek-r1-2025` 摘要 |
| “CoT 越长越好” | 不成立。测试时计算有成本，收益随任务/模型变化；没有“越长越好”的普遍结论 | `snell-2024`；`turpin-2023` |
| “CoT 可以替代可解释性审计” | 不成立。CoT 可能是事后合理化；不能把生成的解释当成可靠的因果记录 | `turpin-2023` 摘要 |
| “所有模型都适合 CoT” | 不成立。Wei 等说这种能力在足够大的模型上才明显出现；小模型/简单任务不一定 | `wei-2022` 摘要 |

## 不进入定稿的句子

| 句子 | 原因 |
|---|---|
| CoT 是 2022 年发明的 | 2021 年的 scratchpad 已经让模型写中间步骤；2022 年是 CoT prompting 的系统化论文。写“2022 年 CoT prompting 论文”，不写“发明” |
| CoT 让模型“真的推理” | 不能把生成的文本等同于内部认知过程；改为“生成中间步骤，并在一些任务上提升表现” |
| 所有 CoT 都是忠实的 | Turpin 等的反例；不写 |
| CoT 在所有任务上都提升 N% | 论文只在特定基准/模型上报告；不写普遍数字 |
| R1 的推理过程就是人类可读的完整思维 | 论文讲的是 RL 激励出的推理行为；不写“完整思维” |
| 某产品隐藏了 CoT，所以它没有推理 | 没有取证具体产品行为；不写 |
| “先思考，再回答”是模型内部的先后顺序 | 它描述的是输出格式；内部计算顺序不可见 |
| 任何“CoT 让模型更安全”的结论 | 本次没有读安全评测；不写 |
