## 1. 主题

**Firebird 的引擎是一个库，服务端只是可选的外壳。** 同一个引擎既能当服务端被连接，也能整个装进你自己的程序。围绕这一个形态差别，讲清数据怎么放、怎么改、怎么并发、出错怎么办。

- 观众：写过 SQL、没读过引擎源码的人（系列定位，见 `videos/database-engines/README.md`）。
- 看完要能回答的一个问题：Firebird 为什么能既是服务端又是嵌入式？
- 策划者指定：片长 **4–7 分钟**（`check.duration` 240–420 秒），视觉严格契合 Firebird 的风格，配乐电子乐、富有节奏感。

## 2.1 承上启下：怎么体现

这一集是系列的第四集，前面有 MySQL（MyISAM、InnoDB）与 PostgreSQL，后面有 SQLite。**承接要看得出来，但不过度。**

**三条线，任选其一或组合，但全片都要看得见：**

| 线 | 怎么做 | 为什么不过度 |
|---|---|---|
| **点名** | 开场 `o5`–`o5a` 点出 MySQL 和 PostgreSQL；收尾 `z7` 说出对照：它们的引擎住在服务端进程里 | 点名是自足的事实陈述，**没看过前集的人也懂**；不出现「上一集」「前几集」「第一个问题」这类需要记忆的串场（F10、P16） |
| **同一条主线** | `z1`–`z6` 用系列统一的四个问题收束：怎么放 / 怎么找 / 怎么改 / 怎么并发 / 出错怎么办 | 问的是同一组问题，观众看完前三集积累的正是这组；不逐集回顾答案 |
| **同一批数据** | 沿用前三集同一张示例表与同一批数据（`users` 8 行 alice/bob/carol…、`notes` 3 行） | 画面上出现同样的名字与同样的数，认得出来就是接上了，一个字都不用多说 |

**启下**：`next` 那一段要把三个形态排成一条轴——服务型（MySQL、PostgreSQL）→ 库型（Firebird）→ 嵌入型（SQLite）。这条轴是本系列自己的路线（`research/FACTS.md` 的 C03），画出来就把「这一集在系列里的位置」说清楚了。

**不要做的**：逐集回顾前两集讲了什么；用「上一期的第一个问题」导航；做 MySQL / PostgreSQL / SQLite 之间的性能比较（没有同条件实测，见 `research/FACTS.md` 的 C01 与 F09）。

## 5. 术语写法

| 写法 | 说明 |
|---|---|
| Firebird | 拉丁专名，读作「Fire bird」；`SAY` 表已写 |
| InterBase | 读作「Inter Base」 |
| `fdb` | 库文件扩展名，逐字母读 |
| `inet://` / `xnet://` | 读作「i net」/「x net」，后面接「开头」 |
| TCP | 逐字母读 |
| ODS 13.1 | 读作「O D S 十三点一」 |
| Cache Writer / Garbage Collector | 英文原名，后面各接一句中文作用 |
| 页 | 8192 字节一页；页类型用官方编号与名称（1 header / 2 page inventory / 3 transactions / 4 pointer / 5 data / 6 index root / 7 index / 8 blob / 9 gen-ids / 10 SCN inventory） |
| 行版本 | 同一个物理行在页上留下的多份副本；**不要**说「记录版本」或「回溯版本」 |
| 嵌入式 | 引擎在客户端进程里；与「远程」「环回」并列 |
