## update · 05 把 30 改成 31

预估 58.5 秒。

| 句号 | 字幕 / 旁白原文 |
|---|---|
| u1 | 接着，把 Alice 的年龄改成 31 |
| u0 | 这次修改，放在一个可以提交或撤销的事务里 |
| u2 | 如果只把旧值抹掉，另一个正在读的事务 |
| u3 | 就可能失去它本来应该看到的内容 |
| u4 | Firebird 会保留需要的历史版本 |
| u5 | 当前记录，沿着回溯指针连向旧版本 |
| u6 | 读者再根据事务状态，判断该读哪一版 |
| u7 | 写入者还没提交，自己能读到 31 |
| u8 | 另一边的普通读取，仍能拿到旧值 30 |
| u9 | 这就是多版本：同一行，保留不同时间的状态 |
| u10 | 旧版本不再有事务需要时，才可以回收 |
| u11 | 回收可以在访问时顺带做，也能由后台做 |
| u12 | 因此，长时间不结束的旧事务 |
| u13 | 可能拖住清理，让版本链越来越长 |
