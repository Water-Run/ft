# 一个数据库引擎是如何实现的？——OLAP的MergeTree和列式存储：ClickHouse

数据库引擎系列第 5 集：ClickHouse 怎样存数据——它几乎只用 MergeTree 这一种表引擎，按列存进不再改动的片段、后台合并、用稀疏索引找数据。面向写过 SQL、没读过引擎源码的观众，约 12 分钟，只做中文。

## 简报

<!-- 立项时写，准备方或制作方都可以写。策划者在会话里提的要求，原话与日期照录在这里，优先于任何缺省做法（docs/roles.md 第 2 节）。 -->

- 目标观众已有的知识：写过 SQL；不假定看过前几集，也不假定知道行存、索引、事务这些名词的细节。
- 看完能回答的一个核心问题：一亿人的平均年龄，ClickHouse 为什么只读一列、几毫秒就能算完？为此它放弃了什么？
- 用哪个具体例子走完解释，关键因果与边界是什么：同一张 `users(id, name, age)`，先用系列第一集的 8 行小表看「每列一个文件」，再放大到一亿行（Alice 2050 号、42 岁）；Dave 注册（一行一个片段），Ivan、Judy、Mallory 同时注册（异步插入合成一个片段），Alice 过生日（变更：只重写 age 列、其余硬链接）、注销（`_row_exists`），Bob 读的时候 Carol 写（片段快照），写到一半强行终止（临时目录与改名）。边界：数字是这台机器、热缓存、规律极强的演示数据上的实测；年龄列的压缩比不代表真实数据。
- 逐章怎样推进，各章的答案（第 4 稿）：引子（前面四期——MyISAM、InnoDB、PostgreSQL、SQLite——都是一个人一行地存的事务型 OLTP，擅长找一个人、改一个人 → 换一种问法：一亿人的平均年龄，七毫秒，读了哪些数据？→ 一次要看很多人的数据，叫 OLAP）→ 01 来历（历史部分：为网站统计造的；先汇总的办法与局限；2009 年起的 OLAPServer 与局限；ClickHouse 的初衷；2016 年开源；更早的分析型数据库与云数据仓库）→ 02 一张表的引擎（84 种表引擎，存数据几乎只用 MergeTree）→ 03 一列挨一列（每列一个文件、排序键、压缩、省空间；回答开场）→ 04 片段（写好的文件不改、一次插入一个片段、成批与异步插入）→ 05 合并（先讲片段多的坏处：900 片段 vs 合并后、片段数上限；再讲卡片归并的小例子；层层并成树，MergeTree 名字的由来；LSM 树）→ 06 稀疏索引（传统索引一行一项；颗粒、标记、二分）→ 07 改 → 08 删 → 09 同时读写（快照）→ 10 出错怎么办 → 11 五个问题 → 12 取舍（回到七毫秒、重写一整列、省空间）→ 13 SQL 之外（说的还是 SQL；系列五期全是 SQL；JSON 也拆成列；整份文档不如原样存 → MongoDB）。
- 决定不讲的材料与理由：分区、副本（ReplicatedMergeTree）、跳数索引与投影、向量化执行、编码（Delta 等）、合并选择算法——与「按列存、片段、合并、稀疏索引」这条主线无关或篇幅不够；轻量更新与补丁片段只一句带过（待策划者定）。

策划者 2026-11-08 看过审片页后选定（审片页第 04–07 节按此做出，等文案确认后进入实现）：

- **视觉：平面为主，参照前几集**（2026-11-08 起取代上一轮的「A 与 B 融合」；策划者：「画面不用为立体而立体，效果也还行，参考前面几期的」）。前四集各取自己引擎官方材料的样子，全片平面，常驻引擎身份标识，整套结构按真实比例画出来，注解贴在被解释的东西旁边，立体只在封面——本集照做：官网的黄 `#FAFF69` 与近黑 `#151515`、细网格、等宽的 clickhouse-client 终端与文档部件（回显、注解框、真实数字），左上角常驻 ClickHouse 与版本（26.8 LTS），不放产品标志。四个关键帧（`src/design/kf-d1/2/3/4.html`，共用 `kf-d.css`）：03 列文件、05 合并（归并走到一半，下一张是 4 号）、06 稀疏索引（颗粒、索引项、二分、三个列文件的标记）、01 来历（Metrica 时间线与分析型数据库的年代）。上一轮「A 与 B 融合」的三帧（`kf-ab1/2/3.html`，用真 CSS 3D 把平面面板贴到有厚度的板上）留作备选：只有「厚度表示行数」这类立体确实携带含义时才用，不为立体而立体。
- **贯穿的对象**：一个片段，从插入、合并、被读、被变更、被标记删除、被快照留住到崩溃后被清理，全片都在它身上发生；第 04 章的合并用同一组八个人（真实回显 `research/lab/out_12_merge.txt`）。
- **封面：A「只读一列」**（`src/design/cover-a.html`，共用 `cover3d.js`）：三根黑色的列，只有 age 通体发光，列脚标压缩后的大小（383 MiB、499 MiB、529 KiB），「一亿行求平均，只读一列 · < 10 ms · 热缓存」。按系列封面约定：PART 5、问句、大标题、立体图、实测数据；底部约 15% 不放字。正式出图在文案确认之后（`covers.js`）。B、C 两张候选留在 `src/design/` 备查。
- **配音：温润青年**（MiniMax `Chinese (Mandarin)_Gentle_Youth`，已写入 `project.json` 的 `tts`；语速试听用 1.18，约每秒 4.9 字，定稿前按实测定）。本系列男女声交替，本集男声。
- **配乐：B「列」与 C「合并」的融合**（`tools/music_sketch.py BC`）：96 拍/分，D 多利亚落到 D 小；B 的八个金属槌音一小节加一列，中段进 C 的三条旋律线，先错开，然后八个槌音与三条线一起向小节头收拢，最高处八个音叠成一个和弦与一声低沉的重击，最后回到单音。制作方无法实际听，只核对了合成、响度与每小节能量曲线。
