## 设计

方向：**一个文件，一片纸**。画面取 sqlite.org 文档的朴素：白纸底、深蓝墨色、平涂、直线连接，不用卡片、阴影与渐变。颜色、标志与标语的出处见 [MATERIALS](research/MATERIALS.md)。

| 元素 | 规定 |
|---|---|
| 颜色 | 墨色 `#003b57`（标志字标）；常驻元素与章节条 `#044a64`（官网导航条）；标志蓝 `#0f80cc` 只给正在走的路线与焦点；浅羽毛蓝 `#97d9f6` 只作被读到的页的底色 |
| 常驻 | 左上角官方标志 sqlite370_banner.svg，右上角章节号与章名，下方一条深青细线 |
| 图形 | 页是全片唯一的基本图形：文件是 553 个格子（7 × 79），树里的每个节点也是页。内部页画成「指针格与分界格交替」的空心框，叶页实心；路线用标志蓝粗线 |
| 主画面 | 01 库内分层到文件；02 整棵 users B+ 树（256 个叶页全部画出）与整棵姓名索引 B 树；03 两条路线逐层点亮；04 叶页 130 按真实比例展开；05 主文件与回滚日志并排、三个进程与三种锁的时间线；06 主文件与 WAL 帧并排、同一时间线对照 |
| 字体 | Inter（拉丁与数字，对应官网的 Verdana）、Noto Sans SC、JetBrains Mono（SQL 与页号，对应官网的 Courier New） |

第 14 稿起的颜色与焦点规则（WaterRun 看 r6：「为什么色彩一直变来变去的看的眼花缭乱 完整梳理解决这个问题 全片的」）：每样东西从出场到退场颜色不变，颜色只表示身份，不表示「正在讲」。

|---|---|
| 白底黑框 | 结构：框、页、文件、表 |

「看这里」只有一种：深青描边的焦点框（parts.js 的 focus()），框住旁白此刻说的那一样（一组就框外接矩形），换对象时滑过去；只在画面上摆着好几样、要观众找到其中一样时才用。新出场的东西靠出场动作吸引视线，不另加框，不给对象改色。

## 交接

主实验显式用 **1024 字节页**；同批 users 与索引另做 **4096 字节页**对照。页号、层数、分裂阈值仅属于本样本，不是引擎常数。

原始 SQL 和完整回显为每组 out_*.txt，可用数据为 out_*.json。第三方源码、工具包在忽略的 research/_src/；二进制数据库在忽略的 out/lab/。

尚未做：函数调用轨迹、真实断电、设备持久性、吞吐与时延、操作系统冷缓存、WAL 模式的崩溃恢复、WITHOUT ROWID 等扩展。08 记录的是 SQLite 向操作系统发出的读请求，不观测系统缓存与设备。

## 复现

`python videos/database-engines/sqlite/research/lab/run_all.py` 重跑 01–10；`python videos/database-engines/sqlite/tools/gen_data.py` 从实测 JSON 生成 `src/js/data.js`，并核对关键数字。

Python 3.10 或更新；首次联网取得经 SHA3-256 核对的官方工具包与源码。其他系统可指定 FT_SQLITE 为同版本命令行程序；当前只在 Windows 实测。脚本不调用 Python 自带 SQLite。每次在本片 out/lab/ 新建目录，不覆盖、删除已有数据库。

公开证据不带个人路径、主机名或凭据。WAL 的盐值与回滚日志随机校验种子会变化，相关二进制哈希不承诺跨次相同；稳定的整树测绘数据可逐字节比较。
