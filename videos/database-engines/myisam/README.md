# 一个数据库引擎是如何实现的？——从 MyISAM 说起

数据库引擎系列第一集的新版：给写过 SQL、没有读过引擎源码的观众，用 MyISAM 引入「数据库引擎」，沿 Alice 与几个同伴的同一段经历，讲清数据怎样落到文件、怎样被找到、怎样被改和删，以及没有事务时同时读写与中途出错会怎样。约 10 分钟，仅中文。[系列说明与全系列文案主线](../README.md)；技术事实唯一来源为 [research/FACTS.md](research/FACTS.md)。

## 简报

| 项 | 内容 |
|---|---|
| 观众 | 写过 SQL、没有读过数据库引擎源码 |
| 核心问题 | 一条 SQL 交给存储引擎之后，数据怎样落到文件里、怎样被找到、怎样被改和删？没有事务的引擎，在有人同时读写、有人中途出错时会怎样？ |
| 在系列里引入什么 | 数据库引擎（存储引擎）这个概念；B 树第一次出场，讲清分界、子页、同层叶子与分裂（见主线的「去重」表） |
| 人物与经历 | 主线的固定人物：Alice 随 4096 个用户注册（2050 号，42 岁），按姓名被查到，过生日改成 43，最后注销；Bob 在她改动时读；Carol 同时要写；Dave 在删除后注册；管理员批量修改时进程被终止 |
| 六个问题 | 增：数据文件一行挨一行、索引文件里一棵 B 树；查：B 树 → 行位置 → 乘法算出偏移；改：定长行原地覆盖；删：删除标记与空位链，Dave 复用空位；事务与并发：没有事务，整表一把锁；出错：没有日志，事后检查与修复 |
| 结构 | 先立整体（两个文件与整棵树），再沿人物的经历进入局部；旧版先拆页字节、后画整树，新版倒过来 |
| 时长与语言 | 约 10 分钟（WaterRun 2026-10-24 给的预期），仅中文 |
| 判断标准 | 直观、清晰：正常速度看一遍就懂，不需要暂停反复看；以旧版 MyISAM 的讲法为基准，不在页内细节上堆负担 |

### 环境的选择

新版改用 **MySQL 9.7.4 LTS**（2026-10-24 官方下载页列出的长期支持版），在本机以官方 Windows 压缩包原生运行，数据目录放在本片忽略的 `out/lab/`。理由：

- 同一个服务器里 MyISAM 与 InnoDB 都可选，「同一条 SQL 交给不同的存储引擎」能在一台服务器上演示，也与新版 InnoDB 一集共用环境。
- 不依赖旧版用过的仿真机，按 SQLite 一集的做法写成可重跑的脚本，固定下载地址与官方 MD5。
- 9.7 的官方手册仍列出 MyISAM（基于已不再提供的 ISAM；B 树索引；有索引缓存、无数据缓存；表级锁；无 MVCC）。

要在 FACTS 里重新核对的变化：8.0 起没有 `.frm`，表定义进了数据字典，MyISAM 表另有 `.sdi` 文件；「MySQL 5.5 起默认引擎改为 InnoDB」作为历史事实单独取证。

### 取证计划

| 实验 | 要回答的问题 |
|---|---|
| 01 环境 | 固定版本、下载地址、MD5 与源码标签；初始化独立数据目录，只监听本机 |
| 02 整体结构 | 建 `users`（MyISAM，定长行）写入 4096 行；目录里有哪些文件；`.MYD` 的行长与 Alice 的偏移；`.MYI` 里主键、姓名、年龄三棵 B 树的全部块与层级，由字节重建并与 `myisamchk` 核对 |
| 03 查 | 按姓名找 Alice：索引路径与行位置；键缓存的请求数与读盘数；扫描对比 |
| 04 改 | Alice 改成 43：同一偏移处前后字节 |
| 05 删与复用 | Alice 注销：删除标记与空位链；Dave 注册写进同一个空位 |
| 06 表锁 | Bob 读着时 Alice 的修改在等；Carol 也在等；进程列表里的等待状态 |
| 07 没有事务 | `ROLLBACK` 撤不回 MyISAM 的修改及其警告 |
| 08 中断 | 管理员给每个人的年龄加一，中途终止服务进程；重启后一半改了一半没改；表被标为未正常关闭，检查与修复 |
| 09 源码定位 | 同版源码里 `storage/myisam/` 的写行、删行、查找、键缓存与表锁入口 |
