## 连贯阅读

先通读问题、解释与章节推进，再到逐句表定位意见。下文按源稿顺序连接字幕，保留原文字与标点；不含静默 cue。口播读法与停顿另按配音规则核对。

### intro · 无章节卡

一条查询，一行结果，零点零零七秒 这一瞬间，数据库在磁盘上做了什么 数据放在哪里，又是怎样被找到的 回答这些问题的部件，叫做*存储引擎* 要看清一个引擎是怎样实现的，*MyISAM* 是很好的起点 它是 MySQL 5 时代的经典引擎，结构足够简单 简单到每一个字节，都可以摊开来看

### s1 · 01 引擎的位置

MySQL 的内部分为两层 上层理解 SQL：解析语句，选择执行计划 下层负责把数据写进磁盘，再读出来 这一层，就是*存储引擎* 两层之间，是一组固定的接口 写入一行，读下一行，按索引查找 引擎可以替换，只要实现这组接口 上层并不关心数据怎样存放 MyISAM 在 MySQL 3.23 加入，接替了更早的 ISAM 在 5.5 版本之前，默认的引擎就是 *MyISAM*

### s2 · 02 一张表，三个文件

用 MyISAM 建一张表，写入八行数据 数据目录里，出现了三个同名的文件 *.frm* 文件记录表结构：有哪些列，各是什么类型 它由上层维护，无论使用哪种引擎都会有 *.MYD* 文件存放数据，也就是每一行的内容 *.MYI* 文件存放索引 后两个文件，就是 MyISAM 的全部 实现一个引擎，本质上是为这些文件定下读写的规则

### s3 · 03 数据文件：定长行

先打开数据文件 它只有 128 个字节，没有文件头 从第一个字节开始，就是数据 每十六个字节，是一行 第一个字节是标志位：表示这一行有效，并记录哪些列为空 接下来四个字节是 id 十个字节是名字，不足的部分用空格补齐 最后一个字节是年龄 每一行的长度都相同，这叫*定长格式* 它的好处是定位简单 第 N 行的位置，就是 N 乘以十六 不需要查找，一次乘法就够了 改一行也不用挪地方：新的一行，写回原来的位置 alice 过生日，文件里只有年龄那一个字节变了

### s4 · 04 删除与空位

删除一行时，文件不会变小 引擎只改写这一行开头的七个字节 首字节写成零，表示这一行已删除 后面六个字节是一个指针，指向上一个空位 再删一行，新的空位又指回前一个 空位连成一条链，链头记在索引文件里 之后插入新行，会先取链头的空位来填 没有空位，才追加到文件末尾 所以，行在文件里的顺序，并不等于插入的顺序

### s5 · 05 变长行与碎片

如果有变长的列，比如 VARCHAR，行的长度就不再相同 这时使用*动态格式* 每一行前面有一个小的头部，写明这一行有多长 空间省下了，也带来新的问题 把第一行改长，原来的位置就放不下了 引擎把放不下的部分写到别处，再用指针把两段连起来 一行数据，就这样分成了两段 更新越多，碎片越多，读一行可能要跳转好几次 整理碎片，要执行 OPTIMIZE TABLE 把数据文件重新整理一遍

### s6 · 06 索引文件与 B 树

只有数据文件时，要找 id 等于 5 的行 只能从头逐行比较 索引文件的作用，就是避免这种扫描 它的开头是文件头，记录整张表的状态 一共多少行，空位链从哪里开始，每个索引的根在哪里 行数直接记在这里，所以统计总行数不必扫描，立即返回 文件头之后，空间按 1024 字节切成一页一页 页里是排好序的索引项 每一项有两部分：键的值，和这一行在数据文件里的位置 八行数据，一页就放得下 数据多了，一页放不下，就分裂成两页，上面再长出一层 这就是 *B 树* 十万行的表，这棵树也只有三层 根页把十万行分成 21 段，下一层每一页再分成几十段 每往下一层，要找的范围就缩小几十倍 主键和普通索引的结构完全相同 存的都是行的位置，而不是行本身

### s7 · 07 一次查询的全过程

现在把这些连起来，看一次完整的查询 在十万行的表里，按主键找 id 等于 4242 的一行 上层调用引擎的接口：按索引查找 引擎从文件头得到根页的位置，读入根页 在页内二分查找，确定该走哪个子页 再向下两层，在叶子页里找到了 4242 它旁边记着行号：4241 行号乘以十六，就是数据文件里的偏移 从那里读出十六个字节，按列解码，交还上层 三次读页，一次读行，查询完成 读过的索引页，会留在内存的*键缓存*里 再查一次，这三页就不必再从磁盘读 数据文件则交给操作系统去缓存

### s8 · 08 并发：表锁

多个连接同时访问一张表，MyISAM 的办法很直接 给整张表加锁 读锁可以共享，多个查询能同时进行 写锁是独占的：一个连接在写，其他连接都要等待 bob 正在统计整张表 carol 想改 alice 的年龄，只能等 bob 读完 只有一种例外 如果数据文件中间没有空位，新行只会写在末尾 这时插入和查询可以同时进行，称为*并发插入* 可只要中间有了空位，新行要先去填空位，插入又得排队 读多写少时，这样的开销很小 写入一多，整张表就成了瓶颈

### s9 · 09 没有日志的代价

简单也有代价 一次插入要改动好几处 数据文件，每一个索引，还有文件头里的行数 MyISAM 不记日志 如果在这些改动之间断电，文件之间就会对不上 这是一次模拟：新行已经写进数据文件 索引和行数还是旧的 这一行明明在磁盘上，却查不出来 文件头里有一个计数器：开始修改时加一，正常关闭时减一 打开时它不为零，说明上次没有正常结束，这张表需要检查 修复的办法，是重新扫描数据文件，重建索引 它也没有事务 执行 ROLLBACK，MySQL 只回一句警告 有些不支持事务的表，没法回滚 改过的数据，原样留在了文件里 不能回滚，崩溃后也无法保证数据完整

### s10 · 10 四个问题

回头看，MyISAM 用最少的机制 回答了一个引擎必须回答的四个问题 数据怎么放：一个数据文件，一行接一行 怎么找：B 树索引，加上行的位置 改和删：原地覆盖，删掉的留下空位，给后来的行 怎么并发：一把表锁 出错怎么办：检查，然后修复 2010 年，MySQL 5.5 把默认引擎换成了 InnoDB 行级锁，事务，崩溃恢复 刚才那句撤不回的 ROLLBACK，在它那里能撤回 它在同样的四个问题上，给出了更复杂的答案 而要读懂那些答案，可以从这三个文件开始
