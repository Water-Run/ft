## 连贯阅读

先通读问题、解释与章节推进，再到逐句表定位意见。下文按源稿顺序连接字幕，保留原文字与标点；不含静默 cue。口播读法与停顿另按配音规则核对。

### open · 无章节卡

4096 个人，住在同一个文件里 其中一个叫 Alice，42 岁 要在四千多人里找到她 MySQL 只读了 3 块索引，和 56 个字节 一行结果，转眼就回来了 这一瞬间，磁盘上发生了什么？ 回答这个问题的部件，叫*存储引擎* 要看清一个引擎是怎样造出来的，*MyISAM* 是很好的起点 它简单到每一个字节，都可以摊开来看

### layers · 01 引擎的位置

MySQL 的内部分成两层 上层读懂 SQL：解析语句，选定执行计划 下层把数据写进磁盘，再读出来 这一层，就是存储引擎 两层之间是一组固定的接口 写入一行，读下一行，按索引查找 只要实现这组接口，引擎就可以替换 本片用的 MySQL 9.7.4 里，就并排放着好几种引擎 默认的 InnoDB 支持事务，MyISAM 不支持 MySQL 5.5 以前，默认的就是 MyISAM 它的结构足够简单

### files · 02 一张表，三个文件

用 MyISAM 建一张 users 表，住进 4096 个用户 数据目录里，多出了三个同名的文件 .sdi 记着表的结构：有哪些列，各是什么类型 表结构登记在 MySQL 的数据字典里，这是它的一份副本 .MYD 放数据，每个人一行 .MYI 放索引 后两个文件，就是 MyISAM 的全部 造一个引擎，说到底，是给这些文件定下读写的规矩

### fixed · 03 数据文件：定长行

先打开数据文件 它没有文件头，第一个字节就是数据 每 56 个字节，是一个人 第一个字节是标志，表示这一行有效 接着 4 个字节是 id，低位在前 50 个字节是名字，不够就用空格补齐 最后 1 个字节，是年龄 每一行都一样长，这叫*定长格式* 找位置不用找：第 n 行，就从 n 乘以 56 开始 Alice 的行号是 2049，乘以 56，就是第 114744 个字节 她过生日了，年龄从 42 改成 43 引擎回到同一个位置，只改写了最后一个字节

### holes · 04 删除与空位

有人注销了账号：2 号用户 文件没有变小，引擎只改写了这一行开头的 7 个字节 第一个字节写成 0：这里已经没有人了 后面 6 个字节，记着下一个空位在哪 5 号也注销了。新的空位，指回 2 号留下的那一个 空位连成一条链，链头记在索引文件里 Dave 来注册。引擎先看链头，让他住进 5 号的位置 下一个新用户，住进 2 号的位置 再下一个，没有空位了，才排到文件末尾 所以，文件里的先后，并不是注册的先后

### dynamic · 05 变长行与碎片

留言有长有短 表里一旦有 VARCHAR 这样的变长列，行就不再一样长 这时用*动态格式*：每一行是一块，块头写着它有多长 Alice、Bob、Carol 各留了一句话，三块首尾相接 后来，Alice 把留言改长了 原来那一块，放不下了 引擎把放不下的部分写到文件末尾，在原处留下它的地址 一行，就这样断成了两段 一行分成几段，读它就要跟着地址跳几次 要重新拼好，得用 OPTIMIZE TABLE 把整个数据文件重写一遍

### btree · 06 索引文件与 B 树

只有数据文件时，要找 Alice，只能从头一行一行比过去 索引文件，就是为了不这样做 它的开头是文件头：一共多少行，空位链从哪开始 每个索引的根在哪一块 后面的空间，按 1024 字节切成一块一块 每一块里是排好序的索引项：一个名字，加上这一行的行号 从空表开始，一个一个住进来 前 20 个名字，一块就装下了 第 21 个来时，这一块装不下了 分成两块，上面长出新的一层 新的根里只放了一个名字；左边 19 个，右边 1 个 这就是 *B 树*：每一块都排好了序 上一层告诉你，往下该走哪一块 住满 4096 人，姓名索引长成了三层 一个根，12 块中间层，205 块叶子 中间层里的每一项，也是一个真实的人 索引里存的不是那一行，只是它的行号

### query · 07 一次查询的全过程

现在，把这些连起来：按名字，找 Alice 上层调用引擎的接口：按索引查找 引擎从文件头找到根，读入第 260 块 A 排在所有名字前面，走最左边：第 62 块，再到第 43 块 4096 个名字，过了根只剩 360 个，再下一层只剩 20 个 叶子里的第一项就是 Alice，旁边记着行号 2049 行号乘以 56，到数据文件读出 56 个字节，交还上层 第一次查询，从磁盘读入了 3 块索引 再查一次，这 3 块都留在内存的*键缓存*里，一块也不用读 数据那一行，却还要再读一次 MyISAM 只缓存索引，数据交给操作系统 如果不用索引，就要把 4096 行一行一行读完

### locks · 08 并发：表锁

许多人同时用这张表 MyISAM 的办法很直接：给整张表上锁 Bob 正在翻看整张表 Alice 想改年龄，Carol 也想改，都只能等 Bob 看完 反过来，Alice 改的时候，Bob 和 Dave 也得等她 只有一个例外 文件中间没有空位时，新行只会写在末尾 Bob 读着，新用户照样能在末尾注册，这叫*并发插入* 可一旦有人注销、文件里留下空位，新来的人也得排队 读多写少时，一把表锁很省事 写的人一多，整张表就成了一道窄门

### nolog · 09 没有事务的代价

MyISAM 没有事务 Alice 开始一个事务，改了年龄，又说要回滚 MySQL 只回了一句警告：有些表不支持事务，没法回滚 改过的年龄，留了下来 同样几句话，换成 InnoDB 的表，年龄就回到了原样 再看出错的时候 管理员要给每个人的年龄加一 改到一半，服务进程被强行结束 重新启动：前 155 个人老了一岁 后面 3940 个人，还是原样 没有什么把它补齐，也没有什么把它撤回 文件头里有个计数：开始修改时加一，正常关闭时减一 它停在了 1：上次没有正常结束 CHECK TABLE 报告：年龄索引和数据对不上，表已损坏 REPAIR TABLE 能把表修好，却修不回那改了一半的数据

### outro · 10 回到开头

回头看，MyISAM 用最少的东西 回答了一个引擎必须回答的问题 数据怎么放：一个文件，一行挨着一行 怎么找：B 树给出行号，一次乘法找到位置 怎么改，怎么删：原地覆盖，打上标记，空位留给后来的人 怎么并发：一把表锁 出错怎么办：检查，然后修复 MySQL 5.5 起，默认引擎换成了 InnoDB 那一句没能撤回的回滚，在它那里，能撤回 它在同样的问题上，给出了复杂得多的答案 而要读懂那些答案，可以从这三个文件开始
