## 简报

策划者 WaterRun 原话：

- 2026-10-26：「现在 可以思考下一期 PostgreSQL了. 开场白还是占用率, 用户基于看完InnoDB. 当然, 新版本的内容要详细的多. Pg的美学很有特点, 你应该一个视觉稿就能契合.」「pg用最新生产版本」
- 2026-10-26，标题：「开源巅峰这个标题可能不够好, 体现老牌又成新潮代替MySQL 正统SQL等的特点, 和我探讨新标题」「需要体现Pg的严肃性的」；从候选里定为「学院派的正统吧」。新标题：**学院派的正统：PostgreSQL**。片里要撑住它：伯克利 Ingres、POSTGRES 的学院出身与 Stonebraker 的图灵奖（学院派）；对 SQL 标准的高符合度、约束在库内强制执行、DDL 也能在事务里回滚（正统、严谨）；「老牌」与「在开发者调查里超过 MySQL」放在开场讲。不写「取代 MySQL」：调查是自报、可多选，不说明市场份额或迁移。
- 2026-10-24（[P54](../../../docs/log/feedback.md#2026-10-24数据库引擎系列的重做与全系列计划)）：「另外落盘计划, 前几期要重做. MyISAM的叙事很好, 主要是美术风格不够契合MyISAM的问题. InnoDB, Pg的也还行吧, 但是显然比如B树都没有缺漏还是大的.」「重置版本包括Credit的更新完整.」
- 2026-10-24（系列「制作顺序」）：「Pg引入第二种实现(开场白还是占有率)」；侧重（P61）：「InnoDB引入事务性当然大头是事务, Pg前面讲过那就不是重点了」。
- 2026-10-25 系列约定（[系列说明](../README.md#共同约定)）：每集回答五个问题、倒数第二章；封面立体、有质感、可读；片尾用数据库查询列名单；不放产品标志，视觉契合本集引擎（P84：「比如下一期的Pg, Pg的视觉风格和独特明显」）。
- 旧版的评价（2026-10-20，8 分，P30–P32）：「设计风格还是很契合 Pg 的，叙事整体也不错」「主要出在动画过于简陋，缺乏视觉冲击力」。

由此定下：观众看过 InnoDB 一集；开场仍用占有率；本集的重点是**另一种实现**，处处与 InnoDB 对照——表是堆、每个索引各是一棵树、修改写新版本、旧版本留在表里、回收靠 VACUUM、不需要 undo 也能崩溃恢复；事务与预写日志的概念 InnoDB 已讲，这里只讲 PostgreSQL 自己的做法。内容比旧版详细得多：整体结构实测画全，增删查改、并发、回收、恢复每一步都走 Alice 的同一行。

## 叙事提纲（草案，待取证后写成文案）

人物与数据沿用系列：`users(id, name, age)` 4096 行，2050 号 Alice 42 岁（与 InnoDB 一集同一张表，便于对照）；Bob 读、Carol 同时写、Dave 注册。

| 章 | 要回答的 | 主画面（PostgreSQL 自己的对象） |
|---|---|---|
| 开场 | 开发者调查里 PostgreSQL 与 MySQL 的此消彼长（2022 → 2026，补齐中间年份）；看过 InnoDB 的观众，把同一张表、同一句 UPDATE 交给 PostgreSQL：改一行，页里多了一行 | 调查条形；InnoDB 与 PostgreSQL 并排的一页（视觉稿第 1、2 帧） |
| 01 来历 | Ingres → POSTGRES（Post-Ingres）→ Postgres95 加上 SQL → PostgreSQL；伯克利、社区、对象关系、宽松许可；每年一个大版本，今天的 18 | 一条年代线，版本节点；只交代到能看懂 |
| 02 一张表放在哪 | 一张表 = 一个堆文件（8 KB 一页，按到达顺序）+ 每个索引各一个文件（主键树、姓名树）+ FSM、VM 两个小文件；4096 行实测：堆多少页、两棵树各几层、行的地址 ctid；与 InnoDB「表就是主键树」对照 | 堆页条与两棵实测 B 树，叶子指向堆页（第 3 帧） |
| 03 一页之内 | 页头、项目指针从前往后、行版本从页尾往前；元组头 23 字节：xmin、xmax、t_ctid、标志位；Alice 那一行的实际字节 | 手册「页布局」的横向画法（第 4 帧） |
| 04 增 | Dave 注册：FSM 找有空的页、写元组、加项目指针；再往每个索引各插一项；索引页满了分裂（B 树形状前两集已讲，用本集实测树简述） | 行落进堆页，两棵树各长一项 |
| 05 查 | 规划器怎样选顺序扫描还是索引扫描（EXPLAIN）；按名字找 Alice：姓名树 → ctid → 堆页 → 项目指针 → 元组 → 可见性检查；仅索引扫描与 VM；与 InnoDB 回表对照 | 一条完整路径，逐层亮起 |
| 06 改 | Alice 42 → 43：不覆盖，写新版本；旧版本记下 xmax、t_ctid 指过去；改了索引列时每个索引都要插新项，只改 age 且同页有空时走 HOT，索引不动；与 InnoDB 原地改 + undo 对照 | 页里两版并存、版本链、HOT 的页内跳转 |
| 07 事务与并发 | 事务号、提交状态（pg_xact）、快照；可见性规则；Bob 在 Alice 未提交时读到 42；PostgreSQL 默认读已提交，下一句就读到 43，可重复读仍是 42；Carol 同时改同一行要等 Alice 结束；死锁检测 | 快照数轴与提交状态（第 5 帧），两人的泳道 |
| 08 删与回收 | Alice 注销：DELETE 只写 xmax，行还在；VACUUM 等所有快照都不需要时收回空间、清掉索引项、项目指针改成重定向或空闲；autovacuum；长事务挡住回收；事务号 32 位，冻结防回绕；Dave 住进腾出的空间 | 页里的死元组、VACUUM 扫过（第 6 帧） |
| 09 出错怎么办 | WAL：提交等日志落盘，脏页稍后写回；检查点；检查点后第一次改某页，整页写进 WAL（对照 InnoDB 的双写缓冲区）；强行结束进程后从检查点重放；没提交的不用撤——在 pg_xact 里不是已提交，元组本来就看不见（对照 InnoDB 的 undo 回滚） | WAL 带、崩溃与重放 |
| 10 五个问题 | 片尾总结式，一屏五块，各用前面的画法重演一个最小过程 | 同 InnoDB 一集的版式，换成本集的对象 |
| 11 取舍与引出 | 与 InnoDB 的取舍（主键读、二级索引、更新的写放大与 HOT、回收与膨胀、默认隔离、可扩展：类型、索引方法、扩展）；开源两巨头之外，一个更小众、既能当服务也能嵌进程序的引擎 | 两种实现并排收束 |

时长参照约 15 分钟（`project.json` 检查范围 720–1080 秒），以讲清、跟得上为准；取证后按实测内容再定每章长短。

## 设计

视觉稿 R1：[review/keyframes-r1.html](review/keyframes-r1.html)。一种风格，七帧：开场占有率、改一行多一行、整体结构、一页之内、快照与可见性、VACUUM、片尾名单。

- **语汇取自 PostgreSQL 官方文档，不放大象标志**：Pg 蓝 #336791 是 PostgreSQL 与此刻在讲的东西；深蓝 #193145；浅蓝 #699eca 是旧版本、快照与路径；文档表头 #e0ecef；MySQL / InnoDB 用中性灰；砖红只给拒绝、等待与「还在进行」。Open Sans（拉丁与数字）、中文黑体、等宽字给 psql。
- **文档的部件当画面部件**：带横线的蓝色标题；「图 n」图注；注解用文档的「注意」框，贴在被解释的东西旁边；所有 SQL 都以 psql 会话出现（`postgres=#`、对齐的结果表、`(n rows)`）；pageinspect 的原样输出就是「实物」。
- **主画面是 PostgreSQL 自己的对象**（旧版评价「动画过于简陋」，F18）：一长条 8 KB 的堆页、两棵独立的 B 树、带 xmin/xmax 的行版本、快照数轴、pg_xact、VACUUM 的扫过、WAL 带。每章一个主画面，过程逐步推进。
- **镜头**：沿用 InnoDB 一集最终版的连续二维微动（WaterRun 2026-10-26 对 InnoDB 镜头的最新要求），画面静止靠内容的分步变化。
- **封面**：立体、有质感、可读——一摞 8 KB 堆页的立体，页里看得见新旧两版行，上方一棵索引树；集数标签、问句、大标题与实测数字；图形取自本片，不沿用别集。
- **片尾**：psql 里 `SELECT * FROM credits;`，名单只取自 `project.json`（视觉稿第 7 帧）。
- 视觉稿里的数字都标了出处：调查数字为旧版取证（新版重核）；行版本与页的数字为旧版在 18.4 上的实测（alice 30 → 31），新版在 18.6 上用 Alice（2050，42 → 43）重测；未实测的只画结构。成片里不用渐变（稿里的斜纹与网格到实现时改成平涂或 SVG 图案）。

## 声音

- **配音**：系列一集男声、一集女声交替（InnoDB 是女声），本集用男声。文案定稿后，按 InnoDB 一集的语速（1.2）出 5 个男声候选给 WaterRun 试听；`project.json` 里的音色只是占位。
- **配乐**：WaterRun 2026-10-26：「配乐也是学术派的, 体现Pg的庞大严谨史诗」。本集重写为一首**赋格**：D 小调，庄重的慢主题，管风琴与弦乐的音色；第二声部在属音上回答，对题随后，一声部一声部按规矩进入——最讲规矩的作曲形式对应「学院派的正统」。和内容呼应：写新版本时多进一个声部、织体变厚，VACUUM 时声部依次退出回到干净的主题，WAL 是持续的低音踏板，崩溃时全体停一拍、重启后从主题重新进入；章节高潮全声部合奏，加低沉的重击；开场与片尾用完整的合唱式和声。和 MyISAM 的终端电子乐、InnoDB 的「两个事务」区分开。先做约一分钟的小样，和男声候选放在同一个试听页给 WaterRun。
