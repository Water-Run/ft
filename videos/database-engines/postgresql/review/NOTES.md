做法（参照 MyISAM 一集 README「设计」里写下的原则，不抄它的画面）：

- **物理结构先在场**：每个文件画成它真实的页（8 KB 一页、页号），页里按真实布局画页头、指针、从页底往上放的行；逻辑结构（表、B 树）画在上面，用线连到它在文件里的那一页。读到哪一页，就在那个文件条上点亮哪一页。
  - 实测里的好例子：年龄树 7 页，第 0 页是元数据页、第 3 页是根，叶子按键排是第 1、5、4、6、2 页，逻辑顺序与在文件里的位置不同。
- **跟得上、不过载**：
  - 讲谁亮谁，旁边的压暗；
  - 一屏只留正在讲的主画面，用过的标签及时收走；
  - 按词对齐的画面统一提前 0.12 秒（`parts.js`）。
- **不抖**：
  - 镜头不漂移（换屏时 0.04 秒回位就是抖动的来源）；
  - 不对边框粗细做动画。
- **配音**：
  - 「PostgreSQL」合成写作「Postgres-QL」；
  - 中文与英文、数字之间的空格合成前去掉；
  - 字母之间的空格保留（试读：「SQL先」会念歪，「S Q L二零二三」连贯）。
- **逐章**：
  - 开场：讲 InnoDB 时 PostgreSQL 一侧压暗、反之亦然，最后打出「PostgreSQL 的路」；

### 病根

r1、r2 是「每句话贴一个标签或一段 SQL」的幻灯片：主画面不动，变化靠小字出现。像素检查过了，观众还是跟不上。改造的标准：

- **每章一个会动的主画面**，占满版面中央。每句旁白都让它发生一步看得见的变化，比如移动、变形、写入、划掉、流向。这一步卡在说到那个词的时刻，不靠标签解释。
- **SQL 不是闪一下**：命令逐字敲出（`keyed` 按时间分段），执行时这条命令「送进」引擎的画面；结果行逐行滑入。随后主画面演出这条命令做了什么。
- **反复出现的对象连续变形**，不重新出现：名字、页、行版本、事务号都一样。不闪来闪去，进出要衔接，例如从上一个位置移过去。
- **不过度**：一个意思一个动作，不做装饰性运动。
