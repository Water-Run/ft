## 简报

- **目标观众已有的知识**：写过 SQL，知道表、行、索引；没有读过数据库引擎源码；不一定看过本系列前几集（单集独立可懂，F10）。
- **看完能回答的一个核心问题**：没有表、不写 SQL 的 MongoDB，把一份文档交给 WiredTiger 之后，数据实际怎样存在磁盘上、怎样被找到和改动，又怎样在并发和崩溃时保持一致？
- **用哪个具体例子走完解释**：本系列同一批 4096 个用户，Alice 是第 2050 个、42 岁（FACTS「环境与版本」）。她注册（47 字节的 BSON，13 字节是字段名；RecordId 2050；三棵树各一项）→ 被按名字找到（姓名索引第 1 项 → 集合树第 2 个叶页）→ 过生日改成 43（更新链；检查点把整页写到文件末尾，旧页不覆盖，索引记的是 2050 所以不用改）→ 注销（删除标记；Dave 拿到 4097，他那一页用上第 2 个叶页最初的位置）→ Bob 快照读、Carol 写冲突 → 强制结束后从检查点重放日志。关键因果：WiredTiger 只认「键→字节」的 B 树；内存页与磁盘页是两种格式，检查点才把缓存里的改动整理成新块写出；不覆盖写换来新检查点写完之前，上一个检查点始终完好。边界：各章实验都从同一份新装的数据出发（B09、B10），旁白在第 03 章交代一次、各章开头再点明；并发一章用单节点副本集；崩溃实验是单机上的进程被强制结束，不是断电。
- **逐章怎样推进**（第 2 稿，章名即章节卡的问题）：
  - 开场：Alice 存进去、原样找回来，没定字段、没写 SQL → 前五期（点名）都是先建表、用 SQL 的关系数据库，ClickHouse 拆成列也还是表 → MongoDB 不一样 → SQL 前面加 No：NoSQL、非关系型数据库、四类（MongoDB 是文档数据库，键值数据库最后还会遇到）→ 文档与集合，people 集合里样子各不相同、字段名随文档存 → 问题还是那几个，答案要找到 WiredTiger。
  - 01 一个集合，三棵树（没有表，文档放在哪里？）：mongod 与存储引擎；WiredTiger 只认键和值、当字节存；一个集合 = 三个文件三棵树。
  - 02 增（写下了什么？）：ObjectId、BSON 逐段（13 字节是字段名）、RecordId 2050；三棵树里各放什么，为什么姓名索引把 2050 接在键后；姓名索引是后建的；之后的注册一个内部事务写三棵树。
  - 03 落盘（什么时候进文件？）：文件只有 4 KB → 缓存；60 秒的检查点；两种页的格式、整理与压缩；文件里树的真实形状，在这里给 B 树起名；交代每章重新装数据。
  - 04 查（走了哪条路？）：没有索引扫 4096 份；有索引 1 个键 1 份文档，按实测分界走；年龄没有索引；索引的代价。
  - 05 改（磁盘上改了什么？）：更新链；检查点把整页写到新地方，索引不用改，旧页不覆盖，文件 96→132 KB。
  - 06 删（去了哪里？）：删除标记；2049 后面就是 2051；文件没变小；Dave 4097 不复用编号，但用上了空出的块。
  - 07 事务与并发（谁等谁？）：内部事务与应用事务之分、单节点副本集；快照让 Bob 读到 42；写冲突与整个事务重来（乐观并发）；不开事务时服务端重试。
  - 08 出错怎么办（丢了什么？）：日志每 100 毫秒落盘，默认写法与 j: true；崩溃后检查点 + 重放；默认写法立刻结束两轮 5 次分别留下 0、1 次，j: true 与隔 0.3 秒都在；只测了结束进程。
  - 09 五个问题：系列约定的五问。
  - 10 不是 SQL（换来什么，付出什么？）：字段自由 vs 字段名重复；数据住在磁盘的树里 → 还能不能更简单一点：键值数据库、内存 → 进程一死靠什么回来 → 更简单的 Redis。
- **决定不讲的材料与理由**：KeyString 的名字与编码细节（只说「按字节排好序」）；WT_INSERT 与 WT_UPDATE 的区别（统一讲「挂新版本」）；缓存大小公式、系统库的文件、`_mdb_catalog`、`sizeStorer`（画面注解可用，旁白不讲）；副本集与 oplog、分片（不是存储引擎的问题）；聚合管道（与引擎实现无关）；断电与操作系统缓存（本片没有实测）；WiredTiger 成为缺省引擎的具体版本（单一出处待核实）。
- **时长上限与语言**：系列参照约 11 分钟、不是硬上限；策划者 2026-11-17 要求「至少13分钟」。第 2 稿按试听实测语速推算约 19 分 16 秒（第 1 稿同口径 11 分 49 秒），是否压缩列为待定问题。只做中文。

| 表格、步骤 | 文档页表格（灰表头、细分隔线）；带圆形序号的步骤卡 | 三棵树各一项、两轮五次的实测、五个问题（「讲在」一栏是蓝色下划线的章节链接）；写关注的两种回复时机、崩溃实验的步骤 |
| 徽标、行内代码 | LeafyGreen 式的圆角徽标（浅底细边）；等宽浅灰行内代码 | 状态与条件（已提交、unique、用不上） |
| 章末 | 文档页底部的「下一页 → 07 删」 | 改、删、并发三章的结尾问句 |

亮绿 #00ED64 仍只给正在讲的那一样东西，红色只给出错与丢失；不用阴影、渐变（`flat: true`）。字体以 Noto Serif SC、Inter + Noto Sans SC、JetBrains Mono 代替 MongoDB 自有字体。


**第 4 轮（2026-11-21）：全片重做。** 策划者看 r3 时说「这整幕的画面都改 太低级了」「动画太简陋是普遍问题」「太简陋太PPT了」「整个图注全部改下, 参考前几期, 现在的毫无意义令人迷惑」「什么时候该有得有 什么时候不该有得没有, 注解的内容」「还有各种框啊什么的细节问题, 以及动画过度」「镜头晃来晃去的老毛病甚至出现了」「好好改改, 看看前5期」。对照前几集的成片后定下的做法：

| 部件 | 第 3 轮 | 第 4 轮 |
|---|---|---|
| 主画面 | 零散的小卡片、药丸、提示框，大片留白 | 每章一个大而满的实物：第 01 章时间轴 + 每个年代一幅会动的图；02–07 章「上面内存、下面磁盘」的同一个舞台（缓存里的页、集合树、按真实偏移排开的文件带），块的搬动照实测偏移；08 章泳道与时间轴；09 章检查点、日志与实验步骤 |

| 指认 | 药丸复述字幕 | 念到哪一样，框到哪一样（带 data-name 的指认框淡入淡出），或那一样变色、分步出现；不复述字幕 |
