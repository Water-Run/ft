## 简报

**定位：引入现代数据库引擎与事务性的一集，作为引子。** MyISAM 一集引入了「存储引擎」；这一集引入「事务」——现代数据库引擎的核心。观众看完要能说清：事务是什么，InnoDB 怎样做到全成或全不成、同时读写互不干扰、崩溃后回到一致。

## 取证计划

环境：MySQL 9.7.4 LTS 官方 Windows 版，原生运行在临时数据目录（与 MyISAM 一集的补充实测同一版本），实验脚本放 `research/lab/`。旧版的 9.7.2 实验由「GPT-6（型号未记录）」完成，型号确认不了，新版不沿用其数据，只把 `research/r8/` 当线索与出处索引。

| 项 | 要得到什么 |
|---|---|
| 整棵树 | users（4096 行）与大表的主键树、姓名索引树：每层几页、页号、每页多少条记录、键的范围、页的填充（直接按页解析 `.ibd`） |
| 一行 | Alice 那一行在叶页里的字节：记录头、主键、事务号、回滚指针、各列 |
| 增 | 插入落在哪一页；页满分裂前后的页与层级 |
| 查 | 主键查与姓名查的访问路径（回表）；缓冲池命中与读盘 |
| 改 | 原地改行、行头的事务号与回滚指针变化、undo 里的旧值 |
| 删 | 删除标记；有读视图挡着时记录仍在页里，提交后 purge 移除 |
| 事务 | 回滚；可重复读与读已提交下的快照读；锁定读 |
| 锁 | 记录锁、间隙锁挡住插入（幻影）、死锁检测与回滚 |
| 出错 | 强行结束进程后重启：已提交的在、未提交的回滚；redo、检查点与 doublewrite 的配置实查 |
| 史实 | Innobase、2005 年 Oracle 收购、2010 年 5.5.5 成为默认引擎等，沿 `research/r8/` 的出处重新核对 |
