# Lua 语言的设计哲学：一切皆表

本片讲 Lua 为什么把全部数据结构压成一张表、这条统一思想如何延伸出元表、闭包与一等值，以及它为此付出了什么代价。目标时长 8–10 分钟，中英双语各一版。

制作流程与标准见仓库的 `docs/`；片中每一句陈述的出处见 `research/FACTS.md`。

目标观众已有的知识：写过至少一种脚本或动态语言（Python、JavaScript、Ruby 之一即可），知道变量、函数、数组与字典的基本概念；知道「Lua 是脚本语言」或听过它嵌在软件里。不需要写过 C，不需要读过 Lua 手册，不需要知道元表与闭包。

看完应能回答的一个核心问题：Lua 只提供一种数据结构，它凭什么既能当数组、又能当字典、还能当类和闭包？代价在哪里？

逐章怎样推进问题、最后回答什么：
- open —— 用「一份配置文件要交给一个没装过这个语言的人」这件具体事引出：Lua 里没有数组类型也没有字典类型，只有一张表；给出本片路线。
- ch1 为什么只有一种数据结构 —— 回答「表为什么够用」：一张表同时是数组、字典、记录、集合；数组部分与哈希部分；键是任意值。
- ch2 元表：把行为也变成数据 —— 回答「表怎么获得类型」：元表是普通表，元方法挂事件；`__index` / `__newindex` / `__call` / `__add` 分属两条路径；元方法 raw 查找；每种类型共享一个元表。
- ch3 函数、闭包与一等值 —— 回答「函数凭什么能和表平起平坐」：所有值都是一等值，函数是值，闭包捕获的是变量本身。
- ch4 值的内部 —— 回答「这统一背后编译器在做什么」：数字的两个子类型、字符串 intern、轻量 userdata 是指针值。
- ch5 代价与边界 —— 回答「这条思想的代价是什么」：`#` 只给一个边界、元表查找是运行时开销、没有类、字符串到数字的强制转换是历史包袱。
- ch6 5.x 演进与版本差异 —— 回答「统一思想在 5.x 里怎么变」：5.3 的整数子类型、5.4 的待关闭变量、5.5 的全局变量声明；同一段代码在三版上的实测差异。
- outro —— 回到核心问题：一张表加一张元表，换来的是小、嵌入容易、可移植；付出的是运行时开销与若干历史包袱。

本片决定不讲的材料及理由：
- Lua 的垃圾回收算法与分代回收细节 —— 属于实现机制，不服务于「一切皆表」这条思想，且会挤掉元表与闭包的解释时间；只在 ch6 用一句带过 5.5 改为增量完成大规模回收。
- LuaJIT、其它实现与各语言的比较 —— 本片讲 Lua 自己，不做横向评测。
- 与「电子发展史」系列《Lua 语言的发展史》重叠的版本沿革细节 —— 两片角度不同：那一集讲时间线上的演进，本片只讲取舍；本片只在 ch6 用三次发布日期交代版本坐标。
- tagged NaN 给 light userdata 打标签的做法 —— 官方手册与 5.5.1 源码中均无记载，按 `FACTS.md` 的 L35 记为待核实，不进定稿；改为讲已核实的「轻量 userdata 是值、无独立元表、按地址相等」。
- 协程、模块系统、包管理与标准库细节 —— 与本片思想无关。

- **转场**：章节之间用镜头在同一张表上推进或拉远完成，不用整屏擦除；只在换章时允许一次淡入。
