# 编程语言哲学

## 定位

| | |
|---|---|
| 讲什么 | 一门语言的设计哲学：这门语言的一条统一思想——它为什么长成这样、在什么地方取舍 |
| 面向谁 | 写过程序、想知道「为什么这样设计」的观众 |
| 怎么讲 | 讲思想从哪来、解决什么问题、代价是什么；每个论点配一段能运行的短代码，实测输出作为证据；严格事实核查，设计者的原话与实现细节回到原始文档与源码核对；统一视觉风格与节奏 |
| 每集多长 | 建议 8–12 分钟，围绕本片主旨按内容取舍 |
| 语言 | 只做中文（缺省，2026-10-24 起） |

**收录的语言**（片单顺序）：Lua、Python、MiniScript、Rust、Zig、Nim、C#、F#、Fish、PowerShell。只收有统一思想的语言；函数式、面向对象一类的编程范式不在本系列。

**与实现类独立片的分界**：本系列围绕语言的设计哲学；Lua 源码解析等独立片围绕实现。每片明确一条可展开、可论证的主旨，语法、特性和历史都服务于这条主旨。

**与「电子发展史」系列里语言史各集的分界**：`../silicon-history/` 里的 Python、Lua、C、Java、C#、JavaScript 与 TypeScript 几集讲的是时间线上的演进与版本转折；本系列讲的是这门语言的设计哲学。设计哲学与语言史围绕各自的问题展开，不互相照搬。

## 共同约定
各集真正共享的约定记在这里，一项一行。视觉与配乐默认每集取自本集的讲解对象（经验规则 F16、F21），除非下面写明了策划者的决定；某一集的设计决定写在那一集的 README。要改约定先改这里。写法见 [系列](../../docs/guides/series.md)。

| 项 | 约定 |
|---|---|
| 标题 | `<语言> 语言的设计哲学：<一条思想>`，思想一句话点出该语言最值得讲的一点 |
| 主旨 | 每片立住一条明确、可论证的思想；在简报里写清核心问题与要回答的判断，用例子、设计取舍和代价把它展开 |
| 结构 | 围绕主旨组织推进，结尾回应开头的问题；不按特性清单逐项罗列 |
| 视觉与声音 | 按本页定位保持系列视觉风格与节奏；首集将实际共用的版式与节奏约定写回这里。各集的图形取自自身对象、配乐按内容设计，不把上一集的具体方案当作模板（F16、F21）。 |
