**口吻变了：去掉制作方的腔调。** 第 4 稿的口语是「整理过的口语」：路标句（b1「先说最要紧的：」、x1「下面这些，哪种模式都能用」）、安抚句（b9「谁也不碍着谁」、w6「就专心写」）、对称的两段式（「不用……也不用……」「不管是……还是……」）。策划者的写法：

- **用观众已经认识的东西作参照**：x3b「和 Claude Code 的 /btw 类似」、x4b「这个则类似于 Codex 的 /side」。第 4 稿刻意不提别家产品，只用功能本身解释。目标观众本来就用编码智能体，类比一句话就讲清，比解释机制快。
- **用圈内的梗和直白的语气**：y2「现在是梁文峰还是梁文谷」（谐「高峰 / 低谷」）、s5「再套一层马甲」、y6「对于有这种癖好的用户」、y7「还不满足的话」、s7「否则后果自负」、d2「其实啥都能干」。
- **对观众说话，给建议**：d2b「你不知道选什么的时候，选这个就行」、y1「进入页面，你会发现……」、w2「你可以把……」、w3「并勾上你这次想要用到的」。
- **以产品名开头介绍功能**：x1「DeepSeek Harness Uncensored 还提供了一系列便于使用的通用增强」、x11「DSHU 另外引入了输入预测」、k1「对了，DSHU 还有……」——每样功能都挂在品牌名下，不用结构性的过渡句。
- **先说需求，再给命令**：x2「主线正在跑一个长任务，你想搞明白进度如何」→ x3「直接 /btw，这叫随问」。顺序也改了：先讲最常用的随问，再讲旁问；旁问之后给用法小窍门（/clear、关掉自动清空），不讲保证。
- **一件事一句话**：第 4 稿用两句讲 dsh-purge（b4「破甲这部分，用的是 dsh-purge 的成果」、b5「具体是它还在用 MIT 许可时的那一版」），再另起一句讲破甲内置；策划者合成一句「DSHU 沿用 dsh-purge 早期的 MIT 版本，直接内置了破甲提示词」。开场也删掉了与 01 章重复的 o5，以及口播缩写的 o3b。
- **结尾给动手的余地**：新增 f4a「DSH 是 TypeScript 写的，你当然也可以自己打包一个」。
- **术语注解标记全部去掉**（案件、独立代理、文风卡、旁问、随问）：宣发片里这些名字看界面就懂，或者已由类比讲清，不需要停下来下定义。

**事实仍以 FACTS 为准，但要分清事实与说法。** 改写稿里有几处与出处不符（「参考」应为「沿用」、「每次开启时自动清理」、「点一下金额」看余额曲线），核对后按出处修正。制作方第一轮还改了「实验功能」「可选的」两处，策划者要求保留：前者是作者对自己功能的定性，后者与事实（可以关掉）不矛盾。核对时只改与出处冲突的地方，不借核对把作者的说法换成自己更稳妥的措辞。口吻可以放开，事实不能跟着放开。
